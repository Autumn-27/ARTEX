# 逆向PWN · 算法/加密还原的思路

### 拿到二进制第一步:先测熵、看装载、别急着反编译
**Q1**: 手上一个陌生 ELF/PE,不知道是明文逻辑还是加壳/加密,该先做什么决策?
**A1**: 别急着丢进反编译器。先做零成本侦察:`file`/`strings`/`binwalk`,再对整段和 `.text` 分别测熵。熵接近 8 且入口段极小 = 加壳或自解压;熵中等且有大量可读字符串 = 明文逻辑,直接静态。判据是"熵梯度":壳的特征是"小解压桩 + 高熵大 blob"。
**Q2**: 熵很高但 `strings` 又能看到不少库函数名,矛盾了?
**A2**: 说明只加密了数据段/资源,代码段没壳。这类目标算法逻辑往往在明文代码里,加密的只是常量表(S-box、密钥、flag 密文)。优先反编译代码,把高熵 blob 当"待解密数据"标记,不要浪费时间脱壳。
**Q3**: 确认加壳了,是自己脱还是硬啃?
**A3**: 先查已知壳(UPX/themida/vmprotect 特征段名、`upx -d` 试脱)。已知壳有现成工具就别手工。判据:花在脱壳的时间不该超过总预算的 20%。
**Q4**: 脱壳这条路被墙了(反调试 + 变形壳,脱不出干净 dump)怎么办?
**A4**: 转正交维度——不脱壳,改在运行时抓。壳最终要把明文代码解到内存执行,用 OEP 断点 / 内存断点在解压完成瞬间 dump,或直接 hook 关键 API(加解密/比较函数)拿明文中间值,绕过静态还原算法这条死路。
**Q5**: 连动态都被反调试卡死?
**A5**: 再转一层:改用无痕的动态方案——用 QEMU/Unicorn 做全系统或函数级模拟执行,或用 DBI(Frida/Pin)在 ring3 层 hook,避开针对调试器的检测。反调试通常检测 `ptrace`/调试端口,模拟执行不触发这些。

### 识别加密算法:先认"魔数常量"再认结构
**Q1**: 逆到一段疑似加密的循环,怎么快速判断它是哪种标准算法?
**A1**: 先扫魔数常量。看到 `0x67452301`/`0xefcdab89` = MD5/SHA1 初始化向量;`0x6a09e667` = SHA256;`0x9e3779b9` = TEA/XXTEA 的 delta;AES 有固定 S-box/T-box。用 findcrypt/yara 规则一把梭,常量是算法的身份证。
**Q2**: 没有明显常量,但结构像分组密码?
**A2**: 看轮结构。16 轮 + 每轮左右半交换 = Feistel(DES/TEA 家族);10/12/14 轮 + 字节替换+行移位+列混淆 = AES;看到大量模加、循环移位、异或混合 = ARX 结构(ChaCha/Salsa/RC5)。数轮数和看半块交换是最快的判据。
**Q3**: 常量被改了(魔改算法)怎么办?
**A3**: 关注不变的骨架:魔改通常只改 S-box、初始向量、轮数、delta,但整体数据流不变。先按标准算法框架标注,再逐点 diff 出改动。判据是"结构守恒":改常量容易,改数据流结构代价大,攻击者一般不动。
**Q4**: 识别算法这条路彻底走不通(纯自研混淆算法,不对应任何标准)怎么办?
**A4**: 放弃"识别",转"黑盒建模"。别管它是什么算法,把加密函数当黑盒:固定 key 变明文观察密文关系,测试雪崩效应、是否流密码(逐字节独立)、是否可交换。若发现"密文第 i 字节只依赖明文第 i 字节" = 逐字节映射,直接建映射表爆破,根本不用懂算法。
**Q5**: 黑盒发现有扩散(改一字节全变)?
**A5**: 转向代数/符号分析:用 angr/符号执行把加密函数符号化,或对可逆算法直接找逆函数。有扩散但可逆的自研算法,符号执行常能自动求逆。

### CTF 逆向:找到 check 函数才是真正起点
**Q1**: 一个 crackme,输入 flag 判对错,反编译几千行,从哪切入?
**A1**: 不要顺读 `main`。逆向找锚点:交叉引用 "Correct"/"Wrong"/"成功" 等字符串,或找 `puts`/`printf` 输出成功信息的位置,反向回溯到判定分支。判定分支的上游就是 check 逻辑。判据:从"结果"倒推比从"入口"顺推快一个数量级。
**Q2**: 字符串被加密了,搜不到 "Correct"?
**A2**: 换锚点:找 `strcmp`/`memcmp`/自定义比较函数,或找程序退出码分叉(`exit(0)` vs `exit(1)`)。比较函数的两个参数一个是用户输入变换后的值,一个是目标值——目标值往往就是解题关键。
**Q3**: 找到 check 但它是一大坨约束(每位互相牵连)?
**A3**: 别手算。这是典型 SMT 场景:用 z3/angr 把每个约束翻译成方程,让求解器解。判据:约束是"确定性可逆运算 + 最终等值比较" → 必定能符号求解。
**Q4**: angr 符号执行状态爆炸 / 跑不出来怎么办?
**A4**: 转向"减负"策略:①用 `hook` 跳过昂贵的库函数(如 printf、sleep);②手工提取纯 check 函数单独喂 z3,别让 angr 跑整个程序;③给约束加边界(flag 可见字符 0x20-0x7e)剪枝。若还不行,转动态 patch 爆破。
**Q5**: 符号执行这条路完全被墙(check 里有哈希/不可逆运算)?
**A5**: 换维度——不可逆就不能求解,只能爆破或旁路。若每字节独立哈希后比较,逐字节爆破(256 次/字节);若整体哈希不可逆,找是否有信息泄漏(长度、部分明文提示),或转攻实现漏洞(见"放弃算法转攻实现")。

### 动静结合:静态卡住就上动态确认
**Q1**: 静态看某个变换函数,逻辑绕得看不懂它到底算了什么,怎么办?
**A1**: 别死磕静态。上动态验证:下断点,喂已知输入,直接读寄存器/内存看输入输出对应关系。一个函数逆不明白时,"喂已知值观察结果"比逐指令读汇编快得多。判据:纯变换函数关心的是 I/O 映射,不是过程。
**Q2**: 函数有全局状态/副作用,单点断点看不全?
**A2**: 用 trace:Frida/DBI 记录函数每次调用的入参出参,或用 `ltrace`/自定义 hook 打印。多次调用的 I/O 序列能暴露状态机行为(如流密码的 keystream 递进)。
**Q3**: 目标是反调试的,一下断点就退出?
**A3**: 转对抗:先定位反调试点(`ptrace(PTRACE_TRACEME)`、`/proc/self/status` 读 TracerPid、时间差检测),patch 掉或用插件(ScyllaHide 类)隐藏。判据:反调试是"一次性检查"多,patch 检查点的返回值最省事。
**Q4**: 反调试太多、patch 不完(多处 + 自校验)?
**A4**: 换执行环境:用 Unicorn/QEMU 模拟执行目标函数,只把需要的内存段和寄存器初始化好,单独跑那段算法。模拟器不是真调试器,不触发 ptrace 检测,还能任意读中间状态。
**Q5**: 函数依赖太多外部环境,抽不出来单独模拟?
**A5**: 再转:用全系统模拟(整个进程跑在 QEMU user mode)+ 在模拟层 hook,既有完整环境又能无痕观测,是抽不出函数时的兜底。

### PWN:先摸保护再定攻击面
**Q1**: 拿到 PWN 题二进制,第一个决策是什么?
**A1**: `checksec` 摸保护:NX/Canary/PIE/RELRO 四件套。保护组合直接决定打法:无 NX → shellcode;有 NX 无 PIE → ret2libc/ROP 固定地址;全开 → 需要泄漏 + 精细 ROP。判据:保护决定攻击"预算",先算清再动手。
**Q2**: 保护全开,从哪找突破口?
**A2**: 找漏洞原语,别找"地址"。先定位可控点:栈溢出?堆 UAF/overflow?格式化字符串?格式化字符串是全开下的万金油——能同时泄漏(绕 PIE/Canary)和任意写。判据:全开时优先找"信息泄漏 + 任意写"双原语的漏洞。
**Q3**: 只有一个溢出,没有泄漏手段,PIE 开着不知道基址?
**A3**: 找部分覆盖:PIE 下低 12 位固定,可只覆盖返回地址低字节做局部跳转(one gadget / 关键分支)。或找程序自带的 puts/write 做一次泄漏再第二轮。判据:没泄漏时用"页内偏移不变"这个不变量。
**Q4**: ROP 链需要的 gadget 找不齐怎么办?
**A4**: 转 libc:程序本身 gadget 少,但 libc 里应有尽有。泄漏一个 libc 地址算基址后,用 libc 的 gadget、`system`、one_gadget。判据:静态 gadget 不够就"引入 libc 全集"。
**Q5**: 沙箱(seccomp)禁了 execve,ret2libc 拿 shell 这条路被墙?
**A5**: 转 syscall 维度:seccomp 通常只禁部分调用。改用 `open/read/write` ORW 链直接读 flag 文件,或用允许的 `mmap`+shellcode、`openat`。先用 seccomp-tools dump 规则,看放行了哪些号,顺着放行的调用重构攻击链。

### 堆利用:先判断 glibc 版本再选打法
**Q1**: 一道堆题,决定用哪种堆利用手法前要先确认什么?
**A1**: 先确认 glibc 版本。版本决定哪些手法可用:tcache 从 2.26 引入,2.29+ 有 tcache key 防 double free,2.32+ 有 safe-linking(指针加密)。判据:堆手法有"版本窗口",打错版本必然失败,先 `strings libc | grep GLIBC` 或看题目给的 libc。
**Q2**: 目标 glibc 很新,老手法(unsorted bin attack、fastbin dup)都被 ban?
**A2**: 转新版通用手法:house of 系列(botcake、apple2 等)、tcache stashing、以及打 `__free_hook`/`__malloc_hook` 被移除后转打 IO_FILE(FSOP、`_IO_2_1_stdout_` house of 系列)。判据:新 glibc 下 hook 没了,攻击面转移到 IO_FILE 和 largebin。
**Q3**: safe-linking 让我伪造的 fd 指针不对?
**A3**: 需要先泄漏堆地址算出加密 key(`pos >> 12`),再把目标地址按 `ptr ^ (pos>>12)` 加密后写入。判据:safe-linking 不是不可绕,是"需要先知道 chunk 所在页地址",所以要先搞堆地址泄漏。
**Q4**: 完全没有泄漏原语,堆地址和 libc 都不知道?
**A4**: 转"无泄漏"打法:利用 partial overwrite(低字节部分覆盖)、或利用堆布局的确定性(largebin/unsorted bin 残留的 main_arena 指针做相对写)。判据:无泄漏时靠"残留指针 + 部分覆盖"制造首个泄漏。
**Q5**: 题目限制分配次数/大小,手法施展不开?
**A5**: 换思路:用 chunk overlapping / off-by-one(null byte)制造重叠,一个洞放大成多个原语,突破分配次数限制。若大小受限就找 unsorted bin 切割来构造需要的尺寸。

### VM 逆向:先还原指令集再翻译字节码
**Q1**: 逆到一个巨大的 switch/循环取字节执行,判断是 VM 保护,怎么下手?
**A1**: 确认 VM 结构:找到 ①字节码数组(操作数据) ②dispatcher(取指-译码-执行循环) ③虚拟寄存器/栈(VM 上下文)。别逐条指令读,先把 handler 表逐个逆成"这个 opcode 干什么",建立 VM 指令集文档。判据:VM 逆向本质是"写反汇编器",先建 ISA 再谈逻辑。
**Q2**: handler 有几十个,逆得很慢?
**A2**: 优先逆高频 opcode。先 trace 一遍字节码执行,统计哪些 handler 被调用,先逆核心的算术/比较/跳转,冷门的边逆边补。判据:80% 逻辑由 20% opcode 承载。
**Q3**: 每个 handler 都做了额外混淆(花指令、间接跳转)?
**A3**: 转动态:与其读静态混淆的 handler,不如 trace 每个 opcode 执行前后的 VM 上下文变化(寄存器/栈),用行为反推语义。判据:混淆的是形式,I/O 行为骗不了人。
**Q4**: VM 嵌套 VM(多层虚拟机),逆不动了?
**A4**: 换维度——不还原 VM,直接 trace 数据流。给定输入,记录 VM 内部对用户输入做了哪些实际算术操作,把 VM 当黑盒抽出"输入→输出"的等效运算,再对等效运算做符号求解。多层 VM 只是放大了常数因子,等效运算往往很简单。
**Q5**: 连 trace 都因为反调试/自修改跑不通?
**A5**: 再转 Unicorn 模拟:只模拟 dispatcher + 字节码内存,把 VM 跑在纯模拟环境里,插桩记录每个 opcode。模拟层完全可控,能绕自修改和反调试。

### 混淆对抗:识别混淆类型再对症去混淆
**Q1**: 反编译结果全是无意义的跳转、恒真判断、垃圾计算,怎么系统去混淆?
**A1**: 先归类混淆类型:控制流平坦化(一个主分发块 + 大量状态)、虚假控制流(不透明谓词)、指令替换(简单运算换成复杂等价式)、花指令。不同类型对应不同工具:平坦化用 deflat/符号执行恢复 CFG,不透明谓词用污点/求解证明恒真后删。判据:先分类,别混着硬看。
**Q2**: 控制流平坦化把逻辑打散成状态机,读不出原始流程?
**A2**: 恢复真实后继:识别状态分发变量,用符号执行确定每个真实块执行后的下一个状态值,重建原始 CFG。工具链(如 D-810、miasm、angr 脚本)可自动化。判据:平坦化只是隐藏 CFG 边,状态变量的值决定真实边,求解它即可还原。
**Q3**: 不透明谓词太多,自动工具误删或漏删?
**A3**: 转局部动态验证:对可疑分支,动态多组输入观察是否恒定走一边,恒定的就是虚假分支。判据:不确定的静态判断用动态样本证伪最可靠。
**Q4**: 混淆是商业保护(如 VMP/Themida 变形),自动去混淆全失效?
**A4**: 放弃"去混淆",转"绕过还原"——只 trace 目标算法对具体输入的实际计算轨迹(动态污点跟踪用户输入),从轨迹里提炼语义,不去还原被混淆的完整代码。判据:去混淆是"还原全部",解题只需"还原关键数据流",后者成本低一个量级。
**Q5**: 连动态轨迹都被自修改/多态干扰得看不清?
**A5**: 再降维:把关注点收窄到"用户输入字节"的传播,用符号/污点只跟这几个字节参与的运算,忽略所有无关混淆代码。多态混淆改的是无关代码,污点切片能把它们过滤掉。

### 密码学误用:先找实现弱点而非硬破算法
**Q1**: 目标用了标准强算法(AES/RSA),硬破不可能,还有戏吗?
**A1**: 有。不破算法,破"用法"。列检查清单:ECB 模式?IV 固定/可预测?nonce 重用?弱密钥/密钥硬编码?padding oracle?判据:实战中密码学几乎都是死在"误用"而非"算法本身",先审用法。
**Q2**: 发现是 AES-ECB?
**A2**: 利用 ECB 无扩散:相同明文块→相同密文块。可做字节级爆破(逐字节对齐泄漏,ECB byte-at-a-time),或识别重复块推断结构。判据:ECB 泄漏明文模式,这本身就是漏洞。
**Q3**: 是 CBC 且服务端会告诉你 padding 对不对?
**A3**: padding oracle:利用填充校验的差异反馈,逐字节解密/伪造密文,完全不需要密钥。判据:任何"密文操纵 + 是否有效的可观测反馈"都可能是 oracle。
**Q4**: 算法用法看着没毛病,标准 AES 正确模式,这条路被墙?
**A4**: 转攻密钥来源:密钥怎么来的?硬编码?从弱 PRNG(rand() 未晒种、时间种子)派生?从可预测数据 KDF?算法再强,密钥可预测就全盘皆输。把攻击面从"密文"转到"密钥生成"。
**Q5**: RSA 且没有明显小指数/共模等经典弱点?
**A5**: 转参数分析:n 是否可分解(位数小、Fermat 近似素数、已知因子库如 factordb)?e 与 φ 关系?已知部分私钥位?padding 是否是原始无 padding(可做同态操纵)?判据:RSA 的攻击面在"参数选取",逐一核对已知攻击的前提条件。

### 还原自研哈希/校验:碰撞与原像的取舍
**Q1**: 输入被一个自研 hash 处理后与常量比较,hash 不可逆,怎么办?
**A1**: 先判断需要"原像"还是"碰撞"。若必须还原确切输入 → 找原像;若只需通过校验 → 找任意碰撞即可,后者可能容易得多。判据:先问"我到底需不需要真实输入",很多校验只要碰撞。
**Q2**: hash 输出空间小(如只保留 32 位)?
**A2**: 直接爆破/建彩虹表。输出空间 2^32 以内,GPU/多线程爆破可行。判据:自研 hash 常为省事截断输出,截断即弱化,先看输出位宽。
**Q3**: 逐字节独立哈希(每个字符单独 hash 后拼接)?
**A3**: 分而治之:每字节独立就是 256 空间的映射,逐位置建表反查,秒解。判据:独立性 = 可分解,一定先测雪崩看字节间是否耦合。
**Q4**: hash 有强扩散、输出宽、必须原像,爆破无望这条路死了?
**A4**: 转结构攻击:自研 hash 常有代数弱点。若是线性/仿射结构(纯异或移位)→ 建线性方程组用高斯消元解;若有周期/不动点 → 利用之。判据:不可逆≠无结构,自研算法作者很少做到密码学强度,找线性成分。
**Q5**: 连结构攻击都无从下手(逻辑非线性且宽输出)?
**A5**: 换约束来源:回到题目上下文找旁路——是否有长度泄漏、部分明文已知(格式前缀)、多个相关密文可做差分?把 hash 求解问题转成"带已知约束的搜索",用约束大幅剪枝爆破空间。

### 提取密钥/常量:先动态 dump 再静态定位
**Q1**: 算法逻辑懂了,但密钥/密文是运行时才解密出来的,静态看是乱码,怎么拿?
**A1**: 动态 dump。在密钥被使用的那一刻(如传入加密函数前)下断点,直接读内存拿明文密钥。判据:再强的常量加密,使用时刻必然是明文,守株待兔在"使用点"。
**Q2**: 不知道密钥在内存哪个地址?
**A2**: 反向定位:先找加密函数(靠算法识别),它的 key 参数就指向密钥。或对疑似 key 的内存区域下内存访问断点,谁读它谁就是加密逻辑。判据:从"算法用 key"倒推 key 位置。
**Q3**: 密钥用完立即抹除(anti-dump),断点晚了就没了?
**A3**: 提前 hook:在解密密钥的函数返回处、或密钥写入内存的瞬间断下。用内存写断点抓"密钥刚出现"而非"密钥被使用"。判据:抹除的是使用后,抓生成时。
**Q4**: 全程反调试 + 抹除,动态 dump 这条路被墙?
**A4**: 转模拟执行:用 Unicorn 把"密钥解密函数"单独跑出来,输入端读它的静态密文常量,输出端就是明文密钥,全程无调试器、无抹除干扰。判据:密钥解密是纯函数,抽出来模拟最干净。
**Q5**: 密钥依赖硬件/环境(机器码、时间、外部输入)无法离线复现?
**A5**: 换目标:不提取密钥,提取"密钥使用后的结果"。既然环境相关密钥拿不到,就在目标环境里 hook 拿最终解密产物(明文数据),绕过密钥本身。判据:要的是数据不是密钥时,直接抓数据。

### 白盒密码:攻查找表而非攻密钥
**Q1**: 遇到白盒 AES(密钥融进查找表,内存里根本没有裸密钥),怎么办?
**A1**: 别找密钥,它被编码进 T-box 了。转攻实现:优先尝试 DCA(差分计算分析)——像侧信道一样采集查找表访问轨迹,统计分析恢复密钥,无需理解表结构。判据:白盒的密钥藏在表里但"计算过程仍泄漏信息"。
**Q2**: DCA 没打通?
**A2**: 转 DFA(差分故障分析):在倒数几轮注入故障(patch 中间值),用正确/错误密文对做差分定位密钥。判据:白盒实现难防故障注入,DFA 是经典白盒破解手段。
**Q3**: 不想做侧信道,能直接用这个白盒当 oracle 吗?
**A3**: 能——务实路线:如果目标只是"用这个密钥加解密某数据",根本不用提取密钥,直接调用/模拟这个白盒函数当黑盒加解密机。判据:很多时候你不需要密钥,只需要它的功能。
**Q4**: 白盒还叠加了外部编码(输入输出被额外混淆),DCA/DFA 都失效?
**A4**: 转结构分析剥离编码:先逆出输入输出的编码变换(通常是字节级双射),剥掉后再对内层标准白盒做 DCA。判据:外部编码是"包装层",先脱包装再打核心。
**Q5**: 分析成本太高、时间不够,以上全放弃怎么办?
**A5**: 降级为"功能复用":把整个白盒模块连同其上下文一起搬到你的环境里当加解密黑盒调用,彻底放弃还原,用工程手段换分析时间。这是卡死时的兜底转向。

### 侧信道思维:软件层面也能用
**Q1**: 一个密码校验函数,逐字符比较且比较错就早退(短路比较),能利用吗?
**A1**: 能,这是时间侧信道。正确前缀越长,函数运行越久。用响应时间差异逐字符爆破口令。判据:任何"早退 + 可测量耗时/次数"的比较都漏信息。
**Q2**: 时间差太小测不准?
**A2**: 放大信号:在本地环境用指令计数(插桩统计执行指令数)、缓存命中、或 patch 让每次比较更慢来放大差异。判据:侧信道打不通往往是信噪比问题,想办法放大或换更稳的观测量(指令数比墙钟时间稳)。
**Q3**: 目标是远程服务,只有网络时延?
**A3**: 多次采样 + 统计:大量重复取分位数过滤网络抖动,或找非时间侧信道(错误码差异、返回包长度、内存/资源消耗差异)。判据:远程时间信道噪声大,优先找"确定性"的旁路(状态码/长度)。
**Q4**: 比较是恒定时间实现(memcmp_const),时间侧信道被墙?
**A4**: 转其他侧信道维度:恒定时间只防了时间,不一定防功耗/缓存/故障。软件场景转 DFA(故障注入 patch 中间值)或转攻上游(口令怎么生成的、有没有别的泄漏点)。判据:一个侧信道被堵,换正交的物理/逻辑侧信道。
**Q5**: 所有侧信道都被封?
**A5**: 回到主信道:侧信道是"没有直接漏洞时的迂回",若目标侧信道防护完善,说明该找逻辑漏洞了——重新审计认证流程本身(逻辑绕过、类型混淆、状态机缺陷),别在侧信道死磕。

### 放弃算法、转攻实现
**Q1**: 算法本身还原成本极高(强混淆 + 强算法),投入产出比很差,该不该继续?
**A1**: 停下重评估。红队目标是"达成效果"不是"完美逆向"。问自己:我要的是理解算法,还是拿到某个结果?若是后者,转攻实现——找逻辑漏洞、绕过点、可复用的功能模块。判据:当逆向成本 > 目标价值,立刻转向。
**Q2**: 怎么找实现层的绕过点?
**A2**: 审边界:认证/校验前后的状态、错误处理分支、未初始化路径、整数溢出改变控制流、TOCTOU。强算法常被薄弱的调用逻辑包围,漏洞在"算法之外的胶水代码"。判据:算法越强,作者越可能忽视周边工程质量。
**Q3**: 实现也挺严谨,没有明显逻辑洞?
**A3**: 转复用:直接把目标的加解密/校验模块当组件调用(动态加载其函数、或整个跑起来喂输入),让它替你干活,你不需要懂它。判据:能调用就不用还原。
**Q4**: 模块依赖太重没法单独调用,复用也被墙?
**A4**: 转数据流最小切片:只对"我关心的那几个输入字节"做动态污点跟踪,提取它们经过的等效运算(往往远比整个算法简单),对这个小切片求解。判据:整体不可解 ≠ 关心的子问题不可解。
**Q5**: 连切片都因反分析拿不到?
**A5**: 最后转情报/供应链维度:这算法/protection 是不是第三方商用/开源库?搜版本、找公开分析、找同款的历史 writeup 或已知弱点。别在真空里硬逆一个别人早已破解的东西。判据:卡死时先确认"是不是已知的轮子"。

### 差分分析:构造输入观察输出
**Q1**: 加密函数是黑盒但可任意调用,想快速摸清它的性质,发什么输入?
**A1**: 系统性差分测试:①全零明文 → 看密文基线;②单比特翻转 → 看雪崩范围(哪些密文位变);③相同明文两次 → 看是否确定性(有无随机 IV/nonce);④递增明文 → 看是否有线性/计数器结构。判据:少量精心构造的输入能测出算法族属性。
**Q2**: 发现单字节改动只影响密文局部?
**A2**: 定位分组边界:扩散范围揭示块大小和结构。局部影响 = 弱扩散 = 可分块攻击/建映射表。判据:雪崩范围直接告诉你攻击粒度。
**Q3**: 发现相同明文每次密文不同?
**A3**: 找随机源:有 IV/nonce/salt。检查它是否随密文一起给出(可控)、是否重用(nonce 重用是致命弱点)、是否可预测。判据:随机化不等于安全,重点查随机源质量。
**Q4**: 差分全随机、无任何可利用规律,这条路被墙?
**A4**: 说明是强算法正确实现。转攻密钥/实现(见前述链):黑盒差分打不动强算法很正常,别继续测,转向密钥来源、模式误用、侧信道等正交面。判据:黑盒差分是筛"弱算法"的,筛不出就换战场。
**Q5**: 无法任意调用(只有有限几对已知明密文)?
**A5**: 转已知明文攻击框架:有限明密文对下,针对怀疑的算法族套用对应已知攻击(线性/差分密码分析的已知前提、流密码 keystream 恢复)。判据:样本受限时从"主动探测"转"被动分析已有样本"。

### 位运算逆向:逐步求逆
**Q1**: 一串位运算变换(异或、移位、加减、乘法)作用于输入,要求逆,从哪开始?
**A1**: 倒序逐步求逆。每个可逆操作都有逆:xor 自逆,加↔减,左移↔右移(注意丢位),乘常数↔乘其模逆。从最后一步往前一个个抵消。判据:可逆位运算链 = 从后往前套逆函数,机械可解。
**Q2**: 遇到不可逆操作(如右移丢了低位、与常数 AND 丢信息)?
**A2**: 该位分支爆破:丢失的信息量小(几位),枚举所有可能再验证。判据:局部不可逆时用小范围爆破补回丢失比特,别放弃整条链。
**Q3**: 有乘法但常数与模不互质,无模逆?
**A3**: 转求解而非求逆:列同余方程,用扩展欧几里得/CRT,或对无解位枚举。判据:无模逆≠无解,转到数论方程视角。
**Q4**: 运算链交织了查表和状态,不是纯位运算,逐步求逆断链了?
**A4**: 转符号执行:把整条变换喂给 z3/angr,让求解器处理混合运算,不用手工分解。判据:手工求逆断链就交给 SMT,它不在乎运算多杂只在乎可满足。
**Q5**: 符号执行也因非线性(哈希、乘法爆炸)超时?
**A5**: 转分段:把长链切成几段,对可逆段手工求逆,只把不可逆/非线性的短段交给爆破或 SMT,分段各个击破。判据:整链难解就找"可逆段/难解段"的接缝分而治之。

### 状态机/协议逆向
**Q1**: 目标是个自定义协议/序列化格式,要还原它的编解码,怎么下手?
**A1**: 先抓样本对比。收集多组"输入-输出"或抓包多条报文,做字段对齐:找固定头(魔数)、长度字段、类型标签(TLV)、校验尾。判据:协议逆向先靠多样本 diff 定位字段边界,再逆单字段编码。
**Q2**: 字段像是压缩/加密了?
**A2**: 分层剥离:先判断有无压缩(熵、gzip/zlib 魔数 `78 9c`)、有无加密(熵接近满)。先解压再解密再解析。判据:协议栈是分层的,逆向也要一层层剥。
**Q3**: 有长度或校验字段但算法不明?
**A3**: 逆校验函数:找发送前计算校验的代码,或用多样本反推(改一字节看校验怎么变→ 是 CRC/加和/异或?)。判据:校验字段是"可控输入→可观测输出"的小黑盒,差分几组就能识别。
**Q4**: 协议有握手/加密协商(类 TLS 自研),静态逆协商逻辑太复杂,被墙?
**A4**: 转 hook 明文层:别逆加密协商,在加解密函数的明文侧 hook(SSL_read/write 类的对应点),直接拿收发的明文。判据:加密协议在应用层必有明文出入口,hook 那里绕过整个协商逆向。
**Q5**: 连明文 hook 点都定位不到(全自研栈)?
**A5**: 转数据流追踪:从 socket recv 缓冲区开始正向污点跟踪,看数据经过哪些函数变换,变换终点(进入业务逻辑处)就是明文。判据:数据从网络到业务必然被解密,顺着污点走到"业务开始消费"的点。

### 定位关键算法:交叉引用与数据锚点
**Q1**: 大程序里要找"处理某个特定文件/字段"的算法在哪,怎么快速定位?
**A1**: 用数据锚点做交叉引用。已知的魔数、字符串、常量、文件扩展名,在二进制里搜并看谁引用它。引用点周围就是相关算法。判据:代码围绕数据组织,已知数据是最快的导航锚。
**Q2**: 关心的数据是运行时生成的,静态搜不到?
**A2**: 动态内存搜索:程序跑起来后在内存里搜该数据的特征,下内存访问断点,谁碰它谁相关。判据:静态搜不到就动态"守数据"。
**Q3**: 想定位某个 API 相关逻辑(如网络/文件/加密调用)?
**A3**: 导入表 + API 断点:对 `send`/`CreateFile`/`CryptEncrypt` 等下断,栈回溯到调用者。判据:系统 API 是天然锚点,从 API 反推业务逻辑。
**Q4**: 目标静态链接 + 去符号,连 API 边界都模糊,定位被墙?
**A4**: 转 FLIRT/签名识别:用库函数签名(IDA FLIRT、rizin sig)先把标准库函数认出来还原符号,缩小自研代码范围。判据:静态链接的大部分是库代码,先用签名"减背景"再找业务。
**Q5**: 签名也认不全(魔改 libc / 非常见库)?
**A5**: 转行为聚类:动态 trace 全程调用,按调用频率和数据流把函数分组,定位"处理目标数据的那簇"。判据:认不出函数名就按"它对我关心的数据做了什么"来锁定。

### 选择工具链:静态反编译器的取舍
**Q1**: 一个目标,IDA / Ghidra / Binja 反编译结果不一样,信哪个?
**A1**: 交叉验证,别独信一个。反编译是有损重建,不同引擎在类型恢复、优化还原上各有强弱。关键函数用两个引擎对照,分歧处回到汇编裁决。判据:反编译结果是"参考翻译"不是真相,汇编才是 ground truth。
**Q2**: 反编译出的类型/结构体全错(一堆 `int` 和 offset)?
**A2**: 手工恢复结构体:根据访问偏移模式重建 struct,给变量定类型,反编译会大幅改善。判据:结构体恢复是逆向 C++/复杂逻辑的地基,值得前期投入。
**Q3**: 优化太狠(内联、向量化、尾调用),反编译面目全非?
**A3**: 降精度看汇编 + 分块理解:高优化代码放弃"读伪 C",直接读汇编按基本块理解,或动态 trace 数据流。判据:O2/O3 下伪 C 不可信,转汇编或动态。
**Q4**: 架构冷门(MIPS/RISC-V/单片机/DSP),主流反编译器支持差,被墙?
**A4**: 转动态/模拟:静态支持差就用 QEMU 模拟跑起来 trace,或用支持该架构的工具(Ghidra 架构最全,或写 Unicorn 脚本)。判据:冷门架构静态弱就靠动态执行补,执行不看架构人气。
**Q5**: 连模拟器都不支持该架构/外设?
**A5**: 转硬件/固件视角:上真实硬件调试(JTAG/SWD)、或做外设建模(把 MMIO 寄存器行为桩掉)让固件在模拟器里跑。判据:纯软模拟不了就引入真实硬件或补外设模型,别在纯静态死磕嵌入式。

### 时间预算与转向决策
**Q1**: 逆向一道题/一个目标,怎么判断"该转向了"而不是无脑硬啃?
**A1**: 设时间盒 + 里程碑。每条路线给硬性时间上限(如单一路径 30-45 分钟无进展即止),并定义"进展"是可验证的中间成果(拿到密钥/识别出算法/跑通一次 check)。判据:无里程碑推进 = 转向信号,别用"再看看就懂了"自欺。
**Q2**: 感觉快突破了,但已经超时,继续还是转?
**A2**: 看"确定性"。若剩下的是机械劳动(已知怎么做,只是费时)则继续;若还在"猜测阶段"(不确定这条路对不对)则转。判据:区分"执行成本"和"探索不确定性",前者可续,后者要转。
**Q3**: 手上有多条可能路线,先打哪条?
**A3**: 按"信息增益/成本"排序:先做便宜且能证伪/证实假设的探测(checksec、findcrypt、字符串、一次动态 trace),用小成本砍掉不可能的分支再深入。判据:先做能快速改变判断的动作。
**Q4**: 所有想到的路线都试过都被墙,彻底卡死怎么办?
**A4**: 换抽象层。卡在算法层 → 升到实现/逻辑层;卡在静态 → 转动态/模拟;卡在软件 → 转情报层(这是不是已知保护/已知题型)。判据:卡死的本质常是"层选错了",系统性换层比换战术有效。
**Q5**: 换层也无果,是不是方向从根上就错了?
**A5**: 回到目标定义重问:我真正需要的产出是什么?是否有完全不同的达成路径(如绕过而非破解、复用而非还原、旁路信息而非核心算法)?判据:长时间卡死往往是"解错了题",回到需求本身重新分解,常有正交捷径。

### 格式化字符串:泄漏与写入的节奏
**Q1**: 确认有格式化字符串漏洞,先干什么?
**A1**: 先用它做侦察而非直接打。用 `%p` 序列 dump 栈,定位:栈上的 canary、libc 地址、PIE 地址、以及自己可控输入所在的参数偏移。判据:fmt 是"先侦察后打击"的原语,一次泄漏能同时解决 PIE/Canary/libc 三个未知量。
**Q2**: 找到可控偏移了,怎么稳定任意写?
**A2**: 用 `%n` 家族:`%hhn` 单字节、`%hn` 双字节写,配合精确宽度控制写入值,分字节写目标地址避免一次写超大值卡死。判据:大数值写用分字节 + `%hhn` 才实际可行。
**Q3**: 目标开了 FORTIFY(`%n` 被禁),写入这条路被墙?
**A3**: 转纯泄漏利用:`%n` 不可用时,fmt 仍是超强任意读。用它把 flag/关键数据直接从内存读出来,或泄漏足够信息配合其他漏洞(栈溢出等)完成利用。判据:写被禁,读还在,很多目标光靠任意读就能拿数据。
**Q4**: 只有一次触发机会,泄漏和写入不能分两轮?
**A4**: 单发构造:一条 payload 里既泄漏又写,或改打不依赖泄漏的目标(改 GOT 为 PLT 内已知地址、部分覆盖 return)。判据:一次性场景优先选"不需要先泄漏"的攻击目标。
**Q5**: 输入被过滤了 `%`/`$`,fmt 完全用不了?
**A5**: 换漏洞:fmt 被封就回退到其他原语(溢出、逻辑洞)。判据:某个原语被输入过滤堵死时,重新枚举程序的其他输入点,别在被过滤的点硬凑。

### 整数与类型:溢出改变控制流
**Q1**: 没有明显内存破坏漏洞,但代码里有大量大小/长度计算,该怀疑什么?
**A1**: 怀疑整数问题。重点看:有符号↔无符号比较、`size` 计算里的乘法/加法溢出、负数长度绕过边界检查、截断(int→short)。判据:整数漏洞是"逻辑正确但边界错",专盯计算 size 后用于分配/拷贝的路径。
**Q2**: 找到一处 size 溢出,怎么变成利用?
**A2**: 顺数据流看它流向哪:流向 malloc → 小分配大写入(堆溢出);流向 memcpy 长度 → 越界读写;流向数组下标 → 任意读写。判据:整数 bug 本身不危险,危险在"溢出后的值被用作内存操作的尺寸/偏移"。
**Q3**: 溢出发生了但后续有二次检查拦住?
**A3**: 找 TOCTOU / 检查绕过:检查用的值和使用的值是否同一个、检查后是否被修改、多线程下能否竞争。判据:检查与使用之间的窗口是整数利用的常见突破口。
**Q4**: 分析半天没有可利用的整数路径,被墙?
**A4**: 转别的原语类别:整数漏洞难利用很常见(约束多)。回到内存破坏(UAF/溢出)、逻辑漏洞、类型混淆重新扫。判据:一类漏洞不通就换漏洞类目,别在单一 bug 类型钻牛角尖。
**Q5**: 目标是脚本/托管语言(有 GC、无裸指针),整数溢出思路失效?
**A5**: 换语义漏洞:托管环境转攻反序列化、原型链污染、类型混淆、沙箱逃逸、内置函数误用。判据:换了运行时就换漏洞模型,内存类思路让位于语言语义类漏洞。

### 反调试/反虚拟机对抗的分层拆解
**Q1**: 目标一进调试器就退出/行为异常,怎么系统性拆反调试?
**A1**: 先分类检测手段:①API 类(IsDebuggerPresent、ptrace、NtQueryInformationProcess);②时间类(rdtsc/GetTickCount 差值);③自校验(检测断点 0xCC、校验代码 hash);④环境类(检测 VM 特征、单步陷阱)。判据:反调试是分层的,先枚举它用了哪几层,再逐层对付。
**Q2**: API 类检测怎么处理最快?
**A2**: hook/patch 返回值:让检测函数永远返回"没被调试"。用调试器脚本或 Frida 批量 hook。判据:API 类检测是"问系统要状态",篡改答案即可,成本最低先做。
**Q3**: 有自校验(检测你下的软件断点)?
**A3**: 转硬件断点/内存断点:软件断点改了字节会被 hash 校验发现,硬件断点(DR 寄存器)不改代码字节,绕过代码自校验。判据:自校验防的是"代码被改",换不改代码的断点方式。
**Q4**: 反调试太顽固(多层 + 动态生成检测代码),patch 不完,被墙?
**A4**: 转模拟执行,彻底离开真实调试器:Unicorn/QEMU 里没有真的调试器进程、ptrace、也可伪造 rdtsc,把关心的函数抽出来在模拟环境跑。判据:反调试针对"真实调试环境",釜底抽薪是换到模拟环境。
**Q5**: 检测的是 VM/沙箱本身(拒绝在虚拟机运行)?
**A5**: 转真机/伪装:要么在裸机/裸金属分析,要么伪装 VM 特征(改 MAC、CPUID、注册表/设备特征、隐藏 hypervisor 位)。判据:反 VM 和反调试是正交的两类,分开对付,别混为一谈。

### 随机数可预测:攻 PRNG 而非攻密文
**Q1**: 目标的密钥/token/nonce 由随机数生成,怎么判断能不能预测?
**A1**: 先辨随机源类型。是 `rand()`/`Math.random()`/`mt19937` 这类非密码学 PRNG,还是 `/dev/urandom`/CSPRNG?非密码学 PRNG 状态可恢复即可预测全部输出。判据:先看用的是不是 CSPRNG,不是的话整条随机链都可攻。
**Q2**: 确认是 mt19937 / LCG,怎么预测?
**A2**: 收集连续输出恢复内部状态:mt19937 拿到 624 个连续 32 位输出即可逆推状态、预测后续;LCG 几组输出解同余即可。判据:非密码学 PRNG 的输出足量后状态确定,后续全可算。
**Q3**: 种子是弱种子(时间戳/PID)?
**A3**: 直接爆种子:若用 `srand(time(0))` 类,种子空间极小(已知大致时间 ± 几秒),枚举种子重放整个随机序列。判据:弱种子比恢复状态更省事,先看种子熵。
**Q4**: 随机数用的是 CSPRNG,预测这条路被墙?
**A4**: 转随机数的"使用方式"而非"生成":是否重用同一 nonce/IV(致命)?是否随机数被截断/取模引入偏置?是否随机值随输出泄漏可做关联?判据:CSPRNG 本身不可预测,但"怎么用随机数"常有漏洞,把攻击面从生成器转到用法。
**Q5**: 生成和使用都没毛病?
**A5**: 放弃随机数攻击,转其他面(密钥来源、实现漏洞、逻辑绕过)。判据:随机性是密码系统里最难攻的一环,确认强就该早撤,别在 CSPRNG 上耗时间。

### 从崩溃到利用:先分类 crash
**Q1**: fuzz 或手测触发了崩溃,怎么判断它有没有利用价值?
**A1**: 先给 crash 分类。看崩在哪:PC 被控(直接控制流劫持,高价值)、写地址可控(任意写)、读地址可控(信息泄漏/DoS)、还是纯空指针解引用(多半只 DoS)。判据:crash 的可利用性取决于"哪个可控 + 可控到什么程度",先分类再决定投入。
**Q2**: PC 或某寄存器被输入字节控制了?
**A2**: 高价值,立即深挖:确认控制宽度(几字节)、偏移(输入的哪部分)、约束(哪些字节不能用)。判据:控制流劫持是利用金字塔顶端,优先把它做实。
**Q3**: 只是可控写但控不到 PC?
**A3**: 找"写原语→控制流"的转化:写 GOT/vtable/返回地址/函数指针/堆元数据。任意写要落到"能改变执行流的内存"才有用。判据:可控写的价值 = 能写到哪个关键结构。
**Q4**: crash 看着不可控(崩在无关地址、无法稳定复现)被墙?
**A4**: 转根因分析而非现象:用 ASAN/valgrind 定位真正的越界/UAF 源头,那里往往比崩溃点更可控。或换输入让 bug 在更可控的上下文触发。判据:崩溃点 ≠ 漏洞点,回溯到根因常能找到可控版本。
**Q5**: 确认就是纯 DoS 类、无内存破坏,利用无望?
**A5**: 转别的输入面/漏洞类:老实承认此 crash 无利用价值,回到攻击面枚举找新入口。判据:及时判死一个不可利用的 crash,比反复盘它更省时间。

### 加密流量/存储:找解密的那一刻
**Q1**: 目标把数据加密后存盘/发网,我要明文,静态逆算法太慢,有捷径吗?
**A1**: 有。不逆算法,截"解密瞬间"。程序自己一定会解密来用,在它调用解密函数后、消费明文前 hook,直接拿明文。判据:凡是"加密存储/传输"的数据,程序运行时必然还原成明文,守在还原点最省力。
**Q2**: 不知道解密函数在哪?
**A2**: 从数据反推:对存储缓冲/接收缓冲下内存断点,谁读它 → 往下走就是解密;或对已知的密文常量下访问断点。判据:密文是锚,顺着"谁消费密文"找到解密逻辑。
**Q3**: 想批量、可复现地解密大量样本?
**A3**: 提取解密函数做成离线工具:定位密钥 + 算法后,用 Unicorn 模拟该函数或用 Python/C 重写,批量跑。判据:一次性 hook 适合取样,批量处理值得把解密逻辑固化成独立工具。
**Q4**: 解密依赖服务器/密钥协商,离线复现被墙?
**A4**: 转在线中间人:既然离线解不了,就在目标运行环境里当 MITM——hook 明文接口、或做本地代理拿协商后的会话密钥再解。判据:密钥在服务端时,放弃离线,转到"活的目标环境里取明文/会话密钥"。
**Q5**: 环境也拿不到(只有一份密文和二进制)?
**A5**: 回到硬逆或找弱点:此时只能老实还原算法+提取硬编码密钥,或审算法/密钥管理的弱点(弱 KDF、硬编码、可预测派生)。判据:所有"取巧拿明文"的路都断了,才回到成本最高的完整还原。

### 多阶段解密链:一层套一层
**Q1**: 解出第一层发现里面还是密文/还是一个新二进制,怎么组织多阶段?
**A1**: 把它当剥洋葱,建立"阶段清单"。每层记录:输入、用的算法/密钥、输出。别在一层里迷失,始终清楚自己在第几层、还有几层。判据:多阶段解密最大的坑是"层间迷路",用清单维持全局视图。
**Q2**: 每一层用不同算法,逐层手工太慢?
**A2**: 尽量自动化衔接:写脚本把 layer N 的输出直接喂 layer N+1,形成 pipeline,改一层参数全链重跑。判据:多阶段一定要 pipeline 化,手工搬运数据必错且慢。
**Q3**: 某一层的密钥依赖上一层的输出(链式派生)?
**A3**: 严格保持顺序 + 记录中间态:密钥链式派生时不能跳步,每层输出要留存以供下层派生。判据:链式依赖下,保存全部中间产物是回溯和调试的前提。
**Q4**: 中间某一层卡住解不开,整条链断了怎么办?
**A4**: 转动态跳过该层:既然程序自己能解,就让它跑到卡住层的下一层,直接 dump 那层的解密输出,跳过你手工解不开的中间层。判据:静态解不开的中间层,用"让目标自己解、我在下游取结果"绕过,不必每层都亲手还原。
**Q5**: 目标有反 dump / 每层解完即焚,动态跳过也被墙?
**A5**: 转模拟整链:用 Unicorn 把多阶段 loader 整体模拟执行,在模拟内存里随意 dump 任意层,不受反 dump 影响。判据:反 dump 防的是真实进程内存,模拟环境的内存完全由你掌控。

### 定位"比较点"确定攻击目标值
**Q1**: 无论 crackme 还是校验,最终都归结到某处比较,怎么保证找对那个"决定性比较"?
**A1**: 从判定结果回溯到唯一比较。跟踪"成功/失败"这个布尔是怎么算出来的,一路回溯到产生它的比较指令(cmp/test/自定义 equal)。判据:所有变换都是为最后一次比较服务,锁定它就锁定了目标值。
**Q2**: 找到比较了,一边是我的输入变换、另一边是目标,目标怎么来的?
**A2**: 分类目标来源:①硬编码常量(直接读);②运行时计算(动态断点读值);③另一路输入派生。判据:先确定目标值是静态还是动态,决定用读常量还是下断点。
**Q3**: 目标值是动态算的,能直接读到就等于绕过了整个逆向?
**A3**: 对——若比较是"我的变换(input) == target",而 target 与 input 无关,直接动态读 target,再逆我这半边的变换即可,省掉理解 target 的计算。判据:比较两边独立时,只需逆"含输入的那一边"。
**Q4**: 比较两边都依赖输入(交织校验),读不出独立目标,被墙?
**A4**: 转整体约束求解:两边都含输入 = 一组关于输入的方程,交给 z3/angr 解,而不是分边读值。判据:比较两边耦合就别想"读答案",升级成方程组求解。
**Q5**: 比较是不可逆哈希两边(hash(input)==hash(const))?
**A5**: 转爆破/碰撞或攻上游:哈希比较无法求解,只能逐段爆破输入,或找 hash 输入空间的约束(格式、长度)缩小爆破,或干脆 patch 掉比较跳过校验(若目标只是"让它通过"而非"求出输入")。判据:哈希比较区分"要输入"还是"要通过",后者直接 patch 分支。

### patch 绕过 vs 真实求解的取舍
**Q1**: 目标只是"让程序认为验证通过"(不需要真实口令),该逆还是该 patch?
**A1**: 优先评估 patch。若目标是行为(解锁功能、跳过校验),直接 patch 判定分支(改跳转、改返回值)最快,根本不用理解算法。判据:"要结果不要过程"时,patch 是最短路径,先问自己"我到底要不要那个真实值"。
**Q2**: 怎么最小化 patch?
**A2**: 找单点开关:通常一条 `jz→jnz`/`je→jmp`、或让 check 函数直接 `return 1` 就够。判据:最小 patch = 改动最少、最靠近判定的那一个字节/跳转。
**Q3**: patch 了本地校验但程序有自校验(检测代码被改)?
**A3**: 转内存 patch / 运行时 hook:不改磁盘文件,运行时在自校验之后再改内存,或 hook 校验函数返回。判据:静态 patch 触发自校验时,改到"自校验之后执行的内存"。
**Q4**: 校验在服务端 / patch 客户端根本没用,被墙?
**A4**: 转真实求解:服务端校验无法 patch,必须拿到真实值/伪造合法请求。这时才回头老实逆算法、求真实口令或伪造签名。判据:服务端权威校验下 patch 失效,被迫从"绕过"转"真解"。
**Q5**: 服务端校验且算法也强,真解也难?
**A5**: 转协议/逻辑绕过:攻认证逻辑本身(重放、会话固定、越权、参数篡改)而非破解验证算法。判据:强算法的服务端,攻击面在"认证流程的逻辑漏洞",不在密码学本身。

### shellcode 编写与受限环境
**Q1**: 拿到执行控制权要上 shellcode,写之前先确认什么?
**A1**: 先确认约束:架构(x86/x64/ARM)、坏字符(哪些字节会被截断/过滤,如 `\x00`\`\x0a`)、空间大小(缓冲多大)、执行环境(有无 NX、能否 mprotect)。判据:shellcode 是"戴着镣铐跳舞",先量清镣铐再写。
**Q2**: 空间太小放不下完整 shellcode?
**A2**: 用 stager:先放一小段"读取更多数据到可执行内存并跳过去"的引导,主体二段传输。判据:空间不足就分级投送,别硬塞。
**Q3**: 有坏字符,shellcode 里正好包含?
**A3**: 编码器 + 自解码:用 encoder(如 xor 编码)避开坏字符,加自解码头运行时还原。判据:坏字符用编码绕,但要保证解码头本身不含坏字符。
**Q4**: NX 开着,shellcode 放哪都不可执行,被墙?
**A4**: 转 ROP 而非注入代码:NX 下不能执行数据,改用 ROP 链复用已有可执行代码,或先 ROP 调用 `mprotect`/`VirtualProtect` 把 shellcode 区域改成可执行再跳。判据:NX 封的是"执行数据",用 ROP 复用代码或先改内存权限。
**Q5**: 连 ROP 需要的栈迁移/gadget 都受限(空间/坏字符双重卡)?
**A5**: 转 SROP / ret2csu / ret2dlresolve:这些技术用极少 gadget 完成复杂调用,适合 gadget 匮乏的受限环境。判据:常规 ROP 受限时,转"低 gadget 需求"的高级技巧。

### kernel/驱动逆向的特殊考量
**Q1**: 目标是内核模块/驱动而非用户态程序,逆向思路要怎么调整?
**A1**: 先建立内核视角:关注 ioctl/syscall 入口(用户态怎么跟它交互)、特权操作(内存映射、任意读写原语)、以及它信任了哪些用户态传入的数据。判据:内核漏洞的价值在提权,攻击面是"内核信任用户态输入的边界",先找交互入口。
**Q2**: 怎么定位可利用的内核原语?
**A2**: 找"用户可控 → 内核内存操作":ioctl handler 里未校验的指针/长度、double fetch、引用计数错误(UAF)。判据:内核利用先集齐"任意读 + 任意写 + 泄漏"原语,盯参数校验缺失处。
**Q3**: 有原语了,怎么提权?
**A3**: 经典路径:改 cred 结构提权、覆盖函数指针劫持内核控制流、或改页表。判据:拿到任意写后,目标是改"决定权限的内核结构"。
**Q4**: 内核有 SMEP/SMAP/KASLR/CFI 全套缓解,提权被墙?
**A4**: 逐个转:KASLR→找内核地址泄漏;SMEP→别跳用户态代码,用内核内 ROP;SMAP→别解引用用户态数据,数据也放内核;CFI→找 data-only 攻击(只改数据不劫持控制流,如直接改 cred)。判据:每个缓解都有对应正交绕法,data-only 是 CFI 时代的通用转向。
**Q5**: 缓解太全,内存利用极难,被墙?
**A5**: 转逻辑漏洞:内核里的逻辑洞(权限检查缺失、竞争条件、类型混淆)不受内存缓解影响。判据:内存利用被缓解堆死时,逻辑漏洞是绕开所有内存缓解的正交路径。

### 符号执行的路径爆炸管理
**Q1**: 决定用符号执行解一段逻辑,怎么避免一开始就路径爆炸?
**A1**: 先收窄范围。别对整个程序符号执行,只对目标函数、从"输入进入"到"比较发生"这一小段跑。用 hook 把无关的库调用、IO、循环外部分具体化。判据:符号执行的第一原则是"最小化符号范围",范围越小越可解。
**Q2**: 循环导致状态指数增长?
**A2**: 处理循环:限制循环展开次数、把循环体总结成约束、或对固定次数循环具体化边界。判据:循环是路径爆炸主因,优先给循环设界或抽象。
**Q3**: 某些昂贵函数(哈希、加密库)拖垮求解器?
**A3**: hook 成 SimProcedure / 具体值:能具体化的就别符号化,把已知输入的哈希直接算出来喂进去。判据:符号执行里"能具体化的一律具体化",只留真正未知的符号变量。
**Q4**: 状态还是爆炸,求解器跑不出来,被墙?
**A4**: 转混合具体符号(concolic)或换策略:用具体输入引导(driller 式)、改用有向搜索(朝目标地址剪枝、丢弃无关分支)、或干脆退回手工分析 + 局部 z3。判据:纯符号执行爆炸时,转 concolic 或有向搜索用具体信息剪枝。
**Q5**: 连 concolic 都不行(约束本质难,如含哈希/大爆破)?
**A5**: 承认符号执行不适用,转爆破/侧信道/逻辑绕过。判据:符号执行擅长"可逆约束求解",遇到本质不可逆(哈希、强非线性)就该换范式,别在求解器上无限等待。

### 侧重数据:找出"哪几个字节真正决定结果"
**Q1**: 输入很长但不知道哪部分真正参与校验,怎么缩小分析面?
**A1**: 做输入敏感性测试:逐字节/逐段改动输入,看输出/判定是否变化。不影响结果的字节可忽略,影响的才是关键。判据:先用差分找"活性字节",把分析聚焦到真正参与逻辑的那几个字节。
**Q2**: 发现只有中间一段影响结果?
**A2**: 聚焦该段:只逆处理这段的代码路径(用污点从这些字节正向追),忽略其余。判据:活性字节 + 污点传播 = 精确锁定需要逆的代码子集。
**Q3**: 想知道某关键字节流向了哪些运算?
**A3**: 正向污点跟踪:标记该字节,记录它参与的每个指令。得到的污点切片就是"必须理解的最小逻辑"。判据:污点切片天然剔除无关代码,是对抗大体量/混淆程序的利器。
**Q4**: 污点跟踪因为隐式流 / 混淆传播断了或爆了,被墙?
**A4**: 转黑盒差分建模:污点不可靠时,退回纯 I/O 差分——大量改这几个字节观察输出,统计式地建立"输入字节→输出"的关系模型,不依赖内部跟踪。判据:污点(白盒)断了就退到黑盒差分,用外部观测替代内部跟踪。
**Q5**: 黑盒差分也看不出规律(强扩散)?
**A5**: 说明关键字节被卷进强算法,转前述"识别算法/攻实现/攻密钥"链。判据:字节级差分无规律 = 进入了密码学强度区,离开"缩小分析面"阶段,转密码学攻击范式。

### 逆向的收尾:验证还原结果
**Q1**: 自认还原出算法/解出 flag/写好 exp 了,交付前怎么确认它真对?
**A1**: 端到端验证,别信"看起来对"。还原算法就用它重新加密已知明文对比原密文;解出 flag 就完整跑一遍目标验证;写了 exp 就在干净环境多次复现。判据:红队交付物必须"可复现验证",逆向结论没经端到端验证等于没做完。
**Q2**: 本地对了但目标环境不一定一样?
**A2**: 在贴近目标的环境验证:相同 libc 版本、相同架构、相同输入约束下测。判据:环境差异(libc、对齐、字节序)是"本地成远程败"的头号原因,验证要对齐环境。
**Q3**: exp 时好时坏,稳定性不足?
**A3**: 排查非确定因素:ASLR/堆布局随机、race 窗口、残留状态。加重试、加同步、加堆风水提高稳定性。判据:不稳定的 exp = 未交付,找出随机源并驯服它。
**Q4**: 验证发现结果其实是错的(之前判断有误),怎么办?
**A4**: 回溯定位错误假设:从验证失败点反查是哪一步假设错了(算法认错?字节序?密钥不对?偏移错?),别推倒重来。判据:验证失败是宝贵信号,精确定位错误假设比从头再逆高效得多。
**Q5**: 反复验证反复错,某个环节始终对不上,彻底卡住?
**A5**: 转"让目标自证":不再自己推导,直接动态跑目标、在关键点 dump 它的真实中间值,与你的还原逐步对照,第一个不一致的点就是你的错误所在。判据:自己算不对时,用目标的真实执行当"标准答案"逐点校准,是收尾阶段的终极转向。
