# 逆向PWN · 去混淆与反反调试

### 拿到一个陌生二进制,第一刀该切哪
**Q1**: 手上一个不明来历的 ELF/PE,不知道有没有壳、是不是混淆过,先做什么才不浪费时间?
**A1**: 先做"分诊"三连:`file` 看架构/位数/是否 static/是否 strip;`checksec` 看保护(NX/PIE/Canary/RELRO);`strings`/`rabin2 -z` 扫可读串。这三步决定后面所有路线,任何情况都零成本先做。判据:strip+高熵+无明文串 → 大概率加壳或混淆;明文串一堆(printf 格式串、报错、算法魔数)→ 直接静态开干。
**Q2**: strings 里几乎没有可读串,连 "usage" 都没有,说明什么?
**A2**: 要么整个 .text 被加密(壳/SMC),要么字符串被运行时解密。别急着 IDA,先看节区熵值(`ent`/IDA 的 segment 熵),熵>7.2 的大段 = 打包/加密数据。
**Q3**: 那我怎么快速判断是"标准壳"还是"定制/混淆",两者投入天差地别?
**A3**: 看入口点:标准壳(UPX 等)入口在一个小 stub 里、节区名带特征(UPX0/UPX1);定制混淆入口即是正常代码但充满花指令/平坦化。前者能秒脱,后者要长期作战。
**Q4**: 如果 file 显示 static 且 strip,IDA 里全是 sub_xxxx 没符号,怎么快速恢复语义?
**A4**: 用 FLIRT/签名(IDA lumina、bindiff 同版本 libc)恢复 libc 函数;对 static 二进制先识别 __libc_start_main 找到真正 main,再从 I/O 函数(read/write/printf)反查交叉引用锁定核心逻辑。
**Q5**: 分诊做完还是不知从哪下手,被信息量淹没了,往哪转?
**A5**: 转"动态优先"正交维度:直接跑起来 `ltrace`/`strace` 看系统调用与库调用序列,行为会告诉你它读什么文件、连什么端口、比较什么。静态卡住时,行为观测常常一句话点破意图。
**Q6**: 判据总结成一句可复用的?
**A6**: 熵/符号/明文串三个信号 → 决定"脱壳 vs 反混淆 vs 直接逆 vs 动态观测"四条主路线,永远先花 5 分钟分诊再投入。

### 判断加壳并选择脱壳策略
**Q1**: 熵值高、节区名可疑,我怀疑加壳了,如何确认并定壳型?
**A1**: 用 DIE(Detect It Easy)/PEiD 类查壳;看导入表是否只剩 LoadLibrary/GetProcAddress(壳的典型 IAT);看节区是否可写可执行(自解压段)。定型是选脱壳法的前提。
**Q2**: 确认是 UPX 之类标准壳,直接 `upx -d` 报错怎么办?
**A2**: 报错通常是壳被改了魔术标记/节名(反自动脱壳)。修复方法:把节名/UPX 版本头字段改回标准值再 `-d`;或直接放弃脱壳器走"内存转储"通用法。
**Q3**: 不认识的定制壳,通用脱壳思路是什么?
**A3**: ESP 定律 / 内存断点法:壳解压完必然 jmp 到 OEP。下断在解压循环写入的目标段执行点(硬件执行断点),断下即到 OEP,然后 dump 内存 + 修 IAT(Scylla/importrec)。
**Q4**: dump 下来能跑但 IDA 里 IAT 全是错的地址,怎么修?
**A4**: 用 ImpRec/Scylla 在进程运行态重建导入表:定位 IAT 起始、让工具解析调用目标、修复后回填。IAT 不修静态分析寸步难行。
**Q5**: 壳带反调试,一挂调试器就退出/走假分支,脱壳被墙,转哪?
**A5**: 转"无调试器脱壳"正交维度:用 frida/DBI(Pin/QBDI)在无 ptrace 痕迹下 hook 内存分配与 mprotect(改可执行权限那一刻就是解密完成点),或用模拟器(unicorn/qiling)脱离真实调试环境执行到 OEP。
**Q6**: 如果连模拟都因环境检测失败呢?
**A6**: 最后手段是硬扛:定位每一个反调试点逐个 patch(见反反调试链),把脱壳降级为普通动态分析问题。

### 反编译里全是花指令(junk code),读不下去
**Q1**: IDA F5 失败或反汇编错乱,一堆无意义的 push/pop/jmp+1,判断是花指令吗?
**A1**: 典型花指令特征:跳进指令中间(jmp 到某字节偏移让反汇编错位)、恒真/恒假跳转(xor eax,eax; jz)、无效前缀。确认后目标是把"垃圾"NOP 掉恢复正常 CFG。
**Q2**: 手工一个个 patch 太慢,量大怎么办?
**A2**: 写脚本(IDApython/idc)按 pattern 匹配批量 patch:识别常见花指令模板(如 `EB FF C0 48` 这类跳中间的字节序列),统一填 NOP 并 `MakeCode` 重新分析。
**Q3**: 花指令是恒真跳转套着真代码,盲目 NOP 会破坏逻辑吗?
**A3**: 会。要区分"不透明谓词"(opaque predicate,值恒定但形式复杂)与真实条件跳转。判据:该谓词是否依赖外部输入——不依赖且可静态求值 = 不透明谓词,可安全化简。
**Q4**: 反汇编器一直把数据当代码/代码当数据,来回打架,怎么稳住?
**A4**: 手动 `Undefine` 出错区域,在正确的指令边界 `MakeCode`,把混入的常量数据 `MakeData`。CFG 一旦对齐,后续 pattern 就能批量清。
**Q5**: 花指令去完了 F5 还是失败,被这里彻底卡住,转向?
**A5**: 转"动态 trace 还原真实路径"维度:用 DBI 记录实际执行过的指令地址序列(execution trace),只分析真正跑到的基本块,绕过所有静态未跑到的花指令干扰——动态执行天然过滤死代码。
**Q6**: 复用经验一句话?
**A6**: 花指令的本质是"欺骗反汇编器的线性/递归下降",对策永远是"以真实执行流为准":能静态化简就化简,化简不动就用 trace 直接取真路径。

### 控制流平坦化(OLLVM CFF)怎么还原
**Q1**: 函数被拍平成一个大 while(switch(state)) 分发器,所有基本块挂在 dispatcher 下,怎么恢复真实控制流?
**A1**: 先识别结构:主分发变量(state var)、分发器块、真实块、预处理块。目标是恢复"每个真实块执行后 state 被赋成什么值"→ 重建原始后继关系。
**Q2**: state 转移值是运行时算出来的,静态看不出下一个块,怎么办?
**A2**: 用符号执行(angr/miasm)或污点跟踪:对每个真实块,把 state 变量设为符号量,求解块结束时 state 的取值 → 得到该块的真实后继,拼回 CFG。
**Q3**: 符号执行路径爆炸/超时,还原不出来,退而求其次?
**A3**: 混合法:具体值 + 符号(concolic)。对 dispatcher 分支用具体输入驱动执行,记录真实走过的 state 序列,增量还原;不追求完备,只覆盖目标逻辑相关路径。
**Q4**: 平坦化外面还套了虚假控制流(bogus control flow)和不透明谓词,叠 buff 了怎么拆?
**A4**: 分层去:先干掉不透明谓词(化简恒定分支),再拆平坦化。顺序反了会被假谓词误导 state 分析。有现成 deflat 脚本(基于 angr/miasm)可先跑一遍再手工收尾。
**Q5**: 自动化 deflat 工具对这个魔改 OLLVM 完全失效,被墙,转哪个正交维度?
**A5**: 放弃"完整还原 CFG",转"目标导向的动态观测":你其实不需要还原整个函数,只需知道"输入 X 时它对哪个 buffer 做了什么变换"。用 hook/trace 在 dispatcher 出入口打点,记录 (输入→输出) 对,把混淆函数当黑盒建模,甚至直接符号执行求解你要的那个约束。
**Q6**: 什么时候该停止还原、直接黑盒?
**A6**: 判据:当你的目标是"求满足某条件的输入"(如校验/序列号)而非"理解全部逻辑"时,黑盒+约束求解(angr find/avoid)通常比逐块还原快一个数量级。

### 字符串/常量被加密,静态看不到关键信息
**Q1**: 关键字符串(路径、密钥、提示)运行时才解密,静态一片乱码,怎么拿到?
**A1**: 先定位解密函数:交叉引用那段密文数据,看谁读它 → 大概率一个 decrypt(buf, len, key) 循环。找到后有两条路:静态复现算法,或动态跑一遍直接读明文。
**Q2**: 解密算法简单(单字节 xor/加减),值得静态复现吗?
**A2**: 值得,写个脚本一次性把所有密文串批量解出来回填注释,IDA 里瞬间可读,对后续分析收益极高。用 IDApython 遍历所有引用该 decrypt 的调用点提取参数。
**Q3**: 算法复杂或 key 运行时生成,静态复现成本高,怎么办?
**A3**: 转动态:在 decrypt 函数返回处下断/hook,直接从内存 dump 出所有明文串。或者跑到 main 后一次性搜索进程内存里的可读串(此时都已解密)。
**Q4**: 它是"用时才解密、用完立刻擦除",内存里抓不到全量,怎么办?
**A4**: hook 解密函数本体记录每次输出(frida Interceptor.attach 在 onLeave 读返回缓冲),而不是事后扫内存。惰性解密对付事后 dump,但对付 hook 无效。
**Q5**: 解密函数本身被平坦化/反调试保护,hook 不上,被墙,转向?
**A5**: 转"不执行它、直接算":把解密逻辑抠出来(密文数据段 + 算法),在 unicorn 里单独模拟这一小段函数,喂密文得明文,完全绕开原程序的反调试与保护外壳。
**Q6**: 一句话经验?
**A6**: 字符串解密永远是"复现算法 vs 抓运行时输出 vs 抽出来单独模拟"三选一,按算法复杂度与保护强度递进选择。

### 定位并绕过 ptrace 类反调试
**Q1**: 程序一进调试器就退出或行为异常,怀疑 ptrace 反调试,先查什么?
**A1**: Linux 上首查两处:`ptrace(PTRACE_TRACEME)`(自己 trace 自己,别人就 trace 不了)和读 `/proc/self/status` 的 TracerPid 字段(非 0 即被调试)。strace 一跑就能看到这些调用。
**Q2**: 确认是 PTRACE_TRACEME 自我保护,怎么绕?
**A2**: 三选一:(a) LD_PRELOAD 一个假 ptrace 永远返回 0;(b) 在调试器里断在 ptrace 调用后把返回值改成 0;(c) 静态 patch 掉该调用(改成 xor eax,eax 或 NOP)。
**Q3**: 它读 /proc/self/status 判 TracerPid,LD_PRELOAD ptrace 没用,怎么办?
**A3**: 换靶点:hook open/read 拦截对 status 的读取并篡改 TracerPid 为 0;或在调试器里把读到 buffer 里的 TracerPid 值改掉;或干脆 patch 掉比较逻辑。反调试检测点是"多源"的,要逐个点破。
**Q4**: 检测点太多太散,一个个找累死,有没有系统性方法?
**A4**: 有。DBI/frida 全量 hook 已知反调试 API(ptrace/getppid/sysctl/isDebuggerPresent 等)一次性中和;或用反反调试插件(gef/pwndbg 的相关设置、ScyllaHide/linux 版)批量处理常见检测。
**Q5**: 它没用标准 API,而是自己 syscall 或者用信号/异常检测,插件失效,被墙,转哪?
**A5**: 转"无 ptrace 的观测手段":ptrace 检测的前提是有人在 ptrace,那就用非 ptrace 的 DBI(Pin/QBDI/frida gum)或模拟执行(qiling/unicorn),从根上不触发 TracerPid。检测它检测不到的东西。
**Q6**: 复用一句?
**A6**: 反调试是"检测被观测的痕迹",反反调试的正交升维是"换一种不留该痕迹的观测方式",而非在同一维度和它逐点缠斗。

### 时间差反调试(rdtsc / 时间检测)
**Q1**: 单步或下断后程序走异常分支,怀疑时间检测(测两点间耗时判断是否被单步/断点拖慢),怎么确认?
**A1**: 找 `rdtsc`/`clock_gettime`/`GetTickCount` 调用,尤其是"取两次时间做差 + 与阈值比较"的模式。断点/单步会让时间差暴涨从而被识破。
**Q2**: 确认后怎么破?
**A2**: 让时间差恒小:hook 时间源函数,让每次调用返回值只递增极小固定量;或 patch 掉那次差值比较(把 jg/ja 反转或 NOP)。目标是让它以为运行很快。
**Q3**: rdtsc 是裸指令没法 hook 库函数,怎么办?
**A3**: 两条路:在 CPU/VMM 层拦(某些调试器支持 rdtsc 断点/替换),或静态 patch:把 rdtsc 后的减法/比较改成恒满足;或用模拟器把 rdtsc 语义替换成受控计数器。
**Q4**: 时间检测点很多且分散在关键路径上,逐个 patch 影响正常逻辑,怎么稳?
**A4**: 别 patch 时间源,patch"判定":统一识别"时间差 > 阈值则走坏分支"的比较,只反转/去掉判定跳转,保留时间读取不破坏其它依赖时间的正常逻辑。
**Q5**: 它把时间差混进了后续计算(不是简单跳转,而是参与解密 key),patch 判定也没用,被墙,转向?
**A5**: 转"全速无断点执行 + 事后分析":既然慢就露馅,那就不单步、不下软件断点,用硬件断点或纯 trace(DBI 记录)全速跑,或直接在受控模拟器里让时间恒定,从根上消除"慢"这个信号。
**Q6**: 一句话?
**A6**: 时间反调试打的是"你变慢了",对策是"要么让它以为没变慢,要么根本别慢"——patch 判定 / 恒定时间源 / 全速 trace 三档递进。

### 软/硬件断点检测(0xCC 扫描、DR 寄存器)
**Q1**: 下软件断点后程序崩溃或跳走,怀疑它在扫自身代码里的 0xCC,如何确认?
**A1**: 找程序对自己 .text 段做 CRC/校验和,或逐字节比对 0xCC 的循环。软件断点会把目标字节改成 0xCC,校验就变了。
**Q2**: 确认自校验(code checksum),怎么绕?
**A2**: 不用软件断点,改用硬件断点(不修改内存字节,校验查不到);或先让它算完校验、把校验结果 patch 成恒过;或 hook 校验函数返回固定正确值。
**Q3**: 那它又检测硬件断点(读 DR0-DR7 调试寄存器),硬断也被发现,怎么办?
**A3**: 硬件断点检测通常靠 GetThreadContext/异常处理里读 DR 寄存器。对策:hook 该获取上下文的调用,把 DR 字段清零返回;或改用内存断点(页保护)/ DBI 打点,不占用 DR。
**Q4**: 软断硬断都被检测,内存断点又太慢,三面被围怎么办?
**A4**: 退到"不下任何真实断点"的观测:纯 trace(记录执行流事后看)或模拟执行。检测断点的前提是有断点,没有就无从检测。
**Q5**: 它连模拟环境都能识别(见反虚拟机链),被墙到底,转哪个正交维度?
**A5**: 转"静态 + 少量精准动态"混合:用静态分析把逻辑理解到 80%,只在一两个必须验证的点用最隐蔽手段(如内存写监控/条件极严的硬断)取那一个值,把动态介入面缩到最小以躲过检测。
**Q6**: 复用要点?
**A6**: 断点检测的破法是"换一种不改内存、不占 DR 的观测方式";多重检测叠加时,减少动态介入的"表面积"比硬碰硬更有效。

### 反反调试:动态 patch 还是静态 patch
**Q1**: 找到一堆反调试点,该在调试器里动态改,还是直接 patch 二进制永久去除?
**A1**: 看用途:一次性分析用动态 patch(调试器脚本/条件断点自动改返回值),快且不破坏原文件;要反复运行、写 exploit、或分发改好的样本,用静态 patch 落盘。
**Q2**: 静态 patch 一个反调试后程序直接崩了,为什么?
**A2**: 大概率有自校验(代码/文件 checksum)发现被改。要么连校验一起 patch,要么改用不落盘的动态方式,要么 patch 后重算并修正校验值。
**Q3**: 动态 patch 的最省事姿势是什么?
**A3**: 调试器启动脚本里对每个反调试调用点设"命中即改返回值/改标志位后自动继续"的条件断点,一次配置全程自动化,不用手工干预。
**Q4**: 反调试点分布在多个动态加载的模块/延迟解密的代码里,启动时还没出现,patch 不到,怎么办?
**A4**: 挂在"代码就绪时刻":hook mprotect/dlopen/解密函数,在目标代码被映射/解密为可执行的那一刻再 patch,时机对齐才有效。
**Q5**: patch 了这个又冒出那个,像打地鼠打不完,被拖垮,转向?
**A5**: 转"环境级中和"正交维度:与其逐点 patch,不如换整个执行底座——LD_PRELOAD 统一伪造一批检测函数,或用 qiling/frida 提供受控运行环境批量拦截,把"逐点战"变成"一次性环境战"。
**Q6**: 决策一句话?
**A6**: 少量静态点 → 落盘 patch;多且动态生成 → 时机对齐的 hook;打不完 → 升维到环境级统一中和。

### 加密算法识别(标准 vs 魔改)
**Q1**: 逆到一段明显是密码学的循环,怎么快速认出是什么算法?
**A1**: 认"指纹常量":AES 的 S-box/T-table、SHA 的初始 H 常量、MD5 的正弦表、TEA 的 0x9E3779B9(golden ratio delta)、CRC 的多项式表。findcrypt/signsrch 类插件一扫就知道。
**Q2**: 常量都在,但流程被改了(魔改 AES),标准库解不开,怎么办?
**A2**: 魔改点通常是:改 S-box、改轮数、改密钥编排、加异或偏移。逐项与标准对比,定位改动处,自己按魔改版重写解密即可。别信"看着像 AES 就用标准 AES 解"。
**Q3**: 一个特征常量都没有,完全不认识,是自研加密吗?
**A3**: 可能是自研或换表。别死磕辨识,把它当"未知可逆变换":确认是否可逆(有没有对应解密路径),能否用已知明密文对求解结构,或直接把加密函数抠出来模拟当黑盒用。
**Q4**: 我只需要"给定密文求明文",不需要认出算法,最快路径?
**A4**: 如果加密可逆且解密函数就在程序里,直接调用它(用 unicorn/qiling 单独执行该函数,或用 LD_PRELOAD 让程序帮你解)。识别算法是手段不是目的。
**Q5**: 算法认出来了但 key 拿不到(硬件/服务器侧生成),死在密钥上,被墙,转哪?
**A5**: 转"密钥来源侧":key 不在本地就往产生它的地方追——网络抓包(通信协议逆向)、密钥派生函数(KDF)逆推、或在密钥进入加密函数的那一刻 hook 内存直接读明文 key。攻击 key 的"出生地"而非加密本身。
**Q6**: 复用?
**A6**: 密码逆向优先级:识别标准常量 → 找魔改差异 → 求 key 或 hook 中间态 → 抠函数当黑盒。永远别假设它是纯标准实现。

### 基于虚拟机的混淆(VM 保护)怎么下手
**Q1**: 关键逻辑被转成自定义字节码 + 解释器(VMProtect/自研 VM 类),没有原生指令可读,如何入手?
**A1**: 先别想还原全部。目标分三步:定位 VM 分发器(取 opcode → 跳 handler 的循环)、枚举 handler 集合、理解 VM 上下文(虚拟寄存器/栈在哪块内存)。这是 devirtualize 的地基。
**Q2**: handler 有几十上百个,怎么高效摸清每个干什么?
**A2**: 对每个 handler 用符号执行/小样本 trace 建立"opcode → 语义(等价原生操作)"映射表。很多 handler 是简单算术/访存,逐个标注,VM ISA 就出来了。
**Q3**: 手工建 handler 表太慢,有更快的路吗?
**A3**: 转 trace 驱动:喂一个已知输入,记录 VM 实际执行的 opcode 序列(bytecode trace),只还原真正跑到的那条字节码路径,而非整套 ISA。目标导向比完整 devirt 快得多。
**Q4**: 我根本不想还原 VM,只想知道它对我的输入做了什么校验,怎么办?
**A4**: 黑盒建模:把整个 VM 保护的函数看成 f(input)→output,用 DBI 在 VM 入口/出口打点采集大量 (输入,输出) 对,或直接对 f 做符号执行让求解器找满足条件的输入。不理解 VM 也能求解目标。
**Q5**: VM 还嵌套了反调试、每次运行 opcode 编码还变(多态),彻底摸不清,被墙,转向?
**A5**: 转"更高抽象层观测":你要的答案往往在 VM 之外——VM 算完总要和外部世界交互(比较结果、读写文件、发网络、调用系统 API)。在 VM 的"边界 API"上 hook,观察输入/输出与最终 syscall,绕过 VM 内部完全不碰。多态混淆保护不了它的对外行为。
**Q6**: 一句话战略?
**A6**: 对 VM 保护:能不还原就不还原,优先"目标导向 trace"和"边界黑盒",完整 devirt 只在必须逐指令理解时才做,成本极高。

### 自修改代码(SMC)导致静态失真
**Q1**: IDA 里某段代码看着无意义/校验总不过,怀疑运行时被改写(SMC),怎么确认?
**A1**: 特征:程序对自己代码段有写操作、调用 mprotect/VirtualProtect 把 .text 改成可写、或有"解密一段→跳进去执行"的模式。静态看到的是"改写前"的假象。
**Q2**: 确认 SMC,静态分析的正确姿势是什么?
**A2**: 别信静态字节。在"改写完成、执行前"那一刻 dump 出真实代码:hook mprotect 恢复可执行权限处下断,或运行到该段被执行时从内存重新反汇编(IDA 的 debugger 里 reanalyze)。
**Q3**: 它是"用一段、改一段、边跑边变",没有一个统一的"解密完成点",怎么办?
**A3**: 逐段跟:在每次跳进被改写区域前 dump 当前版本,或全程 trace 记录实际执行的指令流(execution trace),用真实执行序列代替静态视图。
**Q4**: SMC 还和反调试联动(检测到调试就不解密真码),怎么破?
**A4**: 先解决反调试让解密正常发生(见反反调试链),再抓解密后代码。顺序:反反调试 → 触发真解密 → dump 真码。
**Q5**: 解密逻辑依赖只有目标环境才有的输入(硬件/时间/网络),本地永远解不出真码,被墙,转哪?
**A5**: 转"补齐环境或抓成品":要么在目标环境里跑并 dump 解密后代码带回本地分析;要么伪造那些依赖输入(qiling 里 mock 硬件/时间/网络返回)让解密在受控环境完成。攻不动逻辑就补环境。
**Q6**: 复用?
**A6**: SMC 铁律:"以内存中即将执行的字节为准,不信磁盘/初始静态视图";核心动作是在正确时机 dump 真实代码。

### 决定静态优先还是动态优先
**Q1**: 一个中等复杂度目标,该先啃静态还是先跑动态?怎么定?
**A1**: 看三个因素:有无反调试(有 → 静态先,避免动态踩雷)、混淆强度(强 → 动态取真路径)、目标是"理解全部"还是"求某个值/输入"(求值 → 动态/符号执行更快)。没有绝对,分诊后按信号选。
**Q2**: 我选了静态,但混淆重到读不动,该切动态吗?
**A2**: 该。静态卡在"读不懂控制流/被花指令平坦化淹没"时,动态 trace 能直接给你真实执行路径,是静态的天然补充。别在静态里硬耗超过合理时间。
**Q3**: 反过来,动态跑但触发不了目标分支(要特定输入才走),怎么办?
**A3**: 切回静态找"进入该分支的条件",或用符号执行反解触发输入(angr 从入口 find 目标地址)。动态触发不了的路径,静态/符号执行来补。
**Q4**: 两边来回切感觉在原地打转,时间在流失,如何止损?
**A4**: 明确单次目标:每一轮只回答一个具体问题(如"这个 buffer 从哪来""这个比较的另一操作数是什么"),用最省的手段答完就走,避免"全都想搞懂"的贪心导致空转。
**Q5**: 静态动态都卡死,整体被墙,转哪个第三维度?
**A5**: 转"符号/约束求解"这个正交维度:当你其实只需要"满足某约束的输入"时,angr/concolic 把逆向问题变成解方程,常常跳过对逻辑的完整理解直接出答案。第三条腿常被忽略。
**Q6**: 决策口诀?
**A6**: 有反调试/要落盘 → 静态起手;混淆重/要真路径 → 动态;要求解输入 → 符号执行。三者不是站队而是按当前子目标轮换的工具。

### PWN:确定漏洞类型
**Q1**: 拿到一个有交互的服务型二进制,先怎么定位漏洞类型?
**A1**: 逆向所有输入点(read/scanf/recv/gets)看边界:定长 buffer 收超长 = 栈溢出;printf(user) = 格式化字符串;malloc/free 配对逻辑异常 = 堆漏洞;数组下标来自输入无校验 = OOB。先给漏洞归类再谈利用。
**Q2**: 多个输入点都可疑,先打哪个?
**A2**: 按"可控度 × 破坏力"排序:能直接覆盖返回地址/函数指针的栈溢出优先;其次能任意读写的格式化串/堆;OOB 看能读写到哪。先打收益最直接的。
**Q3**: 看着像栈溢出但有 Canary,溢出立刻被拦,怎么办?
**A3**: 先想能不能泄露/绕过 canary(见对应链),或转向不经过 canary 的原语(格式化串任意写、堆漏洞)。漏洞类型定了不代表路径唯一,换利用面。
**Q4**: 静态没看出明显漏洞,程序也不崩,怀疑逻辑更隐蔽,怎么找?
**A4**: 上 fuzzing(AFL++/libfuzzer 桩)喂畸形输入找崩溃点,或对输入处理函数做符号执行找越界/异常。人眼看不出的边界漏洞,fuzz 常常一撞一个。
**Q5**: fuzz 也不崩、静态也没洞,这条目标像没漏洞,被墙,转哪?
**A5**: 转"非内存破坏"维度:重新审题——可能是逻辑漏洞(权限绕过、整数溢出致逻辑错乱、竞态/UAF 时序、命令拼接注入)而非经典栈堆溢出。把视角从"内存腐败"切到"逻辑与状态机缺陷"。
**Q6**: 一句话?
**A6**: 漏洞定位=枚举输入点×检查每处边界与信任假设;经典内存洞找不到就升维到逻辑/竞态/整数缺陷。

### 保护机制决定利用手法
**Q1**: checksec 出来 NX/PIE/Canary/RELRO 一堆,怎么据此定利用路线?
**A1**: 逐项翻译成约束:NX → 不能栈上执行 shellcode,得 ROP/ret2libc;PIE → 地址随机,需先泄露基址;Canary → 栈溢出需先泄露/绕过 canary;Full RELRO → 不能改 GOT,得找别的写目标。保护表就是你的路线图。
**Q2**: 全开(NX+PIE+Canary+Full RELRO),看着无从下手,先攻哪个?
**A2**: 先解决"信息泄露",拿到某个地址(栈/libc/PIE 基址)。没有 leak 其它都是空谈。找任何能回显内存的原语(格式化串、OOB read、未初始化打印)。
**Q3**: 没有 PIE(程序基址固定)但有其它保护,这给我什么便宜?
**A3**: 程序自身的代码/GOT/BSS 地址固定,可直接用作 ROP gadget 来源、写目标、或放数据的稳定区。无 PIE 是一大突破口,优先利用固定地址资源。
**Q4**: Partial RELRO,GOT 可写,该怎么用?
**A4**: GOT hijack:有任意写就改某个即将被调用函数的 GOT 项指向 system/one_gadget。Partial RELRO 是 GOT 覆盖的经典前提,优先考虑。
**Q5**: 保护全开且找不到任何 leak 原语,彻底卡死,转哪个正交维度?
**A5**: 转"利用手法本身绕过泄露需求":如 ret2csu/ret2dlresolve(不需要 libc leak 直接解析符号)、栈迁移到已知固定区、或利用 partial overwrite(只改地址低字节绕过随机化高位)。没有 leak 时,partial overwrite 与 dlresolve 是经典突围。
**Q6**: 复用?
**A6**: 把 checksec 每一项当成一条"禁止规则",利用就是"在所有规则下找一条合法通路";全开时先夺 leak,夺不到就用免 leak 手法(dlresolve/partial overwrite)。

### 泄露地址打 ASLR/PIE
**Q1**: 有 PIE/ASLR,我需要一个地址,从哪找 leak?
**A1**: 常见 leak 源:格式化字符串漏洞(%p 直接打栈上残留的 libc/栈/PIE 地址)、越界读回显、UAF 读已释放块里的指针、未初始化变量打印。先扫哪个输入能"回显内存"。
**Q2**: 格式化串能 leak,但打出来的地址不知道是啥基址,怎么对应?
**A2**: 用偏移法:同一次运行里,某 %p 值减去它对应的已知符号偏移 = 基址。判断是哪种地址看范围(栈地址高、libc 在 mmap 区、PIE 近程序基址),多跑几次看哪些位随机哪些固定来归类。
**Q3**: leak 出来的是 libc 里某函数地址,怎么算 libc 基址进而拿 system?
**A3**: libc 基址 = leak 值 − 该符号在这版 libc 里的偏移。前提是知道 libc 版本(见 libc 识别链),再加各符号相对偏移求出 system/bin_sh。
**Q4**: 一次交互只能 leak 一次然后程序就退出,不够用怎么办?
**A4**: 找"能循环/多次交互"的结构(菜单循环),把 leak 和后续利用放不同轮次;或一次 leak 尽量多打几个 %p 一把梭。没有循环就想办法让程序不退出(部分覆盖返回到 main 重来)。
**Q5**: 就是没有任何 leak 原语,ASLR 硬墙,转哪?
**A5**: 转"免 leak 突破 ASLR":partial overwrite(只覆盖地址低 1-2 字节,高位随机不变,爆破低位随机部分,概率可接受)、ret2dlresolve(不需 libc 地址)、或爆破(fork 型服务 ASLR 不变,可暴力猜)。fork server 是 ASLR 的天然弱点。
**Q6**: 关键判据?
**A6**: fork 服务器 ASLR 每次相同 → 可爆破/partial;非 fork 且无 leak → dlresolve 或 partial overwrite;有 leak → 先分类地址再算基址。

### ROP gadget 不够用
**Q1**: 要构造 ROP 但 ROPgadget 搜出来的片段凑不齐想要的原语(比如没有 pop rdx),怎么办?
**A1**: 先扩大搜索面:搜 static 二进制/整个 libc,不只主程序;放宽匹配(找 pop rdx; ret 找不到就找 pop rdx; pop rcx; ret 之类带副作用可接受的)。gadget 常在 libc 里管够。
**Q2**: 目标 NX+静态编译,gadget 只能来自程序本身且确实缺关键片段,怎么办?
**A2**: 用组合 gadget:没有直接的就用 ret2csu 这种"通用寄存器装载器"(__libc_csu_init 里的 pop rbx/rbp/r12/r13/r14/r15 + call 序列)控制多个参数寄存器。csu 是 gadget 荒漠里的绿洲。
**Q3**: 想直接 system("/bin/sh") 但找不到 "/bin/sh" 字符串也没法写,怎么办?
**A3**: 换目标:用 read/gets 往可写段(bss)写入 "/bin/sh" 再引用其地址;或 ret2libc 用 libc 里现成的 "/bin/sh";或改用 execve syscall 自己布参数。字符串没有就自己造。
**Q4**: gadget 够但栈空间不够放整条 ROP 链,怎么办?
**A4**: 栈迁移(stack pivot):用 leave;ret / xchg rsp 类 gadget 把 rsp 迁到你能大量写入的可控区(bss),在那里展开完整链。空间不足就搬家。
**Q5**: 各种凑都凑不出可用链,ROP 这条路被墙,转哪个正交维度?
**A5**: 转"非 ROP 的控制流劫持":ret2dlresolve(让 loader 帮你解析 system)、GOT/hook 覆盖、__malloc_hook/__free_hook(老 libc)、IO_FILE 伪造(FSOP)触发函数指针调用、或 SROP(用 sigreturn 一次性设置所有寄存器)。ROP 荒漠时 SROP/dlresolve 是经典换维。
**Q6**: 一句话?
**A6**: gadget 不够的解法阶梯:扩大来源 → ret2csu 组合 → 栈迁移换空间 → 换成 SROP/dlresolve/IO 等非 ROP 原语。

### 堆利用手法选择
**Q1**: 确认是堆漏洞(UAF/overflow/double free),面对一堆手法(tcache/fastbin/unlink/...)怎么选?
**A1**: 先看三件事:glibc 版本(决定 tcache/安全检查有无)、你有的原语(能 overflow chunk header?能 UAF 读写?能 double free?)、目标(任意写?leak?)。手法是"原语×版本"的函数,不是背套路。
**Q2**: 新版 glibc(带 tcache + safe-linking),经典 fastbin attack 失效,怎么办?
**A2**: tcache 优先:tcache poisoning(改 next 指向目标)更简单;safe-linking 需要先 leak heap 基址来算异或掩码。先搞 heap leak 再 poison。版本决定你要不要处理 safe-linking。
**Q3**: 我只能 double free,能干什么?
**A3**: tcache double free(老版本无 key 检查直接成环)→ 分配到任意地址;新版有 tcache key 检测需先绕过(错位 free / 改 key)。double free 的价值 = 换一次任意地址分配。
**Q4**: 我需要 libc leak,堆里怎么搞?
**A4**: 让一个 chunk 进 unsorted bin(size 够大不入 tcache),其 fd/bk 会指向 main_arena(libc 内),UAF/OOB 读它 = libc leak。unsorted bin 是堆里 leak libc 的经典水源。
**Q5**: 手法都试了,分配到目标但 glibc 各种 check(size 对不上、bin 完整性)拦住,被墙,转哪?
**A5**: 转"打不受这些 check 保护的目标":如 tcache(检查最少)、__free_hook/__malloc_hook(老 libc,写函数指针一击致命)、或 FSOP/IO_FILE 利用(把任意写导向伪造的 _IO_FILE 触发 vtable 调用)。当 bin 完整性 check 挡路,换成 hook/IO 这类"写一处指针即 getshell"的目标。
**Q6**: 复用要点?
**A6**: 堆利用先锁定"glibc 版本 + 手里原语",据此选 tcache/unsorted/fastbin;被安全检查卡住就转向 check 更弱的目标(tcache/hook/IO)。

### libc 版本识别
**Q1**: 远程题不给 libc,我 leak 到几个函数地址,怎么定 libc 版本?
**A1**: 用地址低 12 位(页内偏移,ASLR 不变)去 libc 数据库(libc.rip / libc-database)匹配:输入 2-3 个 符号名+leak 低位,库反查出具体版本。低 12 位是 libc 的"指纹"。
**Q2**: 只 leak 到一个地址,匹配出多个候选 libc,怎么缩小?
**A2**: 再 leak 一个不同函数拿第二个约束,或用已知的相对偏移差(两符号间距在不同版本不同)排除。一个不够就多取一个交叉验证。
**Q3**: 匹配到版本了,怎么拿到确切的 system/bin_sh 偏移?
**A3**: 下载对应版本 libc.so,用它算 base 和各符号偏移;本地用同一份 libc 打通再上远程。务必"用远程同款 libc"本地复现,偏移差一点就 crash。
**Q4**: 数据库里查不到这个 libc(魔改/发行版特供),怎么办?
**A4**: 转"就地取材":很多利用不需要精确版本——用 ret2dlresolve(免 libc 偏移)、或 leak 更多地址在线性关系里反推、或从题目环境侧想办法拿到那份 libc(有时其它接口能读文件)。
**Q5**: 完全拿不到 libc 且 dlresolve 也不适用,被墙,转哪?
**A5**: 转"不依赖 libc 的利用":纯用程序自身 gadget 做 ROP、直接 syscall(execve)、SROP。把 libc 从利用链里彻底剔除,消除对版本的依赖。
**Q6**: 一句话?
**A6**: libc 识别靠"leak 低 12 位查库",查不到就走免 libc(dlresolve/纯 syscall/SROP)路线绕过版本依赖。

### seccomp 沙箱绕过(禁 execve 只能 ORW)
**Q1**: getshell 后发现 execve 被禁(seccomp),怎么先摸清规则?
**A1**: 用 seccomp-tools dump 跑一遍看它 allow/deny 哪些 syscall。典型是禁 execve/execveat 只放 open/read/write → 意图是逼你 ORW 读 flag 而非弹 shell。先看清白名单再定策略。
**Q2**: 确认只能 ORW,利用链要怎么改?
**A2**: 目标从"getshell"改成"open(flag)+read 到内存+write 到 stdout"。ROP/shellcode 布这三个 syscall 的参数依次调用。手法不变,syscall 换成 orw 三件套。
**Q3**: open 也被禁,只给了 openat 或更少,怎么办?
**A3**: 用等价 syscall:openat 代 open、sendfile/pread 代 read+write、甚至 mmap 文件后直接读。白名单里任何"能把文件内容弄出来"的组合都行,别死认 open/read/write 三件套。
**Q4**: 连读文件的 syscall 都几乎禁光,ORW 走不通,转哪?
**A4**: 转"非文件读取的外泄":如果允许 write/socket,可能用侧信道(通过是否崩溃/延时泄露 flag 逐字节)、或利用允许的 syscall 做爆破式比较。ORW 死了就上侧信道逐字节爆破。
**Q5**: seccomp 是"禁某架构 syscall"型(如只禁 x86_64 没禁 x32 ABI),这算漏洞吗?
**A5**: 算,且是经典绕过点:若过滤没检查 arch 或漏了 x32 ABI(syscall 号 +0x40000000),可用另一 ABI 调被禁的 execve。检查 seccomp 规则是否 arch-complete 是标准突破口。
**Q6**: 复用?
**A6**: seccomp 绕过阶梯:dump 规则 → ORW 三件套 → 换等价 syscall → 侧信道逐字节 → 找 arch/ABI 过滤缺陷用另一 ABI 调禁用调用。

### 本地打通远程打不通
**Q1**: exploit 本地稳定 getshell,远程却崩/无响应,先怀疑什么?
**A1**: 头号嫌疑:libc 不一致(远程用的不是你本地那份)。其次:环境变量/栈对齐差异、缓冲区因 tty 差异表现不同、地址空间布局差异。先锁定 libc 一致性。
**Q2**: 怎么验证是不是 libc 差异?
**A2**: 用远程 leak 出的地址反查版本(libc 识别链),和你本地用的对比;若不同,换成远程同款 libc 重算所有偏移。偏移错一点整链就崩。
**Q3**: libc 一致了还是不通,接着查什么?
**A3**: 栈对齐:某些 libc 的 system/movaps 要求 16 字节对齐,远程崩在 movaps。对策:在返回链前加一个 ret 做对齐。这是"本地过远程崩"的高频原因。
**Q4**: 交互时序问题(远程 recv 收不全、发太快),怎么排?
**A4**: 把 pwntools 的 recvuntil/sendlineafter 用严格锚点同步,别用 sleep 赌时间;确认每步都收到预期回显再发下一步。远程延迟大,时序要靠锚点而非固定等待。
**Q5**: 所有已知差异都排了还是打不通,彻底卡住,转哪?
**A5**: 转"降低对环境敏感度"的利用重构:换更鲁棒的手法——免 libc(dlresolve/syscall)减少版本依赖、one_gadget 换成手搓 execve、加大 leak 冗余。把 exploit 从"精确依赖环境"重构为"环境无关",是远程打不通的根本解。
**Q6**: 一句话?
**A6**: 本地通远程不通,排查顺序:libc 版本 → 栈对齐 → 交互时序 → 环境敏感度;治本是把利用重构成环境无关。

### one_gadget 约束不满足
**Q1**: 想用 one_gadget 一发入魂,但跑到那儿不 getshell,为什么?
**A1**: one_gadget 有前置约束(如 [rsp+0x30]==NULL 或某寄存器为 0)。当前上下文不满足约束就会崩而非 getshell。先用 one_gadget 看每个候选的 constraints。
**Q2**: 有多个 one_gadget,怎么挑能满足的?
**A2**: 在触发点用调试器看当前寄存器/栈状态,对照每个 gadget 的约束选一个恰好满足的。不同触发路径满足不同 gadget,换个调用点约束可能就变好。
**Q3**: 所有 one_gadget 约束都不满足,怎么办?
**A3**: 想办法"制造约束满足的现场":如果约束要某寄存器为 0/某栈位为 NULL,先用 ROP 布置好该寄存器/栈,再跳 one_gadget。约束不满足就先动手满足它。
**Q4**: 布置约束太麻烦或空间不够,放弃 one_gadget 转哪?
**A4**: 转"老实 ret2system":自己 pop rdi = "/bin/sh"; ret; system。多几个 gadget 但无隐藏约束,稳。one_gadget 是捷径不是唯一路,约束难满足就走稳的 system 三步。
**Q5**: 目标禁了 system/execve(seccomp),one_gadget 和 system 都无意义,转哪个正交维度?
**A5**: 转 ORW/syscall 链(见 seccomp 链):既然不能起 shell,目标改成直接 syscall 读 flag,one_gadget 这类"起 shell 原语"整个失去意义,换 syscall 布参。
**Q6**: 复用?
**A6**: one_gadget 失败先看约束→换候选→主动布置满足约束→退回 ret2system→若禁 exec 则彻底转 ORW。捷径不通就走稳路。

### IO_FILE / FSOP 利用转向
**Q1**: 堆利用到了任意写但 __malloc_hook/__free_hook 在新 libc 里没了,怎么办?
**A1**: 转 IO_FILE 利用:新 glibc 去了 hook,主流转向伪造 _IO_FILE 结构 + vtable。目标是在 exit/fflush/fread 等触发 vtable 函数指针调用时劫持到你的地址。hook 没了,FSOP 接棒。
**Q2**: FSOP 的核心攻击面是什么?
**A2**: _IO_list_all 链上的 FILE 结构 + 其 vtable。伪造一个 fake FILE,让其 vtable 指向可控内存,在 IO flush 时触发 _IO_overflow 等虚函数调用你的目标(system 或链)。任意写一个指针就撬动整条 IO 调用。
**Q3**: 新 libc 有 vtable check(_IO_vtable_check 限制 vtable 必须在合法区间),伪造 vtable 崩了怎么办?
**A3**: 用合法区间内的"可利用 vtable":如 _IO_str_jumps / _IO_wstr 系列里能间接调用可控函数指针的项(House of 系列的 apple/emma 等思路),绕过 vtable 区间检查。check 只限区间不限具体,选区间内能借力的。
**Q4**: 我连触发 IO flush 的时机都没有(程序不正常退出/不 fflush),怎么办?
**A4**: 主动触发:很多利用靠劫持 exit → __run_exit_handlers → fflush 遍历 FILE 链;或覆盖 stdout 结构在下一次 printf/puts 时触发。找任何一个必经的 IO/exit 路径当扳机。
**Q5**: IO 利用整条太复杂、check 太多,搞不定,退回哪?
**A5**: 退回评估"有没有更简单原语被忽略":比如能不能直接改 GOT(若非 Full RELRO)、能不能栈迁移 ROP、能不能改 __exit_funcs 里的函数指针(带 pointer guard 需处理)。IO 是高级手段,先确认没有更省的路再上。
**Q6**: 一句话?
**A6**: 新 libc 无 hook → 转 FSOP;遇 vtable check → 用合法区间内可借力的 jumps;缺触发时机 → 劫持 exit/stdout。复杂到卡壳先回头找更简单原语。

### 格式化字符串偏移定位
**Q1**: 确认 printf(user) 格式化串漏洞,第一步怎么定"我的输入在第几个参数位"?
**A1**: 发送 `AAAA%p%p%p...` 或 `%1$p%2$p...`,看哪个 %N$p 打回 0x41414141('AAAA'),那个 N 就是你可控输入的偏移。这是所有格式化串利用的坐标原点。
**Q2**: 找到偏移后,怎么先拿 leak?
**A2**: 用 %N$p 打不同位置:栈上常残留 libc 返回地址、__libc_start_main、canary、栈地址。挨个位置扫,归类出 libc/栈/PIE/canary,先把需要的地址 leak 全。
**Q3**: 要任意写(%n),但只能格式化一次,怎么规划?
**A3**: 一次内既 leak 又写不现实,通常靠程序循环多次进 printf。若只有一次:优先用这次做最关键一击(如改返回地址低位/改一个 GOT 项);多次则第一次 leak、后续写。
**Q4**: 用 %n 写大数值导致要输出天量字符、太慢或被截断,怎么办?
**A4**: 分字节写:用 %hhn(单字节)/%hn(双字节)按字节拆分目标值,每次只输出到需要的低位数,配合 $ 定位不同字节地址。大数拆成几个小写入。
**Q5**: 目标环境把 %n 禁了(FORTIFY / _FORTIFY_SOURCE 拦 %n),写不了,转哪?
**A5**: 转"只读利用 + 换写入原语":格式化串仍可全力做 leak(%p/%s 任意读),把"写"的活交给别的漏洞(栈溢出/堆);或利用 leak 出的信息喂给另一条利用链。%n 被禁则退化为强力任意读,写靠别处。
**Q6**: 复用?
**A6**: 格式化串:先定偏移(%N$p 打 AAAA)→ 扫栈 leak → %hhn 分字节任意写 → 若禁 %n 则当纯任意读器配合其它漏洞。

### 用 hook/frida 插桩定位关键函数
**Q1**: 大二进制里找不到"处理我输入的那个函数",静态交叉引用太多,怎么用动态快速定位?
**A1**: 输入一个独特 magic 值(如 "ZZZZ1234"),用 frida/DBI hook 常见处理函数(strcmp/memcmp/read 回调)或全量 trace,看谁的参数里出现你的 magic。数据流会把你带到关键函数。
**Q2**: 不知道 hook 哪个函数,总不能全 hook,怎么缩范围?
**A2**: 先 hook 边界(read/recv 拿到输入的那一刻),从那里顺着调用栈往下 trace;或用 frida-trace 对一批候选函数批量打点,看命中。从"输入入口"顺流而下最省。
**Q3**: 关键比较用的是自定义函数不是 strcmp,hook 标准库没命中,怎么办?
**A3**: 换策略:内存断点/写监控——你的输入落在某 buffer,监控谁读该 buffer;或 trace 全程指令找"引用了你输入地址"的指令。自定义函数无从 hook 名字时,盯数据地址而非函数名。
**Q4**: 目标有反 frida/反 hook 检测(检测 gum 痕迹/inline hook 的 trampoline),插桩就崩,怎么办?
**A4**: 换更隐蔽的 DBI(QBDI/Pin,不 inline patch 目标内存)或 ptrace 级硬件断点观测;或先解决反 hook 检测(见反 hook 链)。检测 frida 的对策是换一种不留 frida 痕迹的插桩。
**Q5**: 各种插桩都被检测/被墙,动态定位这条路死了,转哪?
**A5**: 转"静态数据流 + 符号执行":从输入 buffer 的地址静态追它被传给了哪些函数(污点分析),或用 angr 从输入符号化开始 explore,让求解器带你到处理逻辑。动态被封就用静态污点/符号补。
**Q6**: 一句话?
**A6**: 定位关键函数:magic 值 + 边界 hook 顺流而下是最快路;自定义比较盯数据地址;被反 hook 就换隐蔽 DBI 或转静态污点/符号执行。

### 反 hook / 完整性自校验检测
**Q1**: 我 inline hook 了目标函数,程序却检测到并崩溃/走假逻辑,它怎么发现的?
**A1**: inline hook 会改函数开头字节为 jmp,目标常见检测:对关键函数前几字节做校验、或检查函数地址是否指向预期模块。它在查"代码被改"的痕迹。先确认检测的是字节完整性还是地址来源。
**Q2**: 确认是"函数头字节校验",怎么绕?
**A2**: 换不改字节的 hook:硬件断点(不改内存)、或 DBI(QBDI/Pin 在副本上插桩,原内存不动),让代码字节保持原样通过校验。改字节被查就用不改字节的观测。
**Q3**: 它检测的是"调用来自非法模块/frida-agent 存在",怎么办?
**A3**: 隐藏注入痕迹:改 frida 默认特征(端口/模块名/线程名)、或用无独立 agent 模块的方案(注入到目标已有内存)。检测注入源就抹掉注入的可识别特征。
**Q4**: 它周期性全代码段 CRC 自校验,任何 patch 都被发现,怎么办?
**A4**: 两条路:定位并中和校验函数本身(让它恒返回正确)——但这也是 patch,可能自校验套娃;或彻底不 patch,用模拟执行/硬件断点做纯观测。校验套娃时优先"零修改观测"。
**Q5**: 反 hook + 自校验 + 反调试三件套联动,处处是墙,整体被封,转哪个正交维度?
**A5**: 转"完全离线的静态/模拟"维度:把目标搬进 unicorn/qiling 全模拟环境,你控制整个 CPU 与内存视图,它的所有"检测被观测"手段(校验/反调试/反 hook)在你即是全知全能的宿主面前统统失效——因为你不是在它体内插桩,而是在体外扮演它的世界。
**Q6**: 战略一句话?
**A6**: 所有"反观测"技术都假设"观测者在被观测者的进程/机器内留痕";升维到全模拟(你就是它的 CPU)是釜底抽薪的通解,代价是模拟环境搭建成本。

### 反虚拟机 / 反沙箱检测
**Q1**: 样本在我的分析虚拟机里啥都不干、直接退出,怀疑反 VM,先查什么?
**A1**: 查常见 VM 指纹检测:CPUID hypervisor 位、注册表/设备里的 VMware/VBox 串、MAC 前缀、特定驱动/进程名、磁盘大小/内存过小、rdtsc 时序异常。strace/API monitor 看它读了什么来判环境。
**Q2**: 确认它查 CPUID/注册表指纹,怎么让它以为是真机?
**A2**: 逐项伪装:patch 掉 CPUID hypervisor 检测分支、改掉 VM 特征注册表键/设备名、改 MAC、加大磁盘内存。或直接 patch 掉"检测到 VM 就退出"的那个判定跳转,一刀切。
**Q3**: 检测点太多不想逐个伪装,最省的做法?
**A3**: 不伪装环境,伪装"结论":定位所有检测汇聚到的那个"是否在 VM"的布尔判定/最终跳转,只 patch 那一个点让它恒判"真机"。抓总闸比拧每个龙头省。
**Q4**: 它检测的是"沙箱行为特征"(比如无用户交互、鼠标不动、运行时间过短),怎么办?
**A4**: 补足人类痕迹:模拟鼠标移动/点击、让机器有历史文件/浏览记录、延长运行等过检测窗口(patch 掉 sleep 或快进时间)。行为型检测要补行为,不是补指纹。
**Q5**: 反 VM 检测手段未知、伪装不全、样本就是不触发真实逻辑,被墙,转哪?
**A5**: 转"物理机/裸机分析"或"全模拟":要么在物理机(带还原卡/快照)上跑消除 VM 指纹;要么反过来用 qiling/unicorn 全模拟——你掌控 CPUID/注册表/时间的每个返回值,想让它看到什么就是什么。伪装不干净就换个你完全掌控返回值的底座。
**Q6**: 一句话?
**A6**: 反 VM 破法:伪装指纹 / patch 总判定 / 补行为痕迹 三选一;都不行就上物理机或全模拟这种"环境返回值完全可控"的底座。

### 间接跳转 / dispatcher 还原(非平坦化)
**Q1**: 反汇编里大量 jmp rax / call [rax] 间接跳转,IDA 追不到目标,CFG 断成碎片,怎么办?
**A1**: 间接跳转目标是运行时算的。先看寄存器来源:是跳转表(switch)、函数指针数组、还是虚函数调用?静态能解的(跳转表基址+索引范围)手工/脚本补全 CFG。
**Q2**: 是跳转表(jump table)但 IDA 没识别出边界,怎么补?
**A2**: 找表基址(间接跳转前的 lea/mov)和索引上界(前面的 cmp/jae 边界检查),据此算出表项数,手动定义为 offset 数组并让 IDA 建立到各 case 的引用。CFG 就接上了。
**Q3**: 是 C++ 虚函数调用,追不到具体实现,怎么办?
**A3**: 找对象的 vtable:定位对象构造处(赋 vtable 指针),vtable 里就是各虚函数地址。或动态断在 call [rax] 处看 rax 指向哪个具体函数。虚调靠 vtable 还原类型。
**Q4**: 间接目标依赖运行时数据(如从文件/网络加载的地址),纯静态无解,怎么办?
**A4**: 转动态:断在间接跳转处记录每次实际跳转目标(trace indirect branches),把运行时观察到的边关系回填静态 CFG。静态解不出的间接边,用 trace 观测实际值补。
**Q5**: 间接跳转是混淆刻意制造的(每次目标经复杂运算),动静都难还原,被墙,转哪?
**A5**: 转"目标导向、不求全 CFG":你多半只关心某条具体路径。用 concolic 沿你要的输入具体执行,只记录那一条实际走过的间接跳转序列,得到"这次运行的真实控制流",不还原全图。
**Q6**: 复用?
**A6**: 间接跳转:先分类(跳转表/函数指针/虚调)静态能补则补 → 依赖运行时数据则 trace 实际目标 → 混淆刻意制造则 concolic 只取目标路径。

### 反混淆工具选择:符号执行 vs 手工 vs 编译器优化
**Q1**: 一段混淆代码,该上 angr 符号执行、手工分析、还是用编译器/优化器化简?怎么定?
**A1**: 看规模与目标:小段+求输入 → 符号执行最快;结构性混淆(平坦化/花指令)有成熟脚本 → 用 deobf 工具(miasm/binary lifter + 优化 pass);逻辑要吃透且量不大 → 手工。别用大炮打蚊子也别用手抠海量代码。
**Q2**: 我用 angr 但路径爆炸/内存爆了,怎么救?
**A2**: 限制探索:设 find/avoid 精确目标、用 concolic(具体输入引导)代替全符号、hook 掉复杂库函数用 SimProcedure 替身、缩小符号变量范围。符号执行不控爆炸就废,先做剪枝。
**Q3**: 混淆是"表达式膨胀"(MBA,把 a+b 写成一堆位运算),工具怎么选?
**A3**: 用专门的 MBA 简化器(基于 SMT 的表达式化简、arybo/msynth 类)或 IR 优化(把代码 lift 成 IR 跑 constant folding/算术化简)。MBA 是数学恒等式膨胀,要用代数化简而非硬读。
**Q4**: 现成工具对这个魔改混淆都不适配,改工具成本高,怎么办?
**A4**: 降级到"trace + 差分":不还原代码,喂大量输入采集输入输出对,用程序合成/回归拟合猜等价函数;或对关键变量做污点跟踪只理解你关心的那部分。工具不适配就退到黑盒行为建模。
**Q5**: 所有自动化都不奏效,手工又太大,项目被拖死,转哪个正交维度?
**A5**: 转"重定义问题规模":退一步问"我到底需要什么"——往往不需要反混淆整个函数,只需某个校验结果/某个 key/某条路径。把大问题切成"只解这一个具体子问题",用最小手段(单点 hook 读一个值)拿到,绕开整体反混淆。
**Q6**: 一句话?
**A6**: 工具选择=规模×目标:小求解用符号执行、结构混淆用 deobf pass、MBA 用代数化简;都不行就缩小问题到单点黑盒。

### 通信类二进制:协议 / 加密流量逆向
**Q1**: 目标是个客户端,要逆它和服务器的私有协议,从哪下手?
**A1**: 先抓包看形态(明文?TLV?加密?)。若明文,直接对照抓包和代码里的打包函数;若加密,重点找"加密前/解密后"的明文触点——网络函数(send/recv)的上一层往往就是明文。抓包定形态,代码定结构。
**Q2**: 流量是 TLS 加密,抓包全是密文,怎么拿明文?
**A2**: TLS 层旁路:hook SSL_write/SSL_read(明文进出 TLS 库的那一刻)、或用 SSLKEYLOGFILE/frida hook 拿会话密钥喂 Wireshark 解密。别去逆 TLS,在它进 TLS 库前截明文。
**Q3**: 它自己实现了应用层加密(TLS 里还套一层私有加密),SSL hook 出来仍是密文,怎么办?
**A3**: 往上再找一层:定位应用层 encrypt/decrypt 函数(通常紧邻业务逻辑),hook 它的明文侧。逐层剥"加密洋葱",每层都在"加密函数的明文那一端"设点。
**Q4**: 它有证书固定(certificate pinning),中间人抓不了包,怎么办?
**A4**: 绕过 pinning:hook 校验证书的函数让其恒通过(frida 常见 unpinning 脚本),或直接 hook SSL_read/write 免抓包直接读明文。pinning 挡的是 MITM,hook 应用层明文不受它影响。
**Q5**: 加密函数被重度混淆/在 VM 保护里,hook 不上也逆不动,被墙,转哪?
**A5**: 转"抠函数当预言机(oracle)":把加密/解密函数连同其初始化,用 unicorn/qiling 单独跑,你喂明文它吐密文、喂密文它吐明文,完全不理解算法就能造/解任意报文。混淆保护不了一个你能单独调用的可逆函数。
**Q6**: 一句话?
**A6**: 协议逆向:抓包定形态 → 在"加密函数明文侧"逐层 hook → pinning 就 unpin 或直接读明文侧 → 逆不动就把加解密函数抠出来当 oracle 调用。

### 大型二进制快速定位关键逻辑
**Q1**: 面对几十 MB 的大程序,只关心一个具体功能,怎么不迷路快速定位?
**A1**: 从"锚点串/行为"反查:该功能相关的报错串、菜单文字、日志、API 调用(如涉及文件就查 open、涉及网络就查 connect),交叉引用锚点直达相关代码。别从 main 顺着读,从目标特征反查。
**Q2**: 没有可用字符串锚点(被加密/无提示),怎么找入口?
**A2**: 从行为差分:做 vs 不做该功能各跑一次,用 trace 差分(coverage diff,如 lighthouse/drcov)高亮"只在做该功能时执行"的代码块,直接圈定相关函数。差分覆盖率是无锚点定位神器。
**Q3**: 定位到一个函数但它调用了几百个子函数,怎么判断哪些值得深入?
**A3**: 按"接近目标数据/系统调用"排序:直接操作你关心的 buffer、直接发起目标 syscall 的子函数优先;纯工具函数(内存拷贝/日志)先跳过。顺着数据流而非调用数量深入。
**Q4**: 交叉引用/差分都做了还是理不清庞大调用关系,怎么办?
**A4**: 上可视化 + 动态调用图:proximity view / call graph 聚焦目标函数的上下游;或 frida-trace 运行时录制真实调用序列,看它实际怎么一步步走到目标。静态图太大就用运行时真实路径裁剪。
**Q5**: 目标功能触发条件苛刻(特定输入/状态才走),动态根本跑不到那段,被墙,转哪?
**A5**: 转"符号执行反向可达性":以目标代码地址为 find,用 angr 从入口反解"什么输入能到这里",既定位了触发条件又找到了路径;或人工从目标块沿 CFG 逆向回溯前驱条件。跑不到就让求解器算出怎么才能跑到。
**Q6**: 一句话?
**A6**: 大二进制定位:锚点串反查 → 无锚点用覆盖率差分 → 顺数据流筛子函数 → 触发不到就符号执行反解可达条件。

### 判断"该继续深挖还是换目标/换手法"的止损决策
**Q1**: 在一个点(某函数/某漏洞/某绕过)投入很久没进展,怎么判断该不该止损?
**A1**: 设"进展信号"检查点:每投入一段时间问"我比刚才多知道了什么具体事实?"。若连续几轮只是"又排除了一个猜想"而无正向信息增量,就是止损信号。感觉在原地打转 = 该换。
**Q2**: 换的话,先换手法(同目标)还是换目标(同任务)?
**A2**: 优先"同目标换正交手法"(静态卡了换动态、动态卡了换符号执行),成本低且经验可复用;手法都试遍才考虑换目标/换攻击面。先横向换维,再纵向换靶。
**Q3**: 怎么避免"换来换去每个都浅尝辄止"的另一个极端?
**A3**: 给每个手法定"最小验证目标"(明确的一个可判定问题)和时间盒,盒内没答到就换、答到了就继续深挖。有边界的坚持,不是无脑硬耗也不是一碰就跑。
**Q4**: 换了几个维度全卡,怀疑是不是方向根本错了,怎么校准?
**A4**: 回到"题设/情报"重读:重新审视目标给的所有线索(文件名、提示、开放的接口、保护配置),很多时候卡死是因为忽略了一个明示的方向。卡到怀疑人生时,答案常在没读懂的题面里。
**Q5**: 确认方向没错但就是所有已知手法都被墙,最后转向哪?
**A5**: 转"降低目标粒度 + 组合原语":把"一步拿下"拆成"先拿一个半成品能力"(一次任意读、一个 leak、一个不完整写),用多个弱原语组合出强利用。全被墙时,弱原语拼接常是唯一出路——red team 的活是把碎片焊成链。
**Q6**: 止损口诀?
**A6**: 以"正向信息增量"为进展判据;先横向换正交手法(有时间盒)→ 再重读题面校准方向 → 最后把大目标拆成弱原语组合。不进则转,转而有界。
