# 信息收集 · 泄露猎取:备份/.git/.env/swagger/JS密钥

### 拿到一个 Web 目标,先定泄露猎取的整体优先级
**Q1**: 手上只有一个 URL/IP,泄露面千头万绪,先打哪一类?
**A1**: 按"性价比 = 命中概率 × 单点收益"排序。先抓被动可拿的:首页 HTML 注释、加载的 JS bundle、robots.txt、sitemap、HTTP 响应头(框架/版本/中间件)。这些零成本、不触发告警,能先勾勒出技术栈和路由骨架,再决定往哪个泄露类型深挖。
**Q2**: 被动看完了,主动扫描先扫什么?
**A2**: 先扫"暴露即高危"的确定性目标:.git/、.svn/、.env、常见备份名、swagger 文档路径。这些一旦命中就是直接凭据或源码,优先级高于宽泛的目录字典爆破。
**Q3**: 怎么判断技术栈以缩小字典?
**A3**: 从响应头 Server/X-Powered-By、Cookie 名(如框架特征 session 名)、JS 里的框架指纹、报错页样式反推。Java 栈重点找 WEB-INF/、.jsp.bak;PHP 栈找 .php~/.php.swp;Node 栈找 .env/source map。字典要随栈切换,别一套字典打天下。
**Q4**: 命中一个泄露点后,是深挖还是横向铺开?
**A4**: 先做一次"广度快照"——记下所有已确认泄露点,再挑收益最高的深挖。避免陷进第一个坑几小时,错过隔壁一个明文 .env。
**Q5**: 这条主动扫描路被 WAF/限速墙了怎么办?
**A5**: 转正交维度:从"主动爆破"转"被动情报"。去公网侧收集——搜索引擎语法(site: + 敏感扩展名)、代码托管平台搜目标域名/API key 特征、证书透明日志找子域、Wayback/历史快照找已下线但仍可访问的旧路径。这些不碰目标 WAF。
**Q6**: 判断这轮泄露猎取"够了可以进下一阶段"的标准?
**A6**: 当你已拿到 ①至少一条可验证凭据 或 ②完整/部分源码 或 ③清晰的接口清单 中任意一项,就该转向利用而非继续扫。恋战扫描是新手最常见的时间黑洞。

### 发现 .git/ 目录暴露如何推进
**Q1**: 扫到 /.git/ 返回 200 或 /.git/HEAD 有内容,下一步?
**A1**: 先确认是"目录列举开着"还是"仅文件可读"。前者直接递归下载;后者需靠 .git 内部结构逐个拉取。先 GET /.git/HEAD、/.git/config,若都能读,基本可 dump。
**Q2**: 目录列举关闭,只能盲拉,怎么还原?
**A2**: 用 git dumper 类工具:从 HEAD → refs → 逐个 object。核心是拿到 /.git/index(记录暂存文件树)和 packed-refs,再顺 object hash 链把 blob 拉全,本地 git checkout 还原工作区。
**Q3**: config 里有什么值得先看?
**A3**: remote url 可能带内网仓库地址或嵌入的凭据(http://user:pass@host);还能看出用了哪个代码平台,便于去平台侧搜同组织其它泄露。
**Q4**: 还原出源码后优先看什么?
**A4**: 先看配置类文件(config/settings/env 样例)、数据库连接、密钥常量、路由定义;再 git log 看提交历史里有没有"删除敏感文件"的提交——删了的东西 blob 还在。
**Q5**: dumper 拉到一半大量 404/对象缺失,失败了怎么办?
**A5**: 说明服务器做了部分过滤或只暴露了工作副本而非完整 .git。转向:①改用 .git/index 直接解析出文件名列表,再按原始路径去 web 根直接 GET 这些源码文件(很多时候 .php/.py 源码本身在 web 目录可读);②转查同类版本控制残留 .svn/.hg;③放弃 .git,转 JS sourcemap 还原前端源码这个正交路径。
**Q6**: 还原出的代码怎么用于下一步?
**A6**: 把它当"白盒",定向找注入点/反序列化/鉴权绕过,而不是继续黑盒瞎试。源码是从 recon 跨入漏洞利用的桥梁。

### .git dumper 跑失败或对象不全的救场
**Q1**: index 能读但 object 大量取不到,是不是白干了?
**A1**: 不一定。先解析 index,它是一份精确的文件清单(路径+mode+hash)。哪怕一个 blob 都拿不到,这份清单本身就是高价值情报:告诉你有哪些配置文件、脚本、密钥文件存在。
**Q2**: 有了文件清单怎么变现?
**A2**: 拿清单里的敏感路径直接去 web 根请求。很多部署把源码目录直接暴露在文档根下,/.git/index 里写着 config/database.yml,那 /config/database.yml 很可能直接 200。
**Q3**: object 取不到常见根因?
**A3**: ①对象被打包进 pack 文件,松散 object 不存在 → 去拉 /.git/objects/pack/ 下的 .pack 和 .idx;②服务器对 .git 下部分路径做了 deny,但漏了 pack 目录;③HEAD 指向的 commit 被 gc 了。逐个换路径试。
**Q4**: pack 文件也拉不下来呢?
**A4**: 转向 refs 侧:/.git/logs/HEAD(reflog)记录了历史所有 ref 变更和 commit hash,能挖出被覆盖的旧提交;/.git/packed-refs 给出分支/tag 的 commit。用这些 hash 再回去试对象。
**Q5**: 全都拿不到,这条路彻底墙死怎么办?
**A5**: 转正交维度。.git 只是"源码泄露"的一种载体,换载体:找 .zip/.tar.gz/.bak 全站备份包、找 IDE 泄露(.idea/、.vscode/)、找 sourcemap。目标是"拿到源码"这个结果,别死磕 .git 这一条通道。

### 备份文件命名爆破的字典策略
**Q1**: 想爆破备份文件,字典怎么构造才不空跑?
**A1**: 备份名 = 基名 × 后缀。基名来源:目标域名主体、站点目录名、已知文件名(index、config、www、backup、目标公司英文名)、当天/近期日期。后缀:.zip/.tar.gz/.rar/.7z/.bak/.old/.sql/.swp/.~。用已知信息组合,别用纯通用大字典。
**Q2**: 最容易命中的是哪几类?
**A2**: ①以域名或网站根目录名命名的全站压缩包(www.zip、目标主体名.zip);②数据库导出(.sql/.sql.gz);③单文件热备(config.php.bak、index.php~)。运维手滑打包整站放 web 根是高频事故。
**Q3**: 怎么低成本判断命中而非误报?
**A3**: 看响应:Content-Length 明显偏大、Content-Type 是 application/zip/octet-stream、支持 Range/断点续传、返回 200 且非软 404 页面。软 404(返回 200 但内容是首页)要靠对比基线长度识别。
**Q4**: 单文件基名怎么来?
**A4**: 从已探明的真实路径衍生。爬到 /admin/login.php,就试 login.php.bak、login.php.swp、login.php~、.login.php.swp(vim swap 隐藏名)。备份猎取要"跟着真实文件走",而不是凭空猜。
**Q5**: 一顿爆破全 404 / 被封了怎么办?
**A5**: 转维度:①从爆破转"信息驱动"——先拿到 .git/源码看真实文件结构,再定点猜备份;②转历史情报,Wayback 里可能存着旧备份链接;③换目标资产,主站严实但测试/预发/旧域名子站往往留着备份。别在一个封了的站上硬刚。
**Q6**: 命中了几十上百 MB 的大包,值不值得下?
**A6**: 先 Range 拉头部几 KB 确认是真压缩包再决定;下载后不必解全,先解出文件树,grep 配置/密钥/密码关键词定向取,别被大包拖死。

### 发现 .env 泄露后的验证与利用
**Q1**: /.env 返回 200 且是明文键值,先干嘛?
**A1**: 通读一遍分类:数据库凭据、缓存/队列凭据、第三方 API key、APP_KEY/加密盐、DEBUG/APP_ENV 状态、邮件/对象存储凭据。先标出"可远程直连的"(DB host、Redis、S3)和"仅本地有意义的"。
**Q2**: 哪些能立刻验证?
**A2**: 对外可达的服务优先验:数据库端口若对公网开放就直连;对象存储/云 key 用官方 CLI 验证权限;第三方 API key 打其只读接口验活。验证前想清楚动静大小和授权边界。
**Q3**: DB host 是内网 IP、外面连不上怎么办?
**A3**: 记下来当"后渗透弹药"。现在连不上不代表没用——一旦拿到一个 web shell 或跳板,这套内网凭据就是横向的第一把钥匙。泄露的价值常常滞后兑现。
**Q4**: 拿到 APP_KEY(框架加密密钥)有什么用?
**A4**: 很多框架用它签名/加密 session 和 cookie。密钥泄露可能导致伪造签名、解密 cookie,甚至在特定框架版本触发反序列化 RCE(密钥用于签名反序列化 payload)。这是从"泄露"直通"RCE"的高价值链。
**Q5**: /.env 直接 404 或被 deny 了,还有别的入口吗?
**A5**: 转同类载体:.env.bak/.env.save/.env.example(样例常暴露变量名结构)、.env.local/.env.production;或换泄露通道从 .git 里取 .env(git 里没 gitignore 干净时);或 phpinfo/调试页里的环境变量段。同一份配置往往有多个泄露面。
**Q6**: 凭据疑似是占位/示例值怎么判断?
**A6**: 看是否为明显占位(your_password、changeme、示例域名)。是占位就别浪费时间验证,转去找真实配置源(生产环境文件、CI 变量泄露)。

### Swagger / OpenAPI 文档暴露后的利用
**Q1**: 扫到 /swagger-ui、/api-docs、/openapi.json,价值在哪?
**A1**: 它直接给你完整接口地图:每个 endpoint 的路径、方法、参数、认证方式、数据模型。等于对方把攻击面清单双手奉上,省掉大量盲猜爬接口的功夫。
**Q2**: 先看文档里的什么?
**A2**: ①标注 internal/admin/debug 的接口;②不需要认证的接口(security 为空);③危险语义接口:文件上传/下载、命令/查询执行、用户管理、导出、SSRF 味道的 url 参数。按危险度排序逐个测。
**Q3**: 文档里接口都要求 token,没 token 怎么办?
**A3**: 先测"文档要求认证但实现没校验"的错位——直接裸打接口,鉴权中间件漏挂是常见事故。再找注册/登录接口自助拿低权 token,或找泄露的 token(JS/.env/git 里)。
**Q4**: 拿到接口清单怎么系统性测越权?
**A4**: 用低权账号 token 遍历文档里所有资源型接口,改 id/改 path 试水平/垂直越权(IDOR)。Swagger 给的参数模型让你精准构造合法请求,越权测试事半功倍。
**Q5**: /swagger-ui 打不开或 404 了怎么办?
**A5**: 换文档载体路径:/v2/api-docs、/v3/api-docs、/openapi.json、/swagger/v1/swagger.json、/api/swagger、/actuator(Spring 栈)。或从 JS 里找前端调用的接口清单反推——前端本身就是一份"活文档"。
**Q6**: 文档太大几百个接口,如何不迷失?
**A6**: 别逐个手测。先按语义 grep 关键词(admin/export/upload/exec/internal/user),锁定 20 个高危再深入。文档的价值是"定向",不是"穷举"。

### 从 JS 文件里挖硬编码密钥
**Q1**: 前端加载了一堆 JS bundle,怎么系统地挖密钥?
**A1**: 先把所有 JS(含动态 import 的 chunk)拉全,用正则/工具批量匹配高熵字符串与已知 key 格式:云厂商 AK/SK、第三方服务 token、JWT、API base、内部域名、邮箱、注释里的临时凭据。工具化扫,别肉眼翻压缩代码。
**Q2**: 匹配出一堆疑似 key,怎么去伪存真?
**A2**: 关键判据:这个 key 是"设计上就该给浏览器的公开 key"(如前端地图/统计的 public key)还是"本不该出现在前端的服务端密钥"。前者基本无用,后者高危。看 key 的用途语义和权限范围,别把公开 key 当战果。
**Q3**: JS 里除了密钥还能挖什么?
**A3**: 隐藏/未发布的 API 路由、管理端路径、feature flag 开关、内部服务地址、上传/下载接口、调试后门参数、注释掉的旧逻辑。JS 是最诚实的接口清单来源。
**Q4**: 代码被压缩混淆看不懂怎么办?
**A4**: 找 sourcemap(.js.map)还原;没有 map 就用美化工具格式化,再靠字符串常量(URL、报错文案、字段名)定位逻辑,不必读懂全部混淆代码,盯"数据流经过的敏感常量"即可。
**Q5**: 挖到的 key 一验证全是失效/无权限,白挖了吗?
**A5**: 转维度:①从"密钥"转"路由"——JS 暴露的隐藏接口本身可能未授权可打;②去代码平台搜同 key 前缀,可能定位到源码仓库更多泄露;③关注 API base 指向的域名,可能是未防护的内部/测试环境。JS 泄露的价值不止密钥一种。
**Q6**: 怎么持续覆盖动态加载的 chunk?
**A6**: 用浏览器实际跑一遍应用、触发各功能,抓所有网络加载的 JS(webpack 按需 chunk 不点不加载),再统一扫。静态只抓入口 bundle 会漏掉大半代码。

### sourcemap (.map) 泄露还原前端源码
**Q1**: JS 尾部有 //# sourceMappingURL 或直接扫到 .js.map,怎么用?
**A1**: 下载 .map,用还原工具把打包后的代码逆回原始项目结构——包含原始文件名、目录树、未压缩源码,甚至注释。等于拿到前端仓库快照。
**Q2**: 没有 sourceMappingURL 注释还能找 map 吗?
**A2**: 能。直接在 JS 文件名后拼 .map 试 GET(main.abc.js → main.abc.js.map)。生产环境经常忘删 map 文件,注释删了文件还在。
**Q3**: 还原出源码后重点看什么?
**A3**: 原始目录里的 config、常量文件、.env 注入的变量、API 封装层(所有接口和默认参数)、鉴权逻辑、隐藏路由表。前端源码常暴露后端接口契约和内部约定。
**Q4**: 只还原出部分文件、大量缺失怎么办?
**A4**: map 可能只覆盖部分 chunk。逐个 chunk 找对应 .map;实在缺失就退回美化 + 常量分析。别因为不完整就放弃已还原的部分。
**Q5**: map 全部 404、生产删干净了怎么办?
**A5**: 转正交路径:去测试/预发环境(常留 map)、去 CDN 的历史版本、去 Wayback 快照。或彻底换赛道,从 .git/备份包拿后端源码,不纠结前端 map。
**Q6**: 还原源码里的注释有多大价值?
**A6**: 很高。开发注释常含 TODO、临时后门、测试账号、内部 wiki 链接、"上线前删掉"的调试逻辑。专门 grep 中英文注释关键词。

### .DS_Store 泄露做目录枚举
**Q1**: 扫到 /.DS_Store,这玩意有啥用?
**A1**: macOS 目录索引文件,内含该目录下所有文件/子目录名。解析它能拿到一份"服务器不会主动告诉你的"目录清单,包括没链接引用的隐藏文件。
**Q2**: 怎么把它变成完整目录树?
**A2**: 递归:解析根 .DS_Store 拿到子目录名 → 对每个子目录再 GET /子目录/.DS_Store → 层层展开,重建整站文件结构。有现成递归工具。
**Q3**: 拿到目录树后干嘛?
**A3**: 在清单里找敏感文件名:备份、配置、上传目录、admin、后台脚本、数据导出。.DS_Store 的价值是把"目录爆破"从盲猜变成精确制导。
**Q4**: 根 .DS_Store 只列了几个普通目录,没敏感项?
**A4**: 别停在根。往子目录递归,敏感文件常在深层(/uploads/、/backup/、/config/)。也检查 .DS_Store 里是否有历史遗留、命名奇怪的目录。
**Q5**: .DS_Store 不存在或被过滤怎么办?
**A5**: 转其它"目录清单泄露"载体:目录列举(directory listing)是否开着、.git/index、sitemap.xml、WEB-INF/web.xml(Java 路由映射)、编辑器工程文件 .idea/workspace.xml。目标是"拿到文件清单",载体可换。

### 目录爆破被限速/封 IP 的应对
**Q1**: dirsearch/ffuf 跑着跑着开始大量 429/连接重置,怎么判断被限了?
**A1**: 看特征:突然全 429/403、响应变慢、返回验证页/挑战页、或直接 TCP reset。对比单个手动请求是否正常——若手动也被拦就是 IP 级封禁,若只是高频被限则是速率控制。
**Q2**: 速率限制(非封 IP)怎么绕?
**A2**: 降并发、加随机延时、随机化 UA 和顺序、避开明显扫描器指纹(默认 UA、无 Referer、请求顺序字典序)。把扫描伪装成正常浏览节奏,慢但能过。
**Q3**: 已经 IP 级封禁了怎么办?
**A3**: 换出口 IP:代理池/云主机换区/住宅代理。同时反思——是否根本不该用大字典硬扫。转"精准低噪"打法:只请求高价值确定路径(.git/.env/swagger/备份),几十个请求而非几万个。
**Q4**: WAF 按路径特征拦(如带 .git 就拦)怎么办?
**A4**: 变形请求:URL 编码、大小写混淆、路径参数干扰(/.git/../.git/config)、加 query 尾巴、换 HTTP 版本/方法。或从 WAF 覆盖不到的入口拿(CDN 回源、备用域名、直连源站 IP)。
**Q5**: 全都被墙、完全打不动了,彻底转向哪?
**A5**: 从"文件系统泄露"这一整个维度撤出,转"公网侧被动情报":代码托管平台搜目标域名/密钥、Wayback 历史路径、证书透明日志找子域和别的资产、搜索引擎缓存。以及横向换资产——这个域打不动,子域/旁站/移动端 API/小程序后端往往软很多。
**Q6**: 怎么避免下次一上来就被封?
**A6**: 先探"防护存在性"再决定烈度:发几个探针看有无 WAF、有无速率控制,再定策略。不做侦察就上大字典是被封主因。

### 编辑器临时文件/交换文件泄露
**Q1**: 想找 vim/编辑器残留,试哪些命名?
**A1**: vim swap:.文件名.swp、.文件名.swo、文件名~;还有 .文件名.un~、#文件名#(emacs)、.文件名.sav。基名跟着已知真实文件走,比如探到 index.php 就试 .index.php.swp。
**Q2**: .swp 拿到了怎么读?
**A2**: 它是 vim 的二进制交换文件,能用 vim -r 恢复出编辑中的源码,含未保存内容。等于拿到某个脚本的源码,可能比线上版本还多调试逻辑。
**Q3**: 为什么这类文件常存在?
**A3**: 管理员直接在生产服务器上用 vim 编辑文件,异常退出/断连就留下 swap;备份文件是手滑 cp。都是运维在生产上直接操作的副产物,高频。
**Q4**: 一个都没命中怎么办?
**A4**: 说明可能不是直接在服务器编辑,或已清理。转其它备份形态:.bak/.old/.orig、编辑器保存的 .save、版本控制残留。别死盯 swap 一种。
**Q5**: 被墙(隐藏文件请求被 deny)怎么转?
**A5**: 隐藏文件(点开头)常被 nginx location ~ /\. 统一 deny。转不带点的备份形态(文件名~、文件名.bak),或从 .git/目录列举 拿源码,绕开点文件封锁这个正交面。

### 备份压缩包下载后的挖掘方法
**Q1**: 下到一个几十 MB 的全站 zip/tar,怎么高效挖?
**A1**: 别急着通读。先解出文件树看结构,再 grep 定向:password/passwd/secret/api_key/token/BEGIN PRIVATE KEY/连接串关键词、配置目录、.env、.git、数据库导出。用关键词把针从草堆里拉出来。
**Q2**: 包里有数据库导出(.sql)怎么用?
**A2**: 里面可能有用户表(账号+hash)、配置表、密钥表。hash 拿去离线破;明文/弱 hash 直接用;管理员账号优先。还能从表结构了解业务模型。
**Q3**: 包里有 .git 目录呢?
**A3**: 直接本地 git log 看完整历史,比线上 dump 更全——能看到所有历史提交里被删的密钥、被改的配置。本地操作无网络限制,尽情挖历史。
**Q4**: grep 关键词全没命中怎么办?
**A4**: 扩展策略:找高熵字符串(可能是未加注释的密钥)、找配置文件后缀(.yml/.ini/.conf/.properties/.json)、看框架约定的密钥存放位置、翻 CI/部署脚本(密钥常在部署环境变量注入处)。
**Q5**: 这个备份包内容全是无用的静态资源怎么办?
**A5**: 说明是前端/静态备份。转找后端备份包(不同命名、不同目录),或转数据库备份,或换资产。一个包空手别气馁,它仍能确认目录结构供后续定向。

### Git 历史里挖已删除的敏感信息
**Q1**: 拿到完整 .git 后,当前工作区看着很干净,还有戏吗?
**A1**: 有,而且往往是最肥的。开发常"提交了密钥→发现→删除→再提交",工作区干净但历史 blob 永久留存。git log --all、git show 每个提交,重点看"删除文件/移除凭据"类提交的父版本。
**Q2**: 怎么系统扫历史而不手翻?
**A2**: 用 gitleaks/trufflehog 类工具全历史扫描,自动匹配所有提交里的密钥模式;或 git log -p 全量 diff 后 grep。工具化覆盖所有分支和悬空提交。
**Q3**: 有些提交被 rebase/force push 覆盖了还找得到吗?
**A3**: 查 reflog(.git/logs/)和悬空对象(git fsck --lost-found)。被覆盖的 commit 只要没 gc 就还在对象库里,fsck 能捞出 dangling commit/blob。
**Q4**: 历史里翻出的密钥大概率还有效吗?
**A4**: 存疑要验。老提交的密钥可能已轮换。但很多组织从不轮换,或轮换后新旧并存。低成本验一下;失效的也别扔,它揭示了命名规律和凭据格式,利于猜现行的。
**Q5**: 历史全是普通业务代码、没密钥怎么办?
**A5**: 转看历史里的其它情报:内部域名/IP(测试环境地址)、开发者邮箱(社工/密码喷洒素材)、接口变更史(废弃但可能仍活的旧接口)、依赖版本(定位已知 CVE)。历史不止密钥一种价值。

### Swagger 暴露的内部/未授权接口测试
**Q1**: 文档里有一批标注 internal 或 admin 前缀的接口,怎么下手?
**A1**: 这些接口设计上假设"只有内部能调",实现上常忘了加鉴权或只靠网络隔离。先裸调——不带任何 token 直接打,测有没有"以为进不来就不设防"的错位。
**Q2**: 裸调返回 401/403 怎么继续?
**A2**: 换认证维度:①用最低权限账号 token 打管理接口测垂直越权;②改 Header 伪装内网来源(X-Forwarded-For、内部标识头);③找接口是否信任某个可控的身份字段。别一个 403 就放弃。
**Q3**: 文档给了参数模型,怎么利用它测危险接口?
**A3**: 精准构造合法请求命中危险语义:带 path/filename 参数的测路径穿越/任意文件读;带 url 参数的测 SSRF;带 cmd/query 的测注入;导出接口测越权拉全量数据。模型让你少踩参数校验的坑。
**Q4**: 接口需要复杂签名怎么办?
**A4**: 签名算法常在前端 JS 里(sourcemap 还原后可见),把签名逻辑抠出来复现;或找不需签名的等价接口;或看签名密钥是否也在 JS/.env 里泄露了。
**Q5**: 所有接口都严格鉴权、越权也测不出,这条墙了怎么办?
**A5**: 转正交面:Swagger 本身若可写(某些配置允许)或暴露了内部服务地址,顺藤摸内部服务;或从接口暴露的数据模型反推数据库结构,转去打注入;或换资产,同组织其它 API 服务防护未必一致。
**Q6**: 怎么记录避免重复测?
**A6**: 把文档接口做成清单,标注每个的鉴权结果和测试状态。几百接口不做记录必然重复劳动或遗漏。

### 从 JS 反推隐藏路由与接口枚举
**Q1**: JS 里散落着一堆 API 路径片段,怎么拼成完整可打接口?
**A1**: 找 API base(常量或 axios/fetch 封装里的 baseURL)+ 各处的相对路径拼接。注意前端路由(SPA 的 #/ 或 history 路由)与后端 API 路由是两回事,要挖的是后端接口。
**Q2**: 挖出的接口在 UI 上从没被触发,价值在哪?
**A2**: 高价值。"代码里有但界面没入口"的接口常是:废弃未下线的旧接口(缺维护更易有洞)、管理/调试接口、灰度未开放功能。这些是防护盲区。
**Q3**: 接口路径里有参数占位怎么补全?
**A3**: 从 JS 调用处看实际传参、从 Swagger 补模型、从业务逻辑推 id 范围。先用自己账号的合法数据打通,再变异参数测越权/注入。
**Q4**: 只有路径没有方法/参数怎么试?
**A4**: 逐个试 GET/POST/PUT/DELETE(OPTIONS 有时直接吐 Allow 头);参数靠字段名规律和报错信息补——很多框架参数缺失会回显期望字段名,顺着回显补齐。
**Q5**: 拼出的接口全部 404、base 猜错了怎么办?
**A5**: base 可能随环境不同。转:①抓真实运行时网络请求拿准确 base;②sourcemap 还原看接口封装层拿到确切拼接逻辑;③换环境(测试域名 base 不同)。别在错误 base 上穷举路径。

### robots.txt / sitemap 情报利用
**Q1**: robots.txt 里 Disallow 一堆路径,该怎么看?
**A1**: Disallow 是"我不想被搜索引擎收录"的清单,反而是敏感目录的自曝:/admin/、/backup/、/api/internal/、/config/。逐个访问,它们经常没有额外访问控制,只靠 robots 求爬虫别看。
**Q2**: sitemap.xml 有什么额外价值?
**A2**: 给出站点认为"正式存在"的 URL 全集,含深层页面和动态参数样例,帮你发现爬虫爬不到的入口。sitemap + robots 一正一反,勾勒出完整路径视野。
**Q3**: robots 里的目录访问都 403 怎么办?
**A3**: 试目录下的具体文件而非目录本身(/backup/ 403 但 /backup/db.sql 可能 200);试目录列举变体;或把这些目录名喂进备份字典(/backup 提示存在备份,猜 backup.zip)。
**Q4**: robots.txt 不存在或为空怎么办?
**A4**: 转其它"路径自曝"源:sitemap、HTML 里的隐藏链接/注释、JS 路由表、.DS_Store、favicon 关联、安全策略文件(.well-known/security.txt 有时含内部联系与系统信息)。
**Q5**: 这些情报和主动扫描怎么配合?
**A5**: 先吃被动情报(robots/sitemap/JS)攒出高质量种子路径,再用它们做定向爆破(加后缀、猜同级),而非空跑大字典。被动喂主动是低噪高效的正解。

### 云存储桶(对象存储)泄露的识别与利用
**Q1**: 页面资源从某个对象存储域名加载,怎么判断桶是否可利用?
**A1**: 提取桶名/endpoint,先测匿名列举(直接 GET 桶根看是否返回 XML 文件列表)。可列举说明 ACL 配错,能看到桶内所有对象,常含备份、日志、用户上传、内部文档。
**Q2**: 能列举后怎么挖?
**A2**: 拉文件清单,grep 敏感:备份包、.sql、配置、私钥、身份证件/用户数据。注意分页(对象多时 XML 有 marker,要翻页拉全)。
**Q3**: 桶不允许匿名列举怎么办?
**A3**: 转测写权限和已知对象读:①用泄露的云 key(.env/JS 里)带凭据访问;②猜可预测的对象路径直接 GET(按命名规律);③测能否上传(可写桶可挂马/覆盖静态资源打 XSS 或供应链)。
**Q4**: 桶完全锁死了怎么办?
**A4**: 转向云凭据本身:若拿到了 AK/SK,用云 CLI 枚举该账号下所有桶和其它云资源(可能远超这一个桶),甚至提权到其它云服务。桶锁死不代表凭据无用。
**Q5**: 桶和凭据都拿不到,彻底墙死怎么办?
**A5**: 撤出云存储维度,回主站找其它泄露面。同时记下 endpoint 归属云厂商,后续拿到内网/凭据后再回来打云侧资源。云面常是后渗透阶段才引爆的弹药。

### CI/CD 配置文件泄露
**Q1**: 源码/仓库里扫到 .gitlab-ci.yml、.github/workflows、Jenkinsfile,看什么?
**A1**: 这些是"部署说明书":暴露构建/部署流程、目标服务器地址、镜像仓库、密钥引用变量名、部署脚本命令。即便密钥用变量占位,变量名和流程本身就是重要情报。
**Q2**: CI 文件里的明文能有密钥吗?
**A2**: 规范做法是引用 secret 变量(不明文),但常见事故:直接硬编码 token/密码、把私钥 base64 贴进去、echo 敏感变量到日志。逐行看有没有偷懒硬编码。
**Q3**: 只看到变量名没看到值怎么变现?
**A3**: 变量名揭示了存在哪些凭据和外部系统(DOCKER_PASSWORD、DEPLOY_KEY、云凭据名)。顺着去找它们的真实来源:CI 平台若可访问、构建产物/日志泄露、其它配置文件。也定位了攻击目标系统清单。
**Q4**: CI 文件暴露了部署目标服务器地址?
**A4**: 高价值。这些常是部署机/跳板/镜像仓库地址,可能防护弱于主站。记为下一批探测目标。部署链路上的机器往往权限高。
**Q5**: 没有 CI 文件泄露怎么办?
**A5**: 转其它 DevOps 泄露载体:Dockerfile/docker-compose(含环境变量与服务拓扑)、k8s manifest、部署脚本 deploy.sh、supervisor/systemd 配置、构建产物里残留的 CI 元数据。DevOps 泄露面很宽。

### Dockerfile / docker-compose 泄露
**Q1**: 扫到 Dockerfile 或 docker-compose.yml,能挖什么?
**A1**: Dockerfile:ENV 里硬编码的密钥、ARG 传入的凭据、COPY 进镜像的敏感文件路径、基础镜像版本(定位 CVE)。compose:服务拓扑、各服务端口映射、environment 里的数据库/缓存明文凭据、volume 挂载路径。
**Q2**: compose 里 environment 明文密码常见吗?
**A2**: 非常常见,尤其 DB_PASSWORD、MYSQL_ROOT_PASSWORD、REDIS_PASSWORD 直接写在 compose 里。这是即拿即用的凭据源。
**Q3**: 拿到服务拓扑有什么战术价值?
**A3**: 知道背后有哪些内部服务(db、redis、mq、内部 API)、它们的端口和网络别名。一旦进入内网/拿到 SSRF,这份拓扑就是精确的横向地图。
**Q4**: 镜像本身能拿到吗?
**A4**: 若镜像仓库地址泄露且未鉴权,可直接 pull 镜像,解层看每一层文件系统——历史层里常有被后续层"删除"但仍存在的密钥(类似 git 历史)。用 dive 类工具逐层挖。
**Q5**: 这些文件都没泄露、也没镜像怎么办?
**A5**: 转应用运行时暴露的等价信息:错误页里的服务连接串、/actuator/env 类端点、探测各内部端口。目标"摸清内部服务拓扑"可从多个正交面逼近。

### 硬编码凭据的有效性验证与横向利用
**Q1**: 手上攒了一批从各处泄露的凭据,先验哪个?
**A1**: 按"可远程验证 × 高权限"排序。对外可达服务(数据库、SSH、后台、云 key)优先;高权账号(admin/root/service)优先。验证顺序影响动静——先挑低风险高收益的验。
**Q2**: 怎么低调验证不触发锁定/告警?
**A2**: 单点单次试,别做喷洒式爆破(触发账号锁定和风控)。对 API key 打只读/无害接口验活;对账号密码,先在最不敏感的入口试一次。控制节奏。
**Q3**: 一套凭据在 A 服务有效,接下来怎么放大?
**A3**: 密码复用假设:同一密码/密钥在其它服务、其它账号、其它环境很可能复用。拿它横向喷其它系统(受控地)。人和组织都爱复用,这是横向的最大红利。
**Q4**: 凭据全部失效怎么办?
**A4**: 别丢。失效凭据仍提供:①密码构造规律(公司名+年份+符号),据此生成定向字典做密码喷洒;②账号命名规律(邮箱/工号格式);③曾用的系统清单。转"规律驱动的定向猜解"这个正交打法。
**Q5**: 凭据是 hash 不是明文怎么办?
**A5**: 判断算法强度和是否加盐,弱 hash/无盐直接离线破或查彩虹表/在线库;强 hash 且带盐则成本高,转找明文源(别处泄露)或 pass-the-hash 类免破直接用的手法(视协议而定)。
**Q6**: 验证时不小心触发了账号锁定/告警怎么补救?
**A6**: 立刻停手降噪,换 IP 和身份,冷却一段时间再以更慢节奏继续;并反思凭据来源是否是蜜罐/诱饵。防守方会埋假凭据钓鱼,验证前掂量真实性。

### 泄露的框架密钥(APP_KEY/signing secret)用途判定
**Q1**: 拿到一个疑似框架级密钥(APP_KEY/SECRET_KEY/JWT secret),怎么判断它能干嘛?
**A1**: 先定位它是哪个框架的哪种密钥:session 加密密钥、cookie 签名密钥、JWT 签名密钥、CSRF token 密钥,还是通用加密盐。不同用途通向不同攻击。别拿到就乱试。
**Q2**: 如果是 JWT signing secret?
**A2**: 可自签任意 JWT——伪造管理员身份、改 claims 越权。先确认签名算法(HS256 对称才靠密钥;RS256 非对称需私钥)。对称算法拿到 secret 基本等于任意身份。
**Q3**: 如果是 session/cookie 加密或签名密钥?
**A3**: 可解密看 session 内容(可能含敏感数据),或伪造签名的 cookie 绕鉴权。在某些框架(用密钥签名序列化对象的),伪造 cookie 可直通反序列化 RCE——这是泄露转 RCE 的顶级利用链。
**Q4**: 怎么确认密钥真的对得上?
**A4**: 用它去验证一个真实的现网 cookie/token 签名:能验通就是对的。或用它签一个再打回去看服务器是否接受。先验证再利用,避免在错密钥上浪费。
**Q5**: 密钥验不通/是旧值怎么办?
**A5**: 密钥可能已轮换。转找当前值:更近的提交、生产 .env、运行时泄露(调试端点)。或转不依赖此密钥的路径。密钥泄露的价值高但时效性强,验不通果断转向。

### Java 应用 WEB-INF / 配置文件泄露
**Q1**: 目标是 Java 站,想拿配置和源码,盯哪些路径?
**A1**: WEB-INF/web.xml(路由/servlet 映射)、WEB-INF/classes/(编译后 class 和 .properties 配置)、WEB-INF/lib/(依赖 jar,定位版本 CVE)、application.properties/application.yml(Spring 配置含数据库/密钥)。
**Q2**: WEB-INF 正常不可直接访问,怎么读到?
**A2**: 靠其它漏洞把它读出来:路径穿越、任意文件读、某些中间件解析缺陷(特定 servlet 容器版本可绕过 WEB-INF 保护)。WEB-INF 泄露常是"文件读漏洞"的战果,而非直接扫到。
**Q3**: 拿到 web.xml 有什么用?
**A3**: 它是路由全图:哪些 URL 映射到哪些 servlet、有哪些 filter(鉴权在哪)、有没有暴露的调试/管理 servlet。据此定位未受保护的接口和鉴权 filter 的覆盖盲区。
**Q4**: 拿到 .class 文件怎么审?
**A4**: 反编译回 Java 源码审计,重点找反序列化点、注入、硬编码密钥、SSRF。Java 反编译还原度高,近似白盒。
**Q5**: WEB-INF 读不到、没有文件读漏洞怎么办?
**A5**: 转 Spring 生态其它泄露面:/actuator/ 系列端点(env/heapdump/mappings 可导出配置、内存、路由)、错误页堆栈泄露类名和路径、jar 包若在静态目录可下。Java 栈的泄露面很有特色,换端点。
**Q6**: 拿到 heapdump 能挖什么?
**A6**: 内存转储里可能有明文密码、token、session、数据库连接串。用工具在 dump 里搜敏感字符串,这是 Spring Boot 暴露 actuator 时的经典高价值泄露。

### phpinfo / 调试页面泄露
**Q1**: 扫到 phpinfo() 页或框架 debug 页,能榨出什么?
**A1**: phpinfo:完整环境变量(常含注入的密钥/数据库凭据)、真实路径(绝对路径供文件写/包含利用)、加载的扩展(判断可用攻击手法)、配置项(disable_functions、open_basedir 决定 RCE 可行性)、服务器内网 IP。
**Q2**: 环境变量段为什么重点看?
**A2**: 现代部署把密钥通过环境变量注入,phpinfo 的 $_ENV/$_SERVER 段可能明文吐出数据库密码、API key、框架密钥。等于一个 .env 泄露。
**Q3**: 框架 debug 页(报错调试)有什么价值?
**A3**: 详细堆栈暴露源码片段、文件绝对路径、SQL 语句、配置值,有的调试工具栏还能执行查询/看 session。debug 模式误开在生产是重大泄露。
**Q4**: 拿到绝对路径有什么用?
**A4**: 为文件包含(LFI→绝对路径)、日志投毒、上传后 getshell 的落地路径、写 webshell 提供精确坐标。很多利用卡在"不知道 web 根绝对路径",phpinfo 直接给。
**Q5**: 这类调试页都 404 / 关了怎么办?
**A5**: 转主动触发报错:构造异常参数、类型错误、访问不存在资源,逼框架吐堆栈(若 debug 未彻底关)。或转其它信息页(server-status、server-info、探针脚本)。让应用自己暴露,而非找现成页。

### 服务器配置文件(.htaccess/nginx conf)泄露
**Q1**: 想拿 web 服务器配置,盯什么?
**A1**: .htaccess(Apache 目录级规则:重写、访问控制、隐藏路径)、.htpasswd(basic auth 的用户 hash)、nginx.conf/站点 conf(upstream 后端地址、location 规则、隐藏 proxy_pass 到内部服务)。
**Q2**: 拿到 .htaccess 有什么用?
**A2**: 看 RewriteRule 反推真实后端脚本(前台 /article/1 实际打的是 /article.php?id=1,暴露真实注入点)、看哪些路径被 deny(反而提示敏感目录存在)、看有没有可绕的访问控制规则。
**Q3**: .htpasswd 拿到了怎么用?
**A3**: 里面是 basic auth 的用户名+密码 hash,离线破了就能过 basic auth 保护的后台/接口。也提供了账号命名和密码规律情报。
**Q4**: nginx conf 泄露的最高价值是什么?
**A4**: proxy_pass 后的内部服务地址(内网 IP:端口)——暴露了反向代理背后的真实后端拓扑,是 SSRF 和横向的目标坐标。还能看出哪些路径被内部保留。
**Q5**: 配置文件都读不到怎么办?
**A5**: 转行为侧探测:靠响应头/报错判断中间件类型和版本、靠不同路径的响应差异反推 rewrite/proxy 规则、靠特定解析差异(路径穿越/CRLF)绕过配置的访问控制。读不到配置就"黑盒探规则"。

### 前端 webpack chunk 与 sourcemap 深挖
**Q1**: 目标是 SPA,入口 JS 里 import 了一堆 hash 命名的 chunk,怎么拿全?
**A1**: 入口 bundle 里有 webpack 的 chunk 映射表(chunkId → 文件名规则),解析它能枚举出所有 chunk 文件名,即便 UI 从没触发加载也能直接下。别只抓浏览器实际加载的那几个。
**Q2**: 为什么要挖没被加载的 chunk?
**A2**: 按需 chunk 对应未开放/权限受限的功能模块(管理后台、付费功能、内测特性),其代码含对应的接口、密钥、逻辑。这些是普通用户视角看不到的攻击面。
**Q3**: chunk 都拿到后如何统一挖?
**A3**: 全部还原(有 map 用 map,无 map 美化)后合并扫描:接口清单、密钥、隐藏路由、权限判断逻辑(前端权限判断常暴露后端有哪些角色和越权点)。
**Q4**: 前端有权限判断逻辑,对攻击有何提示?
**A4**: 前端 if (user.role === 'admin') 之类揭示了角色体系和受保护功能。若后端未同等校验(只靠前端隐藏),直接调对应接口即越权。前端权限码是越权点的路标。
**Q5**: chunk 映射被混淆得读不出、map 也没有怎么办?
**A5**: 转运行时抓取:用无头浏览器跑遍应用各功能触发按需加载,抓全部网络 JS;或改前端逻辑(本地断点/改 flag)强制加载隐藏模块。静态挖不动就动态触发。

### 目录列举(directory listing)开启的利用
**Q1**: 访问某目录直接返回文件列表页(Index of /),怎么最大化利用?
**A1**: 递归浏览所有子目录,把整棵可见文件树抓下来。重点找:备份、日志、上传目录、配置、临时文件、看似无关的旧文件。列举开启等于文件系统半透明。
**Q2**: 列举里最容易被忽略的高价值项?
**A2**: 上传目录(可能含他人上传的敏感文件、也是 getshell 落点)、日志文件(含 token/内部路径/请求详情)、备份和导出、开发者遗留的测试脚本。别只盯"看起来敏感"的名字。
**Q3**: 列举页只显示部分、深层目录又不列举怎么办?
**A3**: 深层可能单独配了 index 文件或关了列举。转对已知文件名做定向猜测,或结合 .DS_Store/.git 补全深层清单。列举关的地方用其它清单源补。
**Q4**: 目标根目录列举关着,还有机会吗?
**A4**: 找特定子目录可能单独开着(常见 /uploads/、/static/、/backup/、/logs/),这些目录配置常和根不同。逐个探子目录的列举状态。
**Q5**: 全站列举都关闭怎么办?
**A5**: 撤出"列举"这一维度,转爆破/清单泄露(.git index、sitemap、robots、JS 路由)重建文件视图。列举只是获取清单的一种便利手段,非唯一。

### 错误页面与堆栈信息泄露
**Q1**: 怎么主动逼出有价值的报错信息?
**A1**: 构造异常输入:参数类型错误(数字位传字符)、超长/特殊字符、缺必填参数、非法编码、访问不存在资源、错误的请求方法。观察是否吐出堆栈、SQL、路径、框架版本。
**Q2**: 报错里最有价值的几类信息?
**A2**: ①绝对路径(定位 web 根,供后续利用);②框架/组件精确版本(查已知 CVE);③数据库报错(暴露表/字段名、印证注入点);④内部类名/包名(反推技术栈和源码结构);⑤内部 IP/主机名。
**Q3**: 数据库报错回显意味着什么?
**A3**: 强烈的注入信号——错误被直接回显说明输入进了 SQL 且未妥善处理,这是从"信息泄露"转"SQL 注入"的直接跳板。顺着报错构造 payload。
**Q4**: 报错被统一成友好页、什么都不吐怎么办?
**A4**: 转盲测和旁路:响应时间差异、状态码差异、响应长度差异推断内部行为(布尔/时间盲);或从其它未统一处理的入口(老接口、非标准路径)找仍会吐详细错误的角落。
**Q5**: 完全没有可利用报错怎么转?
**A5**: 报错泄露只是信息面之一,转其它:响应头版本泄露、favicon/静态资源指纹识别组件、时间侧信道。别在"逼报错"上耗太久。

### 版本控制残留:SVN/.hg/.bzr 等
**Q1**: .git 没有,还有哪些版本控制残留值得试?
**A1**: /.svn/(尤其老版本 SVN 的 .svn/entries、pristine 副本含完整源码)、/.hg/(Mercurial)、/.bzr/(Bazaar)、CVS/。不同团队用不同 VCS,别只认 .git。
**Q2**: .svn 怎么还原源码?
**A2**: 老版 SVN 每个目录都有 .svn 且 pristine 存了文件原始副本(.svn/text-base/ 或 .svn/pristine/),直接拉这些副本即得源码;新版结构不同,用专门 svn dumper 工具。
**Q3**: 怎么快速判断用的哪种 VCS?
**A3**: 依次探测各自的标志文件(.svn/entries、.hg/requires、.bzr/branch)。命中哪个就用哪套 dump 方法。也可从开发者习惯、公司技术栈年代推测(老项目更可能 SVN)。
**Q4**: VCS 残留都不存在怎么办?
**A4**: 转其它源码泄露载体:IDE 工程文件(.idea/、.vscode/、.project 暴露路径和配置)、备份包、sourcemap、编辑器临时文件。"拿源码"目标不变,穷举各载体。
**Q5**: 残留目录存在但被 deny(点开头统一拦)怎么办?
**A5**: 试路径变形绕 deny(编码、大小写、穿越);或从 CDN/备用域名/直连源站绕过前置 deny 规则;或换不带点的载体。deny 规则常有覆盖盲区。

### 泄露的第三方 token 的验证与边界
**Q1**: 挖到疑似第三方服务 token(代码平台/协作工具/云/支付),怎么安全验证?
**A1**: 每种 token 有官方的"查当前身份/权限"只读接口(whoami 类),用它验活并看权限范围,不做任何写操作。先搞清"这 token 是谁、能干嘛",再谈利用。授权范围内、无害验证优先。
**Q2**: 代码平台 token 有效意味着什么?
**A2**: 可能读到该账号所有私有仓库——源码、更多密钥、内部文档,泄露量指数级放大。这是"一个 token 撬开整个组织代码"的高杠杆点。优先核实其可访问的仓库范围。
**Q3**: 协作/IM 平台 token 有效呢?
**A3**: 可读内部聊天、文件、成员信息——大量社工素材和明文凭据(人们爱在群里发密码)。也可能可发消息做钓鱼。价值在情报和社工跳板。
**Q4**: token 验证返回无效/过期怎么办?
**A4**: 转找更新的:同源其它泄露点、更近的提交、运行时泄露。或换 token 类型——一个失效不代表其它类型的 token 也失效。也检查是否是故意投放的诱饵。
**Q5**: 担心 token 是蜜罐怎么办?
**A5**: 警惕特征:权限异常大而"恰好"暴露、命名过于刻意、验证接口有异常监控迹象。用最小动作验证,避免登录敏感操作触发溯源。真实红队要权衡"利用价值 vs 暴露风险"。
**Q6**: token 权限很低、几乎没用怎么办?
**A6**: 低权 token 也可能用于:枚举更多资源名(为进一步攻击铺路)、确认组织资产边界、作为社工可信度背书。转"情报利用"而非"直接权限利用"。

### 泄露信息的去重、降噪与优先级(避免被假线索淹没)
**Q1**: 扫出成百上千条疑似泄露,信息过载了,怎么办?
**A1**: 先分层过滤。第一层去噪:剔除公开无害项(前端 public key、CDN 地址、开源库自带示例)。第二层归类:凭据/源码/接口/路径/拓扑分开。第三层排序:可立即验证且高权的排最前。别被数量淹没。
**Q2**: 怎么快速区分"真敏感"和"看着敏感其实无用"?
**A2**: 问三个问题:①这东西设计上就该公开吗(前端 key、公开 API)?②它可远程验证吗?③验证成功能带来什么权限?三问都指向高价值才深入。省下时间给真弹药。
**Q3**: 大量疑似密钥来自开源依赖的示例值怎么识别?
**A3**: 高熵串未必是真密钥——比对是否是知名库的固定示例/测试值(可搜到公开出处的就是噪声)、是否是占位符格式。命中公开语料的直接丢弃。
**Q4**: 怎么避免重复劳动?
**A4**: 建一份"泄露台账":来源、类型、验证状态、结论。多来源(.git 里的 .env 和直接扫到的 .env)可能指向同一凭据,去重后只验一次。台账也防止换天再打时重扫。
**Q5**: 过滤太狠、把真线索误杀了怎么办?
**A5**: 对"拿不准是否有用"的中间层别直接删,单列"待定"区,主线索打完再回头验。降噪是为聚焦,不是丢弃。保留可回溯性。
**Q6**: 所有高价值项都验证失败,台账见底了怎么办?
**A6**: 回到"待定区"和"低价值区"重新评估——之前判为无用的,在拿到新上下文(如已知某内网 IP)后可能突然变得有用。泄露情报的价值随攻击进展动态变化。

### 目录扫描全 403 / 全 302 跳转的转向
**Q1**: 爆破结果全是 403 或全 302 跳登录,啥都区分不出,怎么办?
**A1**: 先建立基线:请求一个必然不存在的随机路径,看它返回什么。若随机路径也 403/302,说明是"统一拦截/统一跳转",你的结果全是假阳性,当前爆破方式无效。
**Q2**: 统一 302 跳登录怎么突破?
**A2**: 关注"跳转前的蛛丝马迹":302 响应的 Content-Length 差异(有的路径跳转前已渲染部分内容)、响应头差异、跳转 Location 差异。或找不触发跳转的入口(静态资源、API 前缀、特定方法)。
**Q3**: 统一 403 怎么办?
**A3**: 试 403 绕过技巧:路径大小写、末尾加 /、加 %20/%00/./、换 HTTP 方法、加伪造头(X-Original-URL、X-Rewrite-URL、X-Forwarded-For)。前置代理和后端对路径的理解差异是绕过口。
**Q4**: 绕过也不行,确认防护太强怎么办?
**A4**: 转攻击面而非死磕这个入口:换资产(子域/旁站/移动端 API/小程序后端,防护常不一致)、换协议面(HTTP 打不动看看有没有其它开放端口的服务)、转被动情报(公网侧泄露)。
**Q5**: 怎么判断"该转了"而不是再多试试?
**A5**: 定个止损线:同一防护面尝试 N 种绕过均无效、投入产出明显递减,就转向。红队的核心能力之一是及时放弃低产出路径,把时间投到软的地方。

### 备份文件太大或下载受限的处理
**Q1**: 确认存在一个几百 MB/GB 的备份,但直连下载超时/被断,怎么拿?
**A1**: 用 HTTP Range 分块下载(断点续传),小块拉、可续传、绕过单次超时和大响应拦截。先 Range 拉前几 KB 确认是真备份再决定是否拉全。
**Q2**: 服务器不支持 Range 怎么办?
**A2**: 评估是否必须拿全。很多时候只需文件树和几个配置文件:若能通过其它方式(.git、目录列举)拿到结构,就定点取需要的文件,不必下整包。
**Q3**: 只想验证包里有没有敏感内容,怎么少下?
**A3**: 若是 zip,其目录结构在文件"尾部"的中央目录记录——用 Range 拉尾部就能列出包内文件名清单,先看清单值不值得下全。tar.gz 则需从头流式读。
**Q4**: 下载中途反复被 WAF 切断怎么办?
**A4**: 转低调分块 + 换 IP 轮换 + 降速;或换下载入口(CDN 缓存、备用域名、源站直连)。也可能触发了大响应告警,冷却后再取。
**Q5**: 实在拉不下来这个大包怎么办?
**A5**: 转其它更小的等价泄露:单个配置文件、数据库单表导出、增量备份、日志片段。大而全的备份诱人但不是唯一路径,拆小目标降低下载成本。

### 泄露猎取整体卡死,往哪个正交维度转
**Q1**: .git/.env/备份/swagger/JS 全都试过了,一无所获,是不是没戏了?
**A1**: 先自检覆盖度:是否只打了主域主端口?是否只用了默认字典?是否忽略了非 80/443 的服务?很多"卡死"其实是"没铺开"。先横向扩资产面再下结论。
**Q2**: 资产维度怎么扩?
**A2**: 子域枚举(证书透明日志、被动 DNS)、旁站、C 段、其它端口的 Web 服务、移动端 App/小程序反编译出的后端接口、API 网关。主站防护严不代表兄弟资产也严,泄露常在边角资产。
**Q3**: 主动扫全被墙,转哪个被动维度?
**A3**: 公网侧情报:代码托管平台搜目标域名/组织名/密钥特征、Wayback 历史快照(旧路径/旧备份仍可达)、搜索引擎语法定向搜敏感文件、公开数据泄露库查目标邮箱凭据。全程不碰目标 WAF。
**Q4**: 泄露维度确实榨干了,该转哪类攻击面?
**A4**: 从"信息收集/泄露"转"直接漏洞利用":用已收集的接口清单/技术栈/版本信息,定向打注入、反序列化、文件上传、SSRF、已知组件 CVE。前期 recon 的产出正是为此刻的定向攻击铺路。
**Q5**: 连漏洞利用面也僵持怎么办?
**A5**: 转人的维度——社工与凭据攻击:用泄露的邮箱/命名规律做定向钓鱼、密码喷洒(受控、防锁定)、查目标员工在公开泄露库中的复用凭据。技术面硬碰不动时,人往往是最软的边界。
**Q6**: 怎么系统性决定"下一步往哪转"?
**A6**: 用正交维度清单自检:资产(横向铺开了吗)、协议/端口(只打了 Web 吗)、时间(历史快照看了吗)、身份(有低权账号能换视角吗)、人(社工试过吗)。每个僵局对应一个尚未穷尽的正交面——红队的转向能力就是系统性遍历这些维度,而非在单一维度里越挖越深。
