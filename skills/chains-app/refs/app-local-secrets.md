# App客户端 · 客户端本地存储与硬编码利用

### 拿到一个 APK/IPA,先分流侦察路线
**Q1**: 手里刚落地一个安装包(APK 或 IPA),我该把有限时间先花在哪条路上?
**A1**: 先做"零成本静态分流",别急着上 Frida。判据是投入产出比:①先看包体积和框架类型(原生 Java/Kotlin、Flutter、React Native、Unity、Cordova/Ionic、Electron)——框架决定后续工具链完全不同;②`strings`/`grep` 扫一遍看有没有裸奔的 http(s) 端点、AK/SK 前缀、`-----BEGIN`、`token=`、`Authorization`;③看 manifest/Info.plist 找导出组件、URL scheme、网络安全配置。三分钟内就能判断这是"密钥直接躺在 assets 里"的软目标,还是"加固+pinning+反调试"的硬目标。
**Q2**: 静态一眼没看到明文密钥,是不是该立刻转动态 hook?
**A2**: 不。先确认包是否被加固/加壳(见脱壳链)。静态没结果有两种可能:真没有,或者被壳藏起来了。先用 `apktool`/`jadx` 反编译看 Application 入口是不是 SDK 壳的代理类(类名像 `com.*.StubApp`、`ProxyApplication`),DEX 数量异常少、方法体是 native。确认加固后再决定脱壳 vs 直接动态,而不是盲目上 Frida 浪费时间。
**Q3**: 框架是 Flutter/Unity,jadx 打不开逻辑怎么办?
**A3**: 这是最常见的"看起来卡死"点。Flutter 逻辑在 `libapp.so`(AOT 快照,需 blutter/reFlutter),Unity 在 `libil2cpp.so`+`global-metadata.dat`(用 Il2CppDumper 恢复符号)。转向维度:从"读 Java 层"切到"读 native 层符号恢复",或者干脆放弃逆向逻辑,转到网络层观测行为(它的密钥最终还是要发出去)。
**Q4**: 这条静态路整体失败——包加固、native、字符串全加密,该往哪个正交维度转?
**A4**: 转"运行时/网络边界"维度。客户端再怎么藏,密钥在使用瞬间必然明文出现在内存和网络请求里。放弃硬啃字节码,改为:①插桩抓运行时内存;②抓包看它实际发什么(即使 pinning 也可绕);③抓它落地的本地文件(运行后 SharedPreferences/沙盒里往往缓存明文)。
**Q5**: 时间紧,只能选一条,优先级怎么排?
**A5**: 软目标优先静态 grep(可能 30 秒出货);硬目标优先"运行后抓落地文件+抓包",因为动态观测比逆向脱壳快。逆向脱壳是最后手段——它信息最全但最耗时。
**Q6**: 判断"值不值得继续打这个 App"的止损线在哪?
**A6**: 若目标是拿服务端权限,则客户端只是入口。当客户端已经交出可用的服务端凭证/端点/加密协议时立刻转服务端;当客户端啥都没有且加固极硬,评估是否有更划算的入口(Web、API 网关),别在一个加壳 App 上耗到底。

### 反编译工具链选型与失败回退
**Q1**: 要反编译 Android 包,jadx、apktool、ghidra 我该先上哪个?
**A1**: 按目的选。看 Java 层逻辑/搜字符串用 `jadx`(反编译到 Java,可读性最好);要改资源、看 smali、重打包用 `apktool`;native `.so` 分析用 `ghidra`/`IDA`。iOS 则是 `class-dump`/`Hopper`/`ghidra` + 砸壳(frida-ios-dump)。默认起手 jadx-gui,全局搜索最快。
**Q2**: jadx 报错反编译不全、大量方法 `// decompilation failed`?
**A2**: 别卡在单一工具。降级到 smali(`apktool d`)读原始字节码——反编译失败但 smali 一定在。或换 CFR/Procyon 等其他反编译器交叉验证。关键逻辑用 smali 逐指令读,虽然慢但不会漏。
**Q3**: 全局搜关键词从哪些词根入手?
**A3**: 密钥类:`secret`、`password`、`passwd`、`pwd`、`key`、`token`、`apikey`、`appkey`、`appsecret`、`aes`、`des`、`iv`、`salt`、`sign`。云厂商前缀:`AKIA`(AWS)、`LTAI`(阿里云)、`AKID`(腾讯云)。端点类:`http://`、`https://`、`.com/api`、`internal`、`test`、`dev`、`staging`。凭证格式:Base64 长串、`eyJ`(JWT 头)、`-----BEGIN`。
**Q4**: 搜出来几百个 `key` 命中,噪音太大怎么筛?
**A4**: 加约束缩小信噪比:①正则匹配固定长度的十六进制/Base64(如 32/16 位对齐的 AES key);②看赋值上下文是否 `static final`(硬编码常量);③过滤第三方库路径(`okhttp`、`gson`、`androidx`)只看应用自身包名;④优先看"和加密函数/网络函数在同一类"的常量。
**Q5**: 工具链全用了还是读不懂逻辑,这条静态逆向路失败,转哪?
**A5**: 转"动态插桩替代静态阅读"。不理解算法没关系,直接 hook 加密函数入口打印明文入参、hook 网络函数打印明文请求体。逆向的目的是拿到密钥/协议,动态能直接给结果,绕开读代码的智力成本。

### 硬编码密钥搜索:哪些藏身之处最容易漏
**Q1**: 我 grep 了 smali 没找到密钥,是不是就没有硬编码?
**A1**: 不能下这个结论。硬编码有很多非代码藏身处,常被漏掉:`assets/` 下的 config.json/*.properties/*.xml/证书文件、`res/raw/`、`res/values/strings.xml`(常有 `google_api_key`、`facebook_app_id`)、`AndroidManifest.xml` 的 `<meta-data>`、`resources.arsc`、Native `.so` 的 `.rodata` 段、甚至图片/字体的尾部隐写。逐个覆盖。
**Q2**: strings.xml 和 meta-data 里通常能挖到什么?
**A2**: 第三方 SDK 的公开-但敏感凭证:地图 key、推送 appkey、统计 SDK secret、`google_maps_key`、Firebase 配置(`google-services.json` 常直接打进 assets,里面有 project id、api key、database url)。这些能横向进第三方云后端。
**Q3**: 密钥是拼接/异或/Base64 编码后存的,grep 搜不到明文?
**A3**: 这是常态。看代码里"对某常量做变换后传给加密函数"的模式——常量本身是密文。手段:①把编码常量抠出来在本地复现解码逻辑;②或不解码,直接动态 hook 变换函数的返回值。判据:只要变换是纯客户端可复现的,密钥就等于公开。
**Q4**: `.so` 里的密钥怎么找?
**A4**: 先 `strings libxxx.so` 扫 `.rodata`;找不到就 ghidra 定位 JNI 导出函数(`Java_com_xxx`),回溯它引用的常量数据。native 常把 key 拆成字节数组分散初始化(反 strings),这时静态很痛苦——转动态 hook 该 JNI 函数返回值更快。
**Q5**: 找遍所有静态藏身处都没有,这条"硬编码"假设本身可能错了,怎么转?
**A5**: 转"密钥不在包里,而在运行时下发/派生"的假设。可能是:首次启动从服务端拉取(抓包看初始化请求)、由设备指纹派生(hook 派生函数)、存在远程配置里。此时正交转向是抓"密钥获取的那次网络交互"或"派生密钥的那个函数",而不是继续在包体里翻。
**Q6**: 旧版本会不会藏着新版删掉的密钥?
**A6**: 会。转"版本历史对比"维度:从第三方 APK 站/应用市场缓存拉多个历史版本,diff strings 和 config——开发常在某版本"修复"了硬编码(删了明文)但旧版仍可下载,老 key 若服务端没轮换仍有效。

### 加固脱壳的决策与时机
**Q1**: 确认是加固包(常见商业加固壳),我要不要脱壳?
**A1**: 先问脱壳的必要性。如果你的目标(端点、密钥、协议)动态 hook 就能拿到,别脱壳——脱壳成本高、易失败。脱壳只在"必须通读完整业务逻辑/找隐藏分支/静态审计"时才值得。判据:目标是"点状拿密钥"就动态,是"面状审代码"才脱壳。
**Q2**: 决定脱壳了,方法怎么选?
**A2**: 优先"运行时内存 dump"类通用脱壳,不针对特定壳版本:Frida-DEXDump 一类工具,在 App 运行到主界面后从内存扒出解密后的 DEX。这比逆向壳的解密算法快一个数量级。落地后再 baksmali 恢复。
**Q3**: DEXDump 扒出来的 DEX 不完整/有些类是运行时才解密的?
**A3**: 这是抽取壳(方法级抽取)的特征——DEX 结构在但方法体是运行时填充。转向:用"主动调用"或指令级 dump(如 fart、youpk 这类基于 ART 主动调用+日志的方案),遍历触发所有方法完成填充后再 dump。或者接受"只 dump 到关键类"够用即止。
**Q4**: 脱壳环境反调试/反 Frida,App 一起就闪退?
**A4**: 先解决检测再脱壳(见反调试绕过链)。转向选择:用非注入式方案(基于 ART hook 的 LSPosed 环境,或修改 ROM/模拟器)、或用 unidbg 纯模拟执行局部逻辑而不真跑 App。
**Q5**: 脱壳整条路反复失败(壳太新、环境对抗强),往哪个正交维度转?
**A5**: 彻底放弃"拿到完整代码"的执念,转"黑盒行为观测"。你要的不是代码,是它的对外行为:抓包看协议、hook 单点函数拿密钥、观察它读写的本地文件。加固保护的是代码可读性,保护不了它运行时的实际行为——从可读性维度转到行为维度。

### SSL Pinning 绕过的分层决策
**Q1**: 抓包时 App 报证书错误连不上,判断是 pinning 吗?
**A1**: 先区分是系统不信任用户 CA(Android 7+ 默认)还是应用层 pinning。判据:装了系统级 CA(或 magisk 模块信任用户 CA)后能抓,就只是信任问题;装了还抓不到,才是应用层 pinning。别一上来就假设 pinning,先排除 networkSecurityConfig 的信任配置。
**Q2**: 确认应用层 pinning,先试什么绕过?
**A2**: 成本从低到高:①先上通用 Frida 脚本(frida-multiple-unpinning/objection `android sslpinning disable`)——覆盖 OkHttp、TrustManager、原生 SSLContext 等主流实现,一键成功率高;②不行再看具体 pinning 实现(是 OkHttp CertificatePinner、还是自实现 X509TrustManager、还是 native BoringSSL)针对性 hook。
**Q3**: 通用脚本失效,pinning 在 native 层(如 Flutter/自研 .so)?
**A3**: Flutter 不走系统代理且 pinning 在 BoringSSL,通用 Java hook 无效。转向:①hook native `ssl_verify`/`SSL_CTX_set_custom_verify`(reFlutter 或 patch libflutter.so);②或用 iptables/proxy 强制流量转发 + 修改 so 里的校验返回。这是从"Java 层 hook"正交转到"native 层 patch"。
**Q4**: 双向认证(客户端也带证书 mTLS),服务端要求客户端证书怎么办?
**A4**: 从包里找客户端证书:`.p12`/`.pfx`/`.bks` 常硬编码在 assets,密码常硬编码在代码里。提取出来导入抓包工具做客户端证书,即可完成双向握手。这把"pinning 绕过"问题转成了"硬编码证书提取"问题。
**Q5**: 所有 hook/patch 都失败,就是抓不到明文流量,往哪转?
**A5**: 放弃"在网络链路上解密",转"在应用内部取明文"。流量加密前后必然在内存/函数入参里是明文:hook 加密函数(如 `doFinal`、`SSL_write`)拿加密前的明文请求体,或直接 hook 业务层网络封装函数(`Retrofit`/`OkHttp` 的 Request 构造)。这样根本不碰 TLS 层,pinning 再强也拦不住。

### Root/越狱检测导致 App 拒启动
**Q1**: 目标 App 在我 root 的测试机上直接闪退/提示环境异常,怎么定位?
**A1**: 先判定是 root 检测还是别的(签名/完整性)。root 检测常查:`su` 二进制路径、`Superuser.apk`、`test-keys`、`ro.debuggable`、magisk 特征、`/system` 可写。先抓 logcat 看退出前日志,或 hook `System.exit`/`Process.killProcess` 回溯调用栈定位检测点。
**Q2**: 定位到检测函数,怎么绕最省事?
**A2**: 优先环境侧隐藏,而非逐个 hook:Magisk Hide/Zygisk + Shamiko/DenyList 隐藏 root,LSPosed 的 HideMyApplist 隐藏可疑包。环境层解决一次能过很多 App。判据:通用隐藏能过就别写针对性 hook。
**Q3**: 环境隐藏后仍被检测(App 自查很刁钻)?
**A3**: 转函数级 hook:objection `android root disable` 或 Frida hook 具体检测方法让其返回"未 root"。若检测在 native,hook `fopen`/`access`/`stat` 对敏感路径的调用返回失败。逐点消除。
**Q4**: 完全绕不过 root 检测,又必须动态分析,往哪转?
**A4**: 转"无 root 动态分析"维度:①用 frida-gadget 重打包注入(不需要 root 的设备,把 gadget 打进 App);②或用 unidbg 模拟执行目标 .so 中的算法(根本不启动完整 App);③或换真机非 root + 免 root 容器框架。绕过检测的正交解是"不给它可检测的 root 环境"。
**Q5**: 连重打包注入都被签名校验挡住(见完整性链),彻底动态受阻怎么办?
**A5**: 回退到纯静态+局部模拟。用 unidbg/qiling 把关键算法函数单独抠出来在 x86 上跑,喂输入拿输出,完全不依赖真实运行环境。这是从"整机动态"降维到"函数级仿真"。

### Frida hook 的目标函数选择
**Q1**: 我要 hook 拿密钥/明文,但不知道 hook 哪个函数,怎么定位?
**A1**: 不要盲 hook。先缩小范围:①静态 jadx 里找加密/签名相关类,定位 `doFinal`、`getSignature`、`sign`、`encrypt`;②或用 objection/frida-trace 通配符批量 trace(`javax.crypto.Cipher.*`、`java.security.*`)先观测哪些被调用;③从网络请求特征(某个加密 header)反推构造它的函数。
**Q2**: 想一网打尽所有加密调用怎么做?
**A2**: hook 加解密的收口点:`javax.crypto.Cipher` 的 `init`(拿 key/iv)和 `doFinal`(拿明文/密文对),`Mac`(HMAC 签名),`MessageDigest`。一把 hook 住 `Cipher.init` 就能截获所有 AES/DES 的 key 和 iv,不用管业务在哪调的。
**Q3**: hook 上了但函数被调用无数次,输出刷屏分不清哪个是目标?
**A3**: 加过滤条件:按调用栈(打印 `Thread.currentThread().getStackTrace()`)只留业务包名触发的;按参数特征(密文长度/明文含目标关键词)过滤;或在触发目标操作(如点登录)前后打时间戳窗口内的调用。
**Q4**: 目标逻辑在 native,Java hook 拿不到?
**A4**: 转 native hook:`Interceptor.attach` 到导出符号(`Module.getExportByName`),或对未导出函数用基址+偏移 hook。常 hook 的 native 收口:`SSL_write`/`SSL_read`(拿 TLS 明文)、`memcpy`/`strcpy`(拿拷贝中的密钥)。
**Q5**: App 有反 Frida,一注入就崩,hook 路走不通,转哪?
**A5**: 见反调试链——先过检测。若实在过不了,正交转向"离线仿真":unidbg 加载目标 .so,自己实现 JNI 环境调用目标函数,在没有反 Frida 干扰的纯净环境里拿结果。反 Frida 保护的是"在真机注入",保护不了"函数被搬到别处执行"。

### SharedPreferences / plist / 沙盒文件提取
**Q1**: App 跑起来后我想看它本地存了什么敏感数据,先看哪?
**A1**: 按"明文概率"排序翻沙盒:Android `/data/data/<pkg>/shared_prefs/*.xml`(登录 token、用户信息常明文)、`/databases/*.db`、`files/`、`cache/`;iOS `Library/Preferences/*.plist`、`Documents/`、`Library/Caches/`。开发图省事常把 token/密码/用户资料明文塞 SharedPreferences。
**Q2**: shared_prefs 里的值是加密的(乱码)怎么办?
**A2**: 加密说明有 key,而 key 大概率也在客户端。转"找解密 key":可能硬编码、可能在 Keystore、可能设备派生。判据:若用了 `EncryptedSharedPreferences`,key 在 AndroidKeystore(见 Keystore 链);若自研加密,key 常硬编码——hook 它的解密函数直接拿明文,比找 key 更快。
**Q3**: 没 root 拿不到 /data/data 怎么办?
**A3**: 转免 root 提取:①`adb backup`(若 App allowBackup=true,见备份链);②debuggable 的 App 用 `run-as <pkg>` 访问私有目录;③iOS 用备份提取或已越狱设备。或者干脆重打包设 debuggable/allowBackup 再装。
**Q4**: 想找"哪个文件存了目标数据"但文件太多?
**A4**: 用行为触发定位:清空沙盒→执行目标操作(登录/支付)→diff 沙盒变化,新增/改动的文件就是目标。或 hook 文件写入(`FileOutputStream`、`SharedPreferences.Editor.putString`)打印键值和路径。
**Q5**: 本地存储全加密且 key 在硬件 Keystore 取不出,这条"扒本地文件"路失败,转哪?
**A5**: 转"运行时内存"维度。数据在展示/使用时必然解密进内存:hook 读取函数拿解密后的返回值,或直接 dump 进程内存搜明文。本地文件加密防不住"App 自己解密来用"的那一刻——在使用点拦截。

### Keystore / Keychain 内数据的取用
**Q1**: 敏感数据用 Android Keystore / iOS Keychain 保护,我能直接导出 key 吗?
**A1**: 通常不能直接导出(硬件级 key 不出 TEE/SE)。但这不代表拿不到数据。改变思路:你要的不是 key 本身,是"用 key 解密后的明文"。App 有权限用这个 key,你 hook App 让它替你解密即可。
**Q2**: 具体怎么让 App 替我解密?
**A2**: hook Keystore 相关调用:Android hook `Cipher.doFinal`(此时 key 已从 Keystore 加载,你拿明文输出)或 hook `KeyStore.getKey` 后的使用点;iOS hook `SecItemCopyMatching`(直接返回 Keychain 里的条目)。判据:只要 App 在运行且已解锁,它的解密能力就是你的。
**Q3**: iOS Keychain 里的项目想批量导出?
**A3**: 越狱设备用 keychain-dumper,或 objection `ios keychain dump`。注意 `kSecAttrAccessible` 属性决定可访问性(锁屏态、本设备限定等)。这直接给出所有 App 存的凭证。
**Q4**: key 设了生物识别/用户认证才能使用(setUserAuthenticationRequired),hook 时它要求指纹?
**A4**: 转向绕过认证门:hook 生物识别回调(`BiometricPrompt` 的 `onAuthenticationSucceeded`)直接触发成功路径,或 hook 认证校验函数返回 true。让"认证通过"的分支无条件走,后续解密就正常执行。
**Q5**: 硬件 key、强认证、native 解密全齐,拿不到明文,往哪个正交维度转?
**A5**: 放弃客户端侧,转服务端信任边界。Keystore 保护的是"这台设备本地的数据",但 App 用它解密后终究要和服务端交互——转去抓解密后发往服务端的明文,或直接攻击服务端 API(客户端加密再强,服务端逻辑漏洞与它无关)。

### 硬编码云凭证(AK/SK)落地利用
**Q1**: 我从包里挖到一对疑似云厂商 AK/SK(不同厂商有固定前缀),下一步?
**A1**: 先验活再谈利用。别直接猜权限,用官方 CLI/SDK 最小动作探活:如查询当前身份、列举资源。判据:能返回身份信息说明凭证有效,返回的账号/ARN 还告诉你这是子账号还是主账号、大概什么服务。
**Q2**: 凭证有效,怎么摸清它能干什么?
**A2**: 枚举权限而非乱试:先试只读+列举类动作(list buckets、describe instances)划定服务边界,再逐服务探权限。工具化用对应云厂商的权限枚举脚本。原则:先普查权限地图,再定向利用高价值资源(对象存储、云主机、密钥管理、数据库)。
**Q3**: 凭证权限被限得很死(只能访问某个 bucket)怎么办?
**A3**: 从窄权限找提权/横向线索:①这个 bucket 里可能有其他配置文件/更高权限凭证;②检查是否能 `iam` 相关动作(PassRole、AttachPolicy)做提权;③对象存储里的对象可能含服务端源码、备份、其他系统凭证。窄权限是跳板不是终点。
**Q4**: AK/SK 已失效或触发风控被禁,这把凭证废了,转哪?
**A4**: 转其他凭证源,别在死凭证上耗:①同包里的其他 SDK 凭证(推送/短信/存储各一套);②STS 临时凭证获取接口(客户端常有换 STS 的逻辑,hook 它拿新鲜临时凭证);③服务端下发凭证的接口(抓包)。正交转向"凭证的活水源头"而非纠结一潭死水。
**Q5**: 只有对象存储的 bucket 访问权,能扩大战果吗?
**A5**: 能。对象存储常是横向枢纽:找里面的 `.env`/config/备份/日志→挖更多凭证;若 bucket 挂载为网站源→可能可写入 webshell;若被内部系统当可信数据源→投毒。把"存储访问"升级为"代码执行/凭证扩散"。

### 硬编码 token/JWT 的权限探测与重放
**Q1**: 挖到一个硬编码的长期 token(API key 或 JWT),怎么判断它值不值钱?
**A1**: 先解析再重放。JWT 直接 base64 解 header/payload 看:签发者、过期时间(`exp`,长期或永不过期最危险)、权限 scope、角色 claim、用户/租户标识。API key 则看它在哪个请求头用、配哪个端点。判据:payload 里的角色/scope 直接告诉你权限上限。
**Q2**: 想知道这 token 实际能调哪些接口?
**A2**: 拿抓包看到的 API 结构做横向探测:带着 token 遍历已知端点,观察 401/403(无权)vs 200(有权)。重点试:管理类端点、其他用户资源(改 ID 做越权)、内部/调试端点。token 的真实权限=服务端实际放行的集合,靠探测得出。
**Q3**: JWT 想篡改提权(改 role=admin)但有签名?
**A3**: 试经典 JWT 弱点:①`alg:none` 是否被接受;②签名密钥是否弱/硬编码在客户端(若客户端能签发,你就能伪造任意 claim);③RS256→HS256 混淆(用公钥当 HMAC 密钥)。判据:客户端存在签发/校验逻辑时,密钥大概率也在客户端可得。
**Q4**: token 过期了或被吊销,重放失败,转哪?
**A4**: 转"获取新 token 的流程":抓登录/刷新接口看它怎么换 token。若硬编码的是"能换取用户 token 的上游凭证"(如 client_secret、refresh_token),价值远高于单个过期 access_token——用它走 OAuth 流程换新鲜 token。正交转向"发证机制"而非"某张过期证"。
**Q5**: token 有效但权限就是个普通用户,榨不出更多?
**A5**: 转"越权/横向"维度:token 身份不变,但服务端可能存在 IDOR、越权接口、多租户隔离缺陷。用这个合法低权 token 做认证,去打服务端授权逻辑漏洞——客户端给的是"入场券",服务端授权缺陷才是"提权门"。

### 重打包/完整性校验绕过
**Q1**: 我想改代码/注入 gadget 后重打包,但担心 App 有签名校验,先怎么判断?
**A1**: 先小成本试探:apktool 解包→随便改点无关资源→重签名安装→跑。若正常运行,大概率没签名自校验;若闪退/提示"非官方版本",则有完整性校验(签名比对/DEX CRC/文件哈希)。先摸清有没有校验再决定要不要精细绕过。
**Q2**: 确认有签名校验,通常校验什么、怎么绕?
**A2**: 常见校验点:`PackageManager.getPackageInfo` 取自身签名比对硬编码值、校验 APK 文件 CRC、校验 classes.dex 哈希。绕法:hook `getPackageInfo`/`getPackageSignatures` 返回原始签名;或找到校验函数直接 patch 成永远通过。静态改比运行时 hook 更稳(改完就干净)。
**Q3**: 校验在 native 层且比对逻辑复杂?
**A3**: 转向"不重打包"路线。既然改包会触发校验,那就不改包:用免 root 注入以外的方式,如 LSPosed 模块(hook 不改 APK 文件)、或 Frida 直接 attach 运行中进程。校验的是"文件被改",你不改文件它就无从检测。
**Q4**: 我只是想抓包/hook,不是必须改包,还需要死磕重打包吗?
**A4**: 不需要。反问自己目的:若目的是动态分析,用 attach 式 Frida/LSPosed 完全不碰 APK 文件,直接绕开整个完整性校验话题。只有"需要分发改后版本给受害者"或"必须持久化注入"才非重打包不可。
**Q5**: 必须重打包(如做钓鱼/需要 gadget 持久化)但校验绕不过,转哪?
**A5**: 转"在校验之前劫持"或"服务端侧下手":①用免 root 容器免修改原包运行并注入;②若校验依赖服务端下发的期望哈希,攻击那个下发通道;③或分析校验是否有 TOCTOU 窗口。正交转向:从"骗过本地校验"转到"控制校验所依赖的外部输入"。

### 客户端本地鉴权/业务校验绕过
**Q1**: App 的某功能(VIP、开锁、审批通过)看起来是客户端本地判断的,能绕吗?
**A1**: 先确认判断到底在哪端。判据:断网/改本地数据后功能状态是否变化。若本地改 `isVip=true`(改 SharedPreferences 或 hook getter)就生效,说明是客户端鉴权——这是设计缺陷,直接绕。若本地改无效、每次都问服务端,则本地绕不了。
**Q2**: 确认是客户端本地判断,怎么绕最直接?
**A2**: 三条:①改本地存储的标志位;②hook 返回判断结果的函数让它恒真(`isVip()`→true、`checkLicense()`→pass);③patch smali 里的条件跳转(把 if-eqz 逻辑反转/删除)。选哪个看要一次性验证(hook)还是持久化(patch 重打包)。
**Q3**: 关键校验会请求服务端,但响应是"客户端解析"的,有空子吗?
**A3**: 有。转"篡改服务端响应"维度:服务端返回 `{vip:false}` 但由客户端解析生效——用抓包工具改响应包为 `{vip:true}`,或 hook 解析函数。判据:只要"最终决策在客户端做",服务端说什么都能被中间人改写。
**Q4**: 我怀疑绕过了但功能其实是服务端控制的(改了没用),怎么快速证伪?
**A4**: 做对照实验:本地全绕(标志位+hook+改响应)后,让功能真正产生服务端副作用(如真下单、真解锁远程设备)。若只是界面显示变了但服务端不认账(下单失败/设备不动),说明真正的 gate 在服务端,本地绕过是"自欺"。及时止损别在假胜利上浪费时间。
**Q5**: 确认核心校验在服务端,客户端绕过无效,转哪?
**A5**: 转服务端授权攻击面:抓客户端与服务端交互的鉴权请求,去打服务端的越权(IDOR)、参数篡改、支付/订单逻辑漏洞、竞态。客户端只是 UI,真正的权限决策在服务端——把战场从设备转到 API。

### WebView / 混合应用的本地攻击面
**Q1**: App 大量用 WebView,本地存储和硬编码的攻击面有何不同?
**A1**: WebView 引入 web 侧本地存储:`/data/data/<pkg>/app_webview/` 下的 Cookies、Local Storage、IndexedDB(SQLite 文件,常存 session/token 明文)。此外看 JS Bridge(`addJavascriptInterface` 注册的原生接口)——它常暴露读文件、取设备信息、调原生功能,是 web→native 的桥。
**Q2**: 想利用 JS Bridge 怎么下手?
**A2**: 逆向找注册的接口名和方法(jadx 搜 `addJavascriptInterface`、`@JavascriptInterface`)。若 WebView 加载的 URL 可控(明文 http、可中间人、或有 XSS),就能从 web 侧调用桥方法读本地文件/拿 token。判据:桥方法权限×加载内容可控性=攻击价值。
**Q3**: WebView 加载的是 https 且内容不可控,桥用不了?
**A3**: 转"本地 web 存储直取":不通过桥,直接扒 app_webview 目录下的 Local Storage/Cookies 文件,里面的 session token 往往能直接重放到 web 端。或看 WebView 是否 `setAllowFileAccess`/`setAllowUniversalAccessFromFileURLs` 开了导致 file:// 越权读本地文件。
**Q4**: 这是 Cordova/Ionic 这类纯 Hybrid App?
**A4**: 那整个业务逻辑在 `assets/www/` 下的 JS 里,几乎裸奔:直接读 JS 源码找硬编码密钥、API 端点、鉴权逻辑——比逆向 Java 简单得多。转向"当作前端源码审计"来做。
**Q5**: WebView 本地存储加密、桥有权限校验、内容全 https,web 侧路走不通,转哪?
**A5**: 回到 native 主体:Hybrid 只是外壳,核心加密/凭证可能仍在原生层。转前面的原生 hook/沙盒/Keystore 路线。或转服务端——WebView 加载的后端接口本身也是攻击面。

### 导出组件 / 深链接 / URL scheme 滥用
**Q1**: 我在 manifest 看到 exported 的 Activity/Service/Provider,和本地存储利用有什么关系?
**A1**: 导出组件可能成为"读本地敏感数据的合法通道"。重点看 exported 的 ContentProvider——若它对外提供 App 私有数据(数据库/文件)且无权限校验,任意其他 App(你的恶意 App)可直接查询拿到 token/用户数据,绕过沙盒隔离。
**Q2**: 怎么判断导出组件能榨出什么?
**A2**: 逐类看:导出 Activity 是否接受 Intent extra 控制加载内容(可能注入 URL/参数);导出 Provider 的 `authority` 和它 query 返回的表(直接 content:// 查);导出 Service/Receiver 是否处理不可信 Intent 做敏感操作。判据:exported=true + 无 permission + 处理外部输入=可利用。
**Q3**: URL scheme/深链接怎么利用?
**A3**: 逆向找注册的 scheme(manifest 的 `<data android:scheme>`)和处理逻辑。若深链接参数被用于:加载任意 URL 进 WebView(→XSS/取 token)、拼接文件路径(→路径穿越读本地文件)、触发免鉴权操作,则可构造恶意链接诱导受害者点击。
**Q4**: 组件都加了权限保护/signature 级 permission,直接调不动?
**A4**: 转"降级/间接触发":①找是否有中间组件无保护但能转发到受保护组件;②`grantUriPermission`/`FLAG_GRANT_READ` 临时授权是否可诱导;③signature permission 但 App 签名校验薄弱时结合重打包。或直接放弃组件路,转其他本地存储维度。
**Q5**: 组件攻击面整体无收获,转哪?
**A5**: 转"主动数据读取"到"被动数据捕获":组件是"我去戳 App",若戳不动,就转 hook/沙盒/抓包等"App 自己暴露"的路线。IPC 攻击面枯竭不代表本地数据拿不到,换直接读存储或运行时拦截。

### 日志/剪贴板/临时文件的敏感信息泄露
**Q1**: 主路径卡住了,有没有"顺手捡漏"的低成本本地信息源?
**A1**: 有,先扫三处易泄露点:①logcat(`adb logcat` 过滤包名,开发常打印 token/请求体/密码到日志);②剪贴板(支付/登录场景 App 往剪贴板写敏感串);③临时文件/缓存(`cache/`、`/sdcard/Android/data/<pkg>/` 外部存储里的明文缓存、崩溃日志、导出文件)。
**Q2**: logcat 里怎么高效捞?
**A2**: 触发关键操作(登录/支付/刷新)同时 `adb logcat | grep -iE 'token|auth|passwd|http|secret'`。老版本 App 或未关闭 debug 日志的会直接打印完整请求/响应。判据:release 包若仍有 Log.d 明文输出就是低级泄露,白捡。
**Q3**: App 用了外部存储(SD 卡)存东西?
**A3**: 外部存储无沙盒保护,任意有存储权限的 App 可读。查 `/sdcard/Android/data/<pkg>/` 和根目录下 App 建的文件夹:缓存的图片/文档、导出的报表、明文数据库、下载的配置。这类数据不需要 root 就能拿。
**Q4**: 这些顺手点都没货(日志干净、无外部存储明文),说明什么、转哪?
**A4**: 说明目标 App 卫生做得好,捡漏无效,回主线。这只是低成本旁路,没货就不恋战,转回硬编码逆向或运行时 hook 主路径。别把捡漏当主攻。
**Q5**: 剪贴板/日志泄露拿到片段凭证但不完整?
**A5**: 转"片段拼图":把日志片段(如 token 前半)与其他源(抓包、内存 dump)交叉,拼出完整凭证;或用泄露的片段信息(用户 ID、请求结构)辅助服务端探测。片段本身是线索不是终点。

### adb backup / iTunes 备份提取
**Q1**: 无 root/未越狱,想拿 App 私有数据,备份提取可行吗?
**A1**: 看两个开关。Android 看 manifest `android:allowBackup`——若 true(很多 App 忘了关),`adb backup -f x.ab <pkg>` 能导出私有目录,解包(abe/android-backup-extractor)后翻 shared_prefs/databases 拿明文凭证。iOS 用 iTunes/爱思助手做无加密备份后提取沙盒。
**Q2**: allowBackup=true 但备份出来某些文件没有?
**A2**: 检查是否配了 `fullBackupContent`/backup rules 排除了敏感文件(开发有意排除某些)。被排除的正是他们认为敏感的——转其他方式(run-as、root、hook)专门取那几个文件。排除规则反而给你指了路。
**Q3**: allowBackup=false 备份路被堵,转哪?
**A3**: 转其他免 root 提取:①App 若 debuggable=true,用 `run-as <pkg>` 直接进私有目录;②重打包把 allowBackup 改 true 或加 debuggable 再装(需过签名校验);③退一步上 root/越狱设备。备份只是免 root 提取的一种,不是唯一。
**Q4**: iOS 备份是加密的,提取不了明文?
**A4**: 加密备份需密码。若不知密码,转越狱后直接读沙盒(frida-ios-dump + 直接拷 Documents/Library),或 Keychain dump。加密备份挡住的是"备份文件解析",挡不住"设备上直接读"。
**Q5**: 所有免 root 提取路都失败(allowBackup 关、非 debuggable、无法 root),转哪个正交维度?
**A5**: 放弃"静态拿本地文件落地态",转"运行时拿数据":用免 root 的 frida-gadget 重打包注入(即使不能读文件,能 hook 内存/函数拿到同样的数据)。本地文件读不到,但 App 运行时把这些数据加载进内存的那一刻仍可拦截。

### 客户端加密算法逆向(自研加密协议)
**Q1**: 抓包看到请求体是加密的,想还原明文/伪造请求,从哪切?
**A1**: 目标是拿到算法+密钥+IV。先定位加密收口:hook `Cipher.init`(拿 key/iv/模式)和 `doFinal`(拿明文密文对)是最快的——不用读懂算法,直接拿到密钥参数。若是标准算法(AES-CBC 等),有了 key/iv 就能自己加解密任意数据。
**Q2**: 加密是自研的(非标准 Cipher,一堆位运算)?
**A2**: 转字节码/native 精读或仿真:把加密函数用 unidbg/frida 主动调用当黑盒——喂已知明文看输出,推断变换。若纯客户端可复现(无服务端随机因子),就能离线复刻加解密,进而伪造/篡改任意请求。判据:算法是否只依赖客户端可得的常量。
**Q3**: 密钥每次请求不同(一包一密)怎么办?
**A3**: 找密钥的生成源:通常客户端本地生成随机 key,再用一个"固定的上层密钥"(常硬编码/非对称公钥)加密后随包发给服务端。抠出那个固定上层密钥/私钥逻辑,就能解每包的会话密钥。转向"密钥协商流程"而非单包密钥。
**Q4**: 加密里掺了服务端下发的随机盐/时间戳,离线复刻不出来?
**A4**: 转在线中继:不追求完全离线复刻,而是每次需要时 hook App 让它替你加密(把你要发的 payload 喂给它的加密函数,拿它的输出)。这叫"用 App 当加密预言机",绕开自己复刻算法的难题。
**Q5**: 算法极其复杂+强反调试+native 混淆,逆向彻底卡死,转哪个正交维度?
**A5**: 放弃解密协议,转"更高层攻击面"。加密只保护传输,但明文数据在 UI/内存/加密前函数入参处都存在——hook 业务层拿明文,或直接打服务端的其他非加密接口/逻辑漏洞。传输加密强不代表整个系统安全,绕开它找软肋。

### 内存 dump 提取运行时密钥
**Q1**: 密钥在包里加密/派生,静态拿不到,但运行时肯定明文,怎么从内存捞?
**A1**: 运行时 dump 进程内存搜特征。手段:Frida `Memory.scan`/枚举 ranges 后 dump,或 objection `memory dump all`,或 GDB/fridump。搜索锚点:已知格式(32 位 hex key、`eyJ` JWT、Base64 长串)、已知前后缀、或先 hook 定位大致地址再精读。
**Q2**: 内存太大搜不动/噪音多?
**A2**: 缩小时空范围:在触发加密操作的瞬间(hook 加密函数入口时)dump,此刻 key 刚被加载进内存最易命中;或只扫 App 自身 so/heap 的可读可写段而非全进程。用 hook 定位到 key 所在对象的引用,再顺藤读内存。
**Q3**: 密钥用完立即被清零(内存卫生好),dump 抓不到?
**A3**: 转"使用瞬间拦截"而非"事后 dump":直接 hook 使用密钥的函数(`Cipher.init` 的 key 参数),在它被清零前的那一刻拿到。内存卫生防的是"残留",防不住"正在用的那一刻"。
**Q4**: 是 native 且密钥在 SO 私有堆里,Frida 枚举不到?
**A4**: hook native 分配/使用点:`Interceptor` 挂到解密函数,读它的入参寄存器/栈上的 key 指针。或 unidbg 仿真执行到密钥生成处直接读仿真内存。转 native 级精确拦截。
**Q5**: 内存 dump 整条路都失败(强对抗、清零、native 隐藏),转哪?
**A5**: 转"不需要密钥"的路线:既然拿不到 key,就用"App 当预言机"——让运行中的 App 替你完成需要 key 的操作(加密/签名),你只用它的输入输出。绕过"必须持有密钥"这个前提。

### 版本历史/多版本对比找回退凭证
**Q1**: 当前版本密钥都轮换/加固了,还有别的办法吗?
**A1**: 转时间维度挖旧版本。从第三方 APK 归档站、应用市场历史、CDN 缓存拉多个历史版本。老版本常有:未加固的裸包、已被"修复"删掉但服务端未轮换的硬编码密钥、更弱的加密、暴露的调试端点。diff 新旧 strings/config 找差异点。
**Q2**: 怎么高效对比多个版本?
**A2**: 批量反编译后 diff:比对 assets/config、strings.xml、smali 中的常量、端点列表。重点看"新版删除或加密了什么"——被删的往往就是敏感项,而它在旧版是明文,且服务端凭证未必轮换。
**Q3**: 找到旧版硬编码密钥,但担心早失效了?
**A3**: 直接验活(见凭证验活逻辑)。开发轮换代码里的硬编码,但常忘了在服务端吊销旧凭证(尤其第三方 SDK key、云 AK)。判据:验活成功=服务端没轮换=旧版考古有效。这是极高性价比的旁路。
**Q4**: 拿不到旧版本(全网只有最新版)?
**A4**: 转"包内历史残留":最新包里也可能有历史遗留——注释掉的旧端点、`.bak` 资源、混入的测试证书、git 泄露的痕迹。或转应用的 Web/API 版本找旧接口。
**Q5**: 版本考古无收获,转哪?
**A5**: 回运行时主线。考古是低成本旁路,没货就转动态 hook/内存/抓包。时间维度枯竭,回到空间维度(当前运行态)继续。

### 桌面客户端(Electron/asar)本地存储与硬编码
**Q1**: 目标是 PC 端 Electron 应用,本地存储/硬编码怎么挖?
**A1**: Electron 几乎是"带壳的网页",极易挖。核心是 `resources/app.asar`——用 `asar extract` 解包直接得到 JS/HTML 源码,里面硬编码的 API 端点、密钥、鉴权逻辑基本裸奔。本地数据在 `%AppData%/<app>/` 下(Local Storage、IndexedDB、Cookies、config.json)。
**Q2**: asar 里的密钥被简单混淆/拆分?
**A2**: 前端级混淆很弱:美化(beautify)后读,或直接在 Electron 里开 DevTools(很多没禁用)运行时读变量。或改 main.js 注入代码打印。Electron 的"逆向"难度接近读网页,别用移动端那套重工具。
**Q3**: app.asar 被加密/用了 bytenode 编译成 .jsc?
**A3**: 转运行时:①`--inspect` 挂调试器;②替换/patch main 进程注入代码;③从内存 dump(V8 堆快照)拿明文。bytenode 编译挡静态,但运行时 V8 里仍是明文函数。
**Q4**: 是 .NET/C++ 原生桌面客户端不是 Electron?
**A4**: 换工具链:.NET 用 dnSpy/ILSpy 反编译(常直连数据库,连接串+密码硬编码在配置或代码里,极高价值);C++ 用 IDA/ghidra。本地数据看安装目录、`%AppData%`、注册表(HKCU 下常存凭证)、Windows 凭据管理器。
**Q5**: 桌面客户端硬编码指向数据库/内部服务,是终点吗?
**A5**: 不,是跳板起点。桌面端(尤其 C/S 架构 ERP/OA)常硬编码数据库直连串——直接连库=拿下核心数据+可能通过数据库提权(存储过程执行命令等)横向进内网。转"数据库/内网横向"维度,客户端只是把你送进了服务端后院。

### 反调试/反 Frida 对抗
**Q1**: 一上 Frida/调试器 App 就崩或行为异常,怎么定位对抗点?
**A1**: 先识别检测类型:反调试(`ptrace` 自附加、`TracerPid` 检查)、反 Frida(扫端口 27042、扫内存里 `frida`/`gum` 字符串、检测 `frida-agent` 线程/maps)、反 Xposed/root。抓崩溃前调用栈或 hook 常见检测 API 定位。
**Q2**: 反 Frida 具体怎么绕?
**A2**: 按检测手段对症:改 frida-server 默认端口/进程名;用 Gadget 模式(改名、非标准端口)规避端口扫描;hook `open`/`read` 对 `/proc/self/maps`、`/proc/net/tcp` 的读取过滤掉 frida 痕迹;或用魔改版对抗字符串扫描。
**Q3**: 反 ptrace 反调试怎么处理?
**A3**: hook `ptrace` 让 `PTRACE_TRACEME` 返回成功、让检测 TracerPid 的读取返回 0;或用不依赖 ptrace 的插桩方式。native 反调试则在 IDA 里 patch 掉检测分支。
**Q4**: 对抗做得极硬(多重检测、时间检测、自校验),hook 猫鼠游戏打不赢,转哪?
**A4**: 换战场,不在"有对抗的真机进程里"玩:①unidbg/qiling 仿真执行目标函数——纯净环境无任何反调试触发;②静态硬 patch 后重打包(需过完整性校验);③物理旁路:直接抓包+读落地文件,根本不注入进程。反调试保护"进程内动态",绕到进程外去。
**Q5**: 仿真也因缺环境/复杂依赖跑不起来,彻底卡死,最后转哪?
**A5**: 回退到纯黑盒:只观测输入输出(网络请求/响应、UI 行为、文件变化),用行为差分推断逻辑。放弃拿内部密钥/算法,改在服务端接口层找漏洞。对抗再强也改变不了它对外交互的可观测性。

### 第三方 SDK 硬编码凭证的横向价值
**Q1**: 包里挖到一堆第三方 SDK 的 key(推送、统计、地图、IM、客服),这些值钱吗?
**A1**: 分级看。多数是"设计上就要放客户端"的公开 key(如地图 JS key),价值有限;但有些是 secret 级别(能调管理 API、发全员推送、读用户列表)。判据:该 key 能否调用"管理面/服务端"API 而非仅客户端 SDK。查 SDK 文档区分 client key vs server secret。
**Q2**: 哪些第三方 key 最容易被误放成高危?
**A2**: 推送 SDK 的 MasterSecret/AppSecret(可群发推送做钓鱼/DoS)、IM SDK 的管理密钥(可读写任意会话、拿用户资料)、短信/邮件 SDK 凭证(可发任意短信,消耗+钓鱼)、对象存储 SDK 的完整 AK/SK(见云凭证链)、地图 web 服务 key(可被盗刷)。
**Q3**: 找到 IM/推送管理密钥怎么升级利用?
**A3**: 用它调服务端管理 API:枚举用户、读消息、发消息。这可能直接拿到大量用户数据或做定向社工。转向"第三方后台=另一个服务端攻击面",硬编码只是钥匙。
**Q4**: 这些 key 都是纯客户端公开 key,榨不出管理权限?
**A4**: 转它们的"间接价值":①暴露的 project/app id 帮你摸清目标技术栈和其他资产;②某些 SDK 的调试/配置接口可能越权;③Firebase 类的 config 可能连着可未授权访问的数据库(见后端配置链)。公开 key 也是资产测绘线索。
**Q5**: 第三方 SDK 方向全是低价值公开 key,转哪?
**A5**: 回目标应用自身的凭证:第三方 key 只是旁支,主目标的服务端凭证/端点才是核心。转去挖自研 API 的鉴权、自研加密、自研端点。别在第三方公开 key 上过度投入。

### 后端配置泄露(Firebase / 云函数 / 内部端点)
**Q1**: 包里 grep 出一堆 URL,怎么从里面找到高价值后端?
**A1**: 分类这些端点:生产 API、测试/预发(`test.`/`dev.`/`uat.`——鉴权常更弱)、内部服务(`internal`/内网域名/IP——暴露即高危)、云托管(`*.firebaseio.com`、`*.cloudfunctions.net`、对象存储域名)、第三方回调。优先测试环境和内部端点。
**Q2**: 挖到 Firebase 配置(project id + api key + database url)怎么利用?
**A2**: 试未授权访问:Realtime Database 直接 `https://<project>.firebaseio.com/.json` 看规则是否 `true`(公开可读写);Firestore/Storage 同理试匿名读写;Firebase Auth 的 api key 可尝试匿名注册/枚举。判据:很多 Firebase 因规则配成 `allow read: if true` 导致全库裸奔。
**Q3**: 挖到内部/内网域名或 IP 端点,当前打不通?
**A3**: 记录为"内网横向目标"。这些是资产测绘的金矿:一旦通过其他途径(SSRF、VPN、已入内网)能触达,这些内部 API 常无认证或弱认证。转向"把外部信息喂给内网阶段",客户端硬编码给你画了内网地图。
**Q4**: 端点都是生产环境+强认证,直接打不动?
**A4**: 转"找弱认证的同源资产":测试/预发端点(常与生产共库但认证弱)、老 API 版本(`/v1/` 未下线但无新版校验)、文档/健康检查/actuator 类暴露端点。或用挖到的凭证配这些端点做认证。
**Q5**: 所有端点方向都硬,后端配置榨干无果,转哪?
**A5**: 回客户端-服务端交互的运行时观测:静态端点列表不全,抓包能看到静态没有的真实调用端点和参数结构。转动态抓包补全攻击面,再针对真实流量找逻辑漏洞。

### 客户端到服务端的信任边界穿透
**Q1**: 客户端本地能拿的都拿了(端点、凭证、算法),下一步战略上该怎么走?
**A1**: 明确客户端只是"信任边界的钥匙保管处",真正目标在服务端。把客户端产物转化为服务端攻击弹药:用逆向出的加密算法伪造合法请求、用硬编码凭证认证、用暴露的端点扩面。从"分析设备"正式转入"打服务端"。
**Q2**: 客户端有很多"只有官方 App 能调"的加密/签名保护接口,怎么用起来?
**A2**: 客户端加密/签名的本质是"证明请求来自合法 App",但你已逆向出算法/密钥=你也能生成合法请求。用它构造任意 payload 调服务端接口,此时服务端把你当合法客户端——去打它的越权、注入、逻辑漏洞。客户端保护反而给了你"可信身份"。
**Q3**: 怎么判断服务端是否盲信客户端传来的数据?
**A3**: 测客户端本应校验的东西改到服务端会不会被接受:改价格、改数量、改用户 ID、改权限标志。若客户端本地算好价格直接传服务端且服务端不复核,篡改即生效。判据:"客户端计算/校验、服务端照单全收"=信任边界缺陷。
**Q4**: 服务端校验严格,伪造请求都被拒(签名/时间戳/防重放齐全)?
**A4**: 转"用真实 App 产生的合法请求做变异":不自己伪造,而是抓真实请求后在有效期内做最小篡改重放(改一个业务参数,保留合法签名结构)。或用 App 当签名预言机替你签改后的数据。防重放挡随机伪造,不一定挡"合法请求的微调"。
**Q5**: 服务端整体固若金汤,客户端穿透服务端这条路失败,转哪?
**A5**: 转其他信任边界:①横向到该厂其他 App/Web(常共用后端/SSO,一处凭证通吃);②供应链(第三方 SDK 后台、CI/CD);③社工/内部人员。单个 App→服务端打不穿,就换攻击面,别只盯一个入口。

### 硬编码非对称私钥/证书的利用
**Q1**: 包里发现 `-----BEGIN PRIVATE KEY-----` 或 `.p12`/`.jks`,这比对称密钥更值钱吗?
**A1**: 通常更值钱,且用途不同。判断它是什么私钥:①TLS 客户端证书私钥(mTLS,用于连服务端);②签名私钥(签请求/JWT/更新包);③业务数据加解密私钥。不同用途利用路径不同,先看代码里它被喂给哪个 API。
**Q2**: 是 JWT/请求签名用的私钥,能干什么?
**A2**: 你能伪造任意合法签名的 token/请求。若是 JWT 签发私钥,伪造任意用户/管理员身份;若是请求签名私钥,伪造任意 API 调用通过服务端验签。这是"以合法身份为所欲为"级别的漏洞。
**Q3**: `.jks`/`.p12`/`.bks` 有密码打不开?
**A3**: 密码大概率也在客户端:硬编码在代码里、在同目录 config、或从固定字符串派生。grep keystore 加载处的密码参数,或 hook `KeyStore.load` 拿密码。判据:客户端要用这证书,就必须能拿到密码,你也能。
**Q4**: 私钥用途是软件更新包签名,怎么利用?
**A4**: 高危:能签发恶意更新。若 App 用此公钥验更新包,你用私钥签个恶意包→通过验签→推给用户=供应链投毒/RCE。转向"更新机制"攻击。前提是能劫持更新下发通道(中间人/DNS/服务端)。
**Q5**: 私钥提取到了但服务端已换证/绑定其他因子,单私钥没用,转哪?
**A5**: 转组合利用:私钥配合其他硬编码因子(设备指纹算法、时间戳签名)凑齐完整凭证;或私钥虽换但揭示了签名机制,帮你理解并攻击新机制。或回退到用真实 App 当签名预言机。

### 硬编码凭证的权限/密级判定与止损
**Q1**: 我挖到 5 个疑似凭证,时间有限,先深挖哪个?
**A1**: 按"密级×可达性"排序,别平均用力。密级:能拿服务端管理权/数据库/云主控的 > 单用户 token > 公开 client key。可达性:验活成功且权限大的优先。先花 10 分钟给每个验活+探权限边界,画出价值地图,再 all-in 最高价值的那个。
**Q2**: 怎么快速判断一个凭证的"权限天花板"?
**A2**: 最小探测:云凭证查身份(是主账号还是受限子账号)、token 解析 scope/role、API key 试一个管理动作看放行否。判据是"最坏情况它能造成多大破坏"——据此决定投入。别对一个只读 client key 花几小时。
**Q3**: 高价值凭证探测时触发了目标的告警/风控怎么办?
**A3**: 立即降速并改隐蔽策略:换出口 IP、模拟正常客户端 UA/请求特征、降低频率、避开明显危险动作(批量枚举、删改)。判据:红队要的是"证明可利用"而非"炸醒蓝队"。必要时先固化证据(截图/最小 PoC)再停手。
**Q4**: 所有挖到的凭证验活后全失效/全是低价值公开 key,这个方向枯竭,转哪?
**A4**: 别在死凭证上恋战。转正交维度:①运行时抓"活的"凭证(App 登录后拿到的 session/临时 token 比硬编码的更有效);②转端点/协议逆向找服务端漏洞;③转其他攻击面(Web、其他 App)。硬编码枯竭=转"运行时凭证"或"服务端逻辑"。
**Q5**: 怎么避免陷入"不停挖新凭证但没一个能推进"的死循环?
**A5**: 设判据止损:若连续 N 个凭证都无法转化为"服务端实际权限提升",说明这个 App 的硬编码方向已到顶,该整体换赛道(换目标/换攻击面),而不是继续在同一维度挖第 6、7 个凭证。识别边际收益归零并果断转向。

### 派生密钥/设备绑定凭证的处理
**Q1**: 密钥不是硬编码常量,而是运行时从设备信息(IMEI/androidId/包名/时间)派生的,怎么办?
**A1**: 找派生函数并判断输入可控性。若派生只依赖客户端可获取的稳定输入(包名、固定盐、设备 ID),你就能复现:抠出派生逻辑,在任意环境算出同样的 key。判据:派生的所有输入你是否都能拿到并固定。
**Q2**: 派生逻辑复杂但纯本地,复刻成本高?
**A2**: 别复刻,直接 hook 派生函数的返回值——它算出 key 的那一刻你截获即可。或用 unidbg 仿真调用派生函数喂输入拿输出。运行时拦截永远比静态复刻算法省事。
**Q3**: 派生掺了服务端下发的随机因子(每次不同)?
**A3**: 转"抓下发+当预言机":抓服务端下发随机因子的那次交互;或每次需要时让 App 替你派生。放弃离线固定 key 的想法,转"在线获取每次的有效 key"。
**Q4**: 凭证与设备强绑定(换设备就失效,服务端校验设备指纹),我在自己环境用不了?
**A4**: 转设备指纹伪造:逆向出它上报哪些指纹(hook 采集函数),在你的环境伪造成目标设备的指纹值一致上报。或直接在目标真机/其镜像环境操作。把"设备绑定"转成"设备伪装"问题。
**Q5**: 派生+设备绑定+服务端强校验全齐,离线利用彻底不可行,转哪?
**A5**: 转"就在合法环境里操作":不追求把凭证搬走离线用,而是在已通过所有校验的真实 App 运行态里,hook 业务函数直接执行你要的操作。既然搬不走钥匙,就在门内动手——放弃"提取凭证"改为"劫持已授权会话"。

### 本地 SQLite / 结构化数据库分析
**Q1**: 沙盒里有多个 `.db` 文件,怎么快速判断哪个藏敏感数据?
**A1**: 拉出来用 sqlite 工具直接开,先 `.tables` 看表名:`user`、`account`、`token`、`session`、`message`、`config`、`kv` 这类高价值优先。看列名找 `password`、`token`、`secret`、`cookie`、`phone`、`idcard`。很多 App 把聊天记录、账号、缓存的接口响应明文存 SQLite。
**Q2**: 数据库文件本身被加密(SQLCipher,直接打不开)?
**A2**: SQLCipher 需密钥,而密钥在客户端。转"找 SQLCipher 密钥":hook `SQLiteDatabase.openOrCreateDatabase`/`net.sqlcipher` 的 `openDatabase` 拿传入的 password 参数,或 hook native `sqlite3_key`。拿到 key 后本地用 SQLCipher 工具解开。判据:App 能读库=key 可得。
**Q3**: 想看某条业务数据到底存哪张表?
**A3**: 行为触发定位:操作前后 dump 数据库 diff,新增行所在表即目标。或 hook SQL 执行(`execSQL`/`rawQuery`)打印所有语句,看 insert/update 打到哪张表。
**Q4**: 数据库里字段值是二次加密的(库不加密但单字段密文)?
**A4**: 转字段级解密:找读取该字段后做解密的代码,hook 解密函数拿明文。字段加密的 key 同样在客户端。这退化成前面的"客户端加密算法"问题。
**Q5**: 数据库全加密+字段加密+key 在硬件保护,啃不动,转哪?
**A5**: 转 UI/内存展示层:数据最终要显示给用户,hook 展示前的 getter 或直接从渲染层内存捞明文。数据库怎么加密都防不住"App 自己解密来渲染"。

### React Native 应用的 bundle 与本地存储
**Q1**: 判断是 React Native 应用后,硬编码和逻辑去哪找?
**A1**: 核心在 `assets/index.android.bundle`(打包后的 JS)。它常是明文或仅 minify——直接 grep 端点、apikey、token、鉴权逻辑,和读压缩后的前端 JS 一样。本地存储用 AsyncStorage,落地在 `/data/data/<pkg>/databases/RKStorage`(SQLite)或 files,常明文存 token。
**Q2**: bundle 是 Hermes 字节码(打不开的二进制)?
**A2**: 转 Hermes 反编译:用 hermes-dec/hbctool 把 `.hbc` 反汇编回可读的伪代码/字符串。字符串常量(端点、key)往往仍能直接 strings 提取,逻辑需读 Hermes 汇编。
**Q3**: 想动态 hook RN 的 JS 逻辑?
**A3**: RN 走 JS Bridge 和原生通信,可 hook 原生桥接层(`ReactContextBaseJavaModule` 的方法)看跨语言传的数据,或开 Metro/远程调试(dev 版)。release 版转 Frida hook 底层网络/加密函数。
**Q4**: bundle 加密/拆分、Hermes 也读不动,转哪?
**A4**: 回到"框架无关"的运行时层:不管 JS 怎么打包,最终网络请求走原生 OkHttp/native、加密走标准库——转 hook `Cipher`/网络收口拿明文,以及抓 AsyncStorage 的 SQLite 落地文件。绕开 JS 层直接在原生边界拦截。
**Q5**: AsyncStorage 落地文件也加密了?
**A5**: 转 hook AsyncStorage 读取 API 的返回值(`getItem` 结果),在 JS/桥接层拿解密后明文;或内存 dump。落地加密防不住读取时解密的那一刻。

### 客户端硬编码作为内网/横向的跳板
**Q1**: 客户端逆向出的信息,除了打这个业务后端,还能怎么服务于内网横向?
**A1**: 把客户端当"情报源"看:硬编码里常有内网域名/IP/端口、内部服务名、运维后台地址、数据库连接串、内部 API path、员工/测试账号。这些是内网资产测绘的一手情报,即便当前打不通,进内网后立刻能用。系统性提取归档。
**Q2**: 挖到硬编码的内部服务凭证(如内部消息队列、缓存、数据库账号),当前外网连不上?
**A2**: 标记为"落地内网后的即用弹药"。判据:这些内部服务通常无外网暴露但内网无强认证。一旦有了内网立足点(VPN、SSRF、边界机),这些凭证直接横向。别因为现在连不上就丢弃。
**Q3**: 客户端硬编码了运维/管理后台地址,能直接打吗?
**A3**: 先探可达性和认证强度:很多管理后台图方便挂在能访问的地址且弱口令/默认口令。若客户端还硬编码了后台账号(测试/演示账号)直接试。管理后台一旦进=大范围控制。
**Q4**: 所有硬编码的内部资产当前都不可达,这条内网跳板路暂时断,转哪?
**A4**: 转"先拿立足点再回头用这些情报"。把内网情报存好,回到"如何进内网"的正交问题上:业务后端 RCE、SSRF、VPN 凭证、钓鱼。情报不会过期,先解决可达性。
**Q5**: 硬编码的账号是测试账号,权限低,横向价值有限?
**A5**: 低权账号也是"内网身份":用它认证内部系统后找越权、找它能看到的内部文档/wiki/代码仓(常有更多凭证)、做内部信息收集。低权账号是内网信息收集的合法入口,不是终点。

### 客户端调试后门 / 隐藏配置开关
**Q1**: 我怀疑 App 有开发者留下的调试后门或隐藏功能,怎么找?
**A1**: 搜特征:`debug`、`isTest`、`developer`、`backdoor`、`admin`、`gm`(游戏后台)、`switchEnv`、`bypass` 等标志位;搜隐藏手势/连点触发逻辑;看 BuildConfig.DEBUG 分支里被条件屏蔽的功能。开发常留"内部构建才开"的危险功能,而开关就在客户端可翻转。
**Q2**: 找到 `if(DEBUG)` 保护的调试功能,怎么激活?
**A2**: 翻转开关:hook BuildConfig.DEBUG/isTest 返回 true,或改本地配置,或 patch 条件跳转。激活后可能解锁:环境切换(切到测试后端)、日志详情、跳过鉴权、内部菜单、模拟数据。判据:这些功能设计时假设"只有内部人能触发",翻转后你就是内部人。
**Q3**: 有"环境切换"后门能切 dev/test 后端?
**A3**: 高价值:切到测试环境后,鉴权/风控常更弱,数据可能与生产共享或含真实数据。切过去打测试后端往往比硬刚生产容易得多。这是从"打生产"正交转到"打防护更弱的同源环境"。
**Q4**: 调试后门被服务端二次校验挡住(客户端开了但服务端不认)?
**A4**: 转"后门揭示的攻击面"而非后门本身:后门代码泄露了内部接口路径、参数格式、特殊 header——即使功能被服务端拦,这些情报可用于直接构造对服务端的攻击。后门是地图,不一定是门。
**Q5**: 找遍没有调试后门,这条路空,转哪?
**A5**: 回主线的硬编码/运行时路径。后门是运气型旁路,没有就算了。转回系统性的凭证挖掘和服务端穿透,别执着于"一定有后门"。

### iOS 目标:砸壳与沙盒取证的特殊路径
**Q1**: 目标是 IPA(iOS),和 Android 相比第一步有什么不同?
**A1**: iOS App Store 包有 FairPlay 加密(可执行段密文),静态直接反汇编看到的是密文,必须先"砸壳"脱 DRM。判据:先确认包来源——越狱设备砸壳(frida-ios-dump/dumpdecrypted 运行时 dump 解密后 Mach-O)是主路;拿到解密后的二进制再 class-dump/Hopper/ghidra 分析。企业签/开发包可能未加密可直接分析。
**Q2**: 没有越狱设备怎么砸壳/分析?
**A2**: 转替代:①用已越狱环境或云真机砸壳后拿解密 IPA;②只做静态字符串/资源分析(`Payload/App.app` 里的 plist、bundle 资源、embedded provisioning、`.storyboard` 常有硬编码线索,这部分不加密);③frida-gadget 免越狱重签注入(需重签名和 sideload)。判据:能拿解密二进制才谈完整逆向,否则先榨明文资源。
**Q3**: iOS 本地敏感数据都藏哪,和 Android 对应关系?
**A3**: 沙盒 `Documents/`、`Library/Preferences/*.plist`(对应 SharedPreferences,常明文)、`Library/Caches`、本地 `.sqlite`(Core Data)、`Library/Cookies`;凭证在 Keychain(对应 Keystore,但 keychain-dumper 可整体导出)。iOS 的 Keychain 往往比 Android Keystore 更容易被整体 dump。
**Q4**: App 有越狱检测,砸壳/分析环境一起就闪退?
**A4**: 转越狱隐藏:用 Liberty/Shadow/A-Bypass 这类隐藏越狱特征,或 hook 检测函数(`fork`/`stat` 对 `/Applications/Cydia.app`、`/bin/bash` 等路径的检测)。原理同 Android root 检测绕过——先净化环境再作业。
**Q5**: iOS 目标越狱检测极硬、无可用越狱设备,这条 iOS 逆向路走不通,转哪?
**A5**: 转"平台无关"的服务端边界。同一业务的 iOS/Android/Web 通常共用后端——转去逆向更易搞的 Android 版或直接抓 Web 端,拿到端点和协议后,服务端漏洞与客户端平台无关。绕开难啃的 iOS 客户端,从同源软目标进服务端。

### 抓包看到加密流量,但目标是伪造/篡改请求
**Q1**: 我能抓到加密请求了,但要的是能改参数重放,不只是看,怎么推进?
**A1**: 先定位加密边界:请求是整体加密还是仅签名(明文+sign 字段)。若是明文+签名,只需复现签名算法就能改参数;若是整体加密,需拿加解密能力。先判类型再定策略,别一上来就啃最难的整体加密。
**Q2**: 是"参数明文 + sign 字段"型,签名算法怎么复现?
**A2**: hook 生成 sign 的函数(常是 `参数排序+拼接+固定salt+MD5/HMAC`)拿到算法和 salt。复现后即可任意改参数重新算 sign 提交。判据:salt/密钥在客户端可得=签名可伪造=服务端验签形同虚设。
**Q3**: 不想复现算法,有没有更快的路?
**A3**: 用"App 当签名/加密预言机":搭个中间层,把你要发的改后 payload 喂给 hook 住的 App 加密/签名函数,拿它的输出再提交。适合算法太复杂、只需少量请求的场景。牺牲自动化换省事。
**Q4**: 签名里掺了服务端下发的会话因子或时间戳,离线改包过不了验签?
**A4**: 转"在有效期内的实时中继":用 mitmproxy 脚本挂 App 实时签名,或让 hook 后的 App 在时间窗内即时生成。时间戳/会话因子挡"离线批量伪造",挡不住"实时借 App 之手签名"。
**Q5**: 加密+签名+防重放+设备绑定全上,伪造请求这条路彻底走不通,转哪?
**A5**: 转"不伪造,只重放真实请求找逻辑漏洞":用 App 正常操作产生真实合法请求,在其中找越权(改个 ID 服务端放行)、竞态、数量/价格未复核。或转服务端其他弱防护接口。防伪造挡不住"合法请求本身暴露的服务端逻辑缺陷"。
