# 提权立足点 · 拿到立足点后的第一轮内网信息收集

### 拿到一个 shell 先别急着提权:判定这是什么身份、什么环境
**Q1**: 我刚打进一个 shell,手指痒想直接 sudo -l 或跑提权脚本。第一步到底该干嘛?
**A1**: 先做"三问自检"。一问我是谁(id/whoami、uid、gid、所属组);二问这是什么(容器/虚机/物理机/WSL,判据:/.dockerenv、/proc/1/cgroup 里的 docker/kubepods、hostname 是否随机 hash);三问 shell 稳不稳(半交互?会掉?有超时 kill?)。顺序错了会浪费机会——在 5 秒回收的 webshell 里跑交互式提权必然半途而废。
**Q2**: 怎么快速判断是容器还是真机?
**A2**: 组合判据:根有 /.dockerenv 或 /run/.containerenv;/proc/1/cgroup 出现 docker/lxc/kubepods;PID 1 是应用而非 systemd/init;网卡只有 eth0+lo 且是 172.17/10.x;mount 大量 overlay。命中两条以上基本可判容器。
**Q3**: 如果是容器,信息收集重心和真机有何不同?
**A3**: 重心转向"逃逸面"而非"本机提权":有没有挂载宿主目录(/host、/mnt)、是否 privileged(能否 mount、cap 是否齐全)、docker.sock 是否可见、K8s serviceaccount token 是否存在。容器里本地提权多半没意义,除非要抢某个 cap。
**Q4**: 环境是极简容器,没 id 没 mount 没任何工具,这条路被墙了怎么办?
**A4**: 转向"带资源进来"维度:先解决武器投送,用自带静态 busybox/nsenter 恢复观测能力。观测不到不等于没有面,是工具不够,先补工具再判定。
**Q5**: shell 不稳每次收集都断,如何止血?
**A5**: 优先把不稳 shell 升级成稳定通道:全 TTY(python pty/script/socat)或落更可靠的 C2 beacon。把"通道稳定性"当第一轮的前置基础设施,而不是边收集边掉线硬扛。

### 权限维度先定性:普通用户 / 服务账户 / 已是 root 或 SYSTEM
**Q1**: id 出来是个普通低权用户,精力放哪?
**A1**: 目标是"本机纵向提权到 root/SYSTEM",围绕提权向量收集:sudo -l、SUID/SGID、可写的高权限进程配置、内核版本对已知本地提权的暴露面、以 root 执行且当前用户可写的计划任务。低权阶段别过早铺横向,先站稳。
**Q2**: 如果落地就已是 root/SYSTEM,是不是跳过提权?
**A2**: 是,直接进"变现与横向":抓凭据(Linux:shadow/ssh key/history/配置明文;Windows:lsass/SAM/DPAPI/浏览器)、建持久化、开始横向。最高权限还纠结提权是浪费窗口。
**Q3**: 身份是服务账户(www-data、mysql、某 app 专用),有何特殊思路?
**A3**: 服务账户常对某类资源有超额权限:DB 账户可能能读全库/写文件/UDF 提权;web 账户能读到配置里的 DB 口令和 API key;备份账户可读整盘。判据是"这账户为谁服务",顺职责找被赋予的过量权限。
**Q4**: Windows 服务账户发现有 SeImpersonate/SeAssignPrimaryToken 特权怎么办?
**A4**: 明确信号,转向 Potato 家族(令牌窃取类本地提权),直接抬到 SYSTEM。所以 whoami /priv 是 Windows 第一轮必收,特权列表比用户名更能决定路线。
**Q5**: 账户既非 root 也没明显提权面,sudo -l 要密码、无 SUID 可用,像死路,往哪转?
**A5**: 转向"横向换更好身份":与其死磕这台机纵向,不如用当前身份侦察它能碰到的其它主机/服务,拿凭据换一台提权面更大的机器落脚。提权卡死时,横向常是解药。

### 掌握地形:网络位置、网卡、路由、这台机是不是双网卡跳板
**Q1**: 站稳后怎么快速搞清"我在网络哪个位置"?
**A1**: 收集 ip a/ipconfig /all、路由表、ARP 缓存、DNS 配置。核心判据是网卡数与网段:单网卡是普通节点;多网卡且分属不同网段说明是跨网边界跳板,价值极高,重点保护利用。
**Q2**: 发现第二块网卡指向外面碰不到的内网段,下一步?
**A2**: 立即规划把这台机做 pivot(socks/端口转发/VPN over C2),让后续工具穿透隐藏网段。第一轮里"发现新网段"优先级高于本机继续挖,它决定整个战役纵深。
**Q3**: ARP 表和路由表还能告诉我什么?
**A3**: ARP 邻居暴露同段活跃主机(比全网扫隐蔽);路由条目暴露这台机知道怎么去的网段(哪怕当前不通),是横向候选清单;DNS 服务器地址往往就是域控或核心 DNS,是高价值定位线索。
**Q4**: 想扫内网存活主机,直接上 nmap 全网段大扫行吗?
**A4**: 谨慎。大范围高速扫描最响,极易触发 IDS/NDR 暴露立足点。先用低噪手段:ARP 邻居、netstat 已有连接、hosts、known_hosts、历史命令里出现过的 IP。确需主动扫时窄范围、低速率、只探关键端口。
**Q5**: 主动扫触发告警、蓝队联动,连接快保不住了,怎么转?
**A5**: 转向"降噪+换情报源":停掉主动扫描,切纯被动情报(本机日志、配置、缓存、令牌),用已抓凭据做"认证式横向"(带票直连,像正常访问),而不是靠端口扫描发现目标。噪声路被墙就走凭据路。

### 内核 / 补丁定性:能不能吃现成的本地提权
**Q1**: Linux 低权用户,想知道内核提权有没有戏,从哪判?
**A1**: 先取 uname -a、/etc/os-release、架构;再对照已知本地提权(脏牛类、pkexec/polkit 类、overlayfs、nftables、内核 UAF 等)的影响区间。判据是"版本落在漏洞窗口+相关组件存在"。别盲跑 exp,先版本匹配减少崩内核风险。
**Q2**: 怎么知道打没打补丁 / 缓解开没开?
**A2**: Linux 看内核加固、pkexec/polkit 是否被移除、相关 sysctl(如 unprivileged_userns_clone)是否被关;Windows 用 systeminfo 补丁列表配合已知 KB 做差集。缓解开着现成 exp 大概率失败,得换向量。
**Q3**: 找到疑似可用内核 exp,该直接在目标现编现跑吗?
**A3**: 尽量不现编。目标可能没编译器、编出崩内核重启丢立足点、留痕多。优先本地同版本编静态二进制再投送;必须现场先评估目标是否生产核心机(崩了动静巨大)。内核 exp 是最后手段而非首选。
**Q4**: 内核版本太新/全打补丁/缓解全开,内核提权彻底没戏,往哪转?
**A4**: 转向"配置错误类提权"这个正交维度:内核路封死时,90% 的真实提权其实来自配置面——sudo 规则、SUID 二进制的 GTFOBins 用法、可写 service/cron、弱文件权限、密码复用。放弃 exp 走"人配错了什么"。
**Q5**: 配置面也很干净,一台加固到位的机器,还能怎样?
**A5**: 再转"凭据复用+横向":加固好的单机往往不是被本机提权拿下,而是被别处泄露的口令/密钥/票据横向打穿。把这台当情报源和跳板,而非非要在它身上提权。

### SUID/SGID/Capabilities 面枚举与利用判读
**Q1**: 我要系统性找 Linux 本地提权面,SUID 该怎么收集和判读?
**A1**: find / -perm -4000 -type f 2>/dev/null 列 SUID,-2000 列 SGID。拿到清单先剔标准系统件(passwd、sudo 等),重点看非常规/自定义/带版本的二进制。判据:能否用 GTFOBins 里该程序的 SUID 用法读写文件或起 shell。
**Q2**: 清单里全是标准系统二进制,没自定义的,是不是没戏?
**A2**: 不一定。标准件也可能因旧版本可利用(如某些 pkexec/fusermount/其它)。逐一比对版本;另外别忘 capabilities:getcap -r / 2>/dev/null 找带 cap_setuid、cap_dac_override 等能力的程序,这类容易被忽视。
**Q3**: 找到一个自定义 SUID 程序但不知它内部干嘛,如何分析?
**A3**: strings/ltrace/strace 看它调了什么:是否用相对路径调外部命令(PATH 劫持)、是否 system()/popen 拼接、是否读某个当前用户可写的配置。判据是"它信任了某个我能控制的输入"。
**Q4**: PATH 劫持思路——什么条件下才成立?
**A4**: 该 SUID 以相对路径(非绝对路径)调用外部命令,且未重置 PATH。成立则在可写目录放同名恶意程序并前置 PATH。若它用绝对路径或清了 PATH 就不成立,别浪费时间。
**Q5**: SUID/cap 全都利用不了,这条本地面被墙,转哪?
**A5**: 转向"进程与计划任务面":ps aux 看有没有 root 进程周期性执行可写脚本、有没有以 root 跑的服务读可写配置。SUID 静态面之外,动态执行面是另一大类提权来源。

### sudo -l 的深挖:不止看能不能免密
**Q1**: sudo -l 能跑(免密或知道密码),我该怎么读这个输出?
**A1**: 逐条看允许的命令:是否 NOPASSWD、是否带通配符、是否允许以 root 跑某个可被 GTFOBins 逃逸的程序(vi/less/awk/find/tar/systemctl 等)。判据是"这条 sudo 规则能不能被撬成任意命令执行"。
**Q2**: 允许我 sudo 跑某个看似无害的自定义脚本,怎么办?
**A2**: 读脚本内容:它是否调外部命令(可 PATH/参数注入)、是否处理我能控的文件、是否有 root 写我可读目录。无害脚本常因内部实现被撬。读不了脚本内容时,看它的行为(strace)。
**Q3**: sudo 版本本身有没有可利用点?
**A3**: 记录 sudo --version,对照已知 sudo 漏洞窗口(如某些 sudoedit/参数解析类)。即便 sudo -l 什么都不给,某些漏洞也能绕过。版本匹配上就试对应向量。
**Q4**: 规则里有 LD_PRELOAD/LD_LIBRARY_PATH 相关的 env_keep 怎么读?
**A4**: 大信号:若 sudo 保留了 LD_PRELOAD 且允许跑某程序,可用恶意 .so 提权。检查 Defaults env_keep 列表和 secure_path 是否宽松。这是配置错误型提权的经典点。
**Q5**: sudo -l 要密码而我没有,或明确 not allowed,这条死了,转哪?
**A5**: 转向"拿这个用户的密码"或"绕开 sudo":翻 history/配置/浏览器/密钥找该用户口令(常有复用),或彻底放弃 sudo 走 SUID/cron/内核面。sudo 只是提权的一条腿,不是唯一。

### 计划任务 / cron / 服务:动态执行面的提权
**Q1**: 我想找周期性以高权限执行、且我能干预的东西,从哪看?
**A1**: Linux:/etc/crontab、/etc/cron.*、各用户 crontab、systemd timer;Windows:schtasks /query /fo LIST /v、计划任务里以 SYSTEM/管理员运行的任务。判据是"高权限周期执行 + 执行目标或其路径我可写"。
**Q2**: 发现一个 root cron 调某脚本,我没写权限,但脚本目录我能写,有戏吗?
**A2**: 有——若脚本用相对路径调命令、或 cron 的 PATH 含可写目录、或脚本被通配符 tar/加载了可写的 include。别只看脚本本身权限,要看它依赖链上每一环的权限。
**Q3**: 没有明显 cron,但怀疑有隐藏定时任务,怎么发现?
**A3**: 用进程监控法:pspy 类工具无 root 也能看到周期性新进程,暴露看不见的 cron/timer 和它们的完整命令行。这能发现配置文件里翻不到的任务。
**Q4**: Windows 上想找可被劫持的服务,看什么?
**A4**: 看服务二进制路径是否可写(可替换)、是否 unquoted service path(带空格且路径段可写)、服务注册表 ImagePath/DACL 是否弱、以 SYSTEM 运行。这些是 Windows 本地提权高频点。
**Q5**: 所有计划任务/服务权限都很紧,动态面被墙,转哪?
**A5**: 转向"凭据面":动态执行面封死时,回到抓这台机上缓存的凭据(内存、配置、票据),用别人的高权身份代替本机提权。执行面和凭据面是两条正交的提权路。

### Linux 凭据搜刮:配置、历史、密钥里的明文与复用
**Q1**: 拿到普通/服务账户,想快速捞凭据,先翻哪里?
**A1**: 优先级:~/.bash_history 及各类 history、~/.ssh(私钥/known_hosts/config)、应用配置(DB 连接串、.env、web 配置、CI 配置)、/var/www 下源码里的硬编码口令、备份文件(.bak/.old/.swp)。判据是"哪里最可能有人写死了口令"。
**Q2**: history 里看到别人用明文密码登过东西,怎么用?
**A2**: 记下来做"密码喷洒/复用":内网口令复用率极高,一个 DB 口令常等于某用户 SSH 口令等于域账户口令。把捞到的每个口令都当横向和提权的钥匙,试到多个目标上。
**Q3**: 找到 SSH 私钥,怎么最大化价值?
**A3**: 看 known_hosts 和 config 知道这钥匙开哪些主机(known_hosts 若未哈希直接给主机名/IP,是横向地图);私钥若无密码直接用,有密码则尝试离线爆破 passphrase。私钥+known_hosts 常能一串横向。
**Q4**: 配置文件都规范、无明文口令,凭据搜刮扑空,转哪?
**A4**: 转向"内存与运行态":配置里没有,不代表内存里没有——数据库/应用进程内存、环境变量(/proc/PID/environ)、进程命令行(ps 里的 -p password)常泄露运行态凭据。静态翻不到就翻动态。
**Q5**: 还想扩大凭据面,有没有系统级的地方?
**A5**: 看是否有集中认证泄露:/etc/shadow(有读权就离线爆)、Kerberos keytab、云凭据(~/.aws、~/.config/gcloud)、容器/编排的 secret 挂载、git 仓库历史里的密钥。凭据搜刮要覆盖"个人、应用、系统、云"四层。

### Windows 凭据抓取:lsass / SAM / DPAPI / 浏览器
**Q1**: Windows 上拿到管理员/SYSTEM,凭据从哪抓,顺序?
**A1**: 先 lsass(内存明文/hash/票据,mimikatz/comsvcs dump/nanodump),再 SAM+SYSTEM 注册表(本地账户 hash),再 DPAPI(保存的凭据、浏览器口令),再 LSA secrets(服务账户口令)。判据是"从内存活跃凭据到落盘凭据逐层扫"。
**Q2**: 直接碰 lsass 被 EDR 拦了怎么办?
**A2**: 换取证方式:不用经典 mimikatz 特征,改用系统自带 comsvcs.dll MiniDump、或 PPL 绕过、或直接把内存 dump 拖回本地离线解析,减少在目标上跑敏感操作的特征面。抓 lsass 被拦是"手法"被拦,不是"目标"没了。
**Q3**: lsass 完全动不了(PPL+EDR+RunAsPPL),转哪抓?
**A3**: 转离线/落盘凭据:SAM/SYSTEM/SECURITY 注册表 hive(reg save 后离线解)、DPAPI masterkey+浏览器凭据库、计划任务/服务里存的凭据、GPP cpassword、以及各类配置文件明文。lsass 只是众多凭据源之一。
**Q4**: 抓到的是 NTLM hash 不是明文,能干嘛?
**A4**: 直接 Pass-the-Hash 横向,或离线爆破还原明文(明文能喷洒更多协议)。别因为不是明文就丢——hash 在 NTLM 认证里等价于口令。
**Q5**: 抓到 Kerberos TGT/TGS 票据,怎么用?
**A5**: Pass-the-Ticket:导入票据直接以该用户身份访问服务,绕过口令。TGT 可请求任意服务票,价值高于单个 TGS。票据有时效,抓到尽快用。

### 判定是否加域:单机战 vs 域渗透,两套完全不同的打法
**Q1**: 拿下一台 Windows,怎么第一时间判断它在不在域里?
**A1**: 看 systeminfo 的 Domain 字段、whoami /fqdn、nltest /dsgetdc、环境变量 USERDNSDOMAIN、能否解析域 SRV 记录。判据:有域=进 AD 渗透打法;工作组=当单机+本地凭据横向打法。这个岔路决定后续整套战术。
**Q2**: 确认在域里,第一轮该收集哪些域信息?
**A2**: 域名/域控地址、当前用户在域里的组、域内用户/计算机/组清单、SPN、信任关系、GPO。工具上先低噪的原生命令(net、nltest、setspn、PowerShell AD 模块),再考虑 BloodHound 收集器。
**Q3**: 在域里但当前是本地账户(非域账户),还能做域侦察吗?
**A3**: 能,只要网络可达域控且有任一有效域凭据。若手里只有本地账户,先想办法拿一个域账户(抓缓存的域凭据、域用户登录过的票据)。没域身份时域枚举受限,先解决"有没有域票"。
**Q4**: 判定为工作组/非域机器,思路怎么变?
**A4**: 转单机+本地凭据复用:没有 AD 这张大网,横向靠本地管理员 hash 复用、SMB/RDP 口令喷洒、共享枚举。别去找域控和 Kerberos,那些在工作组里不存在。
**Q5**: 域枚举一动就触发告警(蓝队盯着 LDAP 异常查询),被墙了怎么转?
**A5**: 转"低噪 + 定点"域侦察:放弃 BloodHound 全量拉取,改用精准的单点查询(只查我需要的那个用户/那条 ACL),或用已有的正常管理流量掩护,或干脆基于已抓票据做认证横向而不做大范围枚举。全量枚举被墙就走定点情报。

### 域内攻击面梳理:BloodHound 视角找最短提权路径
**Q1**: 域枚举数据到手,怎么从一堆对象里找"到域管的最短路径"?
**A1**: 用 BloodHound 类图分析:以当前身份为起点,找到高价值目标(域管、DC)的 ACL/组成员/会话路径。判据是"哪条边是我能实际控制的"(如我对某对象有 GenericWrite、某高权用户在我能拿的机器上有会话)。
**Q2**: BloodHound 收集器太响或被 EDR 拦,拿不到全量图怎么办?
**A2**: 转手动定点枚举替代:不需要全图,只需回答几个关键问题——谁是 DA、哪些机器有 DA 会话、我对哪些对象有写权限、有哪些可 Kerberoast 的 SPN。用原生 LDAP 查询逐个回答,拼出局部路径即可。
**Q3**: 图里显示我离域管还很远,没有直接边,怎么推进?
**A3**: 找"中转跳板身份":沿图找我一步能拿到的中等权限账户/机器,拿下后重新以它为起点算路径。域渗透是多跳的,别指望一步到 DA,每拿一个身份就重算最短路。
**Q4**: 发现一条路径依赖"某高权用户在某机器上有活跃会话",怎么利用?
**A4**: 拿下那台机器,抓它内存里该用户的票据/凭据(Pass-the-Ticket/Hash),即可窃取到该高权身份。会话即凭据,有会话的机器是高价值中转点。
**Q5**: 所有路径都卡在某个我拿不下的强化机器上,域内推进被墙,转哪?
**A5**: 转"证书/委派/信任"等结构性向量:换个正交攻击面——ADCS 证书模板错配(ESC 系列)、Kerberos 约束/非约束委派、域信任关系跨域打。ACL 路径走死时,AD 的证书与委派体系常是另一条通天路。

### 半交互 shell 升级为全功能交互 TTY
**Q1**: 反弹到一个 shell 但不能用 Ctrl-C、不能 sudo、tab 不补全,怎么升级?
**A1**: 标准升级链:python3 -c 'import pty;pty.spawn("/bin/bash")' 起 pty,然后 Ctrl-Z 回本地 stty raw -echo 再 fg,回到目标 export TERM=xterm、设 stty rows/cols。判据是升级后能跑 sudo、能用交互程序、Ctrl-C 不断连接。
**Q2**: 目标没有 python 怎么升级 TTY?
**A2**: 换等价工具:script -qc /bin/bash /dev/null、socat 双端 pty、或用 expect/perl/其它脚本语言起 pty。判据是"能不能拿到一个真 pty",工具不唯一。
**Q3**: 为什么非得升级 TTY,不升级会卡在哪?
**A3**: 不升级时:sudo 会报 no tty、交互式提权(输密码/确认)失败、Ctrl-C 会直接杀掉整个反弹连接、很多交互程序(vi/ftp/ssh)不可用。第一轮很多提权动作依赖交互,不升级等于自断手脚。
**Q4**: 升级过程中一不小心把连接搞断了,反复断,怎么稳?
**A4**: 转向"先落持久稳定通道再升级":与其在脆弱反弹上折腾,不如先用这个脆弱 shell 落一个正规 C2 beacon 或 autossh 反连,拿到稳定通道后在稳定通道里做 TTY 升级和后续所有操作。
**Q5**: 环境限制极严(受限 shell rbash、没常用二进制),升级被墙,转哪?
**A5**: 转"逃逸受限 shell"这个专门维度:找 rbash 的逃逸点(带 shell 逃逸的程序、PATH 未锁死、能改环境变量),或换一条完全不同的立足方式(如通过服务/计划任务拿一个非受限的执行上下文)。

### 无出网 / 离线环境下的武器投送
**Q1**: 目标不能连我这边(无出网),我需要的工具传不进去,怎么办?
**A1**: 先精确判定出网面(见下条),确认真无出网后转"就地取材+现有通道投送":用已有的 C2/隧道上传、用目标已存在的工具(certutil、curl、wget、bitsadmin、python、powershell 下载),或走 SMB/内网可达的中转机分发。
**Q2**: 目标连编译器、脚本解释器都没有,怎么带能力进去?
**A2**: 用静态编译二进制:本地把工具静态编成目标架构(注意 arch 匹配),通过现有通道落地,不依赖目标环境。判据是"我的工具不依赖目标任何运行时"。
**Q3**: 落盘就被 AV 秒删,工具活不过三秒,怎么办?
**A3**: 转"无文件/内存投送":不落盘,直接内存加载(reflective load、fileless、把 payload 塞进已授信进程)。或先做免杀/去特征再落。落盘被杀是"落盘"这个动作的问题,换内存执行绕开它。
**Q4**: 内网里有一台机能出网、目标机不能,怎么用?
**A4**: 把能出网的机器做分发中转:工具先到中转机,再经内网通道(SMB 共享、HTTP、内网 socks)分发到隔离目标。第一轮里"谁能出网"是关键地形情报,专门标记出来。
**Q5**: 什么通道都建不起来(极度隔离、纯单向命令回显),投送彻底被墙,转哪?
**A5**: 转"纯 living-off-the-land":放弃投送任何外部工具,只用目标自带二进制完成信息收集和提权(系统命令、内置脚本引擎)。极端隔离时,自带工具是唯一武器,能力从工具转向对系统原生命令的熟练度。

### 出网检测:摸清这台机能怎么和外面说话
**Q1**: 我想知道立足点能不能出网、怎么出网,该怎么系统性测?
**A1**: 分协议逐一测:DNS 外带(几乎最常通)、HTTP/HTTPS 直连、经代理出网、ICMP、常见端口(80/443/53)出站。判据是"哪种协议、哪个端口、要不要代理能到我控制的外部资产"。别只测一种就下结论。
**Q2**: 直连不通,但内网有代理服务器,怎么判断和利用?
**A2**: 找系统/浏览器/环境变量里的代理配置(http_proxy、PAC、WPAD、注册表 ProxyServer)。企业网出网常强制走代理,拿到代理配置就能借它出网。代理信息本身也是第一轮该收的情报。
**Q3**: 只有 DNS 能出去,能做什么?
**A3**: 用 DNS 隧道做 C2 和数据外带:慢但极难封。判据是能否解析我控制域名的任意子域。DNS 出网是"看起来什么都不通"环境里最后的生路,优先测它。
**Q4**: 全协议出网都被墙(真正的隔离段),C2 建不了,转哪?
**A4**: 转"内网中继回连":不直连外网,而是把流量经内网里另一台能出网的机器多级中转出去(pivot 链)。出网能力可以是"借来的",不必是本机自己的。
**Q5**: 出网测试本身会不会暴露我?
**A5**: 会——反复往外打各种端口/协议是明显信标,可能触发出站告警。所以要节制:先看被动线索(现有配置、已有出站连接 netstat)推断出网方式,再最小化主动测试,别把出网探测做成扫描。

### AV/EDR 识别:动手前先知道谁在盯着
**Q1**: 落地一台机,动提权/抓凭据前,怎么先摸清防护?
**A1**: 枚举安全产品:进程/服务里的 AV/EDR 特征(常见厂商进程名)、已安装的安全软件目录、Windows Defender 状态(Get-MpComputerStatus)、内核驱动列表、是否有 EDR 的 minifilter。判据是"我接下来的动作会不会撞在它枪口上"。
**Q2**: 确认有 EDR,我的操作策略要怎么变?
**A2**: 从"能跑就跑"转向"每个动作先估特征":避开高特征命令(经典 mimikatz、明显的 whoami /all 组合、大范围枚举脚本),优先原生命令、内存操作、拆分动作降低关联。有 EDR 时慢即是快。
**Q3**: 怎么判断 EDR 是纯本地拦截还是会上报云端联动?
**A3**: 看有没有外连的 EDR 云通道、是否 SOC 值守时段。保守假设"一定上报",按会被人复盘的标准操作。判据宁可高估对手,低估会导致立足点被连根拔。
**Q4**: 我的核心工具被 EDR 直接拦死,提权动作做不了,转哪?
**A4**: 转"换手法而非换目标":同一目标(如抓 lsass)有多种技术路径,被拦的是某条路径的特征。换低特征实现、换无文件方式、换先 dump 后离线解析。也可先做 EDR 致盲/绕过再操作。
**Q5**: EDR 太强,任何敏感操作都难,是不是该放弃这台?
**A5**: 不一定放弃,而是转"把它降级为纯情报/跳板":不在这台强防护机上做危险动作,只用它做低风险侦察和网络中转,把提权和抓凭据的活挪到防护弱的邻居机上做。选阻力最小的机器动手。

### 持久化时机:什么时候埋、埋在哪一层
**Q1**: 刚站稳,要不要马上做持久化?
**A1**: 分层看。先在当前权限下留一个低调的"保命通道"(哪怕不高权),防止唯一入口丢失;但重活(高权持久化)等提权稳了再做。判据:入口越单一,越要尽早留冗余;权限越低,持久化价值越有限。
**Q2**: 持久化方式怎么选才不容易被发现?
**A2**: 选和环境融合的:优先复用系统已有机制(合法的计划任务风格、服务、启动项、SSH authorized_keys、web 的合法路径),避免独创的显眼后门。判据是"蓝队做基线对比时这条会不会跳出来"。
**Q3**: 高权持久化(域级)什么时候做、注意什么?
**A3**: 拿到域管等高权后,做少量隐蔽的域级持久(如票据类、证书类、特定账户 ACL),但要克制——埋得越多被发现概率越高。判据是"用最少的持久化换最大的重进入保障"。
**Q4**: 我埋的持久化被清了 / 立足点还是丢了,怎么办?
**A4**: 转"多样化冗余"思路:不要把所有持久化押在同一机制/同一台机。应在不同主机、不同层(用户态/服务/凭据/证书)分散埋点,一处被清仍有别处能重进。丢失说明单点冗余不足,补冗余。
**Q5**: 到底该先提权还是先持久化,资源有限只能选一个先做?
**A5**: 看入口稳定性决定顺序:入口极不稳(随时掉)→先留最低限度保命通道再提权;入口稳固→先提权拿到更高权限再做更牢的持久化。别机械二选一,按"哪个先丢损失最大"排序。

### 数据库账户落脚:从 DB 权限撬本机与横向
**Q1**: 我拿到的是数据库账户(能连 DB 但还没系统 shell),怎么升级到系统层?
**A1**: 顺 DB 的能力找出口:能否写文件(导出 webshell 到 web 目录)、能否读文件(读配置/密钥)、能否执行系统命令(UDF、xp_cmdshell 类、扩展)。判据是"这个 DB 账户被授予了哪些越过数据边界的能力"。
**Q2**: DB 账户是高权(如 DBA 级),优先做什么?
**A2**: 高权 DB 账户往往能直接命令执行或加载扩展提权到 DB 服务账户权限(常是较高的系统权限)。同时 dump 库里的凭据表(应用用户、其它系统对接口令),库里的口令是横向金矿。
**Q3**: DB 账户权限很低,只能读某几张表,还有价值吗?
**A3**: 有——库里的业务数据/口令 hash/token 本身可能就是目标或横向燃料。低权 DB 也先把能读的凭据类数据捞干净,再考虑权限提升。数据即战果,不是只有 shell 才算。
**Q4**: 想写 webshell 但不知道 web 目录绝对路径,怎么办?
**A4**: 从 DB 侧或已有信息推断路径:读配置表、看报错泄露路径、试常见路径、用 DB 读系统文件反推 web 根。路径未知时,写文件类提权卡在"写哪",先解决定位。
**Q5**: DB 无写文件、无命令执行、被沙箱化,DB 提权路被墙,转哪?
**A5**: 转"用 DB 里捞到的凭据横向":即便撬不动本机系统,库里的口令/密钥拿去打其它系统(密码复用)往往一击即中。DB 落脚点的价值一半在系统提权,一半在它存的凭据。

### Web 目录 / 源码 / 配置:立足点脚下的情报金矿
**Q1**: 我从 web 服务打进来,除了当前 shell,脚下还有什么可挖?
**A1**: 系统翻 web 根及应用目录:配置文件(DB/缓存/消息队列/第三方 API 凭据)、源码里的硬编码密钥、上传目录、备份和临时文件(.bak/.git/.svn)、日志(可能含 token/session)。判据是"开发和运维在这台机上留下了哪些秘密"。
**Q2**: 发现 .git 目录暴露,怎么最大化利用?
**A2**: 拉取完整 git 历史:历史提交里常有被"删掉"的密钥、口令、内网地址、其它系统对接信息。当前代码干净不代表历史干净,git log/历史 diff 是专门的情报维度。
**Q3**: 配置里全是环境变量占位符、没有实际值,怎么办?
**A3**: 转去运行态取值:配置引用的环境变量实际值在进程环境里(/proc/PID/environ)、在编排/容器的 secret、在 CI/CD 变量、在密钥管理服务。占位符指明了"有哪些秘密",顺着占位符名去运行态找真值。
**Q4**: 源码里发现了内部 API/其它服务地址,有什么用?
**A4**: 这是横向地图:暴露了内网还有哪些服务、它们的地址和认证方式,可能有更弱的内部服务可打。源码里的"内部依赖"清单常比端口扫描更准地指出下一个目标。
**Q5**: web 目录权限收得很紧、翻不到任何配置,这条被墙,转哪?
**A5**: 转"系统级和用户级搜刮":web 目录之外,系统的 /etc、用户家目录、临时目录、内存、历史命令仍可能有凭据。web 目录只是众多情报源之一,一处干净就换层。

### 横向目标优先级:一堆可达主机,先打哪个
**Q1**: 内网侦察发现十几台可达主机,资源有限,怎么排优先级?
**A1**: 按"价值×可达性×阻力"排:域控/文件服务器/DB/运维跳板价值最高;有我现成凭据能直连的可达性最高;防护弱的阻力最小。判据是先打"高价值且我已有钥匙且防护弱"的交集,别按 IP 顺序盲打。
**Q2**: 怎么快速判断一台主机是不是高价值?
**A2**: 看角色线索:主机名/DNS(dc、sql、backup、jump 等命名)、开放端口(域控的 88/389/445 组合、DB 端口)、谁登录过它(高权用户会话)、它被多少机器依赖。角色比 IP 更决定价值。
**Q3**: 有台机明显高价值但防护极强,该硬啃吗?
**A3**: 一般不。转"迂回":先拿它周边的弱机、拿在它上面有会话的用户凭据、找它信任的路径,间接抵达。高价值强防护目标很少正面拿下,多是被周边渗透"包抄"。
**Q4**: 我不确定哪些主机真的可达(能打通),怎么低噪确认?
**A4**: 用认证式探测替代扫描:拿已有凭据尝试 SMB/WMI/WinRM 连接,连通即可达且顺带验证凭据有效性,比端口扫描隐蔽。可达性和凭据有效性一次动作同时确认。
**Q5**: 排好的目标一个都打不动(凭据都不复用、都打了补丁),横向卡死,转哪?
**A5**: 转"回本机深挖换更好凭据":横向打不动往往是钥匙不够,回到已控机器抓更多凭据(更高权账户的票据、域凭据)、或提权到能访问共享凭据的层级,再重排目标。横向的瓶颈常在凭据而非目标。

### Kerberoast / AS-REP Roasting:低权域账户也能撬的口令
**Q1**: 我只有一个普通域账户,想不碰域控直接搞点高权口令,有啥招?
**A1**: 试 Kerberoasting:请求带 SPN 的服务账户的 TGS 票,离线爆破其口令(服务账户常是弱口令且高权)。任何有效域账户都能发起,低噪。判据是"域里有没有配了 SPN 的服务账户"。setspn/查询 SPN 先确认目标池。
**Q2**: 请求到票据了但爆不出来(口令强),怎么办?
**A2**: 换 AS-REP Roasting:找设置了"不要求预认证"的账户,直接拿可离线爆破的 hash,不需要先有票。两者是互补的正交手法,一个失败试另一个。都失败说明口令普遍够强,转别的向量。
**Q3**: 怎么挑最值得爆的服务账户?
**A3**: 优先挑高权限的 SPN 账户(在特权组里的、DA 级服务账户),爆出来直接高权。判据是"这个账户口令值不值得花算力"。SPN 列表要结合组成员信息一起看,别无差别爆。
**Q4**: Kerberoast 请求被检测(蓝队盯着异常 TGS 请求)怎么办?
**A4**: 转低频定点:只请求少数高价值 SPN 的票,而不是一次性 roast 全域(全量请求是强告警信号)。或改走已有凭据的其它横向路。手法降频,别把 roast 做成扫描。
**Q5**: 域里根本没有可 roast 的账户(无 SPN、都要预认证),这路空了,转哪?
**A5**: 转"委派 / ACL / 证书"结构性面:Kerberoast 是口令面,失败就换 AD 的其它错配面——非约束/约束委派、危险 ACL、ADCS 模板。口令面无收获不代表 AD 没有洞。

### ADCS 证书面:被低估的域提权高速路
**Q1**: 域内口令面和 ACL 面都不顺,我该不该看证书服务?
**A1**: 该,ADCS 常年是被忽视的提权高速路。先判定域里有没有 CA(证书服务),再枚举证书模板的配置。判据是"有没有模板允许低权用户申请到能用于认证/提权的证书"。有 CA 就值得专门查一轮 ESC 系列错配。
**Q2**: 具体查模板的哪些错配?
**A2**: 看几类:模板是否允许申请者自定义 SAN(可冒充任意用户,ESC1 类)、是否有过宽的注册权限、CA 是否接受任意 SAN、是否有可被滥用的 EKU、CA 服务器本身的 web 端点是否可 relay。判据是"哪一处让我能拿到冒充高权用户的证书"。
**Q3**: 找到一个可滥用模板,怎么把证书变成域权限?
**A3**: 用它申请到冒充目标(如 DA)的证书,再用证书做 Kerberos 认证(PKINIT)拿目标的票/hash。证书=可持久且难吊销的身份凭证,拿到即等于拿到该身份。
**Q4**: CA 没有明显模板错配,ADCS 直接路走不通,还有别的角度吗?
**A4**: 转 relay/端点角度:CA 的 web enrollment/证书接口可能可被 NTLM relay(ESC8 类),配合强制认证把机器账户 relay 到 CA 拿证书。模板面干净时,端点面是另一条 ADCS 路。
**Q5**: 域里压根没部署 ADCS,证书路彻底不存在,转哪?
**A5**: 转回"委派 + 关键机器凭据":没有 ADCS 就把力气放在 Kerberos 委派滥用、抓域控/关键服务器上的高权票据、以及信任关系。ADCS 只是众多通天路之一,不存在就走别的。

### MS17-010 / SMB 类远程面:该不该在内网用重武器
**Q1**: 内网扫到几台开 445 的老机器,想直接 MS17-010 一波,该上吗?
**A1**: 先判"值不值+稳不稳"。判据:目标是否真在漏洞版本窗口、是不是生产核心机(内存破坏类 exp 有蓝屏风险)、有没有更稳的认证横向替代。老旧未打补丁机器可用,但重武器优先级应低于"用凭据干净横向"。
**Q2**: 怎么先确认目标确实可能中招,减少盲打?
**A2**: 用安全的探测(协议指纹/漏洞检测脚本,只判定不利用)确认版本和补丁状态,再决定是否发实弹。判据是"检测通过再上",别拿蓝屏风险去赌。
**Q3**: 有认证横向(现成 hash/口令)可用时,还用远程 exp 吗?
**A3**: 优先认证横向。带票 PsExec/WMI/WinRM 又稳又像正常运维流量,远优于内存破坏 exp。重武器是"没有凭据、又必须拿这台老机"时的备选,不是首选。
**Q4**: exp 打过去目标蓝屏/服务崩了,反而惊动蓝队,怎么补救?
**A4**: 立即停用同类重武器,转认证式或漏洞更温和的横向。并评估暴露程度决定是否切换立足点/降低活动。蓝屏是强告警,后续要按"已暴露"标准收敛动作。
**Q5**: 目标全打了补丁、SMB 远程面全封,这类路被墙,转哪?
**A5**: 转"凭据 + 应用层":SMB 远程漏洞面封死时,内网横向主力回到凭据复用和应用层漏洞(内网 web、中间件、DB)。远程内存破坏漏洞只是横向的一小块,补丁齐全就走别的面。

### Zerologon / 域控直击类:高收益高风险的判定
**Q1**: 我定位到域控,听说有直击域控的漏洞,该不该赌一把?
**A1**: 极其谨慎。判据:域控是否在漏洞版本窗口、该 exp 是否会破坏域控(某些会改机器账户口令,处理不当导致域控故障、影响生产、强告警)。域控直击一旦出事是全局灾难,必须先评估回滚/修复能力。
**Q2**: 决定要用这类高风险 exp 前,必须准备什么?
**A2**: 准备"复原方案":搞清 exp 会改什么(如机器口令),准备好恢复步骤,避免把域控打瘫且无法还原。判据是"我能不能把它安全地打了再复原",不能就别碰生产域控。
**Q3**: 有没有更稳的拿域控方式,不走这种高风险 exp?
**A3**: 有,优先走凭据链:通过 Kerberoast/委派/ACL/证书/抓高权会话一步步拿到 DA 或域控机器账户,再干净地 DCSync 拉 hash。这比破坏性 exp 稳得多,应作为首选路径。
**Q4**: 高风险 exp 打域控失败或被拦,怎么办?
**A4**: 果断放弃这条并转结构性提权:失败的域控直击可能已告警,转回 ACL/委派/证书等"看起来像正常操作"的路径慢慢磨到 DA。直击失败不等于域拿不下,只是这条捷径没走通。
**Q5**: 拿到域控后第一件事该干嘛?
**A5**: DCSync 导出域内 hash(尤其 krbtgt),krbtgt 到手可做黄金票据实现长期任意身份。同时低调建域级持久,并克制动作避免立刻被复盘。拿下域控是开始收割而非结束。

### Pass-the-Hash / Pass-the-Ticket:有凭据后怎么用最合适
**Q1**: 我手里有一堆 hash 和票据,横向时到底该用哪种、怎么选?
**A1**: 按凭据类型选协议:NTLM hash→PtH(走 NTLM 认证的 SMB/WMI);TGT/TGS→PtT(走 Kerberos);明文→可喷洒所有协议。判据是"目标接受哪种认证 + 我这把钥匙是哪种类型"。别拿 hash 去硬试只认 Kerberos 的场景。
**Q2**: PtH 打某台机被拒(hash 有效但连不上),可能什么原因?
**A2**: 排查:目标是否禁了本地账户远程 NTLM(如受限管理模式/LAPS 改了口令)、是否需要域账户而我用的是本地、防火墙挡了对应端口。转用域账户凭据或换协议(Kerberos)。被拒常是"认证方式不匹配"而非 hash 无效。
**Q3**: 什么时候该优先 PtT 而不是 PtH?
**A3**: 域环境里 Kerberos 更"正常"、更少触发 NTLM 相关检测,且票据可请求多服务。有票优先 PtT。此外一些强化环境禁 NTLM,只能走 Kerberos,这时 PtT 是唯一选择。
**Q4**: 手里凭据横向到处碰壁(不复用、被隔离),怎么办?
**A4**: 转"提纯凭据质量":当前钥匙不行,回去抓更高价值凭据——域管票据、机器账户、krbtgt。横向不通常是"钥匙级别不够",而非没有路,升级钥匙再打。
**Q5**: 怎么避免用凭据横向时把动静搞大?
**A5**: 选低噪协议和低频节奏:优先 WMI/WinRM 而非满屏 PsExec、别对全网喷洒同一 hash(喷洒是强告警)、复用现成会话而非反复新建。凭据横向的隐蔽性取决于"像不像正常运维",节制使用。

### 内网端口扫描:必须扫时怎么把噪声压到最低
**Q1**: 被动情报不够,我确实得主动摸内网端口了,怎么扫才不炸告警?
**A1**: 三原则:窄(只扫目标网段/关键端口如 445/3389/22/80/443/DB 端口,别全端口)、慢(低并发低速率,避开扫描器指纹)、分散(分批分时,别一口气全网)。判据是"让流量像零散的正常访问而非一次扫描"。
**Q2**: 想先知道哪些主机活着再决定扫谁,存活探测怎么做低噪?
**A2**: 优先无扫描的存活情报:ARP 邻居、DNS 反查、域内计算机对象列表、netstat 已有连接。实在要探,用少量高命中端口(445/135)轻探而非 ping 全段。存活判定尽量借"已有数据"而非"新流量"。
**Q3**: 通过 pivot 代理扫内网,速度和稳定性怎么权衡?
**A3**: 经代理扫会更慢更易丢包,更要降并发。判据是"宁可慢而准,别快而丢结果还炸代理"。代理链上的扫描要比直连更保守,否则既暴露又拿不到可靠结果。
**Q4**: 扫描刚起就发现触发了 NDR 告警,怎么办?
**A4**: 立即停扫,转认证式发现:用已有凭据去连(SMB/WinRM),连通即确认可达,完全不发扫描流量。端口扫描被墙时,"用凭据去敲门"是隐蔽的替代发现手段。
**Q5**: 完全不允许任何主动流量(极敏感环境),端口情报怎么来?
**A5**: 纯被动重建:靠本机的 netstat、ARP、hosts、known_hosts、应用配置里的对端地址、日志里的连接记录,拼出内网拓扑。极端环境下,拓扑情报全部来自"已控主机记得的东西"。

### 搭 pivot:把立足点变成通往深层网段的隧道
**Q1**: 我发现内层网段只有这台立足机能到,怎么让我的工具穿进去?
**A1**: 建代理隧道:socks 代理(经 C2 或 ssh -D)让本地工具经立足机访问内层。判据是"我的扫描/横向工具能不能透明地打到内层 IP"。首选复用已有稳定通道(C2 内置转发/ssh)而非另起显眼服务。
**Q2**: 立足机没有 ssh、也不方便传大工具,怎么建隧道?
**A2**: 用轻量/内存化的转发:C2 自带的 socks、小巧静态转发二进制、或系统自带能力做端口转发。判据是"最小落地面换到穿透能力"。工具越小越静越好。
**Q3**: 隧道建起来但又慢又频繁断,怎么稳?
**A3**: 排查:单跳还是多跳(跳越多越不稳)、带宽/延迟、C2 心跳配置。稳定性优先于速度——把并发降下来、加重连、必要时在中间加一台更近的中继缩短链路。深层作业依赖隧道稳,别在抖动隧道上做关键操作。
**Q4**: 立足机随时可能被清,隧道一断深层就失联,怎么防?
**A4**: 转"多跳冗余入口":在深层网段里再拿一个立足点作为第二入口,别让整条通道吊在单台机上。一旦某台被清,还有另一条路进深层。pivot 也要有冗余。
**Q5**: 目标网段做了严格 ACL,连立足机都到不了内层,隧道无从建,转哪?
**A5**: 转"找真正的边界机":当前立足机不在通往内层的路径上,得先找到那台双网卡/被授权访问内层的跳板机(看路由、看谁在和内层通信),拿下它再做 pivot。到不了就换一台够得着的机器当跳板。

### 云上立足点:元数据服务与云凭据是第一优先
**Q1**: 我发现立足点其实是云上实例(ECS/EC2 类),第一轮该先抓什么?
**A1**: 优先云元数据服务(IMDS,常见 169.254.169.254):可能直接吐出实例绑定的临时云凭据(角色 token)。判据是"能不能从 IMDS 拿到 STS/角色凭据",拿到就等于拿到这台机在云上的权限,价值常高于本机系统提权。
**Q2**: IMDS 拿到角色凭据后能干嘛?
**A2**: 用它调云 API:枚举权限、列存储桶/对象、读其它资源、看能否横向到别的实例或提权到更高云角色。云凭据把战场从"这台机"扩到"整个云账户"。先摸清这把凭据的权限边界。
**Q3**: IMDS 被加固(要 token 的 v2、或被禁),这条路封了怎么办?
**A3**: 转其它云凭据源:机器上的 ~/.aws / gcloud / az 配置、环境变量里的 AK/SK、CI 变量、应用配置里的云密钥、挂载的云 secret。IMDS 只是云凭据来源之一,加固了就翻落盘的。
**Q4**: 判断这是不是云、是哪家云,怎么快速定?
**A4**: 看指纹:元数据地址可达性、DMI/BIOS 厂商信息、内核里的云驱动、网卡/主机名命名规律、有没有云 agent 进程。判定云厂商后才知道该找哪种元数据接口和凭据文件。
**Q5**: 确认是云但云凭据一无所获,云路径暂时空,转哪?
**A5**: 转回传统内网/本机维度:云环境里同样有普通的系统提权、内网横向、DB、AD(云上也可能有域)。云凭据是加速器不是唯一路,拿不到就按常规内网打法继续。

### 容器 / K8s:从 Pod 里往外看整个集群
**Q1**: 确认自己在 K8s Pod 里,第一轮往哪看?
**A1**: 先看 serviceaccount:/var/run/secrets/kubernetes.io/serviceaccount 里的 token 和 CA。判据是"这个 SA token 能调 API Server 干什么"(能否列/创建 Pod、读 secret、跨 namespace)。SA 权限决定了在集群里能走多远。
**Q2**: SA token 权限不错,怎么升级到控制节点/集群?
**A2**: 常见路径:有权 create Pod 就挂宿主机根目录/特权容器实现节点逃逸;能读 secret 就拿其它服务/云凭据;能跨 namespace 就扩大面。判据是"哪个 API 权限能让我踩到宿主机或高权 secret"。
**Q3**: 想从容器逃到宿主机,先判断什么?
**A3**: 判逃逸面:是否 privileged、有哪些 capabilities、有没有挂 docker.sock 或宿主目录、能否 mount、内核是否有可用逃逸漏洞。判据是"有没有一处让我摸到宿主机文件系统或内核"。逐项过一遍逃逸清单。
**Q4**: SA token 权限被收得极窄、逃逸面也全封,K8s 路很紧,转哪?
**A4**: 转"应用/网络层":容器内跑的应用本身、Pod 能访问的内网服务(数据库、内部 API、其它 Pod)、集群网络里的东西向流量。逃不出去就在容器可达的网络面里横向。集群硬,应用未必硬。
**Q5**: 拿到高权 SA(如 cluster-admin 级),第一件事?
**A5**: 稳控 API 面并收割:列全 namespace 的 secret(集群里所有服务/云/DB 凭据的集散地)、找控制面组件、按需建隐蔽持久(如带毒的 DaemonSet)。cluster-admin 等于整个集群,重点是收凭据和稳持久。

### 识别蜜罐 / 蜜账户 / 诱饵:别一头栽进陷阱
**Q1**: 内网里出现一台"好得不真实"的机器(明显弱口令、满是诱人文件),我该兴奋还是警惕?
**A1**: 警惕。判据:防护严密的内网里出现异常好打/异常暴露的目标,可能是蜜罐。看它是否与真实业务割裂(无正常流量、命名突兀、文件像刻意摆放、账户从不登录)。真实资产有生活痕迹,诱饵通常没有。
**Q2**: 怎么识别蜜账户(honey account/honey token)?
**A2**: 看反常:一个高权名字的账户却从不登录、口令永不改、被"故意"放在容易发现的地方(如配置里明晃晃的凭据)。用这类账户认证极可能立刻告警。判据是"这凭据是不是被摆在那等我用"。
**Q3**: 怀疑但不确定是不是蜜罐,该怎么试探?
**A3**: 低承诺试探:先只做只读/被动观察(看它的正常流量、进程、与谁通信),别立刻用高特征动作或投毒。判据是"用最小暴露确认真假",确认是诱饵就绕开,是真的再下手。
**Q4**: 我怀疑已经踩了蜜罐/被引导进了监控沙盒,怎么办?
**A4**: 转"假设已暴露"模式:立即收敛动作、评估从这台机暴露了哪些手法和入口、切换到独立的备用立足点和通道继续。踩蜜罐最大的风险是顺藤摸到你的整套 TTP,断开关联最重要。
**Q5**: 整个网络疑似高度布防、处处像陷阱,还怎么推进?
**A5**: 转"贴着真实业务走":只碰有真实业务流量、真实用户活动的资产,顺正常业务链横向,避开一切"孤立、暴露、无生活痕迹"的诱饵。布防越重,越要用真实流量做掩护而非找捷径。

### 痕迹与日志:边打边想"我留下了什么"
**Q1**: 第一轮信息收集做完,我该怎么盘点自己留下的痕迹?
**A1**: 分类盘:落地文件(工具、payload、dump)、日志(登录、命令、认证事件)、新建的连接/进程/账户/任务、shell 历史。判据是"蓝队若现在来看这台机,哪些是我留下的异常"。心里要有一份自己的"脏数据"清单。
**Q2**: 要不要清日志?清了会不会更显眼?
**A2**: 权衡。清空/大改日志本身是强告警信号(日志断档很扎眼)。判据:优先"少留"而非"事后清"——用不落盘、原生命令、复用合法路径减少产生痕迹;真要清也是定点删自己那几条,而非清空整个日志。
**Q3**: 我在 shell history 里留了一堆敏感命令,怎么处理最稳?
**A3**: 优先一开始就不写(设置不记录 history/用不落 history 的执行方式);已经写了就定点清理自己那几行并注意时间戳一致性。判据是"改动要最小且不产生新异常(如文件时间戳突变)"。
**Q4**: 我意识到某个动作已经触发了告警、痕迹已暴露,怎么办?
**A4**: 转"损失控制":不纠结抹掉那条已暴露的痕迹(往往来不及),而是评估它暴露了什么、会不会牵连其它立足点,并把关键能力迁移到干净的备用通道。已暴露的痕迹重点是"切断关联"而非"擦干净"。
**Q5**: 长期驻留,怎么持续把痕迹维持在最低?
**A5**: 转"融入日常"原则:动作贴合正常运维时间和方式、复用合法账户与工具、控制活动频率、避免任何"断档/突变/孤立"的异常。持久隐蔽靠的是长期像正常用户,而非某次高明的清理。

### 全线卡死的复盘:提权和横向都推不动时怎么系统性转向
**Q1**: 提权试遍了、横向也打不动,彻底卡住,我该怎么系统性地找突破口而不是瞎撞?
**A1**: 做"维度盘点":把攻击面拆成正交维度逐个自查有没有遗漏——本机(内核/SUID/cron/sudo/服务)、凭据(内存/落盘/历史/浏览器/云)、网络(新网段/pivot/出网)、身份(域/服务账户/云角色)、应用(源码/配置/DB/内部服务)。卡死通常是某个维度根本没查,而非查过的都真没洞。
**Q2**: 怎么判断是"真没有洞"还是"我情报没到位"?
**A2**: 反问"我的观测盲区在哪":是不是工具不够看不到(补工具)、权限不够读不到(先小提权再看)、噪声顾虑不敢查(换低噪手段查)。大多数"没洞"其实是"没看全"。先扩观测再下"无洞"结论。
**Q3**: 每个维度好像都浅浅看过但都没突破,接下来?
**A3**: 从"广度扫"转"深度钻一个点":挑最可能的一个维度(通常是凭据复用或某个自定义应用)往深挖到底——读全源码、爆全 hash、跟全调用链。卡死时深度往往比再铺一层广度更出结果。
**Q4**: 确实一个能动的立足点都提不动了,是不是该收工?
**A4**: 先转"换立足点/换入口"再谈收工:回到最初的攻击面找第二个入口(另一个漏洞、另一台边界机),用全新起点绕开当前死局。同一个立足点卡死,换一个立足点常豁然开朗。
**Q5**: 时间/资源快耗尽,必须取舍,怎么定最后的主攻方向?
**A5**: 按"期望收益/剩余阻力"排,集中火力打一个:通常是"我已有半把钥匙且目标价值高"的那条(如已抓到 hash 只差找对目标、已发现域错配只差利用)。终局别再广撒网,押注最接近成功的单点全力突破。

### 立足点保活:让入口在对抗中活得更久
**Q1**: 第一轮收集期间,我怎么保证这个来之不易的入口不轻易丢?
**A1**: 立刻建"冗余通道":不要只依赖最初那条连接。尽早再落一条独立机制、独立出网方式的备用通道(不同协议、不同端口、不同触发方式)。判据是"任意单条通道被切,我还进得来"。单点入口是最大脆弱性。
**Q2**: 主通道和备用通道该怎么设计才不会一锅端?
**A2**: 让它们正交:不同的落地位置、不同的 C2/协议、不同的持久机制、最好在不同主机。判据是"蓝队发现并处置一条时,不会顺带暴露另一条"。同源同特征的多通道等于一条通道。
**Q3**: 我担心 beacon 心跳太频繁被流量分析抓到,怎么平衡存活与隐蔽?
**A3**: 调低心跳频率+加抖动+贴正常业务流量特征。判据是"通道要活得久就得少说话、说得像正常流量"。存活性和隐蔽性在这里是统一的:越吵越短命。
**Q4**: 立足机看起来快被处置了(蓝队在上面动作),怎么抢救战果?
**A4**: 转"抢救优先级":趁还在,第一时间把已抓的凭据/情报回传、把能力迁到别处的备用立足点,而不是恋战继续收集。机器要没了,先保住已得的凭据和另一个入口,东西比这台机重要。
**Q5**: 唯一的立足点已经丢了、所有通道断了,怎么办?
**A5**: 转"用已收集的情报冷启动重进":之前抓的凭据、摸清的网段拓扑、发现的其它入口点,就是重新进来的钥匙。第一轮信息收集的最大价值之一,正是在立足点丢失后还能靠情报把路再走一遍。所以情报要及时外带,别都压在那台机上。
