# 提权立足点 · Windows提权决策树

### 刚落地一个低权 shell,第一件事该做什么
**Q1**: 我刚拿到一个身份未知的 shell,最不该干的是立刻甩 winPEAS。先做什么?
**A1**: 先花 60 秒定位自己:`whoami`、`whoami /priv`、`whoami /groups`、`hostname`、`systeminfo`。回答三问:我是谁、机器什么成色、在不在域里。没这三点就跑自动化,会被无关输出淹没,还徒增落地文件被 EDR 抓的风险。
**Q2**: 我是普通用户、完整性 Medium,下一步判据?
**A2**: Medium 意味着即便在本地管理员组也没高完整性令牌——这决定走"提权到 SYSTEM"还是"仅需 UAC bypass"。`whoami /groups` 看是否已在 Administrators:在组内但 Medium → UAC bypass;不在组内 → 真正的本地提权。
**Q3**: `whoami /priv` 该第一眼扫什么?
**A3**: 扫 SeImpersonate、SeAssignPrimaryToken、SeBackup、SeRestore、SeDebug、SeTakeOwnership、SeLoadDriver。只要 Enabled 一个,路径基本锁定,比漫无目的翻服务快十倍。
**Q4**: 如果是服务账户(IIS APPPOOL/mssql 等),优先级怎么变?
**A4**: 服务账户几乎必带 SeImpersonate,直奔 Potato 家族。这是投入产出比最高的一条,别绕远。
**Q5**: 侦察这条路卡住了——命令受限、输出被吞、shell 不稳,往哪转?
**A5**: 转"稳定立足点"这个正交维度:先把 shell 升级成稳定回连或落一个 beacon,或换更完整的执行通道。提权前提是能稳定执行命令,shell 一断全白搭。
**Q6**: 侦察信息怎么留存以免重复劳动?
**A6**: 把 systeminfo/whoami /all/服务/软件/网络各存一份到自己的战报(不落目标盘)。提权是迭代过程,常回头比对,重复跑命令既慢又增加暴露。

### 手里有 SeImpersonate,怎么变成 SYSTEM
**Q1**: SeImpersonate Enabled,该选哪个 Potato?
**A1**: 先看版本与补丁。老系统/COM 可用 → JuicyPotato;新系统 RPC/COM 被封 → PrintSpoofer(Spooler 管道)、RoguePotato(远端 OXID)、GodPotato(较通用)。判据是"哪个前置在这台机上成立",不是"哪个最新"。
**Q2**: PrintSpoofer 报找不到 spoolss 管道怎么办?
**A2**: Spooler 被停了。别死磕,切 RoguePotato/GodPotato,不依赖 Spooler。SeImpersonate 提权本质是"骗 SYSTEM 进程连我的命名管道",实现手段多、前置各异,挨个试成本很低。
**Q3**: 怎么验证真成功而非被工具骗?
**A3**: 别信工具打印的 success。让 payload 干件可验证的事:新起高权进程回连、或在只有 SYSTEM 能写的目录建文件。眼见 SYSTEM 令牌为实。
**Q4**: Potato 全被 EDR 拦(命名管道行为被检测)怎么办?
**A4**: 转正交:①自写令牌窃取代码改掉工具特征;②转向"服务账户本身权限"——它可能对某数据库/共享/域对象有特权,横向或直接读凭据更隐蔽。
**Q5**: RoguePotato 需要外部 135 中继,机器出网受限怎么办?
**A5**: 本机做端口重定向把 OXID 解析引回回环,或换全本地的 GodPotato。出网是硬约束时优先"全本地"变体。

### 我在本地管理员组但只有 Medium 完整性(要过 UAC)
**Q1**: whoami /groups 显示我在 Administrators,但没高完整性,怎么拿高权?
**A1**: 这不是"提权"是"越过 UAC"。选一个 auto-elevate 白名单程序做 UAC bypass(fodhelper、computerdefaults、sdclt、劫持相关注册表键或 DLL)。判据是当前 UAC 级别:默认级别下这些绕过大多有效;最高级别("总是通知")则大部分失效。
**Q2**: 我怎么知道哪个 bypass 在这版本 Windows 上还有效?
**A2**: 按 build 号匹配。UAC bypass 高度版本相关,老技法在新 build 被堵。先 `ver`/build,再挑对应窗口内的技法,别拿老技法硬撞新系统。
**Q3**: 试了两个 fodhelper 类都没弹高权进程怎么办?
**A3**: 可能 UAC 设到最高或该 auto-elevate 项被移除。转正交:既然已是管理员,直接用管理员凭据走"非交互高权"路径——以 SYSTEM 身份创建服务/计划任务、或 PsExec 到本机 admin$,绕开 UAC 交互模型。
**Q4**: 我有明文管理员口令但只是 Medium,最干净的拿 SYSTEM 方式?
**A4**: 用该口令新建/接管一个以 SYSTEM 运行的服务或计划任务,比内存注入类更稳更隐蔽。有合法凭据时优先"用合法机制",而非漏洞。
**Q5**: 全部 UAC 绕过失败,这台就是拿不到高权,往哪转?
**A5**: 换目标。既已是本地 admin,横向价值(抓本机 hash、读 LSASS、当跳板)已够用;把"本机拿 SYSTEM"降级,转向域内横向,常有另一台机器更好拿域权限。

### 服务类提权:未加引号的服务路径
**Q1**: 我想找 unquoted service path,怎么快速定位可利用的?
**A1**: 列服务路径,找"含空格且未加引号、且我对某级中间目录可写"的三重条件。三者缺一不可利用。光有空格没写权限是假阳性,别浪费时间。
**Q2**: 找到一个候选,怎么确认我能写入劫持点?
**A2**: 对路径每一段空格前的目录测写权限(建个临时文件删掉即可)。能写 → 放一个同名 .exe 劫持;不能写 → 这条作废,看下一个。
**Q3**: 服务是手动/禁用启动,放了 payload 也不触发怎么办?
**A3**: 看我能否重启服务(sc start 权限)或等系统重启。不能主动触发就把它挂起来当"重启后生效"的持久+提权,同时并行找能主动触发的路径,别干等。
**Q4**: 这类服务全都规规矩矩加了引号,提权无从下手,往哪转?
**A4**: 转到服务的另两个正交面:①服务二进制文件/所在目录的 ACL 是否可写(直接换 exe);②服务的注册表键 ImagePath/权限是否可改。unquoted 只是服务错配的一种。
**Q5**: 怎么避免改服务把生产业务打挂(留痕/告警)?
**A5**: 优先选非关键、可快速自恢复的服务;劫持 exe 里先拉起我的 payload 再调用原真二进制,保持服务功能正常,减少运维告警。

### 服务二进制/注册表可写(弱 ACL)
**Q1**: 自动化提示某服务二进制可被我修改,怎么核实?
**A1**: 对该 exe 及其目录查有效权限(icacls / accesschk 思路)。确认我的用户/组有 Write 或 FullControl。工具报的"可写"要亲手复核,ACL 继承常有坑。
**Q2**: 确认可写后,怎么改最稳?
**A2**: 别直接删原文件(可能锁定/校验)。优先"就地替换为一个 wrapper":先执行我的高权动作,再启动备份的原二进制,保证服务正常。然后触发重启或等重启。
**Q3**: 我对服务的注册表键有写权限但对文件没有,能提权吗?
**A3**: 能。改 ImagePath 指向我的 payload,或改 FailureCommand(服务失败时执行)、或加 Parameters。注册表侧和文件侧是两个独立攻击面,一个不通试另一个。
**Q4**: 服务以我同级或更低权限运行,改了没提权意义,怎么办?
**A4**: 先确认服务运行账户。只有跑在 SYSTEM/高权账户下的服务才有提权价值。跑在低权下的就跳过,转去找 LocalSystem 服务。
**Q5**: 全盘没有弱 ACL 服务,转哪?
**A5**: 转"可写的自动执行点"这个大类:计划任务、启动项、Run 键、DLL 搜索路径。服务只是自动高权执行的一种载体。

### SeBackup / SeRestore 特权在手
**Q1**: whoami /priv 有 SeBackupPrivilege,怎么用它提权?
**A1**: SeBackup 让我能绕过 DACL 读任意文件。经典用法:导出 SAM、SYSTEM、SECURITY 注册表 hive(或卷影里的),离线抽本地账户 hash。这不直接给 SYSTEM,但给我本地管理员 hash 用于 PtH。
**Q2**: 我把 SAM/SYSTEM 拷出来了,下一步?
**A2**: 离线用 secretsdump 类工具抽 hash,再对本机/同镜像其它机做 pass-the-hash。判据:本地 admin hash 常在同批机器复用,价值远超单机。
**Q3**: 文件被占用拷不出来怎么办?
**A3**: 走卷影副本(VSS)读锁定文件,或用 SeBackup 语义的备份 API 读。别用普通 copy 硬碰锁定的 hive。
**Q4**: 只有 SeRestore 没有 SeBackup,思路一样吗?
**A4**: 不一样。SeRestore 是"写任意文件/注册表"——可覆盖高权服务二进制、改注册表键、甚至替换镜像劫持相关键实现执行。写权限的提权面比读更直接。
**Q5**: hive 拿到了但 hash 破不出、PtH 也被禁,往哪转?
**A5**: 转 DPAPI/域凭据面:hive 里 SECURITY 还含 LSA secrets、缓存域凭据、服务账户口令。抽这些往往比爆破本地 hash 更有横向价值。

### SeDebugPrivilege 在手
**Q1**: 我有 SeDebugPrivilege,能直接提权吗?
**A1**: 能。SeDebug 让我打开任意进程(含 SYSTEM 进程)。最直接:向一个 SYSTEM 进程注入,或复制其令牌起高权进程,或直接 dump lsass。判据是"哪个动作 EDR 眼里最轻"。
**Q2**: 直接 dump lsass 太扎眼,还有别的用法吗?
**A2**: 有。用 SeDebug 找一个 SYSTEM 进程,DuplicateToken 后 CreateProcessWithToken 起我的进程,不碰 lsass,行为更温和。令牌窃取比内存 dump 隐蔽。
**Q3**: 注入被 EDR 拦(远程线程/内存写被 hook)怎么办?
**A3**: 转正交:换令牌复制路线(不写目标内存),或改用 SeDebug 之外我已有的其它特权。别在被重点监控的注入原语上反复撞。
**Q4**: 我确认有 SeDebug 但代码 OpenProcess 还是拒绝,为什么?
**A4**: 特权可能是 Disabled 状态,需先在令牌里 Enable 它。很多工具没显式启用特权就调用。先 AdjustTokenPrivileges 启用再操作。

### 内核/系统漏洞提权(exploit 类)什么时候用
**Q1**: 配置类都试完没戏,该不该上内核 exploit?
**A1**: 内核 exploit 是"高收益高风险"选项。判据:①能精确匹配 OS build 与补丁(patchlevel);②该 exploit 稳定不易蓝屏;③业务可容忍潜在崩溃。三者不全就慎用,蓝屏会毁掉立足点还惊动运维。
**Q2**: 怎么把 systeminfo 的补丁信息变成可用 exploit 列表?
**A2**: 拿已装 KB 列表比对已知提权 CVE(Watson/WES-NG 思路),缩到"缺了对应补丁"的少数几个。别拿一堆通用 exploit 盲打。
**Q3**: MS17-010 这类怎么定位?
**A3**: 那是远程 SMB 面的,通常横向用而非本地提权;本地提权更多看 CVE 类内核 LPE(如各年份 win32k/ALPC/CLFS 提权)。选型先分清"本地 LPE"还是"远程 RCE"。
**Q4**: exploit 跑了没提权也没崩,怎么判断?
**A4**: 大概率补丁其实打过、或 build 不匹配。别重复跑(增加崩溃概率)。回去核对确切 build/patch,不匹配就换 exploit 或彻底放弃这条线。
**Q5**: 内核路线整体走不通(全打了补丁),往哪转?
**A5**: 转"第三方软件本地漏洞"面:已装的杀软/驱动/数据库/备份软件常有本地提权漏洞(BYOVD 易受攻击驱动尤甚)。系统补丁全≠第三方补丁全。

### 凭据搜刮:文件系统与配置里的明文
**Q1**: 配置提权都不通,我想翻凭据,先翻哪?
**A1**: 先翻"部署/运维遗留":unattend.xml、sysprep.inf、Autologon 注册表、各 web/app 配置(连接串)、脚本里的硬编码口令、PowerShell 历史。这些出货率最高。
**Q2**: 关键词怎么定?
**A2**: 全盘/关键目录 grep password、pwd、pass、cpassword、connectionstring、secret、AccessKey 等。判据是"哪个口令对应更高权账户或域账户"。
**Q3**: 找到一堆口令,先用哪个?
**A3**: 按权限价值排序:域管/服务账户 > 本地 admin > 其它。先验证它在本机能否提权(runas/服务),不能则转横向。别按找到的顺序盲试。
**Q4**: GPP 里的 cpassword 怎么处理?
**A4**: SYSVOL 的 Groups.xml 等含 cpassword,用公开固定 AES 密钥可直接解密。这是域内经典遗留,值得专门找。解出的常是本地管理员口令,横向价值大。
**Q5**: 翻遍了没有明文口令,往哪转?
**A5**: 转加密凭据面:DPAPI blob、浏览器/邮件客户端/数据库客户端保存的凭据、Windows 凭据管理器。明文没有不代表没凭据,只是要解密。

### DPAPI 保护的凭据怎么解
**Q1**: 我找到一些 DPAPI 加密的 blob,怎么解?
**A1**: DPAPI 用户主密钥受用户登录口令保护。若我已在该用户上下文运行,可直接调 CryptUnprotectData 解;若拿到该用户口令或其 hash,可离线解 masterkey 再解 blob。
**Q2**: 我不在该用户上下文、也没口令,还能解吗?
**A2**: 若已是本地 SYSTEM/域管,可用 DPAPI backup key(域级)解任意用户 blob。所以 DPAPI 常是"拿到高权后进一步收割其它用户凭据"的工具,而非起点。
**Q3**: 解出来的是什么值得关注?
**A3**: 保存的 RDP 凭据、计划任务存储的账户口令、浏览器 cookie/密码、Wi-Fi、VPN 凭据。判据同样是"哪个通向更高权或更多主机"。
**Q4**: DPAPI 全线解不动,往哪转?
**A4**: 转 LSASS 内存面——很多凭据在内存里是明文/可复用票据,不必解 DPAPI。DPAPI 与 LSASS 是两条独立的凭据来源。

### LSASS 抓凭据的取舍
**Q1**: 我到了本地管理员/SYSTEM,想 dump lsass,直接 mimikatz sekurlsa?
**A1**: 先评估 EDR。lsass 访问是头号监控点。判据:目标有没有 EDR、lsass 有没有 PPL 保护、我能不能容忍一次高风险动作。有 EDR 就别裸跑经典工具。
**Q2**: lsass 开了 PPL(RunAsPPL)读不了怎么办?
**A2**: 要么用 BYOVD 装个签名驱动去掉 PPL,要么绕开——转向不碰 lsass 的凭据源(DPAPI、缓存 hash、票据文件、注册表 secrets)。别硬刚 PPL,动作大。
**Q3**: 想抓但要低调,怎么减小特征?
**A3**: 不用现成工具名/内存签名:用系统自带机制(如 comsvcs MiniDump 之类)落一个 dump 文件,拖回本地离线解析。把"读内存"和"解析"分离,减少目标机上的可疑行为。
**Q4**: dump 出来只有 hash 没明文怎么办?
**A4**: 新系统默认不缓存明文(WDigest 关)。有 hash 就走 PtH/PtT,或抓 Kerberos 票据(PtT)。别执着于要明文,hash/票据一样能横向。
**Q5**: lsass 完全碰不了(PPL+EDR 双保险),往哪转?
**A5**: 转"域侧无需碰 lsass 的攻击":Kerberoast、AS-REP roast、ADCS 证书滥用、DCSync(若已高权)。这些从票据/证书拿凭据,绕开本机内存。

### 计划任务可写导致提权
**Q1**: 我想找可劫持的计划任务,判据是什么?
**A1**: 找"以高权账户运行 + 任务调用的脚本/程序我可写 或 任务定义文件我可写"。列任务、看 Run As 和 Action 指向的文件路径,再逐个测写权限。
**Q2**: 找到一个 SYSTEM 任务但触发条件是"每天凌晨",利用要等一夜?
**A2**: 看我能否手动触发(schtasks /run 权限)或改触发器。不能就当"定时生效"的提权+持久挂上,同时并行找即时触发的路径,别把整条战线卡在等待上。
**Q3**: 任务指向的目录我可写,但文件本身权限严,能利用吗?
**A3**: 看 DLL 搜索/相对路径:若任务从可写目录加载 DLL 或用相对路径调用程序,我放同名文件即可劫持。目录可写常比文件可写更好用。
**Q4**: 计划任务这条全封死,往哪转?
**A4**: 转其它自动高权执行点:服务、Run/RunOnce 注册表键、启动文件夹、WMI 事件订阅。计划任务只是"定时高权执行"的一种实现。

### 启动项 / Run 键 / AutoElevate 程序可劫持
**Q1**: 想通过开机自启程序提权,先看什么?
**A1**: 枚举 HKLM 及各用户 Run/RunOnce、启动文件夹、以高权启动的自启程序。判据:该自启项以更高权账户运行,且其 exe/DLL/所在目录我可写。
**Q2**: HKLM Run 我能写但项目以当前用户身份跑,有用吗?
**A2**: 那只是持久不是提权。要提权得找"以管理员/SYSTEM 或其它用户身份自启"的项。分清"持久化"和"提权"两个目的,别混。
**Q3**: 找到个管理员登录时运行的程序,它在可写目录,怎么办?
**A3**: 放置劫持二进制/DLL,等管理员下次登录触发。这是"等待高权用户交互"型提权,收益取决于是否有高权用户会登录该机;若无人登录,价值有限。
**Q4**: 没有高权用户会登录这台机器,这条作废,往哪转?
**A4**: 转"不依赖交互"的自动执行:SYSTEM 服务/计划任务在无人登录时也跑。需要用户交互的技法在无人服务器上是死路。

### DLL 劫持 / DLL 搜索顺序
**Q1**: 我盯上一个高权程序,想 DLL 劫持,怎么判断可行?
**A1**: 找该程序加载但系统目录里缺失、或从可写目录先搜索到的 DLL(搜索顺序/side-loading)。用进程监控看它 load 时的 NAME NOT FOUND 记录,定位可投放的 DLL 名与路径。
**Q2**: 目标 DLL 在 System32 已存在,还能劫持吗?
**A2**: 若程序用相对路径或其工作目录在搜索顺序里靠前且可写,仍可能先命中我的 DLL。判据是"我的可写目录在该程序的实际搜索顺序中是否先于真 DLL"。
**Q3**: 放了 DLL 但程序崩了没执行我的代码怎么办?
**A3**: 我的代理 DLL 要转发原 DLL 的导出函数(proxy/forward),否则程序缺函数即崩。劫持要"既执行我的又不破坏原功能"。
**Q4**: 该程序有 DLL 签名校验/防篡改,劫持失败,往哪转?
**A4**: 转另一个高权程序,或转非 DLL 面(服务/任务/凭据)。DLL 劫持依赖具体程序的加载行为,一个不行换目标比硬啃防护划算。

### PATH 环境变量劫持
**Q1**: 我发现系统 PATH 里含一个我可写的目录且排在前面,能提权吗?
**A1**: 能,若某高权服务/任务/程序调用命令时没写全路径(如只写 `cmd`、某工具名),就会在 PATH 里先命中我可写目录下的同名 exe。先确认"有高权进程会以短名调用命令"。
**Q2**: 怎么找到会被这样触发的高权调用?
**A2**: 看服务/计划任务/登录脚本里以短名调用的程序,或某些程序启动时探测的辅助工具。没有触发者,可写 PATH 目录只是潜在面不是实招。
**Q3**: 这条不成立,往哪转?
**A3**: 转具体的 DLL 搜索劫持或服务/任务面。PATH 劫持依赖"短名调用"这个偏少见的前提,不成立就别恋战。

### AlwaysInstallElevated 策略
**Q1**: 我想查 AlwaysInstallElevated,查什么?
**A1**: 查 HKLM 和 HKCU 下 Installer 的 AlwaysInstallElevated 是否都为 1。必须两个都为 1 才生效——这时任何 .msi 都以 SYSTEM 安装。
**Q2**: 确认都为 1,怎么利用?
**A2**: 生成一个执行我 payload 的 .msi,以 msiexec 静默安装,即得 SYSTEM。这是极干净的一条,策略错配即通吃。
**Q3**: 只有 HKCU 为 1,HKLM 为 0,能用吗?
**A3**: 不能,必须两者皆 1。缺一即失效,别浪费时间构造 msi,转其它面。

### 已装第三方软件的本地漏洞 / BYOVD
**Q1**: 系统补丁全打了,还有提权面吗?
**A1**: 有。枚举已装第三方软件及其服务/驱动版本:杀软、备份、虚拟化、数据库、远程管理工具常带本地提权漏洞。系统全补≠第三方全补。
**Q2**: 怎么把已装软件变成可用漏洞?
**A2**: 列已装程序版本比对已知本地提权 CVE。重点看"以 SYSTEM 运行的第三方服务"和"已加载的第三方内核驱动"。
**Q3**: 想用 BYOVD,判据是什么?
**A3**: 我需要能装/加载一个已知易受攻击的签名驱动(需管理员权限先)——所以 BYOVD 更多用于"admin→内核/绕 EDR",而非从低权起步。搞清它在链条中的位置。
**Q4**: 第三方漏洞也没有,往哪转?
**A4**: 回到凭据搜刮与横向:本机提不动就换机器。内网里总有配置更松或补丁更旧的主机,别在一台硬啃到底。

### 域机器:本地提权还是直接冲域权
**Q1**: 这是域成员机,我拿到了本地 SYSTEM,下一步冲域权还是继续本机?
**A1**: 本机 SYSTEM 已榨干本机价值,重心转域。用 SYSTEM 身份的机器账户做域侦察(BloodHound 数据)、抓本机登录过的域用户票据/hash。本机 SYSTEM 是通往域的跳板,不是终点。
**Q2**: 我还没拿本机 SYSTEM,但域里可能有更快的路,怎么权衡?
**A2**: 并行评估:若域侧存在 Kerberoast/AS-REP/ADCS ESC/无凭据的 zerologon/PetitPotam+ADCS 链,可能比本机提权更快到域管。判据是"哪条路的前置我已满足"。
**Q3**: 本机提权全线卡死,但我有个普通域账户,往哪转?
**A3**: 彻底转域侧无需本机高权的攻击:Kerberoast 拿服务账户 hash 离线破、AS-REP roast 找不需预认证的账户、查 ACL 错配(BloodHound 找可控路径)。低权域账户本身就是一把钥匙。
**Q4**: 我拿到域管了,还要回来搞这台本机 SYSTEM 吗?
**A4**: 通常不必。有域管就能 PsExec/WMI 任意域成员拿 SYSTEM。别倒着做无用功;把域管权限用于目标主机/DC 才是重点。

### 从立足点做 Kerberoast
**Q1**: 我只有一个普通域账户,想 Kerberoast,前提够吗?
**A1**: 够。任意认证域用户即可请求 SPN 账户的 TGS。先枚举带 SPN 的用户账户(服务账户),请求其票据,离线爆破。低权账户就能发起。
**Q2**: roast 出一堆票据,先破哪个?
**A2**: 优先 SPN 属于高权/域管组、或口令可能弱(老服务账户)的。判据是"破出后权限跃升最大"。别平均用力。
**Q3**: 票据都用强口令(AES),离线爆不动怎么办?
**A3**: 转 AS-REP roast(找关了预认证的账户)、或转 ACL/证书面。Kerberoast 只在"存在弱口令服务账户"时高效,强口令环境要换维度。
**Q4**: 域里没有可 roast 的 SPN 账户,往哪转?
**A4**: 转 ADCS 证书滥用(ESC 系列)或委派配置错误(约束/非约束/RBCD)。这些不依赖弱口令,靠配置错误。

### ADCS 证书模板滥用(ESC 系列)判断
**Q1**: 域里有 CA,我想看有没有 ESC 提权面,先看什么?
**A1**: 枚举证书模板(Certify/certipy 思路),找"低权可申请 + 可指定任意 SAN/可用于认证"的模板(ESC1 类),或 CA 配置错误(ESC6/ESC8 等)。判据是"我这个低权身份能不能申到一张能冒充高权账户的证书"。
**Q2**: 找到一个可疑模板,怎么确认可利用?
**A2**: 看它是否允许 enrollee 提供 subject、EKU 是否含客户端认证、我所在组是否在 enroll 权限里。三条齐才是 ESC1 可用。缺一转看其它 ESC 编号。
**Q3**: 申到证书后怎么变成权限?
**A3**: 用证书做 PKINIT 认证拿目标账户 TGT,或抓其 NT hash。证书是"以目标身份认证"的凭据,拿到即等于拿到该账户。
**Q4**: CA 都配置正确,没有 ESC 面,往哪转?
**A4**: 转委派滥用、DACL 攻击路径(BloodHound)、或强制认证+中继(PetitPotam→ADCS ESC8 需 web enrollment)。ADCS 只是众多域提权面之一。

### PrintNightmare / Spooler 类
**Q1**: 我想用 Spooler 相关漏洞本地提权,判据是什么?
**A1**: 先确认 Print Spooler 服务在跑,且对应补丁未打。PrintNightmare 类可本地加载恶意驱动 DLL 以 SYSTEM 执行。服务停了或补丁全就没戏。
**Q2**: 本地 PrintNightmare 提权触发了没反应怎么办?
**A2**: 多半补丁已打或 Point-and-Print 策略收紧。别重复触发(易留大量事件日志)。核对补丁,不行就转别的驱动/服务面。
**Q3**: 这条被墙,往哪转?
**A3**: 转其它"服务以 SYSTEM 加载我可控内容"的面,或转凭据横向。单一 CVE 被补不代表整机没洞,但也别在一个 CVE 上耗到底。

### 凭据复用:横向后回头提权
**Q1**: 本机提不动,但我在别处拿到一批口令/hash,怎么用来提权本机?
**A1**: 逐个在本机验证:某个本地/域账户口令可能就是本机管理员。用它 runas/PtH 到本机高权。提权不一定靠漏洞,凭据复用常一击即中。
**Q2**: 怎么快速判断某 hash 是不是本机 admin?
**A2**: 对本机做一次 PtH 认证测试(如访问 admin$ / SMB 认证)。成功即本机 admin,直接 PsExec 拿 SYSTEM。别一个个手工 runas。
**Q3**: 手里 hash 对本机都不认,往哪转?
**A3**: 转"抓本机上其它用户的凭据"或域侧攻击。本机不认外来 hash,就从本机内存/DPAPI 里挖它自己认识的凭据。

### 只有 hash 没明文:PtH 还是破解
**Q1**: 我抓到 NTLM hash 但没明文,该 PtH 还是拿去爆破?
**A1**: 先 PtH——NTLM hash 可直接用于 NTLM 认证的横向/提权,不需要明文。除非目标只认 Kerberos 或我需要明文复用到非 Windows 系统,才去爆破。
**Q2**: 目标环境禁用了 NTLM,PtH 不通怎么办?
**A2**: 转 Kerberos:用 hash 做 overpass-the-hash 拿 TGT(pass-the-key),再 PtT。hash 不止能 PtH,还能换 Kerberos 票据。
**Q3**: 两条都被限(NTLM 禁 + 强 Kerberos 策略),往哪转?
**A3**: 转破解出明文再走合法登录通道,或换凭据来源。当认证协议被收紧,回退到"像正常用户一样用明文登录"最稳。

### 受限执行环境:AppLocker / WDAC / 约束语言模式
**Q1**: 我的 PowerShell 处于 Constrained Language Mode,提权脚本跑不了,怎么办?
**A1**: 先确认限制来源(AppLocker/WDAC 触发的 CLM)。绕过思路:走非 PowerShell 执行(受信任的 LOLBins、编译 exe、其它脚本引擎),或找 CLM 的已知绕过。别在被锁的 PS 里硬写。
**Q2**: exe 也被 AppLocker 白名单挡了怎么办?
**A2**: 走微软默认放行的可写路径(某些系统目录白名单例外)、或用被信任的 LOLBin 加载我的逻辑。判据是"哪条执行路径在白名单策略的缝里"。
**Q3**: 执行限制太死,任何 payload 都落不了地,往哪转?
**A3**: 转"无需落地新可执行体"的路线:纯用系统内置工具(living-off-the-land)完成侦察与凭据搜刮,或把提权点选在"配置错误"(改服务/任务,用系统自己的机制执行),而非投放二进制。

### 只有非交互命令执行(无稳定 shell)下的提权
**Q1**: 我只能通过一个 Web/命令注入点单条执行命令,没交互 shell,怎么提权?
**A1**: 先想办法把执行升级:每条命令都独立、无状态很难做提权。优先落一个稳定回连(反向 shell)拿到交互与上下文。没有稳定通道,提权几乎做不了。
**Q2**: 出网被封,弹不出反向 shell 怎么办?
**A2**: 转正向连接、或走已开放端口/协议隧道(DNS、HTTP 隧道、已开的服务端口复用)。执行通道被墙时,先解决"怎么稳定通信",再谈提权。
**Q3**: 通道死活建不起来,只能盲打单命令,往哪转?
**A3**: 把提权改成"一次性可完成"的动作:用单条命令写一个 msi/服务/任务让系统在高权下执行我的载荷,把"需要交互的提权"转成"投放即自动高权执行"。

### EDR/AV 拦截提权动作怎么办
**Q1**: 我的提权 exploit/工具一落地就被杀,怎么判断是静态还是行为查杀?
**A1**: 先分辨:落地即删=静态特征;执行到某步才拦=行为检测。静态问题改样本(重编译/去特征/无文件执行);行为问题换技法路径而非换免杀。判错方向白费力。
**Q2**: 静态免杀后又在运行时被行为拦,怎么办?
**A2**: 说明被拦的是"动作模式"(如注入 lsass、命名管道模式)。换一条实现同目的但行为不同的路径:令牌复制代替注入、配置错误利用代替内存操作。
**Q3**: 反复试免杀会不会打草惊蛇?
**A3**: 会。每次被杀都产生告警。别在一台重点机上连续撞 EDR。判据:撞两三次没过就停,转"最不像攻击"的配置类提权,或换机器。
**Q4**: 这台 EDR 太硬,提权动作全暴露,往哪转?
**A4**: 转到无需在本机做高危动作的路线:域侧攻击(Kerberoast/ADCS 从别处发起)、或直接横向到 EDR 薄弱的主机再回来。硬碰硬的机器绕开打。

### 服务账户对外部资源的特权(横向即提权)
**Q1**: 我是个数据库/应用服务账户,本机提不动,它还有别的价值吗?
**A1**: 有。服务账户常对数据库、文件共享、其它服务器有特权。与其死磕本机 SYSTEM,不如用它的既有权限横向:连数据库执行命令、访问它有权的共享/主机。账户身份本身就是权限。
**Q2**: 比如我是 mssql 服务账户,怎么用?
**A2**: 该账户在数据库里常是高权;通过 DB 执行 OS 命令(若开启相关功能),或用它的域身份去 roast/委派。判据是"它在别处的权限有没有比本机 SYSTEM 更值钱"。
**Q3**: 服务账户外部权限也很有限,往哪转?
**A3**: 回到本机内存抓它缓存的其它凭据,或转普通域侧攻击。一个账户榨干后就换攻击面,别在单一身份上原地打转。

### WSUS / SCCM / 内网分发系统错配
**Q1**: 我怀疑能通过补丁/软件分发系统提权,先看什么?
**A1**: 看本机是否配了内网 WSUS 且走 HTTP(非 HTTPS),或有 SCCM 客户端。WSUS over HTTP 可被中间人下发恶意"更新"以 SYSTEM 执行;SCCM 有多种滥用(NAA 凭据、策略下发)。
**Q2**: WSUS 是 HTTP 但我不在中间人位置,怎么办?
**A2**: 需能篡改本机到 WSUS 的流量(本机 hosts/代理改写,或网络位置)。做不到中间人这条就不成立,转 SCCM 客户端侧或别的面。
**Q3**: 这类企业分发面都没有或都加固了,往哪转?
**A3**: 转标准本地提权与凭据面。分发系统滥用是"环境特定高收益"面,不存在就别强求,回主线。

### WMI 事件订阅 / 其它自动执行持久点被复用为提权
**Q1**: 常规自动执行点(服务/任务/Run)都封了,还有哪些高权触发面?
**A1**: WMI 永久事件订阅、登录脚本(GPO 下发)、Image File Execution Options(IFEO)劫持、辅助功能(sticky keys 类,需高权先写)。找"以高权执行且定义/目标我可写"的任何一个。
**Q2**: 我对某 GPO 下发的登录脚本目录可写吗要怎么想?
**A2**: 若我能写 SYSVOL 里的登录脚本或其引用文件,能影响所有应用该 GPO 的用户/机器,提权+横向兼得。但这通常需要已有一定域权限,判据是"我现在的权限够不够改到那个点"。
**Q3**: 这些冷门点也都不可写,往哪转?
**A3**: 说明本机配置面基本被榨干。转凭据/域侧,或换机器。穷举完自动执行点仍无果,继续找同类点的边际收益已很低。

### 提权到 SYSTEM 后立足点该怎么稳
**Q1**: 我拿到 SYSTEM 了,先干什么以免得而复失?
**A1**: 先固化立足点:确保有一条独立于当前漏洞的回连/持久(高权服务或任务),再抓本机全部凭据(hash/票据/DPAPI)。别急着炫技横向,先把"回得来"和"手里有钥匙"落实。
**Q2**: 持久化选哪种最稳又低调?
**A2**: 优先"看起来正常"的机制:一个命名普通的服务/计划任务,或复用已有合法自启项。避免高特征后门。判据是"运维例行检查时不显眼"。
**Q3**: 我该不该马上清日志?
**A3**: 谨慎。大规模清日志本身是强告警信号。优先精准处理关键条目或依赖行为伪装,而非清空。清得太干净比留点噪声更可疑。
**Q4**: 拿到 SYSTEM 但这台是孤立机(不入域、无横向价值),往哪转?
**A4**: 重估目标价值:若它只是边缘机,把重心转向它能触达的网段/凭据。SYSTEM 本身不是目标,它连通的东西才是。

### 全线提权失败:回到信息收集重扫
**Q1**: 配置、内核、凭据、域侧我都试了,全卡死,是不是该放弃这台?
**A1**: 先别放弃,先怀疑"我漏扫了"。提权失败十有八九是信息不全:换个自动化工具交叉验证、手工复核服务/任务/凭据、看有没有非默认路径的软件目录。盲区比"真无洞"更常见。
**Q2**: 重扫具体补哪些常见盲区?
**A2**: 用户 profile 深处的配置、非常规盘符/目录、计划任务的 XML 定义、注册表里冷门自启键、已停但可启的服务、PowerShell/命令历史、内存里的进程命令行(含明文口令参数)。
**Q3**: 换个身份视角会不会有新面?
**A3**: 会。有些可写点/凭据只对特定用户可见。若我能切到另一个已控账户的上下文再扫一遍,常暴露之前看不到的攻击面。权限面随身份变化。
**Q4**: 确实重扫也无果,该怎么理性转向?
**A4**: 转横向,别在单机上无限投入。判据:这台的信息价值(凭据、连通性)是否已榨取够本次目标;够了就把它当跳板,去打配置更松的邻居机。红队是找最弱一环,不是攻克最硬一台。
**Q5**: 万一这台就是必须拿下的关键靶(如目标数据就在本机),又提不动怎么办?
**A5**: 那就换战术目标:不一定要 SYSTEM 才能拿数据。以当前权限能否直接读到目标文件/数据库?能就绕过提权直取战果。提权是手段不是目的,盯住真正的战利品。

### SeTakeOwnership / SeRestore 组合夺取高权文件
**Q1**: 我有 SeTakeOwnershipPrivilege,单靠它能提权吗?
**A1**: 单独不够,它只让我"接管任意对象所有权"。提权链是:先 TakeOwnership 一个高权服务的 exe/关键文件,成为 owner 后自己给自己改 DACL(owner 可改权限),再写入我的载荷。它要和"改 ACL+写文件"配合才成闭环。
**Q2**: 我想接管某 SYSTEM 服务的二进制,怎么选目标最稳?
**A2**: 选一个非核心、可重启且会以 SYSTEM 拉起的服务二进制,接管后替换为 wrapper(先跑我的再调原逻辑),触发重启生效。别接管关键系统文件,改坏了整机不稳还惊动运维。
**Q3**: 我接管并改了权限,但文件被进程占用写不进去怎么办?
**A3**: 改一个当前未运行/可停止的服务的文件,或改注册表侧(ImagePath 指向我可写处),避开占用锁。占用是文件替换的常见坑,换"未加载的目标"绕过。
**Q4**: 只有 SeTakeOwnership 没有配套写/改 ACL 能力,这条断了,往哪转?
**A4**: 转其它明确的单点特权(SeImpersonate/SeBackup/SeRestore/SeDebug)或配置类面。特权提权讲究"这个特权的完整利用链是否闭合",链不闭合就别耗,换一个能独立成链的特权。

### 会话劫持:窃取已登录高权用户的令牌/会话
**Q1**: 我已是本机 SYSTEM,机器上还有别的用户登录着,能不能横向到那个身份?
**A1**: 能。SYSTEM 可枚举当前登录会话(query user / 进程令牌),窃取其它已登录用户(可能是域管/运维)的令牌起进程,或劫持其 RDP/交互会话。判据:是否有比我当前掌握的更高价值身份正登录着。
**Q2**: 有个管理员的断开(disconnected)RDP 会话,怎么利用?
**A2**: 以 SYSTEM 身份把该断开会话接管/连到我的会话(tscon 类机制),即可无口令进入其桌面上下文。这是"用 SYSTEM 换一个域高权用户身份"的经典跳板动作。
**Q3**: 我想窃取其令牌但该用户进程受保护/EDR 盯着,怎么办?
**A3**: 换取凭据而非令牌:该用户登录着,其凭据/票据大概率在 lsass 或 DPAPI 里,抓 hash/票据横向,避开直接操作其进程。令牌窃取和凭据窃取是两条路,一条被盯换另一条。
**Q4**: 机器上根本没有其它高权用户登录,这条作废,往哪转?
**A4**: 转"等待或诱导高权用户登录"(埋一个等登录触发的收集点),或直接转域侧主动攻击。会话劫持依赖"有高权用户在场",无人在场就别指望,回主动路线。

### 非域(workgroup)独立主机的提权取向差异
**Q1**: 这台是 workgroup 独立机不入域,提权思路要变吗?
**A1**: 要变。没有域,就没有 Kerberoast/ADCS/DCSync 这些域侧捷径,重心全压在本机:配置错误(服务/任务/AlwaysInstallElevated)、单点特权、内核/第三方漏洞、本机凭据。攻击面收窄但也更集中。
**Q2**: workgroup 机器的凭据价值怎么评估?
**A2**: 看本地账户口令是否在其它 workgroup 机复用——独立机常用同一套本地管理员口令批量部署(无 LAPS 时尤甚)。抓到本机 admin hash 做 PtH 扫同网段,常一把通吃多台。
**Q3**: 本机提权卡死,又没有域可借力,横向靠什么?
**A3**: 靠本地凭据复用 + 网络服务漏洞。转向:抓本机 SAM/LSASS 里的本地凭据去 PtH 邻居机,或找同网段开放的可利用服务(SMB/RDP/数据库)直接打进另一台。无域时"凭据复用+服务漏洞"是横向主力。
**Q4**: 目标就这一台孤立机、也不复用口令、服务也没洞,彻底没路了吗?
**A4**: 回到最基本判据:重扫信息盲区(见"全线失败"链),并重估是否真的需要提权——若战利品用当前权限已可取,直接拿数据收工。孤立机穷尽本机面后,提权的边际价值要和任务目标重新校准。
