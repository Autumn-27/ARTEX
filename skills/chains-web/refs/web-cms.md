# Web · CMS通用打法:识别→已知漏洞→后台getshell

### 拿到一个 Web 目标,第一步该不该急着扫漏洞
**Q1**: 面前一个 http://目标X,我是直接上漏扫,还是先做别的?
**A1**: 别急着漏扫。漏扫是"拿着锤子找钉子",效率低且吵闹。起手第一优先是**指纹识别**:先搞清"这是什么"(CMS/框架/中间件/语言),再决定"打什么"。判据:确定 CMS 品牌+大版本后,后续每一步(找 EXP、找后台、找上传点)都收敛成有限集合,决策成本骤降。
**Q2**: 怎么快速判 CMS 品牌?
**A2**: 多维交叉,不迷信单一特征。看:① 特征路径(/wp-admin、/administrator、/admin.php、?s=模块 等风格)② 静态资源指纹(favicon hash、特定 js/css 路径、meta generator)③ 响应头(X-Powered-By、Set-Cookie 名)④ robots.txt/sitemap/版权字样里的路径习惯。
**Q3**: 多个特征互相矛盾怎么办?
**A3**: 说明可能是二次开发/套壳/反代。以最难伪造的证据为准:favicon hash、独有资源路径比版权字样可信。矛盾本身是情报——套壳往往改了前台没改后台,后台路径和默认漏洞可能仍在。
**Q4**: 指纹这条路彻底不出结果(全被魔改)怎么办?
**A4**: 转正交维度——从"识别品牌"转到"识别行为特征":错误页(404/500 报错栈)的框架痕迹、参数风格、Cookie 结构,推断底层框架而非上层 CMS。再不行进入"按输入点找通用漏洞类"的纯黑盒模式,不依赖品牌。
**Q5**: 确认品牌后下一决策?
**A5**: 立刻求**精确版本**。品牌+版本才能一对一映射已知漏洞;版本不明时,已知漏洞只是概率游戏。

### CMS 品牌确定了,如何精确到小版本
**Q1**: 知道是某 CMS 了,但漏洞高度依赖小版本,怎么定版本?
**A1**: 版本比品牌值钱。途径:① 版本声明文件(CHANGELOG、README、version 常量、composer.json/package.json)② 资源版本化路径或 ?ver= 参数 ③ 版本间独有文件的存在性探测(有 A 无 B → 落在某区间)。
**Q2**: 版本文件被删/被 deny 了?
**A2**: 转"差异指纹"——用各版本间会变化的静态资源(js/css/图片的内容 hash)建比对库,响应体 hash 命中即定版本。被动式,不依赖敏感文件可读。
**Q3**: 只能定到区间定不到具体点?
**A3**: 够用就往下走。跨全区间存在的漏洞直接打;只在子区间的按"存在则赚、不存在再退"的顺序用无害 PoC 试探。
**Q4**: 版本看着很新像打了补丁?
**A4**: 别放弃已知漏洞。很多站"版本新但补丁没跟"或"只补核心没补插件"。转向:① 查该版本 **1day**(刚公开、多数站没修)② 火力从 CMS 核心转到**第三方插件/主题/扩展**——版本独立、更新滞后,是已知漏洞重灾区。
**Q5**: 完全无法确认版本、时间有限,往哪走?
**A5**: 放弃"版本驱动",转"输入点驱动"。不管版本,枚举所有可控输入(搜索/登录/注册/找回密码/上传/API),按通用漏洞类逐点黑盒测。版本只是提效的先验,不是必需品。

### 有了品牌+版本,如何系统化找已知漏洞
**Q1**: 品牌和版本都确定了,怎么变成可执行的攻击清单?
**A1**: 建"版本→漏洞"映射并按**收益/成本/隐蔽性**排序。优先级:未授权 RCE > 未授权任意文件读写 > 未授权 SQLi(可导后台)> 认证后 RCE > 需高权限的漏洞。越是前置条件少的越可能一击命中。
**Q2**: 漏洞很多先打哪个?
**A2**: 先打**前置条件最少且最隐蔽**的。一个需登录的 RCE 不如先看有没有未授权读配置文件的洞——读到数据库密码/密钥可能直接改变战局。同时评估动静,低噪声信息泄露先摸清环境再定杀招。
**Q3**: 公开 EXP 直接复制来打靠谱吗?
**A3**: 不靠谱,必先读懂原理。公开 EXP 常被阉割关键 payload、写死别的环境路径、或带后门。理解触发链后自己构造 payload,EXP 只作参考;否则打不通时你无法区分"没洞"还是"EXP 坏了"。
**Q4**: 一个已知洞打了没反应,是没洞还是环境问题?
**A4**: 分离变量。先用**无害探测**确认漏洞存在(时间盲注、DNSlog 确认 SSRF/命令执行出网),再上利用。区分"漏洞不存在"vs"存在但利用条件不满足(open_basedir、disable_functions、无回显)"——后者换手法不换漏洞。
**Q5**: 所有已知漏洞都试完全部无效怎么办?
**A5**: 转正交维度:① 从"CMS 本体"转**运行环境**(中间件/解释器/后端组件的已知漏洞)② 从"已知漏洞"转**配置缺陷**(目录遍历、备份、源码泄露、默认凭证、未授权接口)③ 从"通用漏洞"转**业务逻辑**(越权、流程绕过、验证码缺陷)。真实站常死在配置和逻辑上,而非 CVE。

### 未授权攻击面优先:登录框之前先看什么
**Q1**: 看到后台登录页,就该去搞登录吗?
**A1**: 先别扎进登录框。认证之前往往有**未授权可达的攻击面**:安装页重装、未授权 API、静态资源目录、调试接口、忘关的 setup/install。任何"不需要密码就能碰的东西"都比爆破登录先看。
**Q2**: 未授权面怎么枚举?
**A2**: ① 安装/初始化路径是否还开(能重装=直接控)② 调试/开发接口(debug/test/phpinfo/actuator 类)③ 未授权数据/管理 API(REST/GraphQL 越权)④ 目录列表开着的路径 ⑤ swagger/文档暴露的接口清单。
**Q3**: 找到疑似未授权接口但返回 403/401?
**A3**: 别放弃,试**授权绕过**:改 HTTP 方法、改路径大小写/结尾斜杠、路径穿越(..;/、%2e)、伪造来源头(X-Forwarded-For/X-Original-URL)、换 Accept/Content-Type。403 常是"前置代理拦了但后端没拦"。
**Q4**: 未授权面全封死了转哪?
**A4**: 回认证边界但带情报走:未授权枚举收集到的用户名、接口命名习惯、错误信息,拿去优化**认证攻击**(定向弱口令、找回密码逻辑、SQLi 绕登录)。未授权侦察的产出喂给认证攻击。

### 找到后台登录页:爆破还是绕过的取舍
**Q1**: 定位到管理后台登录,第一动作是爆破吗?
**A1**: 爆破是下策不是首选。按序试:① 默认/弱凭证(少量高频组合,不触发锁定)② 登录逻辑漏洞(SQLi 绕过、认证缺陷、找回密码接管)③ 万能密码。都不行再爆破。爆破噪声大、易锁定、易触发风控,暴露成本最高。
**Q2**: 怎么判断能不能爆破?
**A2**: 先探**防护机制**:验证码、失败锁定、频率限制、IP 封禁。用 3-5 次故意失败观察响应变化。若存在锁定,盲目爆破会把真实账号锁死,反而恶化。
**Q3**: 有验证码/锁定,爆破基本被墙,转哪?
**A3**: 转正交:① 攻**认证逻辑**而非密码——SQLi 绕登录、JWT/session 伪造、"记住我"token 可预测、找回密码流程缺陷。② 攻**其他认证入口**——API 登录、移动端接口、SSO 回调,常没有前端那套验证码和锁定。③ 若有未授权可达的管理功能,直接打**认证后漏洞**。
**Q4**: 用户名都不知道,如何缩小爆破空间?
**A4**: 先做用户枚举:登录/找回密码的**响应差异**(用户不存在 vs 密码错误的报错/时长)、注册重名提示、文章/评论作者、API 返回的用户对象。枚举出真实用户名后,爆破从"用户名×密码"降维为只爆密码,成功率数量级提升。
**Q5**: 拿到一组前台/低权账号能撬后台吗?
**A5**: 试**密码复用**和**越权**:同密码试后台/其他系统;低权账号访问高权功能(改 role、直接请求管理接口)。很多 CMS 前后台共用用户表,一个前台弱口令可能就是突破口。

### 进了后台,如何 getshell(通用套路优先级)
**Q1**: 已进管理后台,怎么最快拿到代码执行?
**A1**: 按成功率试:① **模板/主题编辑**(直接写脚本到模板文件)② **插件/扩展上传**(装带 webshell 的插件)③ **文件上传点**(头像/附件/媒体库+解析绕过)④ **配置项写文件**(某些设置会落地成脚本:网站配置、伪静态、缓存)⑤ **数据库操作**(执行 SQL 处 into outfile 或改配置)。
**Q2**: 后台功能多,怎么定位"能写文件/能执行"的点?
**A2**: 盯三类:任何让你**输入代码/模板/规则**的地方(模板引擎、伪静态、自定义标签)、任何**上传文件**的地方、任何**编辑并保存到服务器**的地方(在线编辑、导入导出、备份恢复)。它们是天然写入原语。
**Q3**: 模板编辑处输入被转义/沙箱了?
**A3**: 试 **SSTI** 沙箱逃逸(先辨引擎再针对打)。若真沙箱死,转"上传+解析"链:上传非可执行扩展名文件,再用解析漏洞或 .htaccess/配置让它被当脚本执行。
**Q4**: getshell 了但权限很低(www-data),要不要立刻提权?
**A4**: 先别急提权,先"扎根+扩面":落一个稳定隐蔽的 webshell/内存马,把当前权限能拿的都拿全(数据库、配置、密钥、内网可达性)。提权是后续独立阶段;当前目标是稳住立足点并收集下一跳情报。
**Q5**: 后台什么写文件的点都没有(纯展示型后台)怎么办?
**A5**: 转"**认证后的其他漏洞**":后台可达的 SQLi(→写文件/读配置)、后台参数触发的反序列化/文件包含、后台 SSRF(打内网)。getshell 不一定要"上传",一条认证后 SQLi 配数据库写文件权限同样成立。再不行,退回用后台读到的**敏感信息**(数据库配置、密钥、他系统凭证)做横向,绕开这台机器直接打后面。

### 上传/写文件被 WAF 拦截了怎么办
**Q1**: 上传 webshell 被 WAF 拦,放弃这个点吗?
**A1**: 不放弃。先定位**拦的是哪一层**:文件名/后缀?Content-Type?文件内容(eval/system 特征码)?请求结构?控制变量法逐项测——传纯净合法文件能过说明拦内容/名字,传畸形请求被拦说明拦结构。
**Q2**: 拦的是内容特征码?
**A2**: 转**免杀/变形**:webshell 加密编码、拆关键字、冷门执行函数、动态拼接、回调/变量函数。先传"无害探针"(只写时间戳的最小脚本)确认能过,再逐步加载荷,二分定位被拦关键字。
**Q3**: 拦的是文件名/后缀?
**A3**: 转**解析绕过+扩展名绕过**:大小写、双写、冷门可执行后缀、多后缀、结合中间件解析特性。或改思路:传合法后缀(图片/文档)含代码,再用文件包含/解析加载。
**Q4**: 拦的是请求结构/参数?
**A4**: 转 **HTTP 层混淆**:multipart 边界畸形、Content-Type 变造、参数污染、分块传输、大小写与空白扰动。很多 WAF 与服务端存在解析差异(parser differential)。
**Q5**: 上传这条路 WAF 焊死了,整体转哪?
**A5**: 绕开上传:① 换**非上传的写文件原语**(SQLi 写文件、日志包含、配置写入)② 换**内存马/无文件落地**(反序列化打内存马,不落磁盘绕过文件类规则)③ 换**目标**(WAF 通常只护 Web,转打同网段其他没被覆盖的服务/端口)。
**Q6**: 怀疑前面是云 WAF,能绕它本身吗?
**A6**: 试**溯源真实源站 IP**:历史 DNS、子域名、同证书资产、邮件头、SSRF 回连、源站直连错误配置。找到真实 IP 直接访问源站,云 WAF 形同虚设。这是被 CDN/WAF 挡住时的经典正交转向。

### 目标在 CDN/WAF 后面:先打谁
**Q1**: 目标解析到 CDN 直连打不动,怎么推进?
**A1**: 先分清要不要绕 CDN。只做加速不做防护,漏洞照打;是安全 CDN/云 WAF,优先**找源站真实 IP**:全球多地 DNS 历史、子域名(很多不挂 CDN)、SSL 证书指纹搜同证书资产、目标主动出网点(邮件/SSRF/webhook)、C 段联想。
**Q2**: 找到几个候选 IP 怎么确认源站?
**A2**: 用 Host 头绑定候选 IP 直接请求,比对返回是否与主站一致(同 title/同特定资源)。一致即源站,写死到 hosts,后续所有攻击走源站绕开防护。
**Q3**: 死活找不到源站,只能硬穿 CDN 怎么办?
**A3**: 转**低特征攻击**:用不触发规则的漏洞类(逻辑、越权、信息泄露通常不被 WAF 规则覆盖),避开高特征的 SQLi/RCE payload,或对 payload 变形绕规则。
**Q4**: CDN 还做频率限制/IP 封禁?
**A4**: 转**降速+分布式**:降频到阈值下、轮换出口 IP(代理池)、把爆破/枚举换成低频精准操作,优先选"一发命中"的漏洞而非需大量请求的盲注/爆破。

### 被目标封了 IP / 触发风控,如何继续
**Q1**: 打着打着 IP 被封(全超时/被 ban),还能救吗?
**A1**: 先确认**封的粒度**:封单 IP?封 C 段?封 session/指纹?换一个干净出口 IP 试——通就是封 IP,不通就是封了更细的指纹(UA/Cookie/TLS 指纹/行为)。
**Q2**: 确认封 IP 怎么换?
**A2**: 轮换出口:代理池、云主机、住宅代理(更像真实用户、更难批量封)。侦察阶段用可牺牲 IP,精准利用阶段用干净 IP,别把好 IP 浪费在高噪声操作上。
**Q3**: 换 IP 也很快被封,说明封的是行为?
**A3**: 转**降低行为特征**:放慢节奏、随机化间隔、模拟正常浏览器指纹和访问顺序、去掉扫描器特征(默认 UA、特定 header、固定路径顺序)。把机器行为伪装成人类行为。
**Q4**: 风控太强,正面成本过高,整体往哪转?
**A4**: 转攻击面而非死磕入口:① 换**资产**(其他域名/子域/旁站/C 段,防护强度不均衡,找最弱环)② 换**通道**(转暴露的其他端口:数据库/缓存/管理协议/VPN/邮件,常无 Web 风控)③ 换**路径**(授权范围内的供应链/第三方/社工)。

### 源码泄露 / .git / 备份文件:白盒化机会
**Q1**: 黑盒吃力,有办法拿到源码转白盒吗?
**A1**: 系统找**源码泄露**:.git/.svn/.hg 泄露、备份文件(.bak/.zip/.tar.gz/.sql/带日期名)、编辑器临时文件(.swp/~)、IDE 配置(.idea/.vscode)、vendor 泄露、打包发布带源码上线。拿到源码=黑盒变白盒,挖洞效率天翻地覆。
**Q2**: 发现 .git 可访问怎么利用?
**A2**: 用 git 泄露还原工具拉完整 .git 重建仓库,拿全部源码+历史。**提交历史尤其值钱**:开发者常在历史 commit 误提交过密码/密钥/内网地址,后来"删了"但历史还在。
**Q3**: 拿到源码先看什么?
**A3**: ① 配置文件(数据库/Redis/密钥/第三方凭证,可能直接改变战局)② 认证与上传相关代码(找绕过和 getshell 点)③ 危险函数(eval/system/反序列化/文件操作)反向定位入口 ④ 硬编码密钥(伪造 JWT/session/加密 token)。
**Q4**: 备份文件名猜不到、爆破没结果?
**A4**: 转**规律推断+其他泄露源**:按命名习惯(域名/项目名/日期格式)构造字典;查错误页/日志泄露的路径;查 JS 里的接口和路径。再不行放弃源码路线回黑盒——源码是加速器不是必需品。

### 已知漏洞全打完无效:转 0day/逻辑的分水岭
**Q1**: 该 CMS 所有公开漏洞都验证过确实没有,该放弃这个入口吗?
**A1**: 先问"真没有还是没找全"。盲区:① 第三方插件/主题(独立漏洞库,极易忽略)② 二次开发的自定义功能(不在任何 CVE 库,但可能有明显漏洞)③ 该版本最新 1day/补丁 diff。真实站的洞常在"CMS+客户改的那部分"的接缝。
**Q2**: 怀疑二次开发部分有洞,黑盒怎么挖?
**A2**: 回"输入点驱动":枚举所有自定义功能输入,系统测每类漏洞。二次开发代码通常没过安全审计,是最肥的猎场。若已拿源码则直接白盒审接缝代码。
**Q3**: 官方最新版补丁很新,想找 1day?
**A3**: 转**补丁 diff**:对比修复前后代码差异定位漏洞点反推 PoC。目标站若"版本新但没跟最新补丁"或"有虚拟补丁但源码没修",diff 出的洞仍可打。
**Q4**: 逻辑漏洞怎么找,和技术漏洞差在哪?
**A4**: 逻辑洞不看"函数危不危险",看"**流程能不能被打乱**":越权、状态跳跃(跳过付款/审核/验证)、条件竞争、参数篡改(改价格/角色/负数)、找回密码/绑定接管。这类 WAF 拦不住、扫描器扫不出,是 agent 卡死时最该转的正交维度。
**Q5**: 这个 CMS 铜墙铁壁,战术上如何止损?
**A5**: 转移目标而非死磕:加固到位的主站不如它一个疏于管理的旁站/子域/测试环境/老系统。单点超过合理时间无进展就横向换资产,把该点标记"低优先级,有新情报再回来"。

### getshell 之后:webshell 存活与后门策略
**Q1**: 传上一个 webshell 直接当立足点用可以吗?
**A1**: 先评估**存活性与隐蔽性**。特征明显的 shell 随时被查杀/被 HIDS 告警,连上即暴露。策略:① 用免杀 shell 或**内存马**(不落磁盘,查文件查不到)② shell 藏进正常文件的偏僻位置而非独立可疑文件 ③ 加访问口令,避免被同行/扫描器接管。
**Q2**: 怎么判断落地环境有没有 EDR/HIDS?
**A2**: 落地前先低调侦察:列进程找安全 agent、看 /etc 或注册表里的防护软件痕迹、观察高危命令是否被拦/延迟。发现有 EDR 就切"无文件+低频命令"模式,别用连续高危系统调用。
**Q3**: webshell 连上后命令执行被拦/无回显?
**A3**: 分离问题:确认是**命令被拦**还是**回显被截**。无回显转**外带**(DNS/HTTP 出网)确认命令是否真执行;命令被拦转**免杀执行**(编码命令、换执行组件、用语言内置能力而非调外部命令)。
**Q4**: 想长期驻留,除了 webshell 还有什么?
**A4**: 分层布置多个正交后门:内存马(隐蔽)、计划任务/服务(持久但易被发现)、合法功能的隐藏管理入口。原则:不同类型互为备份,一个被清另一个还在,避免单点后门被清即失去所有立足。
**Q5**: 落地点被发现清了,重新进不去了怎么办?
**A5**: 回到 getshell 前收集的情报做正交进入:之前读到的数据库/其他系统凭证、内网可达服务、密钥。别依赖同一个已暴露的 web 入口——它现在正被盯着。换资产、换凭证、换通道重新建立立足点。

### 目录/路径枚举:怎么扫才高效不吵
**Q1**: 要做目录扫描,直接上大字典全量爆吗?
**A1**: 不。全量大字典又慢又吵还易触发封禁。策略:先用**针对性字典**——已确认 CMS 就用该 CMS 的专用路径字典,命中率远高于通用字典。先精准后泛化。
**Q2**: 扫什么最有价值?
**A2**: 优先级:后台入口 > 备份/源码文件 > 配置/敏感文件 > 未授权接口 > 上传目录 > 调试页面。目标是找"能改变战局的东西",不是把目录列全。
**Q3**: 返回一堆 200/302 真假难辨怎么办?
**A3**: 先测**基线**:请求一个必然不存在的随机路径,看正常"404/存在"长啥样。若不存在的路径也返回 200(伪 404),就用**响应长度/内容相似度**过滤,而非只看状态码。
**Q4**: 扫描被 WAF/频率限制拦了?
**A4**: 转**降噪精扫**:降并发、按情报手工验证少量高价值路径,而非机器全量爆。或换正交侦察源——从 JS 文件、sitemap、robots、页面链接、历史归档里被动提取路径,完全不发扫描流量。
**Q5**: 后台入口就是扫不出来?
**A5**: 转**被动情报**:抓登录后跳转、看前端 JS 里硬编码的后台路由、查该 CMS 默认后台路径的变体、看重定向 Location 头。后台常被改名但前端代码或跳转逻辑会泄露真实路径。

### 用 favicon / 资源指纹反查同类资产
**Q1**: 手上一个目标,想快速扩大战果找同类系统怎么办?
**A1**: 用**favicon hash / 特征资源指纹**做全网测绘反查:同一套系统往往共用同一 favicon 和静态资源,以此反查出同组织/同厂商的其他资产。一个洞可能通打一批同款系统。
**Q2**: 为什么要找同类资产?
**A2**: ① 同款系统同一个已知漏洞可复用,主站难打时旁边同款可能没加固 ② 找到防护弱的同款先拿下,再横向回到主目标 ③ 验证 EXP:在一个同款上确认 payload 有效再用于主目标,降低主目标暴露风险。
**Q3**: 指纹搜出来一堆,怎么筛真正相关的?
**A3**: 按**归属关联**筛:同证书、同 IP 段、同注册信息、同子域命名规律的,才是同组织资产;仅同款但不同组织的属于旁证,用于验证 EXP 而非直接算战果。
**Q4**: 指纹测绘无果(资源被改/无独有 favicon)?
**A4**: 转其他关联维度:同 SSL 证书、同 ICP/whois、同 IP 反查、子域枚举、页面里的第三方统计 ID(同一 ID 常绑定同组织多站点)。资产测绘是多维交叉,不吊死在 favicon 一棵树。

### 安装 / 重装页面还开着:直接接管
**Q1**: 扫到 CMS 的安装/setup 页面还能访问,意味着什么?
**A1**: 高价值。若安装流程未被锁定,可能**重装接管**:重新走安装向导,把数据库指向可控库或重设管理员密码,直接拿到最高后台权限,绕过一切认证。这是"未授权→完全控制"的捷径。
**Q2**: 安装页在但提示"已安装"锁定了?
**A2**: 找**解锁条件**:很多 CMS 用一个 lock 文件标记已安装,若能删/绕过 lock 判断(路径可控、逻辑缺陷)就能重装。或看安装流程里是否有**未鉴权的子步骤**(某一步的接口单独可调),局部利用。
**Q3**: 重装会破坏现有数据,红队该做吗?
**A3**: 谨慎。授权红队要避免破坏生产数据。优先"**非破坏性利用**":只调用安装流程中能泄露信息或写文件的子接口,而非真的覆盖数据库。若必须重装,先评估影响和授权边界。
**Q4**: 安装页被删了这条路没了,转哪?
**A4**: 转**同类"初始化态"漏洞**:配置向导、数据库连接测试接口(常有 SSRF/写文件)、导入/恢复功能。这些和安装页同源——都是"信任初始配置"的逻辑,常缺鉴权。

### 读到数据库/配置文件之后:凭证怎么用
**Q1**: 通过任意文件读拿到了配置文件里的数据库密码,下一步?
**A1**: 别只盯这一个库。配置文件是**凭证金矿**:数据库口令、Redis/MQ 口令、对象存储密钥、第三方 API key、加密盐/JWT 密钥、SMTP。逐一评估每个凭证能撬开什么,按"能直接 RCE/横向"排序利用。
**Q2**: 数据库口令拿到但数据库端口不对外?
**A2**: 转**通过已有立足点连**:若已 getshell,从 web 机器本地连数据库(通常内网互通)。没 shell 就先用其他手段进内网再连。数据库口令的价值在"进得去内网"时兑现,记下待用。
**Q3**: 数据库能连上,怎么升级成 getshell?
**A3**: 试**数据库→文件系统**:写文件到 web 目录(需 FILE 权限+可写目录+知道物理路径)、UDF/存储过程执行命令、改 CMS 管理员密码进后台再走后台 getshell。选阻力最小的一条。
**Q4**: 拿到的是密码 hash 不是明文?
**A4**: 转**破解或复用 hash**:离线破解(字典/规则/彩虹表)、或某些协议可直接 pass-the-hash。破不出就把 hash 当情报存着,配合其他线索(密码复用规律)缩小范围。
**Q5**: 配置里的凭证全部试完都用不上,转哪?
**A5**: 转**密钥类利用**而非口令类:配置里的 JWT/加密密钥可**伪造合法凭证**(自签管理员 token/session),这条路绕过"账号密码"这一整层,常被忽略却极致命。

### 拿到 SQL 注入:从注入到 getshell 的路径选择
**Q1**: 确认了一个 SQLi,直接 dump 数据吗?
**A1**: dump 数据只是最低收益。先规划升级路径:① 读**管理员凭证**→进后台→后台 getshell ② 若有 FILE 权限→**写 webshell 到 web 目录** ③ 读**配置文件/密钥**→横向或伪造凭证 ④ DBMS 特性→**直接执行命令**。按目标环境选阻力最小的升级链。
**Q2**: 怎么判断能不能 into outfile 写 shell?
**A2**: 三个前提:数据库账号有 FILE 权限、目标目录可写、知道 web 目录物理路径。缺物理路径就先从报错/phpinfo/配置泄露里找;缺 FILE 权限就放弃写文件,转"读凭证进后台"路线。
**Q3**: 注入是盲注,数据取不动怎么办?
**A3**: 盲注慢但可自动化。先只盲取**最高价值的少量数据**(管理员账号密码 hash、一个密钥),而非全表 dump。拿到后台凭证就脱离注入这条慢路,进后台走快路。
**Q4**: 注入点被 WAF 拦?
**A4**: 转 **SQLi 绕 WAF**:注释/大小写/编码/等价函数/内联注释混淆、参数污染、改注入位置。或换**注入手法**:报错注入被拦转时间盲注,联合被拦转布尔盲注。再不行换**别的注入点**——一个站常有多个注入,换个防护弱的。
**Q5**: 数据库是不出网也不能写文件的受限环境,注入还有什么用?
**A5**: 回到"注入=读能力"的本质:读**凭证和配置**做横向,读**业务数据**找逻辑突破口,读**其他表**里的其他系统信息。读能力本身就是情报入口,不一定非要在这台机器上 getshell。

### 无回显场景:盲注 / 无回显 RCE 怎么确认和利用
**Q1**: 打一个疑似 RCE 的点,没有任何回显,怎么确认它到底通没通?
**A1**: 无回显不等于没执行。用**带外确认(OOB)**:让目标主动出网访问你可控的 DNS/HTTP(如执行 nslookup/curl 你的唯一子域)。收到请求=命令确实执行了。这是区分"漏洞不存在"和"存在但无回显"的关键判据。
**Q2**: 连 DNS/HTTP 都收不到,目标不出网?
**A2**: 先降级确认:用**时间延迟**(执行 sleep,看响应变慢)确认代码执行——不出网也能测。确认了执行能力,再解决数据带出问题。
**Q3**: 确认执行了但拿不到回显,怎么把结果带出来?
**A3**: 转**盲打外带**:把命令结果编码进 DNS 查询/HTTP 请求的域名或路径里带出。或写结果到 web 可读文件再去读。无回显利用的核心是"另找一条数据出口",不是死等原路回显。
**Q4**: 目标完全不出网又无可读落地点,几乎全盲?
**A4**: 转**内存马/反连**:利用点直接注入内存马,后续通过它交互,绕开"原始利用点无回显"。或想办法让目标反向连接你(需目标能出网到某端口)。全盲下"建立一条自己的交互通道"比修复原点回显更实际。
**Q5**: 反连也被出网限制挡死,彻底盲怎么办?
**A5**: 承认这台机器是"哑终端",转策略:用盲能力只做**最小必要动作**——写一个稳定 webshell 到已知可读路径、或落地一个能被其他通道触达的驻留点,把"盲执行"转成"半盲的文件读写通道",再基于它逐步扩展。

### 文件包含(LFI/RFI):从读文件到 getshell
**Q1**: 发现一个文件包含点,先干嘛?
**A1**: 先确认**类型和范围**:能包含远程(RFI)还是仅本地(LFI)?有无路径限制/后缀强制?RFI 可直接包含远程脚本 getshell,最省事;LFI 则要找"能被包含且含可控内容"的本地文件。
**Q2**: 只有 LFI,怎么升级成代码执行?
**A2**: 找**可控内容的本地文件**去包含:上传的图片马、web/中间件**日志**(把 payload 写进 UA/请求里再包含日志)、session 文件、临时文件、/proc 相关。核心是"先让恶意内容落到本地某文件,再包含它"。
**Q3**: 有后缀强制(自动加 .php 等)或路径限制?
**A3**: 试**截断/协议绕过**:路径穿越定位、封装协议(php://filter 读源码、data://、php://input 视配置)、编码绕过。读不到 shell 至少能**读源码转白盒**和读配置文件拿凭证。
**Q4**: 什么都包含不了,利用条件全不满足,转哪?
**A4**: 把 LFI 降级当**任意文件读**用:读配置拿数据库/密钥凭证做横向,读源码转白盒审计找别的洞。文件包含即使无法 getshell,其"读"能力也是高价值情报入口,别浪费。

### 反序列化入口:识别与利用
**Q1**: 怀疑某处有反序列化,怎么确认入口?
**A1**: 找"**把不可信输入喂给反序列化**"的地方:Cookie/参数里的序列化特征(PHP 的 O:/a:、Java 的 rO0AB/ac ed 00 05、.NET 的特征、Python pickle)、明显的 base64 序列化串。识别语言和序列化格式是选 gadget 的前提。
**Q2**: 确认是反序列化了,但没现成的利用链?
**A2**: 找 **gadget 链**:依赖目标加载了哪些库/组件。先摸清依赖(报错、源码、指纹),再选对应的公开 gadget。同一序列化点,换不同 gadget 链就是换"能不能打通"的关键变量。
**Q3**: gadget 打了没反应,是没链还是被拦?
**A3**: 先用**探测型 gadget**(只触发 DNS/延迟,不直接 RCE)确认链是否可达。可达但 RCE 不成,是 gadget 与环境不匹配→换链;完全无反应可能是入口没真正反序列化→回头验证入口。
**Q4**: 有反序列化但所有已知链都被防护/版本不匹配打不通?
**A4**: 转向:① 利用反序列化做**非 RCE 危害**(SSRF、文件读写、DoS)也能推进战局 ② 转**内存马**利用方式绕文件检测 ③ 放弃这个点,转正交漏洞类。反序列化 gadget 强依赖环境,打不通很正常,别在单点耗尽预算。

### SSTI:识别模板注入并逃逸沙箱
**Q1**: 输入被回显到页面,怀疑 SSTI,怎么确认?
**A1**: 用**数学表达式探针**:输入形如 {{7*7}} / ${7*7} / #{7*7} 等各引擎语法,若回显 49 说明模板在服务端求值=SSTI。哪种语法生效直接暴露了模板引擎类型。
**Q2**: 确认 SSTI 后怎么升级到 RCE?
**A2**: 按引擎选**逃逸链**:不同引擎从模板上下文对象爬到可执行命令的路径不同(访问内置对象→反射/内省→拿到命令执行原语)。先定引擎,再套该引擎的成熟逃逸 payload。
**Q3**: 引擎有沙箱,常规逃逸被拦?
**A3**: 转**沙箱绕过**:换访问路径(不同属性链绕过黑名单)、字符串拼接绕关键字过滤、编码绕过。沙箱通常是黑名单,总有没堵死的间接路径,逐一试对象链。
**Q4**: 沙箱很严,RCE 死活出不来,转哪?
**A4**: 降级利用:SSTI 即使不 RCE,也常能**读服务端变量/配置/密钥**(访问配置对象)、做 SSRF、读文件。拿到密钥可去伪造凭证。把"RCE 失败"转成"信息泄露成功",战局照样推进。

### SSRF:让服务器帮你打内网
**Q1**: 发现一个 SSRF(能让服务器发请求),它值多少?
**A1**: SSRF 是"内网入场券"。价值在于以服务器身份访问**外部够不到的东西**:内网服务、云元数据接口、本机回环上的管理端口。先探测目标能不能出网、能访问哪些内网段。
**Q2**: SSRF 先打什么?
**A2**: 优先级:① 云环境先打**元数据接口**(可能拿临时凭证/AK-SK,直接升级云权限)② 本机回环上的**未授权管理服务**(常绑 127.0.0.1 且无鉴权)③ 内网其他主机的未授权服务(缓存/数据库/管理协议)。
**Q3**: SSRF 有协议/域名白名单限制?
**A3**: 转**绕过**:改 IP 表示法(十进制/十六进制/省略)、DNS rebinding、URL 解析差异、跳转跟随、换协议(gopher 可构造任意 TCP 打内网服务)。gopher 能把 SSRF 从"只能 GET"升级成"能打协议级交互"。
**Q4**: SSRF 只能发请求收不到回显(盲 SSRF)?
**A4**: 转**盲打+外带**:用 DNS 确认可达性,用能"仅凭一个请求就产生副作用"的目标(如向未授权 Redis/内网接口写数据触发 RCE),无需回显也能利用。盲 SSRF 靠"打有副作用的目标"而非"读响应"。
**Q5**: 内网完全隔离、SSRF 出不去也打不到东西,转哪?
**A5**: 把 SSRF 当**内网探测器**用:即使不能利用,用它的响应差异/时长做**内网端口和存活探测**,画出内网拓扑当情报。探测结果指导后续拿到真正立足点后往哪打。

### XXE:XML 外部实体的利用取舍
**Q1**: 目标解析 XML,怀疑 XXE,先测什么?
**A1**: 先测**实体解析是否开启**:注入一个引用外部实体的探针,让它请求你的服务器(OOB)。收到请求=XXE 成立且能出网。这一步同时确认了漏洞和出网能力。
**Q2**: XXE 确认了,能干什么?
**A2**: 主要三类:① **任意文件读**(读配置/源码/凭证)② **SSRF**(以服务器身份打内网,同 SSRF 链)③ 某些环境下的 RCE(依赖特殊扩展)。文件读和 SSRF 是最稳收益,优先。
**Q3**: 有回显直接读,无回显怎么办?
**A3**: 转 **OOB 外带 XXE**:用外部 DTD 把读到的文件内容拼进对你服务器的请求里带出。无回显 XXE 靠带外通道拿数据,和盲注思路一致。
**Q4**: 目标禁用了外部实体 / 有防护,XXE 打不了,转哪?
**A4**: 转其他 XML 相关问题(XInclude、SOAP/SAML 处理缺陷)或干脆转正交漏洞类。同时,凡是"服务器解析用户提供的结构化数据"的地方(不止 XML,还有各种解析器)都是同源攻击面,横向找类似入口。

### 前台注册 / 越权:从普通用户撬到后台
**Q1**: 后台打不动,但前台能注册普通用户,有用吗?
**A1**: 极有用。有了"认证后身份"就打开了**认证后攻击面**:普通用户能访问的接口远多于游客,其中常有越权和上传。先注册进去,把认证后的功能全枚举一遍。
**Q2**: 普通用户怎么升成管理员?
**A2**: 试**垂直越权**:直接请求管理接口(前端不显示不等于后端不可达)、注册/改资料时篡改 role/权限字段(mass assignment)、改 user id 访问他人/高权数据。很多系统前端做权限控制、后端没校验。
**Q3**: 越权都被后端校验挡住了?
**A3**: 转**水平越权+功能滥用**:横向访问其他同级用户数据找突破,或利用普通用户可用的功能(上传/导入/分享)找注入或文件写入。权限撬不动就在"允许的功能"里找技术漏洞。
**Q4**: 注册被关闭 / 需审核?
**A4**: 转**获取一个已有账号**:弱口令爆一个普通用户、找回密码接管、注册逻辑绕过(直接调注册接口跳过前端限制)、或从信息泄露里拿到一组凭证。目标是"搞到任意一个认证身份",来源不限。
**Q5**: 实在拿不到任何账号,转哪?
**A5**: 退回**未授权面和游客可达漏洞**,或转其他资产。认证后攻击面很肥,但前提是有身份;拿不到身份时不要卡在这条路,先去别处找入口,拿到凭证/内网立足点后可能反过来解决这里。

### 验证码 / token / 短信:逻辑绕过的思路
**Q1**: 一个功能(登录/找回密码)被验证码挡住,怎么破?
**A1**: 先别想"识别验证码",先测"**验证码是否真校验**":不传验证码参数、传空、传旧值复用、并发请求,看后端是否真验。大量验证码是"前端摆设/后端不校验/一次生成可复用",逻辑破绽比图像识别好用得多。
**Q2**: 验证码确实校验了,但想爆破?
**A2**: 找**校验缺陷**:验证码是否有次数/时效限制(无限制则可爆)、是否绑定 session、错误后是否刷新(不刷新则可对同一验证码爆密码)。短验证码+不刷新+无锁定=可直接爆破。
**Q3**: 短信/邮件验证码(找回密码)怎么绕?
**A3**: 攻**验证逻辑**而非猜码:验证码是否可爆(4-6 位无锁定)、响应里是否泄露了正确码、校验和重置是否是**两个独立步骤**(直接调重置接口跳过验证)、越权改他人手机号/邮箱、token 可预测。
**Q4**: token(找回密码链接里的)怎么打?
**A4**: 看 token **可预测性/可越权**:是否基于时间戳/自增/弱随机可推算、是否与用户绑定(不绑定则可拿自己的 token 改他人)、是否过期。弱 token 生成是找回密码接管的高频点。
**Q5**: 所有绕过都失败,验证码/token 逻辑很扎实,转哪?
**A5**: 转正交:换**没有验证码保护的入口**(API/移动端接口常无验证码)、换攻击目标(不打这个受保护功能,打别的)。验证码只保护特定功能,绕不过就绕开——找它没覆盖的地方。

### 中间件 / 容器漏洞:CMS 本体之外的入口
**Q1**: CMS 本身很干净,还能从哪进?
**A1**: 抬眼看 **CMS 底下的运行栈**:Web 中间件(Nginx/Apache/IIS/Tomcat)、应用容器、语言解释器、反代/负载均衡、管理面板。这些和 CMS 独立打补丁,常年久失修,是被忽视的入口。
**Q2**: 怎么发现中间件漏洞?
**A2**: 指纹中间件及版本(响应头、错误页、默认页),映射其已知漏洞:解析漏洞、目录穿越、认证绕过、已知 RCE、危险默认配置(如某些管理接口默认开放)。中间件版本比 CMS 更容易暴露且更容易漏修。
**Q3**: 目标跑在容器/云上,有额外攻击面吗?
**A3**: 有。容器编排/管理接口(未授权的编排 API、容器管理端口)、容器逃逸、云元数据接口(拿云凭证)。getshell 进容器后,重点评估**能否逃逸到宿主或横向到其他容器**,以及能否拿到云 AK/SK。
**Q4**: 中间件也全是最新版没洞,转哪?
**A4**: 转**配置层**而非版本层:中间件的错误配置(目录列表、危险 HTTP 方法开放、别名/rewrite 配置不当导致的路径穿越或未授权)。版本再新,配错了照样能打。配置缺陷不吃版本。

### 旁站 / C 段 / 子域:横向选择哪个先打
**Q1**: 主目标很硬,想从周边突破,先打旁站还是 C 段?
**A1**: 先分清关系:**旁站**(同服务器其他站点)一旦拿下直接就在目标机器上,价值最高;**子域**(同组织其他业务)横向价值高;**C 段**(同网段其他主机)关系较松,需确认归属和授权。优先旁站>子域>C 段。
**Q2**: 旁站怎么帮到主目标?
**A2**: 同服务器旁站 getshell = 直接拿到主目标所在机器的权限,主站的加固全绕过。所以主站难啃时,把同 IP 上防护弱的旁站当"侧门",拿下即等于拿下主站宿主。
**Q3**: 子域打下来了怎么回到主目标?
**A3**: 子域是**情报和凭证来源**:同组织常有共享的账号体系、内网访问、SSO、数据库、密码复用。从子域拿到的凭证/内网立足点,回过头打主目标的内网侧或认证侧,绕开其正面防护。
**Q4**: 周边资产也都很硬,横向这条路不通,转哪?
**A4**: 转**授权边界内的其他维度**:供应链(目标用的第三方系统/开源组件)、社工钓鱼(在授权范围)、暴露的非 Web 服务。同时复查是否**授权范围**限制了资产选择——别越界打不在授权内的 C 段主机。

### JWT / session / 密钥:伪造凭证绕过认证
**Q1**: 系统用 JWT/token 做认证,能不能伪造?
**A1**: 先分析 token 结构和签名机制。JWT 常见破绽:① alg=none 绕签名 ② 弱密钥可**离线爆破 HMAC 密钥**再自签 ③ 算法混淆(RS256→HS256 用公钥当密钥)④ 未校验签名。任一成立即可伪造任意用户(包括管理员)。
**Q2**: 拿到了签名密钥(从源码/配置泄露)怎么用?
**A2**: 直接**自签任意身份**:构造 admin 用户/提权 claim 的 token,一步绕过整个登录体系。这就是为什么配置/源码里的密钥比口令更致命——它给的是"伪造合法身份"的能力。
**Q3**: 是传统 session(服务端存储)不是 JWT,还能伪造吗?
**A3**: 看 session 生成/校验:session id 是否可预测、是否绑定 IP/UA、是否存在固定/可注入。若 session 数据序列化在客户端(带签名),同 JWT 思路找密钥伪造。服务端存储的 session 则转**会话固定/窃取**思路。
**Q4**: token 机制很严实,伪造不了,转哪?
**A4**: 转**获取真实 token**而非伪造:XSS 偷 token、中间人、日志/referer 泄露 token、其他接口回显 token。伪造走不通就想办法"借用"一个真的。再不行回到账号密码维度或其他入口。

### API / GraphQL:结构化接口的攻击面
**Q1**: 前端是 SPA、后端是 API,和传统 CMS 打法有何不同?
**A1**: 攻击面从"页面"转到"接口"。先**全量收集接口**:抓前端 JS 里的路由和接口定义、找 swagger/openapi 文档、GraphQL 的 introspection。接口清单越全,可测的越多——很多接口前端没用到但后端可达。
**Q2**: API 重点测什么?
**A2**: ① **越权**(改 id/删授权头访问他人或管理数据,API 是越权重灾区)② 批量参数篡改(mass assignment 改 role)③ 未授权接口(部分接口漏了鉴权)④ 注入(接口参数照样有 SQLi/NoSQLi/命令注入)。
**Q3**: 是 GraphQL,怎么打?
**A3**: 先开 **introspection** 拿全 schema(暴露所有类型和查询)。然后找:未授权查询、越权访问、嵌套查询 DoS、批量查询绕过限流、mutation 里的危险操作。introspection 关了就从前端抓已用的 query 逆推 schema。
**Q4**: 接口都鉴权严格、越权也堵死了,转哪?
**A4**: 转**接口的技术漏洞**而非逻辑:参数注入、文件上传接口、SSRF 型接口(接受 URL 参数的)、反序列化(接口收结构化数据)。逻辑打不动就回归"每个输入参数都是潜在注入点"的黑盒基本功。

### 密码复用与凭证横向:一把钥匙开多把锁
**Q1**: 拿到一组凭证(某处的账号密码),除了当前系统还能干嘛?
**A1**: 立刻**横向复用**。人和组织普遍密码复用:同一密码试后台、试其他子系统、试数据库/SSH/邮箱/VPN。一组凭证的真正价值往往不在它来源的系统,而在它能横向打开的其他系统。
**Q2**: 拿到的是一批用户凭证(脱库),怎么高效利用?
**A2**: 做**凭证喷洒**:提取密码规律(公司名+年份、季节等常见构造),对其他系统的用户批量试。用"少量高频密码 × 多用户"而非"多密码 × 单用户",避开锁定同时最大化命中。
**Q3**: 明文没有只有 hash,复用还有戏吗?
**A3**: 有:① 离线破解出明文再复用 ② 部分协议直接 **pass-the-hash** ③ hash 本身当"同不同"的判据(相同 hash=相同密码,揭示复用关系)。破不出的 hash 也是情报,别丢。
**Q4**: 凭证复用全部失败,转哪?
**A4**: 转**凭证之外的信任关系**:密钥/token/证书(伪造身份而非猜密码)、已建立的会话、机器间的免密信任(内网常见)。密码复用是横向的一条路,不是唯一路;信任关系比密码更值钱。

### getshell 后受限:disable_functions / open_basedir 绕过
**Q1**: 拿到 webshell 但执行命令的函数全被禁(disable_functions),怎么办?
**A1**: 别以为 shell 废了。绕 disable_functions 有多条正交路:① 找**没被禁的执行函数**(禁列表常不全)② 利用语言/扩展特性(如 LD_PRELOAD 配合可触发的外部调用、特定扩展的漏洞)③ 用**内存马**在进程内执行,不依赖被禁的命令函数。
**Q2**: open_basedir 限制了只能访问 web 目录?
**A2**: 试**穿越/绕过**:利用某些函数不受 open_basedir 约束的特性、符号链接、或已知的绕过技巧访问目标目录。绕不过就在**允许范围内**利用:web 目录里的配置/凭证照样能读,拿去横向。
**Q3**: 命令执行绕不出来,shell 只剩文件读写,还能推进吗?
**A3**: 能。"读写"就够干很多事:读配置/密钥/凭证做横向、写文件到能被解析或被其他进程加载的位置、改配置文件影响应用行为。把"受限 shell"当"文件读写原语"而非"命令行"来用。
**Q4**: 各种绕过都失败,这台机器彻底限死了,转哪?
**A4**: 转**用当前有限能力换取更好的立足点**:读到的凭证连内网其他没限制的机器、找同机器上别的服务(权限配置不同)。承认这台被限死,把它当"跳板/情报点"而非"作战平台",战场转移到它能触达的下一台。

### 低权 shell 之后:提权阶段往哪个方向找
**Q1**: getshell 是低权用户(www-data/apache),想提权到 root/system,先看什么?
**A1**: 先**系统性信息收集**再动手。提权是"找配置错误",不是"背 EXP"。收集:系统版本/补丁、运行的高权服务、可写的高权文件、计划任务、sudo 权限、凭证残留。用自动化枚举脚本先画全景,再择优。
**Q2**: 收集完了,提权路线怎么排序?
**A2**: 优先**低风险高确定性**的:错误配置(可写的服务文件/计划任务、sudo 配置不当、SUID 滥用)> 明文凭证复用(找到 root 密码/密钥直接用)> 内核 EXP(最后选,易崩溃且噪声大)。配置错误比内核提权稳得多。
**Q3**: Windows 主机提权看什么不一样?
**A3**: 看**服务与令牌**:未加引号服务路径、可改的服务、AlwaysInstallElevated、令牌权限(SeImpersonate 类→土豆家族提权)、凭证(注册表/文件/内存里的密码和 hash)。域环境里的机器还要评估域层面的提权路径。
**Q4**: 常规提权全试完提不上去,转哪?
**A4**: 转**横向代替纵向**:本机提不上去,但当前权限能读到的凭证/能访问的内网服务,也许在**另一台机器上直接是高权**。红队目标是拿到关键权限,不一定非在这台机器上垂直提权——横着走到更软的高权目标同样达成目标。
**Q5**: 是域环境,单机提权意义还大吗?
**A5**: 视目标而定。若目标是域控,单机 root/system 只是拿本机凭证的手段,重点转**域内攻击链**(Kerberoast、ADCS 证书攻击、委派滥用、zerologon 类)。本机提权服务于"拿到能打域的凭证/机器身份",而非终点。

### 免杀落地与痕迹:隐蔽性与推进速度的取舍
**Q1**: 每一步都要免杀和清痕迹吗,会不会拖慢?
**A1**: 分阶段权衡。**侦察阶段**可以稍吵(反正难避免流量),但**落地和驻留阶段**必须隐蔽——这是最易被 EDR/HIDS 抓的环节。原则:高价值动作(落 shell、提权、横向)务必低特征;低价值探测可容忍噪声。
**Q2**: 怎么判断该多隐蔽?
**A2**: 看**环境防护强度**和**任务目标**。有 EDR/态势感知的环境,一次告警可能全盘暴露,必须极致隐蔽;纯打点拿 flag 的场景可适当激进。先花少量成本探测防护(有没有安全 agent、命令是否被记录),据此定策略。
**Q3**: 已经触发了一次告警,怎么止损?
**A3**: 立刻评估**暴露程度**:告警是否已被响应(封 IP/清 shell/改密码)。若被响应,当前入口作废,切到**预留的正交后门/凭证**低调恢复,别在被盯的入口继续动作。多点驻留的价值在此刻兑现。
**Q4**: 要不要清日志?清了会不会更可疑?
**A4**: 权衡。**授权红队通常不删业务/系统日志**(破坏取证、易被察觉异常)。更稳的是"**少留痕**"而非"事后删":用不落地手法、避开被审计的高危操作,从源头减少痕迹,好过留下"日志被清空"这个更醒目的信号。
**Q5**: 隐蔽要求太高,推进几乎停滞,怎么办?
**A5**: 重新校准**目标与授权**:任务真正要证明什么?若只需证明"可 getshell/可拿某权限",拿到即止,不必步步深入触发更多风险。隐蔽与推进冲突时,回到"这次行动的最小成功判据",达成即收,而非无限扩大战果。

### 全局卡死:如何判断该换维度并重排优先级
**Q1**: 一个目标打了很久毫无进展,怎么判断是"再坚持一下"还是"该换方向"?
**A1**: 设**止损判据**:同一攻击面/同一漏洞类连续多次尝试无实质进展(不只是没成功,是"没有新信息产出"),就该转向。判据不是时间,是"信息增量"——只要每次尝试还在缩小未知,就继续;开始原地打转,就换维度。
**Q2**: 该往哪个正交维度转?有没有系统方法?
**A2**: 用**攻击面矩阵**逐维过:识别层(换指纹/版本手段)→漏洞层(已知漏洞/配置缺陷/逻辑漏洞/0day)→入口层(Web/其他服务端口/认证入口)→资产层(主站/子域/旁站/C 段/供应链)。哪一维还没认真试过,就转哪维。卡死通常是因为在一个维度里死磕。
**Q3**: 怎么避免"频繁乱换、每个都浅尝辄止"的另一个极端?
**A3**: 维护一张**尝试记录**:每个攻击面标注"试过什么、结论、是否还有未尽路径"。转向前先确认当前面确实"该穷尽的都穷尽了",转向后能随时回到有残留价值的点。有记录才能既不死磕也不瞎换。
**Q4**: 所有维度都过了一遍还是进不去,是不是真打不动了?
**A4**: 回头**质疑前提**:目标范围对不对(有没有遗漏的资产/子域)、情报够不够新(有没有刚公开的 1day)、有没有信息盲区(某个泄露源没查)。卡死常不是"没有洞",而是"情报不全"。补情报(重新测绘、重新收集)往往比硬打更有效。
**Q5**: 确认目标当前确实无懈可击,该怎么收尾?
**A5**: 转**时间维度和被动维度**:标记目标为"待新情报",挂上被动监控(新漏洞公开、资产变化、凭证在其他渠道出现),把精力转到更有产出的目标。红队是资源分配游戏,一个暂时打不动的硬目标,不值得无限投入——记录情报,择机再战。
