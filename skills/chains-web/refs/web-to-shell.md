# Web · 从web漏洞落地到系统shell

### SQL 注入：从"能查库"变成"能拿 shell"
**Q1**: 已确认 SQLi 且能读数据，但目标是系统 shell 不是脱裤，先判断什么？
**A1**: 先定三件事：数据库类型（MySQL/MSSQL/Oracle/PG）、当前 DB 用户权限（`current_user`/`is_srvrolemember('sysadmin')`）、DB 与 Web 是否同机。落 shell 的通道强依赖这三点，别急着堆 payload，先把三格填满。

**Q2**: 目标是 MySQL 且是 root，怎么落地？
**A2**: 优先看 `secure_file_priv`：为空则 `INTO OUTFILE` 往 web 目录写 webshell（前提：知道绝对路径 + 目录可写 + 有堆叠或 union 写入位）。拿不到 web 绝对路径就靠报错/`@@datadir`/配置泄露/phpinfo 猜。`secure_file_priv` 有限制则转 UDF 提权（写 `lib_mysqludf_sys` 到 plugin 目录执行系统命令）。

**Q3**: MSSQL 且高权限呢？
**A3**: 直奔 `xp_cmdshell`（关了就 `sp_configure` 开）；被删/被禁则用 `sp_OACreate` 组件、CLR 程序集、Ole Automation 三条备选，本质是找"存储过程→执行系统命令"的桥。

**Q4**: 拿不到 web 物理路径、`INTO OUTFILE` 无处可写，怎么办？
**A4**: 这条路先搁置，转正交维度——不写 webshell，改走"DB 内直接执行命令"（UDF/xp_cmdshell/CLR），它不依赖 web 目录。DB 权限也不够执行命令，再退一层：把 SQLi 当**信息源**，读配置/读口令/dump hash，去横向打别的入口。

**Q5**: 只有低权 DB 账号，既不能写文件也不能执行命令，注入这条线死了吗？
**A5**: 不算死。低权注入价值转为：读 `information_schema` 找敏感表、读应用配置（连接串常含高权账号）、dump 后台管理员 hash 去爆破登录后台，再从后台功能点 getshell。**转向**：从"注入直接落地"转成"注入→凭据→换更肥的攻击面"。

**Q6**: 判断"是否同机"为什么关键？
**A6**: 决定 UDF/xp_cmdshell 拿到的 shell 落在哪台。DB 与 Web 分离时，DB 命令执行给你的是 DB 服务器立足点，可能更贴近内网核心；按目标重新规划横向路径即可。

### 文件上传：绕过校验拿到可解析的 webshell
**Q1**: 找到上传功能想传 webshell，第一步摸清什么？
**A1**: 摸清校验在哪层：前端 JS（改包绕过）、Content-Type、后缀黑/白名单、文件头 magic、内容查杀（WAF/杀软扫 payload）。还要摸清落地路径是否可访问、是否可解析对应脚本。校验层没摸清就乱试等于盲人撞墙。

**Q2**: 后缀是白名单只允许图片，怎么突破？
**A2**: 两条主线：一是**上传解析分离**——传图片马配合 LFI/包含/缩略图处理触发；二是找**解析漏洞或次要后缀**（`.php3/.phtml/.pht`、大小写、双写、末尾特殊字符、`::$DATA`、路径截断）。解析漏洞强绑中间件，先探中间件类型。

**Q3**: 白名单严格、无解析漏洞，但上传目录我能控？
**A3**: 转 `.htaccess`/`web.config` 攻击：上传配置文件让某"无害后缀"被当脚本解析，再传该后缀马。Nginx 无 htaccess 则回到解析漏洞/图片马+包含链。

**Q4**: 传上去但访问 404 或返回源码不解析，怎么转？
**A4**: 说明落点不在 web 可访问路径、或该目录被配为静态/禁执行。**转向**：找配置泄露/报错拿真实落点，或改传到可解析目录；上传路径完全不可控则放弃 webshell，把上传点转为**其他载体**——触发后端处理组件漏洞（图片库 RCE、XXE、ZIP 解压穿越写文件）。

**Q5**: 内容被 WAF 查杀，一句话马刚传就被删？
**A5**: 转免杀维度：拆分/编码/变形一句话，用不含敏感字面量的动态调用、加密马、极小 loader 二段加载。查杀严重时优先落**内存马**减少落地文件被扫窗口。

**Q6**: 全站上传点都堵死，方向终结了吗？
**A6**: 转正交面：从"上传 getshell"转到"上传当探针"——它常暴露物理路径、中间件版本、后端处理链，这些情报喂给 SQLi 写文件、LFI 包含、已知组件 nday。上传点即使不给 shell 也是高价值信息源。

### SSTI：从模板注入推进到命令执行
**Q1**: 页面把输入当模板渲染（`{{7*7}}` 回显 49），下一步？
**A1**: 先**指纹引擎**：用一组探针（`${7*7}`、`{{7*'7'}}`、`#{}`、`<%= %>`）区分 Jinja2/Twig/Freemarker/Velocity/Thymeleaf。引擎不同利用链完全不同，指纹错了后面全错。

**Q2**: 确认 Python Jinja2，怎么走到 RCE？
**A2**: 沿对象链爬：从内置对象经 `__class__`→`__mro__`→`__subclasses__()` 找能调 `os`/`subprocess`/`Popen` 的类，或走 `cycler/joiner/namespace` 的 `__init__.__globals__` 拿 `os`。核心是"从沙箱对象爬到能执行命令的入口"。

**Q3**: 沙箱把 `__`、`class`、`os` 都过滤了？
**A3**: 转绕过：`attr()` 过滤器取属性、`request.args` 拼接、`~` 字符串拼接、`|join`、hex/unicode 编码关键字、字典取值绕点号。用等价手段重建被禁的取属性/取全局链路。

**Q4**: 是 Java 系（Freemarker/Velocity）呢？
**A4**: Freemarker 走 `Execute`/`ObjectConstructor`/`JythonRuntime`；Velocity 走 `ClassTool`/反射调 Runtime。判据是能否 new 出可执行命令的工具类；被限则找白名单静态方法里的反射入口。

**Q5**: 能执行但**无回显**怎么办？
**A5**: 转盲打确认：DNSlog/HTTP 带外验证命令确实执行，再用命令把结果写进可读文件/回传服务器/塞进另一响应位。确认后直接上反弹 shell，不纠结页面回显。

**Q6**: 引擎识别不出、所有算术探针都不回显，是不是 SSTI？
**A6**: 很可能**误判**。**转向**：重新评估——可能是 XSS（客户端）、普通反射、或后端做了转义。别耗，回退对该参数做常规注入测试（SQLi/命令注入/OGNL/SpEL 表达式注入另算），换一类漏洞假设。

### 反序列化：识别利用链并落地 RCE
**Q1**: 抓包看到 `rO0AB`（Java）或 `O:` 开头（PHP）序列化特征，怎么起手？
**A1**: 先定语言与格式，再定**依赖里有没有可用 gadget**。Java 看 CommonsCollections/Beanutils/Fastjson/Jackson 是否在 classpath；PHP 看有无可控魔术方法（`__wakeup/__destruct/__toString`）。反序列化命门是 gadget 不是入口。

**Q2**: Java 反序列化怎么快速找链？
**A2**: 用 ysoserial 各链逐个打观察差异；配合 DNSlog 探针（URLDNS/JRMP）先确认"反序列化确实发生且出网"，再上带命令的链。链多时按目标依赖版本收敛，别全量盲打触发告警。

**Q3**: PHP 且没现成 POP 链？
**A3**: 转手工审计：找入口魔术方法，串联"属性可控→敏感 sink（`system/file_put_contents/call_user_func`）"的调用链。缺 sink 就找文件写/包含 sink 曲线救国。

**Q4**: 确认反序列化点但所有已知 gadget 都打不通（无出网/无回显/报错）？
**A4**: 分层排查：先 DNSlog 确认是否**根本没触发**（可能过滤 magic bytes 或用了白名单反序列化如 Hessian/自定义 readObject）；触发了不出网则转本地 gadget（文件落地/写马/写计划任务）。仍不行**转向**：可能被 SerialKiller/lookahead 防了，改打其他入口或组件 nday。

**Q5**: Fastjson/Jackson 这类 JSON 反序列化怎么区别对待？
**A5**: 它们靠 `@type`/多态触发任意类加载，利用点是能否指定恶意类并让 getter/setter 执行动作（JNDI 注入→远程加载）。判据是版本是否在受影响区间、有无 autoType/黑名单绕过。

**Q6**: JNDI 高版本 JDK 把远程 codebase 加载堵了？
**A6**: 转本地 factory/EL 注入等不依赖远程 class 下载的绕过，或找目标 classpath 里现成可利用工厂类（连接池/模板类的 bean 属性 gadget）。核心从"远程加载 class"转为"用本地已有类拼出执行"。

### 命令注入：绕过过滤把命令送进去
**Q1**: 某参数疑似拼进系统命令（ping、图片处理、导出），怎么确认？
**A1**: 用分隔符探（`;`、`|`、`&&`、反引号、`$()`、换行 `%0a`），配合延时（`sleep`/`timeout`）或 DNSlog 判断是否执行，别依赖回显。确认注入位再谈绕过。

**Q2**: 空格被过滤怎么办？
**A2**: 用 `${IFS}`、`$IFS$9`、`<`、`{cmd,arg}`、Tab 替代空格。关键字被过滤则变量拼接、通配符、反斜杠断词、base64 解码执行。思路是"保持语义、改变字面"。

**Q3**: 有执行但**无回显**？
**A3**: 走带外：DNSlog 外带命令结果（塞进子域名）、curl/wget 回传、写入 web 可读文件再访问。无回显不等于无法利用。

**Q4**: 输入像是放进命令但一直不触发，怎么判断死活？
**A4**: 区分是**过滤拦截**还是**根本没进 shell**（可能用了参数化 execve 数组或安全 API）。前者换绕过，后者这条参数没戏。**转向**：换其他参数/接口重探，或转打该功能背后调用的组件本身漏洞（调用了有 nday 的命令行工具）。

**Q5**: WAF 在传输层就拦命令特征？
**A5**: 转编码与分块：URL 二次编码、参数污染、分块传输、Unicode、注释拆关键字；仍拦则**换维度**——找同应用防护薄弱的入口（内部接口、老 API、非常规 method）。

**Q6**: 确认能执行，怎么落稳定 shell？
**A6**: 先探出网方向，能出网直接反弹并升级 tty；不能出网则先落 webshell 或正向 bind 端口，把一次性命令执行升级成可持续交互控制。

### LFI/文件包含：从"能读文件"到"能执行代码"
**Q1**: 确认 LFI（能读任意文件），怎么升级成 RCE？
**A1**: 目标是"让被包含内容里有我的代码"。盘点可投毒落点：访问日志（UA/URL 注入）、SSH/mail 日志、session 文件、临时文件、上传文件、`/proc/self/environ`。判据是"哪个文件我能写受控内容 + 又能被包含"。

**Q2**: 日志投毒具体怎么做？
**A2**: 往 UA 塞 PHP 代码写进 access.log，再包含日志路径触发执行。前提是知道日志绝对路径且可被包含（无 open_basedir 阻挡）。路径不确定就先用 LFI 读配置猜路径。

**Q3**: PHP 环境且能用 wrapper？
**A3**: 试 `php://filter` 先读源码做审计，`data://`/`php://input`/`expect://` 直接执行（依赖配置），`phar://` 配合反序列化。wrapper 可用与否强依赖 `allow_url_include`/php 版本。

**Q4**: `allow_url_include=Off`、无日志权限、session 控不了，投毒无门？
**A4**: **转向**：用 PHP 临时文件竞争包含（配合 phpinfo 或竞争 upload tmp），或 `php://filter` 链式转换（filter chain）直接构造可执行内容——不依赖外部可写文件的现代 LFI2RCE。仍不行退回把 LFI 当纯读取，读源码/密钥打别的面。

**Q5**: 有 `open_basedir` 限制读不到目标？
**A5**: 转绕过：`glob://`、软链、`chdir`+`ini_set` 组合、已知 basedir bypass；绕不过就在允许目录范围内找可用文件（应用日志/缓存/session）。

**Q6**: 只是远程包含（RFI）能包含我服务器文件？
**A6**: 那更直接——让它包含我 VPS 上的马。但现代 `allow_url_include` 多为 Off，RFI 罕见；成立时注意出网方向与 URL 被 WAF 拦，可用 IP、非常规端口、data 协议规避。

### RCE 到手却**无回显**：先确认执行，再取控制
**Q1**: 打了疑似 RCE，页面无任何输出，怎么判断成没成？
**A1**: 别靠肉眼。上三种侧信道：DNSlog、HTTP 回连（curl 打自己服务器）、时间盲（`sleep 5` 看延迟）。任一命中即证明代码执行。

**Q2**: DNSlog 收到但 HTTP 收不到，说明什么？
**A2**: 说明**能执行、DNS 出得去、但 HTTP/TCP 出网被限**（典型内网只放 DNS）。关键情报：反弹 shell 大概率也出不去，得走 DNS 隧道或纯 webshell 驻留，别浪费时间试普通反弹。

**Q3**: 三种探针全静默，是没打中还是执行了但全隔离？
**A3**: 加时间盲复核：`sleep` 能稳定拉长响应则是执行成功但**完全不出网**；时间盲也无差异则大概率没打中。这个分叉决定后续是"想办法回显/落地"还是"换 payload/换洞"。

**Q4**: 确认执行但完全不出网，怎么拿命令结果？
**A4**: 转"就地回显"：命令输出写进 web 可访问文件再读、写进数据库/日志再查、塞进下一响应字段。把无回显 RCE 改造成"命令→落地→读取"两步回显。

**Q5**: 连 web 目录都不可写、没有可读回落点？
**A5**: **转向**：放弃取回显，直接盲发"建立持久通道"命令——写内存马、加计划任务/服务、创建后门账号，通过独立通道回连或等触发，绕过当前请求响应限制。

**Q6**: 怎么避免盲打把系统打崩或触发告警？
**A6**: 盲态命令要幂等无破坏，先探环境（whoami/权限/杀软进程）再动作；每条命令考虑失败重试与告警面，别一把梭下大量高危命令引来响应团队。

### 拿到 webshell 后：先做态势判断，别急着乱翻
**Q1**: webshell 连上了，第一件事做什么？
**A1**: 态势四问：我是谁（whoami/权限）、我在哪（内网 IP/主机名/域内否）、能不能出网（DNS/HTTP/TCP 各测）、周围有什么（杀软 EDR 进程、端口、其他站点）。这四问决定后续每步。

**Q2**: 为什么出网测试要分协议测？
**A2**: 反弹 shell、下载工具、隧道全依赖出网方向，而内网常做协议白名单（只放 DNS、或只放某代理 80/443）。测出各协议通不通，直接决定用哪种回连/隧道，避免反复试错暴露。

**Q3**: 发现有 EDR/杀软，动作怎么调整？
**A3**: 降噪优先：少落地文件、命令避开高危特征、慎用公开工具（特征强）。信息收集用系统自带 living-off-the-land 命令，工具尽量内存加载。先摸清 EDR 型号再决定是否需免杀。

**Q4**: 当前是 www-data 低权，webshell 功能受限，怎么办？
**A4**: 很正常。webshell 阶段先当**信息与跳板**：读配置拿数据库/其他系统凭据、翻家目录/history、看内网连通。提权是下一独立阶段，别在 web 权限下强行做需要 root 的事。

**Q5**: webshell 时不时掉线不稳定，怎么办？
**A5**: 尽快从"一句话 webshell"升级到更稳的控制通道——反弹一个 tty shell 或落一个稳定 C2 beacon，把关键操作放在稳定通道上；webshell 保留作应急备用入口，不把所有鸡蛋放一个篮子。

### 反弹 shell 被防火墙拦：换方向、换协议、换姿势
**Q1**: 命令执行有了，反弹 shell 连不回来，先怀疑什么？
**A1**: 先分清是**出站被拦**还是**payload 没执行**。用最简单出网探针（curl/dns 打自己）确认出网方向；确认能执行后，问题多半在出站策略——目标做了出站端口/协议限制。

**Q2**: 高端口出不去，怎么调整？
**A2**: 换目标常放行的出站端口试（443/80/53），反弹连到这些端口的监听。很多环境只放行 web 常用出站端口，把 C2 伪装成这些端口能过掉大部分出站 ACL。

**Q3**: 所有 TCP 出站都被拦，只有 DNS 出得去？
**A3**: **转向** DNS 隧道：用 DNS 承载 C2 流量。慢但能穿只放 DNS 的环境。或走 ICMP 隧道（若 ICMP 放行）。核心是找到唯一放行的协议做载体。

**Q4**: 出站全封死（纯隔离网段）怎么办？
**A4**: 反弹思路作废，**转正向**：在目标上 bind 一个端口等我连入（前提入站有路可达，如通过前置跳板/端口转发能摸到该端口）。若入站也不可达，则退回纯 webshell / 落地驻留，靠"轮询拉取任务"式的低频 beacon。

**Q5**: 反弹上来了但是个残废 shell（无 tab、无 Ctrl-C、无交互）？
**A5**: 升级 tty：`python -c 'pty.spawn'`/`script`/`socat` 分配伪终端，再 `stty raw` 同步终端尺寸。交互式 shell 对后续提权和内网操作至关重要，别将就残废 shell。

**Q6**: 反弹命令一直没反应，怀疑被杀软拦了 payload？
**A6**: 换 payload 形态：换 shell 类型（bash/python/perl/php/powershell 挑目标有的）、编码混淆、内存执行不落地。仍不行则换**通道假设**——不反弹，改用现有 web 通道下发命令 + 带外回传，绕开需要新建连接的方案。

### Linux 低权 shell 提权：系统化选路
**Q1**: 拿到 Linux 低权 shell，提权从哪下手，避免乱试？
**A1**: 先枚举（LinPEAS 或手工）：内核版本、SUID/SGID、sudo 权限、cron、可写敏感文件、服务与端口、能力位（capabilities）、环境变量。提权是"找一个我能触碰的高权入口"，枚举先把入口清单列全。

**Q2**: `sudo -l` 显示能免密跑某命令，怎么用？
**A2**: 查 GTFOBins：几乎所有常见二进制都有"从合法功能逃逸到 shell"的姿势（如带 `!` 逃逸、`-exec`、写文件覆盖）。sudo 可跑的命令是最干净的提权路径，优先吃。

**Q3**: 没有 sudo，但有一堆 SUID 二进制？
**A3**: 逐个对照 GTFOBins 的 SUID 段；非标准 SUID 程序则逆向/看是否调用外部命令（PATH 劫持）、是否有已知 CVE。判据是"这个 root 属主程序有没有让我以 root 执行任意代码的缝"。

**Q4**: 枚举完 sudo/SUID/cron 都没戏，卡住了往哪转？
**A4**: **转正交维度**：换到"凭据复用"——翻配置/history/内存里的密码，`su` 到高权用户或复用到其他机器；再不行看**内核提权**（对照发行版内核版本找 local root exploit，但注意崩溃风险，生产慎用）；还可看容器/云元数据（若在容器里，走逃逸而非本机提权）。

**Q5**: 内核版本老但不敢直接跑 exploit 怕搞崩？
**A5**: 先在同版本环境验证 exploit 稳定性再上；生产上优先选无损提权（配置/凭据/服务错配），把内核 exploit 当最后手段，且尽量选公认稳定的实现，控制影响面。

**Q6**: 全都试过还是 www-data，是不是提权无望？
**A6**: 重估目标：也许**不需要 root**。当前权限能读的数据库凭据/密钥可能直接横向到更值钱的机器。**转向**：从"垂直提权"转"水平移动"，用当前权限做跳板打内网，往往比死磕本机 root 更划算。

### Windows 低权 shell 提权：从服务账户到 SYSTEM
**Q1**: 拿到 Windows 低权（IIS/网络服务），提权先看什么？
**A1**: 先 `whoami /priv` 看令牌权限、`whoami /groups`、系统补丁级别（`systeminfo`）、服务与路径、可写目录。Windows 提权高度依赖"我这个令牌有什么特权 + 系统缺哪些补丁"。

**Q2**: `whoami /priv` 里有 `SeImpersonate`/`SeAssignPrimaryToken`？
**A2**: 直奔 Potato 系列（土豆家族）令牌窃取到 SYSTEM——服务账户几乎必带这特权，这是 IIS/MSSQL 落地后最经典的提权。判据就是这两个特权在不在。

**Q3**: 没有可利用特权，走什么路？
**A3**: 查服务错配：未引用服务路径（unquoted service path）、弱服务权限（可改二进制/可改配置）、可写的自动运行程序、DLL 劫持、AlwaysInstallElevated。用 PowerUp/winPEAS 扫这些配置错误。

**Q4**: 配置都没错、补丁也全，卡住往哪转？
**A4**: **转向**凭据与横向：翻注册表/配置/Unattend/GPP 里的口令、跑 mimikatz 抓当前会话凭据、看是否域内（域内则提权问题可能转化为拿域凭据横向）。本机提不动就用抓到的凭据往域里/其他机器移动。

**Q5**: 想抓凭据但 EDR 盯着 lsass？
**A5**: 转规避手法：非常规方式访问 lsass、用系统自带工具 dump、或先绕过/致盲 EDR 再抓。抓不了就退而求其次找**明文/可逆凭据**（配置文件、计划任务、浏览器保存、票据），不一定非要碰 lsass。

**Q6**: 缺补丁但不确定该用哪个内核 exp？
**A6**: 用 Watson/WES-NG 比对 `systeminfo` 输出精确定位可用 exp，别盲投一堆 EXE（易被杀且易崩）。选定后优先内存加载、单发验证，控制噪音。

### 已知组件 nday：指纹先行，别当 0day 硬啃
**Q1**: 面对一个 web 应用/中间件，怎么高效找到 getshell 点？
**A1**: 先**指纹识别**：中间件（Weblogic/Tomcat/JBoss/WebSphere）、框架（Struts2/Spring/ThinkPHP/Shiro）、CMS 及版本。八成的 web-to-shell 是打已知 nday，指纹+版本就是选 exp 的钥匙，别一上来就手工挖 0day。

**Q2**: 指纹出来了但版本模糊，怎么定位到具体可用 exp？
**A2**: 用差异指纹收敛版本（特定静态文件 hash、报错特征、默认路径），把版本卡到 nday 影响区间。版本卡准了，exp 命中率和稳定性都高得多。

**Q3**: 有对应 nday 的 PoC，直接打前要注意什么？
**A3**: 先无害验证（探测型 payload/DNSlog）确认漏洞真实存在且未打补丁，再上 getshell payload。很多目标"版本像有洞其实打了热补丁/WAF 虚拟补丁"，先验证省得暴露。

**Q4**: PoC 验证通过但 getshell payload 打不进（被拦/无效）？
**A4**: 分层：是 WAF 拦特征（转编码/变形/换 payload 变体）还是环境不满足（如需特定组件在 classpath）。**转向**：同一漏洞常有多种利用姿势（写文件/内存马/JNDI/反弹），换一种落地方式绕过当前受阻的那种。

**Q5**: 目标组件确实有洞但被虚拟补丁/WAF 全面防护，怎么办？
**A5**: **换攻击面**：一个应用往往不止一个组件，扫其他端口/子应用/老接口；或找该 nday 的最新绕过变体。硬啃被重点防护的点性价比低，转防护薄弱处。

**Q6**: 完全查不到对应 nday，是不是没戏？
**A6**: 转两个方向：一是配置类问题（默认口令、未授权、控制台暴露）——组件没洞但配错一样 getshell；二是把它当已知类漏洞去手测（该类框架的通用注入/反序列化模式）。nday 查不到不代表没配置洞。

### 前台无洞：绕过认证进后台，从功能点 getshell
**Q1**: 前台扫了一圈没有可直接利用的洞，怎么继续？
**A1**: 目光转后台。后台功能点（模板编辑、插件上传、数据库备份、计划任务、SQL 查询框）往往就是设计上的 getshell 入口。问题变成"怎么进后台"。

**Q2**: 后台登录口，先试什么？
**A2**: 弱口令/默认口令（admin 类）、爆破（注意锁定策略）、以及认证绕过类（SQLi 万能密码、逻辑绕过、JWT 伪造、越权）。先低成本试弱口令，同时找认证逻辑缺陷。

**Q3**: 进了后台但功能点看起来都很"干净"，没有明显上传？
**A3**: 细看：模板/主题编辑（写 PHP）、日志/配置写入、数据库备份改后缀落 webshell、导入导出、计划任务命令、任意文件下载读源码再找洞。后台 getshell 常藏在"看似正常"的管理功能里。

**Q4**: 后台弱口令爆不出、认证也绕不过，卡死怎么办？
**A4**: **转向**：换入口拿后台凭据——SQLi dump 管理员 hash 破解、翻源码泄露里的默认账号、钓鱼/凭据复用、找 session/token 泄露。进后台的路不止爆破一条，从别处偷钥匙进门。

**Q5**: 拿到后台但当前账号权限低，够不到 getshell 功能？
**A5**: 找后台内**越权/水平提权**升到管理员，或找低权账号也能碰的写入点。后台内部同样存在权限边界问题，别默认"进了后台就是最高权限"。

**Q6**: 后台功能确实无 getshell 点（纯展示型）？
**A6**: 那后台的价值转为信息与凭据面：读到的配置、连接串、API key、内部地址，喂给对基础设施（数据库/中间件/内网服务）的直接攻击。后台不 getshell 也能当情报金矿。

### WAF 全程拦截：识别 WAF、定位规则、精准绕过
**Q1**: payload 一发就被拦（返回拦截页/403），怎么系统应对而非瞎改？
**A1**: 先确认是 WAF 拦还是应用本身拒。用递进 payload 定位**触发拦截的具体特征字符/关键字**（二分法删改），知道拦什么才能针对性绕，而不是随机变形碰运气。

**Q2**: 定位到是某关键字（如 `union`/`select`/`script`）被拦？
**A2**: 用等价变形：大小写、内联注释拆词、编码（URL/十六进制/unicode/双编码）、同义替换、空白符替换。目标是保持语义、破坏 WAF 的字面匹配。

**Q3**: 是基于长度/频率/行为的拦截（不是单关键字）？
**A3**: 转策略层：放慢速率避频率封禁、分块传输拆 payload、参数污染（HPP）让 WAF 与后端解析不一致、换 HTTP 方法/Content-Type 让 WAF 走不同解析路径。

**Q4**: 各种绕过都试遍还是拦，往哪转？
**A4**: **转向**换攻击面而非死磕这一处：找 WAF 覆盖不到的入口——直连源站 IP（绕 CDN/云 WAF）、内部/老接口、非常规子域、API 端点。WAF 通常只护主要面，边缘入口常裸奔。

**Q5**: 怀疑是云 WAF（CDN 前置），怎么绕？
**A5**: 找真实源站 IP（历史 DNS、证书、子域、SSRF 探测），直连源站绕过前置防护。源站没独立防护时，绕过 CDN WAF 就等于卸掉了大半防护。

**Q6**: 绕过成功但很脆（时灵时不灵）？
**A6**: 说明贴着规则边缘走，随时会被封或触发响应。**转向**稳定性优先：一旦拿到一次执行机会，立刻落一个不依赖再次绕 WAF 的持久通道（内存马/带外通道），别反复穿 WAF 反复冒险。

### 内存马 vs 落地 webshell：驻留方式的取舍
**Q1**: RCE 到手，该落地文件 webshell 还是打内存马？
**A1**: 看两点：对抗强度（有强 EDR/文件监控→内存马）与稳定性需求（要重启存活→落地或加持久化）。内存马隐蔽（不落文件、扫盘扫不到），但进程/应用重启即失效，是取舍不是优劣。

**Q2**: 决定打内存马，前提条件是什么？
**A2**: 需要能在目标运行时里注入 Handler（Java 的 Servlet/Filter/Listener/Interceptor 型，或中间件层）。前提是有一次代码执行且了解运行框架。判据是"我能不能往它的请求处理链里挂一个我的钩子"。

**Q3**: 内存马注入后怎么保证自己找得到、别人难发现？
**A3**: 用隐蔽触发条件（特定 header/参数/路径才响应），避免注册到显眼的路由。同时记录注入方式以便复访；隐蔽性来自"只对我的暗号响应"。

**Q4**: 应用重启导致内存马丢了，怎么办？
**A4**: 这是内存马固有代价。**转向**冗余驻留：内存马 + 一个低调落地后门 + 系统层持久化（计划任务/服务/启动项）三层，任一存活即可回访。别把驻留押在单一易失点上。

**Q5**: 落地 webshell 但担心被文件扫描/流量特征抓？
**A5**: 从文件和流量两头降特征：文件用加密马/畸形结构避静态扫描，流量用加密通信避特征检测；再把 webshell 藏进正常业务文件、放不显眼路径。文件马的对抗是文件 + 流量双线。

**Q6**: 目标对抗很强，两种都容易被抓，怎么权衡？
**A6**: 优先"打了就走 + 极简驻留"：拿到关键成果（凭据/横向立足点）后尽快转移阵地，减少在高对抗单点长期驻留的暴露；驻留只留最低限度、最隐蔽的一处应急入口。

### Redis 未授权：从缓存服务到系统 shell
**Q1**: 探到一个未授权 Redis（能直连），怎么想到落 shell？
**A1**: Redis 能写文件的特性是关键。先确认能否 `config set` 改 dir/dbfilename，把内容写到敏感位置。判据是权限够不够改配置 + 目标目录可写可解析/可被加载。

**Q2**: 有 web 服务同机，怎么用 Redis 落 webshell？
**A2**: `config set dir` 指到 web 目录、`dbfilename` 设为脚本名，写入含马的 key 再 save，落地 webshell。前提是知道 web 绝对路径、Redis 进程有写权限、目录可解析。

**Q3**: 不是 web 同机 / web 路径拿不到，还有什么姿势？
**A3**: 转 SSH 公钥写入（写 authorized_keys，需 redis 用户家目录可写且 SSH 开）或写 cron（Linux 定时任务反弹，需 crontab 目录可写、发行版兼容）。三条路（webshell/SSH key/cron）按目标条件挑一条满足的。

**Q4**: 三种写入都受阻（权限低、目录不可写、被监控）？
**A4**: **转向**主从复制 RCE（用恶意主库加载 .so 模块执行命令），它不依赖写特定文件；再不行则把 Redis 当**数据/情报源**——里面常存 session、token、业务数据、其他系统凭据，转去横向。

**Q5**: Redis 有密码但弱/或有 SSRF 能打内网 Redis？
**A5**: 弱口令先爆破拿认证；SSRF 场景用 gopher 协议构造 Redis 协议包打内网未授权 Redis，把 SSRF 转成 Redis 写文件 RCE。判据是 SSRF 能否发任意 TCP 载荷。

**Q6**: 新版 Redis 开了 protected-mode / 禁了 config，写入路走不通？
**A6**: 主从复制模块加载往往仍可行（不同前提）；都被防则退回情报利用。别在"写文件"单一路径上耗，Redis 落 shell 有多条正交路，逐条按前提筛。

### SSRF：从"能让服务器发请求"到内网 shell
**Q1**: 确认 SSRF（能让目标代我发请求），离 shell 还有多远，先做什么？
**A1**: SSRF 本身不是 shell，是**内网入口**。先探能力边界：能打哪些协议（http/https/gopher/dict/file）、能否读响应（回显 SSRF 还是盲 SSRF）、能达到哪些内网地址/端口。能力决定后续能打什么。

**Q2**: 能打 gopher 且能达内网，怎么升级？
**A2**: gopher 能构造任意 TCP 载荷，等于把 SSRF 变成"内网任意服务客户端"——打未授权 Redis 写文件、打内网 MySQL、发内网应用的 POST 利用。判据是目标内网有没有这类"发个包就能 RCE"的服务。

**Q3**: 只能发 GET、无 gopher，能力受限？
**A3**: 转"打基于 GET 的内网入口"：内网未授权管理接口、云元数据（拿临时凭据）、其他 web 应用的 GET 型 RCE/回显洞。GET-only SSRF 的价值在于打那些一个 URL 就能利用的目标。

**Q4**: 是盲 SSRF（无响应回显），怎么判断打没打中？
**A4**: 靠带外与行为差异：DNSlog 确认能出、响应时间差判断端口开闭（SSRF 端口扫描）。盲 SSRF 仍可做内网探测 + 打无需回显的利用（如 Redis 写文件），只是拿不回数据。

**Q5**: SSRF 有各种协议/地址过滤（只允许特定域名/IP）？
**A5**: 转绕过：DNS rebinding、IP 变形（十进制/八进制/IPv6/短域名）、`@`/`#` 混淆、跳转（让白名单 URL 302 到内网）、解析不一致。目标是让过滤看到合法目标、实际请求打到内网。

**Q6**: 内网被 SSRF 探了一圈没有可直接 RCE 的服务，卡住往哪转？
**A6**: **转向**：SSRF 当侦察工具用——探活内网存活主机与开放端口，绘制内网地图；拿到的资产信息喂给后续（若已有其他立足点做横向），或聚焦云元数据拿凭据这条不依赖内网服务漏洞的路。

### 源码/配置泄露：白盒化审计找落地点
**Q1**: 发现 `.git`/`.svn`/备份包/`.DS_Store` 等源码泄露，价值怎么用？
**A1**: 这是把黑盒变白盒的机会。先完整 dump 源码，再审两类东西：**硬编码密钥/口令/连接串**（直接用）和**代码里的漏洞**（上传校验逻辑、注入点、反序列化、鉴权缺陷）。源码在手，找洞效率翻倍。

**Q2**: dump 到源码后优先看哪里？
**A2**: 先搜敏感常量（password/secret/key/token/appid）、配置文件、数据库连接；再看鉴权与上传/文件操作相关代码找可利用逻辑。先摘唾手可得的凭据，再做逻辑审计。

**Q3**: 拿到了框架用的加密 key/签名密钥（如 session/JWT/序列化 key）意味着什么？
**A3**: 可能直接通向 RCE 或认证绕过——用泄露的 key 伪造签名、构造合法的加密序列化数据（配合框架反序列化）、伪造管理员 token。硬编码密钥常是 web-to-shell 的捷径。

**Q4**: 源码是编译过的/混淆的，或只 dump 到部分，审不动怎么办？
**A4**: **转向**：即便部分源码也能定位技术栈、路由、隐藏接口、版本，用这些做针对性黑盒测试；混淆代码优先只找配置/密钥这类不需读懂逻辑的产物。别陷在通读混淆代码里，抓能立刻用的。

**Q5**: `.git` 泄露但 dump 工具拿不全历史？
**A5**: 换工具/手工按对象哈希拉取，重点找**历史提交里删掉的密钥**（开发常把密钥提交后又删，但历史还在）。git 历史是凭据泄露重灾区，别只看当前版本。

**Q6**: 审计发现的洞和泄露的凭据都用不上（环境已加固）？
**A6**: 泄露信息仍有横向价值：内部域名、API 地址、员工命名规律、其他系统入口。**转向**把它当内网/横向的地图与字典来源，而非只盯着当前应用 getshell。

### 容器里的 shell：先判断"我在不在容器里"，再决定逃逸
**Q1**: 拿到 shell 后，怎么判断自己是不是在容器里？
**A1**: 查特征：`/.dockerenv`、cgroup 里的 docker/kubepods 字样、进程号 1 是应用而非 init、主机名像随机 hash、精简的文件系统。判断在不在容器决定后续是"本机提权"还是"容器逃逸"。

**Q2**: 确认在容器里，逃逸前先看什么？
**A2**: 看容器配置面：是否特权容器（privileged）、挂载了哪些主机目录（`/`、docker.sock、宿主设备）、capabilities（如 `SYS_ADMIN`）、能否访问 docker/k8s API。逃逸机会几乎都来自这些配置错误。

**Q3**: 发现挂载了 docker.sock 或是特权容器，怎么逃？
**A3**: docker.sock → 直接调 docker API 起一个挂载宿主根目录的新容器拿宿主文件/执行；特权容器 → 通过 cgroup release_agent、挂载宿主设备等经典逃逸。判据是"这个配置错误给没给我碰宿主的手柄"。

**Q4**: 容器配置很干净（非特权、无危险挂载、cap 最小）逃不出去，卡住怎么办？
**A4**: **转向**：逃逸不是唯一目标——容器内往往有服务账号 token（k8s 的 serviceaccount）、环境变量里的凭据、能访问的内网服务。用这些做**横向/打 k8s API**，可能比逃逸到当前宿主更有价值。

**Q5**: 在 k8s pod 里，serviceaccount token 能干什么？
**A5**: 拿 token 打 kube-apiserver：权限够就能创建特权 pod、读 secret、调度到目标节点，等效于集群级横向甚至逃逸。判据是这个 SA 的 RBAC 权限有多大，先枚举权限再动作。

**Q6**: 逃到宿主了但宿主也只是集群一个 worker，如何继续？
**A6**: 视目标而定：worker 上可能有其他 pod 的 secret、kubelet 凭据、节点内网位置。**转向**把宿主当新跳板做集群内横向，路径从"单机逃逸"升级为"集群渗透"。

### 多个洞并存：优先打哪个（攻击面排序）
**Q1**: 一个目标同时扫出多个可疑洞（一个 SQLi、一个上传、一个老组件），先打哪个？
**A1**: 按"落 shell 距离 × 成功概率 × 噪音/风险"排序。已知稳定 nday 通常最短路径优先；能直接 getshell 的（上传/RCE）优先于只能读数据的（SQLi）。别贪多并行乱打，选一条最短最稳的先落脚。

**Q2**: 怎么快速估"落 shell 距离"？
**A2**: 直接命令执行/写文件 = 距离最短；注入/LFI 需二次升级 = 中等；信息泄露 = 最远（需再接一跳）。同时评估前置条件满足度（要不要额外信息、权限）。距离近且前置全满足的先打。

**Q3**: 最优选项打了几次不成功，什么时候切换而不是死磕？
**A3**: 设**止损线**：同一路子几种主流姿势都试过、且已定位到是硬阻断（补丁/强 WAF/环境不满足）而非自己姿势问题，就切下一个候选。避免沉没成本，一条路验证到"结构性受阻"就转。

**Q4**: 全部候选洞都打不动，往哪转？
**A4**: **转向**回到侦察扩面：重扫端口/子域/旁站、找新入口、更细的指纹、被忽略的接口。多半是攻击面没铺够，而不是"真的没洞"。web-to-shell 卡死时，退回信息收集常能开新局。

**Q5**: 有个洞噪音很大（易触发告警）但成功率高，打不打？
**A5**: 看行动目标与对抗强度：追求隐蔽/长期驻留则先试低噪音路；纯 flag/快速拿点则可接受噪音。若必须打高噪音洞，先准备好"打进去立即降噪/转移"的后手，别打完裸奔在原地。

**Q6**: 打通一个后，其他洞还要不要管？
**A6**: 保留价值：其他洞可作**备用入口**（主通道被封时回访），也可能通向不同权限/不同机器。落脚成功后记录未用的洞作冗余，别一拿到 shell 就丢掉其余入口。

### XXE：判断它到底能不能通向 shell
**Q1**: 确认 XXE（XML 外部实体注入），它能直接 getshell 吗，先判断什么？
**A1**: XXE 直接 RCE 条件苛刻，先摆正预期。判断解析器支持什么：`file://` 读文件、http 探内网（SSRF）、`php://filter` 读 PHP 源码、`expect://`（PHP 特定扩展才行，罕见）。多数 XXE 的现实价值是读文件 + SSRF，不是直接 shell。

**Q2**: 是回显 XXE，最大化利用是什么？
**A2**: 读敏感文件（配置/密钥/源码），把读到的凭据/密钥接到别的攻击链（如拿到序列化 key 去打反序列化 RCE）。回显 XXE = 强力任意文件读，价值在"读出能通向 shell 的东西"。

**Q3**: 是盲 XXE（无回显），怎么办？
**A3**: 转 OOB（带外）：用外部 DTD 把读到的数据外带到自己服务器（error-based 或 参数实体外带）。盲 XXE 仍能读文件，只是要靠带外通道取回，构造稍复杂。

**Q4**: 解析器禁用了外部实体 / 各种协议都不通，XXE 这条线走不通？
**A4**: **转向**：把 XXE 降级当 SSRF 用（若还能发内网请求）打内网服务；若连 SSRF 都封了，则这个点作废，回退到该接口的其他漏洞假设（注入/反序列化——XML 接口后端常有反序列化）。

**Q5**: XXE 能读文件，但读什么才最接近 shell？
**A5**: 优先读：应用配置（DB/其他系统凭据）、框架密钥（signing/加密 key）、源码（审出上传/注入点）、SSH/云凭据。目标明确——读"能让我再进一步 RCE 或横向"的文件，而非漫无目的读系统文件。

**Q6**: 通过 XXE 读到的凭据/密钥，怎么衔接到 shell？
**A6**: 分流：DB 凭据→连库走注入落地那套；框架密钥→伪造签名/构造反序列化 RCE；SSH/云凭据→直接登录/调云 API。XXE 的收官是"把读到的东西喂给一条能真正 getshell 的链"。

### 加密类漏洞（如框架固定密钥）：先拿 key，再谈利用
**Q1**: 怀疑目标框架有"固定/泄露密钥导致的可控加密数据"问题（如某些框架的 cookie 加密、序列化签名），怎么起手？
**A1**: 先确认框架与加密特征（cookie 格式、字段结构），再判断**key 从哪来**：默认硬编码 key、源码泄露里的 key、可爆破的弱 key。整条链的门槛在 key，没 key 后面免谈。

**Q2**: 怎么判断用的是默认/弱 key？
**A2**: 拿一组已知默认 key 字典做验证（能否正确解密/构造出被服务端接受的数据）。有回显特征（解密成功 vs 失败的响应差异）就能盲验。key 命中即证明可利用。

**Q3**: key 拿到了，怎么走到 RCE？
**A3**: 用 key 构造合法的加密载荷，塞入服务端会**反序列化**的数据里，配合可用 gadget 触发 RCE。判据是：能构造合法密文 + 后端会反序列化 + classpath 有 gadget，三者齐才通。

**Q4**: key 命中但没有可用 gadget（依赖里没有链）？
**A4**: **转向**：key 仍有价值——伪造认证 cookie/token 做身份伪造、越权登录管理员。反序列化不通就退到"用合法加密数据伪造身份"这条不需要 gadget 的利用面。

**Q5**: key 字典全不中、也无源码泄露，卡住怎么办？
**A5**: **转向**别在爆 key 上耗：换这个应用的其他攻击面。固定 key 类漏洞是"有就秒、没有就别恋战"的类型，key 拿不到基本就该换洞。

**Q6**: 打进去了但发现是新版本已修/换了随机 key，怎么快速判定？
**A6**: 看构造的载荷是否被接受：随机 key 下你的伪造数据一律解密失败/被拒。一旦确认是随机 key，立即判定此路不通并转向，不要反复重试相同 payload。

### 认证绕过/越权：从匿名或低权直达 getshell 功能
**Q1**: 某功能能 getshell 但需要管理员，正面拿不到管理员凭据，怎么绕？
**A1**: 找认证与授权的缝：未授权直接访问（管理接口没鉴权）、水平/垂直越权（改 id/role 越权）、JWT 伪造（弱签名/none 算法/泄露 key）、逻辑绕过（多步流程跳步）。目标是"不登录管理员也能调到那个 getshell 功能"。

**Q2**: 怀疑 JWT 有问题，先测什么？
**A2**: 依次测：`alg:none`、弱密钥爆破（HS256 弱 secret）、算法混淆（RS256→HS256 用公钥当密钥）、kid 注入。任一成立就能伪造任意用户/管理员 token 直达高权功能。

**Q3**: 发现某管理 API 无鉴权可直接调，怎么利用到 shell？
**A3**: 看这个未授权接口能干什么——能否触发文件写、命令执行、配置修改、创建管理员。未授权访问 + 危险功能 = 直接 getshell 或先造个管理员再登录走正常 getshell 功能。

**Q4**: 所有认证/越权尝试都失败（鉴权很严），卡住往哪转？
**A4**: **转向**：从"绕过认证"转"获取真凭据"——SQLi dump、源码泄露、凭据复用、钓鱼、session 泄露。绕不过锁就去偷钥匙。两条路（绕鉴权 vs 拿凭据）是正交的，一条堵死换另一条。

**Q5**: 拿到某普通用户身份了但够不到 getshell 功能？
**A5**: 找**垂直越权**升到管理员：改请求里的角色/越权访问管理端点/利用权限校验只在前端的缺陷。很多系统鉴权只挡了 UI 没挡后端接口，直接打后端端点试。

**Q6**: 逻辑复杂绕不动，是不是放弃这个功能点？
**A6**: 不一定放弃功能点，而是换到达它的路径：也许有第二个入口能调同一后端逻辑（不同 API、旧版本端点、内部接口）。**转向**找"通往同一 getshell 能力的另一条没设防的门"。

### PHP webshell 命令执行受限：disable_functions / open_basedir 绕过
**Q1**: webshell 连上了但 `system/exec` 全被 `disable_functions` 禁，先怎么判断出路？
**A1**: 先枚举环境：`phpinfo`/`ini_get` 看禁了哪些函数、PHP 版本、SAPI（fpm/cgi/apache module）、是否有 `putenv/mail/imap` 等冷门可利用函数。绕过手法强绑 PHP 版本与残余可用函数，先把"还剩什么"列清楚。

**Q2**: 还有若干函数没禁，怎么选绕过路子？
**A2**: 按残余函数挑链：`LD_PRELOAD`（需 `putenv`+ 可触发新进程如 `mail`/`error_log`）、`imap_open`（命令注入）、`FFI`（PHP7.4+ 直接调 libc）、`proc_open` 漏网。判据是"哪条链依赖的函数刚好没被禁"。

**Q3**: 函数禁得很干净，一个可用的都没剩？
**A3**: **转向**利用 PHP 底层漏洞类绕过：特定版本的 bug（如 fpm/opcache 相关）、或 `pwnkit` 思路走文件写触发。都不行则退一步——命令执行不是唯一目标，webshell 本身能读写文件，用它做**文件读写 + 横向情报**，把"拿系统命令"降级为"拿数据和凭据"。

**Q4**: 是 `open_basedir` 限制读不到目标文件？
**A4**: 转经典绕过：`ini_set`/`chdir` 组合、`glob://`、软链、`realpath` 缓存等；PHP 层绕不过就靠已有命令执行（若某条 disable 绕过成功）直接系统层读，两个限制分开各个击破。

**Q5**: 好不容易绕过执行了命令但很不稳定（偶发成功）？
**A5**: 说明绕过依赖竞争/特定时序。**转向**：一旦有一次稳定执行窗口，立刻落一个不依赖该绕过的通道——写一个新的可执行入口、加计划任务、或反弹一个正常 shell，别每次都重走脆弱的绕过链。

**Q6**: 所有绕过都失败，是不是这个 webshell 没价值了？
**A6**: 不是。受限 webshell 仍是内网信息源和文件通道：读配置、下载源码本地审计、翻其他站点。**转向**用它当"文件级立足点"喂给其他攻击链，命令执行受限 ≠ 立足点无效。

### 单机 shell 到内网跳板：出网通道与代理隧道决策
**Q1**: 拿到一台边界机 shell，要往内网打，第一步搭什么？
**A1**: 先定出网能力（前一步已测 DNS/HTTP/TCP 各协议），据此选隧道形态。原则：用目标已放行的通道承载代理流量。能出 TCP 就正向/反向 socks，只出 HTTP 就 HTTP 隧道，只出 DNS 就 DNS 隧道。隧道选型 = 出网能力的函数。

**Q2**: 能出网，直接反向代理（目标连我）还是正向（我连目标）？
**A2**: 看入站可达性：目标能主动连我（有出网）→ 反向 socks 最省事；我能直接摸到目标某端口（边界有映射/同网段）→ 正向。多数从公网打内网的场景用**反向**，因为内网机器主动出比被动被连更可能被放行。

**Q3**: 隧道搭好后怎么规划内网横向的下一跳？
**A3**: 通过 socks 让内网扫描/工具流量走进去，先做内网侦察（存活、端口、域内否），再选目标。跳板机的价值是"把外部工具接入内网"，先绘图再动手，别隔着隧道盲打。

**Q4**: 隧道频繁断 / 延迟高到没法用？
**A4**: 排查是被限速/被检测还是链路本身差。**转向**：换承载协议（TCP 不稳换 HTTP/HTTPS over 443）、加多级跳板分摊、或降低对隧道的依赖——把重活（爆破、大扫描）改在跳板机本地跑，只把结果回传，减少隧道压力。

**Q5**: 内网有分段，跳板机也只能摸到一小片网段？
**A5**: 做**多级隧道**：拿下第二台跨网段的机器作二级跳板，一级一级把代理链延伸进深处。web-to-shell 拿到的第一台机器往往只是外围，横向靠链式跳板逐层深入。

**Q6**: 出网被彻底封死（隔离网段），隧道无从谈起？
**A6**: **转向**非实时通道：靠 web 应用自身作 relay（把命令/结果藏在正常业务请求里）、或利用共享存储/数据库/内部服务做间接通信。全隔离环境下放弃实时交互 shell，改"异步投递 + 异步取回"的作业模式。

### 任意文件读/下载：定向读取通向 shell 的关键文件
**Q1**: 拿到一个任意文件读/下载漏洞（可控路径参数），怎么把它变成通向 shell 的一步？
**A1**: 它本身不给 shell，但能读出通向 shell 的东西。制定**读取清单**（按优先级）：应用配置（DB/其他系统凭据）、框架密钥、源码、SSH/云凭据、`/etc/passwd`+进程信息（探环境）。目标明确地读"能让我再进一步"的文件。

**Q2**: 不知道目标绝对路径，怎么读到配置和源码？
**A2**: 先读能定位路径的文件：中间件配置（拿 webroot）、`/proc/self/cwd`、`/proc/self/cmdline`、启动脚本，逐步推出应用绝对路径，再去读它的配置/源码。路径未知时先"读元信息定位"，再"读目标文件"。

**Q3**: 有路径穿越过滤（`../` 被拦或被规范化）？
**A3**: 转绕过：编码（`%2e`/双编码/unicode）、`....//`、绝对路径、null 字节（老环境）、协议 wrapper。判据是过滤是黑名单还是白名单——黑名单几乎总有等价变形能绕。

**Q4**: 读到了配置里的凭据/密钥，怎么衔接落 shell？
**A4**: 分流：DB 凭据→连库走注入/UDF 落地；框架密钥→伪造签名或构造反序列化 RCE；SSH/云凭据→直接登录或调云 API。任意文件读的收官永远是"把读到的东西接到一条真能 getshell 的链上"。

**Q5**: 只能读特定类型/目录，够不到敏感文件，卡住往哪转？
**A5**: **转向**：在可读范围内榨取价值（应用自身日志/缓存里可能有 session/token/明文），或把它当**信息面**辅助其他洞（拿到源码片段去审上传/注入点）。读取范围受限时，从"直接读凭据"转"读出能配合别的洞的碎片"。

**Q6**: 能读文件但目标其实是想写/执行，读到头了怎么办？
**A6**: 认清任意读的天花板——它就是读。**转向**用读到的情报去找/构造一个**写或执行**的洞（读到上传逻辑找绕过、读到密钥打反序列化）。别指望纯读漏洞直接 getshell，它的角色是"侦察兵"不是"突击手"。

### 存储型 XSS/CSRF：劫持管理员会话打进后台再 getshell
**Q1**: 前后台都没直接洞，但有个存储型 XSS 能打到管理员，怎么规划到 shell？
**A1**: 把 XSS 当"借管理员的手"。路径：XSS 触发时以管理员身份**调用后台的 getshell 功能**（上传/模板编辑/命令功能），或偷 cookie/token 回来自己登录后台。判据是后台有没有可 getshell 的功能点值得这么费劲去够。

**Q2**: 偷 cookie 还是直接用 XSS 代替管理员操作，哪个好？
**A2**: 有 HttpOnly 时 cookie 偷不到，就让 XSS 直接在管理员浏览器里发请求完成 getshell 动作（如 fetch 后台上传接口）。无 HttpOnly 且无强绑定则偷 token 自己登更灵活。看防护决定姿势。

**Q3**: 有 CSRF token / SameSite 防护，XSS 发的请求被拒？
**A3**: XSS 与 CSRF 防护是可共存绕过的：XSS 在同源上下文里能先读页面/接口拿到 CSRF token 再带上发请求，SameSite 也因同源而不拦。判据是 XSS 执行在目标同源——是的话 CSRF token 基本形同虚设。

**Q4**: 等不到管理员触发 XSS / 打点没人访问，卡住怎么办？
**A4**: **转向**：XSS 依赖"受害者上钩"，不确定性高。若有更主动的路（认证绕过、注入拿凭据）优先走；必须走 XSS 则想办法诱导触发（把 payload 放在管理员必看的位置，如工单/评论/日志后台）。降低对被动触发的依赖。

**Q5**: 后台就算进去了也没 getshell 功能，这条链值得吗？
**A5**: 重估性价比：如果后台只是数据没有 getshell 点，费大力气钓管理员不划算。**转向**把管理员权限用于拿更值钱的东西（凭据、其他系统入口）或换攻击面。别为了"进后台"而进后台。

**Q6**: 纯 CSRF（无 XSS）能不能推到 getshell？
**A6**: 能，但更受限：CSRF 只能盲发预构造请求（无法读响应）。若后台某 getshell 操作是"一个固定请求就能完成"（如上传固定内容、开某功能），CSRF 可盲触发。需要读响应/多步交互的则 CSRF 不够，得回到 XSS 或其他路。

### 从 web 落脚点用配置凭据横向到其他系统
**Q1**: web 拿到 shell 了，翻到一堆配置里的数据库/中间件/其他系统凭据，横向该怎么排序？
**A1**: 先给凭据分类排序：能直连的服务（DB/Redis/中间件管理台）、能复用的账号（同口令登其他机器）、高价值凭据（域账号、云 key、运维跳板）。按"直接可用 × 通向核心程度"排，先打一击即中的。

**Q2**: 拿到数据库凭据，除了读数据还能怎么扩权？
**A2**: 连上去看 DB 权限——高权 DB 可 UDF/xp_cmdshell 直接在**另一台 DB 服务器**上落 shell（web 与 DB 分离时这就是第二台机器）。DB 凭据不只是数据，可能是"另一台机器的 shell 入场券"。

**Q3**: 凭据复用（同口令）怎么系统地试而不炸锁？
**A3**: 先小范围验证（拿这组口令试几台/几个服务），确认复用成立再扩面；注意账号锁定与登录告警，控制速率和并发。凭据喷洒要"先验证模式，再谨慎铺开"，别一上来全网段爆破触发防御。

**Q4**: 凭据都是应用专用的、无法登录任何其他系统，横向卡住？
**A4**: **转向**：从"凭据横向"转"网络横向"——用当前立足点做跳板扫内网，找未授权服务、其他有洞的 web、可打的中间件。此路凭据不通就走漏洞路，两个横向维度正交互补。

**Q5**: 拿到的是云平台的 AK/SK 或元数据凭据，怎么用？
**A5**: 这可能比本机 root 值钱得多——调云 API 看权限：能否列/进其他实例、读 OSS/存储桶、改安全组、拿更多凭据。**转向**云控制面横向，一组高权云 key 可能等效于整个环境的钥匙。

**Q6**: 横向打下第二台机器后，怎么避免"打一台丢一台线索"？
**A6**: 每台立足点都重复"态势判断 + 翻凭据/配置"，把新凭据汇入凭据库循环利用（凭据→新机器→新凭据）。web-to-shell 之后的内网推进本质是"凭据滚雪球"，建立凭据与资产的滚动清单别让线索断掉。

### 拿到 shell 后的稳定性与持久化：保住立足点
**Q1**: 好不容易 web-to-shell 成功，怎么确保不会因为一次断连/重启前功尽弃？
**A1**: 先评估当前立足点的脆弱性：webshell 会不会被清、进程会不会重启、连接稳不稳。据此决定持久化强度。原则：**先固化再深入**，别在只有一个易失入口时就一头扎进深水区。

**Q2**: 该建几层持久化，怎么分布？
**A2**: 冗余分层：应用层（webshell/内存马）、系统层（计划任务/服务/启动项/后门账号）、凭据层（拿到可复用凭据本身就是最稳的"持久化"）。层与层触发方式和存活条件要不同，避免一锅端。

**Q3**: 持久化怎么放才不容易被发现/被清？
**A3**: 隐蔽性来自"混进正常"：藏在正常业务文件/常见系统位置、用不显眼的名字、隐蔽触发条件（暗号才响应）。同时记录每个后门的位置和触发方式，自己得找得到、防守方难发现。

**Q4**: 担心持久化动作本身触发 EDR/告警怎么办？
**A4**: 高对抗环境下**转策略**：少留甚至不留系统层持久化，改靠"凭据 + 隐蔽内存驻留 + 随时可重新进入的入口"。持久化的噪音有时比价值大，权衡后可选择"轻持久化 + 快速可重入"而非重落后门。

**Q5**: 立足点突然掉了（webshell 被删/连接断），怎么快速恢复？
**A5**: 走预留的冗余入口重新进入，这正是多层持久化的意义。若全丢了，**转向**用之前抓到的凭据重新登录/复用，或重打最初的入口洞。所以前期务必"边打边囤凭据和备用入口"。

**Q6**: 长期驻留 vs 打了就撤，怎么判断？
**A6**: 看目标与对抗：需要长期控制/持续横向则重持久化，纯快速拿成果则拿到即撤减少暴露。默认倾向"拿到关键成果后尽快转移到更隐蔽的立足点"，别在初始 web 落脚点长期高调停留。

### 何时从"打 nday"转向手工挖 0day
**Q1**: 已知 nday 都试完打不动（打了补丁/防护到位），该继续挖 0day 还是换目标？
**A1**: 先算投入产出：手工挖 0day 成本高、周期长。判据是"这个目标是否非拿不可 + 是否有源码/白盒条件"。有源码泄露或能下载程序做审计时，挖洞性价比才够；纯黑盒硬挖优先级应很低。

**Q2**: 决定挖了，从哪种漏洞类型入手效率最高？
**A2**: 挑该技术栈"最可能 getshell"的类型集中审：上传逻辑、反序列化点、命令拼接、模板/表达式渲染、文件操作。带着"找 sink 反推可控输入"的审计思路，别通读全部代码。目标是 RCE 类洞，不是任意洞。

**Q3**: 黑盒无源码但怀疑有逻辑洞，怎么低成本挖？
**A3**: 聚焦逻辑与配置类（不需读代码）：越权、认证绕过、未授权接口、参数篡改。这类"黑盒可测"的洞比内存/注入类 0day 好挖得多。**先挖黑盒能验证的，再考虑需要白盒的**。

**Q4**: 挖了一阵毫无进展，什么时候止损转向？
**A4**: 设时间/尝试上限。到点就**转向**回到侦察扩面——多半是攻击面没铺够（漏了子域/旁站/其他端口/其他入口），而不是"这个点真有可挖的 0day 等着你"。web-to-shell 卡死时，扩面的期望收益通常高于死磕挖洞。

**Q5**: 挖到疑似 0day 但利用不稳定/条件苛刻，值不值得打磨？
**A5**: 看它是否是唯一路径。若有其他更稳的入口候选，别在脆弱 0day 上打磨；若确是唯一突破口，则先在同环境复现稳定再上目标，避免一次性的不稳定利用打草惊蛇。

**Q6**: 挖 0day 和铺攻击面该怎么分配精力？
**A6**: 默认**先广度后深度**：先把资产/入口铺满、把所有 nday 和配置洞筛一遍，确认"广度真的挖尽了"再投入深度挖洞。绝大多数 web-to-shell 死在广度不够，而非深度不够。

### 表达式注入（OGNL/SpEL/EL）：区别于模板 SSTI 的落地
**Q1**: 怀疑是表达式注入（如 Java 的 OGNL/SpEL/EL）而不是模板 SSTI，怎么区分和确认？
**A1**: 看上下文：表达式注入常出现在框架参数绑定、搜索/过滤表达式、规则引擎、错误消息里，而非页面模板渲染。用对应引擎的探针（SpEL `#{}`/`T()`、OGNL `%{}`/`@`、EL `${}`）确认。引擎判对了利用链才对。

**Q2**: 确认是 SpEL，怎么走到 RCE？
**A2**: SpEL 可用 `T(java.lang.Runtime).getRuntime().exec(...)` 或 `new ProcessBuilder`，核心是通过 `T()` 引用任意类并调静态方法。判据是表达式是否在"可求值上下文"里被完整解析。

**Q3**: 是 OGNL（典型见于某些 MVC 框架参数）呢？
**A3**: OGNL 走 `@java.lang.Runtime@getRuntime().exec()` 或经 context 调用，注意很多框架加了 OGNL 沙箱/黑名单（禁 `#` 访问、禁某些类）。判据是能否绕过框架的表达式安全管控访问到 Runtime。

**Q4**: 有沙箱/黑名单（关键类或语法被禁），表达式跑不通？
**A4**: 转绕过：反射间接调（用 Class.forName 拿被禁的类）、改上下文变量放开限制（某些版本可先关沙箱开关）、编码/拼接绕关键字。**若沙箱是新版本严格实现**则**转向**——该框架此版本的表达式注入可能已被基本堵死，改打它的其他漏洞或其他组件。

**Q5**: 表达式能求值但**无回显**（结果不显示）？
**A5**: 同无回显 RCE 处理：先 DNSlog/延时确认执行，再用表达式把命令结果写文件/带外回传。表达式注入到无回显 RCE 后，落地手法与普通 RCE 一致，不必在表达式层纠结回显。

**Q6**: 探针有反应但构造完整利用链总失败，怎么定位？
**A6**: 分清是"表达式没被完整求值"（可能只解析部分/被截断/被转义）还是"求值了但被沙箱拦执行"。前者调整注入位置/闭合，后者转绕过或换洞。**先确认求值深度，再决定是修 payload 还是换方向**。

### 云上 web-to-shell：拿到 shell 后走云元数据与云凭据
**Q1**: web 打进的是一台云主机（ECS/EC2 类），拿到 shell 后除了本机提权还该看什么？
**A1**: 第一时间探云元数据服务（内网 169.254.x 类地址），常能拿到实例绑定的**临时云凭据**。云上很多时候不需要 root——一组高权云凭据的价值远超本机 root。先看云身份，再谈本机提权。

**Q2**: 拿到实例的临时凭据，怎么判断价值？
**A2**: 枚举这组凭据的权限（能调哪些云 API）：能读存储桶、列/进其他实例、改安全组、拿更多机器的访问，就等于横向甚至接管环境。判据是绑定角色的权限范围——先摸清 RBAC 再规划动作。

**Q3**: 只有 SSRF（还没 shell）但目标在云上，能直接够元数据吗？
**A3**: 能——SSRF 打云元数据是经典组合，让服务器代我请求元数据接口拿凭据，跳过 getshell 直接拿云控制权。判据是元数据服务有没有做防护（如 IMDSv2 需要特定 header/token）。

**Q4**: 元数据服务加固了（IMDSv2/需 token/被禁访问），这条路断了怎么办？
**A4**: **转向**：回到本机翻云凭据的其他来源——配置文件里的 AK/SK、CI/CD 凭据、运维脚本、环境变量、云 CLI 的缓存凭据。元数据被封不代表云凭据不存在，换文件系统里找。仍无则回退常规本机提权/内网横向。

**Q5**: 拿到云凭据但权限很小（只读某个桶），怎么扩？
**A5**: 找云上的**权限提升**：可被 assume 的高权角色、可传递的信任关系、可改的策略、其他实例上的更高权凭据。云环境横向常是"低权凭据→通过配置错误链到高权角色"，像内网凭据滚雪球一样在云 IAM 里滚。

**Q6**: 是容器/Serverless 而非传统主机，元数据这套还适用吗？
**A6**: 适用且更重要——容器/函数往往就靠绑定的云身份运作，元数据/环境变量里的凭据是主要战利品。**转向**云身份维度：这类环境里"拿 shell"意义有限，"拿云凭据 + 打云控制面"才是主线。

### 资产与入口发现：web-to-shell 起点的攻击面铺设
**Q1**: 面对一个目标只给了个域名/一个站点，还没找到任何洞，第一步做什么？
**A1**: 先铺攻击面而不是急着打眼前这一个页面。系统收集：子域、旁站/C 段、端口服务、目录与隐藏接口、指纹与版本、历史资产。web-to-shell 的成败八成取决于攻击面铺得够不够广，入口越多突破口越多。

**Q2**: 主站看着很干净（防护到位），怎么找软柿子？
**A2**: 转边缘资产：老旧子域、测试/预发环境、备份站、管理后台、第三方组件、被遗忘的接口。核心站加固不代表全家桶都加固，边缘资产常年失修，是 web-to-shell 最肥的入口。

**Q3**: 目录/接口扫描要扫出什么才算有价值？
**A3**: 盯几类高价值发现：上传点、后台登录、API 文档/调试接口、备份文件、源码泄露、`.git`、配置文件、已知组件路径。扫描不是为了列目录，是为了找"能通向 shell 或凭据"的入口，围绕这个目标筛结果。

**Q4**: 扫了一圈啥有用的都没出，卡在起点怎么办？
**A4**: **转向**换发现维度：从"目录暴破"转"指纹驱动"（识别出组件再针对性查该组件的已知路径/洞）、从"主域"转"关联资产"（证书、被动 DNS、favicon hash 找同组织其他站）、从"HTTP"转"其他端口服务"。起点卡住往往是发现手段单一，换正交的发现方法。

**Q5**: 资产太多打不过来，怎么排优先级？
**A5**: 按"getshell 距离"筛：有上传/后台/已知漏洞组件/泄露的资产优先，纯静态展示站靠后。别平均用力，把精力压在"最可能一击落 shell"的少数入口上。广度铺满后要立刻做深度优先级排序。

**Q6**: 攻击面铺得很广但每个入口都浅尝辄止没突破？
**A6**: 这是常见反模式。**转向**：广度铺够后转深度——挑 2~3 个最有希望的入口深入打透（一个上传点把所有绕过姿势试遍，一个组件把所有 nday 和配置洞筛遍），而不是在一百个入口上各试一下。web-to-shell 最终靠"在对的入口上打够深"。

### 哑 shell 升级为全交互式 tty：解锁后续提权的前置
**Q1**: 反弹回来一个 shell，但没有补全、Ctrl-C 直接断、`sudo`/`su` 报 "must be run from a terminal"。为什么要先升级？
**A1**: 它是缺伪终端的哑 shell，很多提权动作（交互式 sudo、ssh、passwd、full-screen 程序、内网工具）都要求真 tty。升级 tty 不是洁癖，是解锁后续操作的前置条件——先升级再干活，省掉大量因终端缺失导致的失败返工。

**Q2**: 标准升级链是什么？
**A2**: 经典链：`python -c 'import pty;pty.spawn("/bin/bash")'` 起 pty → 本地 `Ctrl-Z` 挂起 → `stty raw -echo; fg` 交回原始模式 → 目标里 `export TERM=xterm` 并 `stty rows/cols` 对齐窗口尺寸。没 python 就用 `script /dev/null`、`socat` 双端 pty、或 `expect` 分配终端。

**Q3**: 目标很精简，python/script/socat 全都没有？
**A3**: **转向**：上传静态编译的 socat/busybox 拿 pty；或不强求当前通道升级——用"无需交互"的方式完成关键动作（`sudo -S` 从 stdin 喂密码、写 authorized_keys 后直接 `ssh` 进来天然拿到真 tty）。拿真 tty 最干净的办法往往是"想办法 ssh 进去"而非硬升当前哑 shell。

**Q4**: 升级过程中 shell 卡死/终端错乱/断了怎么办？
**A4**: 多是 stty 参数或 fg 顺序错导致。先在本地 `reset` 恢复终端。关键教训：升级 tty 有断线风险，操作前必须保留**冗余通道**（另一条 shell 或能重新触发回连），别在只有单一入口时做这种危险操作，避免一把梭失联前功尽弃。

**Q5**: 升级到全交互后还要做什么才算稳？
**A5**: 对齐窗口尺寸（否则 vim/top 花屏）、设好 TERM、确认 job control 可用。随后立刻把这条来之不易的稳定 shell 用于"固化立足点"（落持久化/抓凭据），而不是继续裸奔在易失的初始通道上。

**Q6**: 为什么不干脆一直用哑 shell 凑合？
**A6**: 哑 shell 会在关键节点卡壳——交互式提权跑不了、密码输入无回显、内网交互工具挂掉，反而拖慢整体节奏。前期花一分钟升级 tty，是对后续每一步的投资；对抗环境下若升级噪音太大，则**转向**直接走 ssh/C2 beacon 拿原生交互，跳过在哑 shell 上折腾。
