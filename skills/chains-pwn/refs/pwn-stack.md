# 逆向PWN · 栈溢出漏洞定位与利用取舍

### 拿到未知二进制第一步:用保护决定利用总路线
**Q1**: 手里一个 ELF,还没逆向,先做什么才不浪费时间?
**A1**: 先 `file` 看架构/位数/是否 stripped/是否静态,再 `checksec` 看 Canary/NX/PIE/RELRO。这五个开关基本决定了利用的"骨架":有没有 Canary 决定要不要 leak 栈金丝雀,NX 决定是不是必须 ROP,PIE 决定要不要泄露基址,RELRO 决定 GOT 能不能改。逆向细节先放,总路线先定。
**Q2**: 保护全开(Full RELRO + Canary + NX + PIE)怎么规划?
**A2**: 这是"必须先 leak 后打"的信号。规划成两阶段:第一阶段用某个信息泄露(格式化串/越界读/栈残留)拿到 libc 或 PIE 基址与 Canary,第二阶段再溢出。别一上来就想一次打穿。
**Q3**: 保护几乎全关(No Canary/No PIE/No NX)呢?
**A3**: 这是"ret2shellcode 或直接跳固定地址"的信号,优先找可写可执行段布 shellcode,或直接看有没有后门。判据是利用复杂度应该和保护强度成正比,保护弱却往复杂里做说明想歪了。
**Q4**: checksec 说 NX disabled 但我塞 shellcode 就崩,怎么回事?
**A4**: 别只信 checksec。用 `vmmap`(gdb/pwndbg)在运行时确认目标段真的 RWX;有的加载器或页属性和 ELF 头声明不一致。把假设放到运行时验证,而不是静态标签。
**Q5**: 这条"按保护定路线"的判断被现实打脸——按规划做发现根本触发不了溢出怎么办?
**A5**: 转正交维度:从"内存破坏"转到"逻辑漏洞"。重读程序流,找整数溢出导致的越界、菜单条件竞争、未初始化变量、命令拼接。栈溢出不是唯一入口,保护再全也可能有逻辑后门。
**Q6**: 怎么快速判断是该继续啃栈溢出还是转逻辑?
**A6**: 给栈溢出方向设时间盒。若在"找不到可控溢出点/偏移算不准/无泄露手段"三点同时卡住超过一个时间盒,就切换维度,而不是在同一坑里加深。

### 定位溢出点:从危险函数与输入源反推
**Q1**: 逆向后想找栈溢出,从哪下手最快?
**A1**: 先搜危险函数:`gets`、`read(fd, buf, 过大长度)`、`scanf("%s")`、`strcpy/strcat/sprintf`、循环里逐字节写栈缓冲。把每个输入源标注"能写多少字节到多大的缓冲",超出即候选。
**Q2**: 反汇编里 read 的长度是个变量,看不出来大小?
**A2**: 回溯该长度参数的来源。若来自用户可控输入(先读一个 size 再 read),那就是可控长度溢出,危险度更高;若是硬编码常量,和缓冲区大小对比即可判定。
**Q3**: 危险函数一个都没有,但我确信有溢出?
**A3**: 转看自实现的复制循环和 `alloca`/变长栈数组。很多题不用标准库函数,而是 `for(i;i<=n;i++) buf[i]=...` 这种 off-by-one 或用户控制 n 的循环。危险不在函数名而在边界检查。
**Q4**: 静态看不清,能否动态定位?
**A4**: 能。喂超长 cyclic 输入,让它崩,看 crash 时 PC/RSP 里的 pattern 值,直接定位是哪个函数、哪个缓冲区被踩。动态 fuzz 一次比读半天汇编快。
**Q5**: 崩溃了但 PC 没被覆盖成 pattern,只是段错误?
**A5**: 说明覆盖的不是返回地址而是中间指针或局部变量(可能是 SFP、某结构指针)。看崩在哪条指令、访问哪个地址,判断是覆盖了指针后解引用——这可能是另一种利用原语(任意写),别只盯着控 PC。
**Q6**: 这个二进制被 strip 了,连 main 都找不到,定位无从谈起?
**A6**: 转向从入口反推:`__libc_start_main` 的第一个参数就是 main;或对已知 libc 函数(printf/read)的调用点做交叉引用,顺藤摸瓜。strip 只是没符号,控制流还在。

### 精确算偏移:cyclic 一步到位
**Q1**: 确认能溢出,现在要算到返回地址的精确偏移,怎么做最稳?
**A1**: 用 `cyclic 200` 生成 de Bruijn 序列发进去,崩溃后取 RSP(64位)或 PC(被覆盖时)里的 4/8 字节,`cyclic -l <值>` 反查偏移。比手数缓冲区大小 + SFP 靠谱,尤其编译器有对齐/额外局部变量时。
**Q2**: 64 位程序崩溃时 PC 不是 pattern,而是 ret 指令报错?
**A2**: 64 位下不可规范地址会在 ret 时崩,此时看 RSP 指向的栈内容里的 pattern 反查偏移。记住 64 位是"栈顶存的返回地址"被覆盖,不是 PC 直接变 pattern。
**Q3**: 偏移算出来了,但填进去 ret 目标还是不对,差几个字节?
**A3**: 检查栈对齐。64 位 movaps 要求 16 字节对齐,若你的 ROP 落地时 RSP 未对齐,进 libc 函数会崩。常见修法是在链首加一个 `ret` gadget 做对齐补偿。
**Q4**: 输入里有长度限制,cyclic 200 都发不进去?
**A4**: 说明溢出长度受限,先用能发的最大长度做二分/短 pattern 定位偏移,再规划"短链"策略(见栈迁移/ret2csu 相关链)。偏移定位和利用长度是两件事,别混。
**Q5**: 本地算的偏移远程对不上?
**A5**: 偏移一般与环境无关(取决于二进制自身布局),对不上通常是发送方式问题:多发了换行、编码不一致、或远程有额外交互。回到收发同步维度排查,而不是怀疑偏移。

### Canary 挡路:leak 它还是绕过它
**Q1**: checksec 有 Canary,溢出会被 `__stack_chk_fail` 拦,怎么破?
**A1**: 三条路选一:①泄露 Canary 值再连同它一起覆盖回去;②利用不经过返回地址检查的原语(改栈上局部指针/GOT);③若有 fork 型服务且 Canary 不变,逐字节爆破。先看程序有没有天然的泄露点。
**Q2**: 怎么泄露 Canary?
**A2**: 找能把栈内容打印出去的原语:格式化字符串 `%p` 定位到 Canary 槽、越界读、或先用 `%s`/puts 读到 Canary 前一字节为 `\x00` 的特征(Canary 低字节恒为 0x00)。定位时就靠这个 `\x00` 结尾特征认它。
**Q3**: 没有任何输出函数,泄露不了?
**A3**: 转爆破维度——仅当目标是 fork/forkserver 且每次 Canary 相同。逐字节枚举,对了不崩、错了崩,8 字节最多 8×256 次。若是非 fork(每次重启换 Canary),此路不通,转 A4。
**Q4**: 既不能 leak 又不能爆破呢?
**A4**: 换利用原语,绕开 Canary 检查本身。Canary 只保护"返回地址"这条路;若能改栈上函数指针、`__stack_chk_fail` 前生效的结构、或触发在 canary 校验前的跳转(如覆盖循环变量造成任意写),就不碰返回地址。这是正交转向:从控 ret 转到控数据/指针。
**Q5**: 我 leak 到一个值,但填回去还是 crash?
**A5**: 核对是否把 Canary 放对了槽位(它在 SFP 前),以及低字节确实是 `\x00`。若 leak 出来低字节非 0,那 leak 的不是 Canary,重新定位偏移。

### NX 开启:从注入代码转向复用代码(ROP)
**Q1**: NX 开着,shellcode 塞进去不执行,思路怎么转?
**A1**: 从"注入代码"转"复用已有代码":ret2text(用二进制自身代码片段)、ret2libc(调 libc 函数)、ROP(拼 gadget)。核心是不再执行栈上数据,而是把栈布成一串返回地址链。
**Q2**: 先做 ret2libc 还是先看有没有现成 system?
**A2**: 先在二进制和已加载库里找现成 `system`/`/bin/sh`/后门函数,能一步到位就别搞复杂 ROP。判据:利用越短越稳,先穷尽"捷径"再上通用 ROP。
**Q3**: 32 位和 64 位下 ret2libc 布局差别大吗?
**A3**: 大。32 位靠栈传参:`system_addr | 返回地址 | binsh_addr`。64 位靠寄存器:需要 `pop rdi; ret` 把 binsh 放进 rdi。别把 32 位的布局套到 64 位,这是高频错误。
**Q4**: 找不到 `pop rdi; ret` 这种关键 gadget?
**A4**: 转 ret2csu(利用 `__libc_csu_init` 里的通用 gadget 组合控制 rdi/rsi/rdx),或用 libc 里的 gadget(leak 基址后 libc 里 gadget 极多)。gadget 短缺时,战场从"二进制自身"转到"整个 libc"。
**Q5**: ROP 链拼好了,单步都对,一 continue 就崩?
**A5**: 查栈对齐(movaps 问题)和链中某个 gadget 是否有副作用(改了你后面要用的寄存器)。逐 gadget 在 gdb 里 telescope 栈,而不是整链盲发。
**Q6**: 整个 ROP 方向走不通(无输出无法 leak libc、gadget 也不够)怎么彻底转向?
**A6**: 转 ret2dlresolve(伪造重定位结构让 loader 帮你解析 system,无需 leak libc)或 BROP(盲打远程逐步爆 gadget)。这是"无信息泄露"绝境下的正交打法。

### PIE 开启:先 leak 基址再谈一切
**Q1**: PIE 开着,二进制自身地址都随机,ROP 目标怎么定?
**A1**: 所有二进制内地址(gadget、后门、函数)都要加上运行时基址,所以第一目标是泄露 PIE 基址。找任何能泄露"代码段/返回地址"的点,减去该符号静态偏移得基址。
**Q2**: 泄露到一个地址,怎么确认它属于 PIE 段而非 libc/栈?
**A2**: 看低 12 位(页内偏移)是否和某个已知静态符号的低 12 位吻合——PIE 加载按页对齐,低 12 位不变。吻合即 PIE 内地址,用它反算基址。
**Q3**: 只能泄露 libc 地址,泄露不了 PIE?
**A3**: 那就别依赖 PIE 内 gadget,把利用完全建在 libc 上(libc 基址已知,gadget/system/binsh 全在 libc 找)。缺哪个基址就把战场移到已知基址的那个模块。
**Q4**: 一次泄露既拿不到 PIE 又拿不到 libc?
**A4**: 找"能反复触发"的结构:若 main 结束能回菜单,可多次 leak,一次拿一个基址。若只有一次机会,优先 leak 能顺藤摸更多的那个(通常 libc,因为 libc 里啥都有)。
**Q5**: 本地泄露正常,远程泄露出来的值明显不像地址?
**A5**: 远程 libc 版本不同导致偏移错位,或收发把地址截断。先确认远程 libc 版本(见 libc 识别链),再核对收包是否吃掉了字节。

### 无 system 无 /bin/sh:构造还是换目标
**Q1**: 想 ret2libc 但 libc 里 `/bin/sh` 字符串找不到,或不想执行 shell?
**A1**: 先确认真找不到——`/bin/sh` 几乎必在 libc,用 `search '/bin/sh'`(pwndbg)或 `ROPgadget --string` 搜。若确实没有(极简 libc/静态裁剪),转"自己写字符串到可写段再传参"。
**Q2**: 怎么把 `/bin/sh` 写进内存?
**A2**: 用一段 ROP 调 `read`/`gets` 往 `.bss` 或已知可写地址写字符串,再把该地址当 system 参数。或用 `mprotect` 改权限后跳 shellcode。判据:有可写段 + 能控 rdi/rsi/rdx 就能写。
**Q3**: 连 system 都被 seccomp 禁了(execve 不让用)?
**A3**: 转 orw:用 open/read/write 系统调用直接读 flag 文件打印出来,不起 shell。这是 seccomp 沙箱下的标准转向。先 dump seccomp 规则确认放行了哪些 syscall。
**Q4**: 那怎么知道 seccomp 禁了哪些?
**A4**: 用 `seccomp-tools dump ./bin` 看 BPF 规则。判断是白名单还是黑名单、禁没禁 execve/execveat、open 是否要用 openat。规则决定 orw 具体用哪几个号。
**Q5**: orw 也走不通(连 open 都禁,只放行 read/write)?
**A5**: 转"利用已打开的 fd"或 `readv`/`sendfile`/`preadv` 等替代读取原语;若 flag 已被程序打开过,直接对其 fd 做 read。绝境里从"我去开文件"转成"复用它开好的资源"。

### 找不到 gadget:ret2csu 与万能 gadget
**Q1**: 64 位要控 rdi/rsi/rdx 传三个参,但只找得到 `pop rdi`,rsi/rdx 没有,怎么办?
**A1**: 用 ret2csu。`__libc_csu_init` 尾部有一段 `pop rbx/rbp/r12/r13/r14/r15; ret` 加一段 `mov rdx,r15; mov rsi,r14; mov edi,r13d; call [r12+rbx*8]`,能把 r13/r14/r15 搬进 edi/rsi/rdx。这是静态二进制凑三参的经典万能件。
**Q2**: 程序是高版本编译,没有经典 csu gadget?
**A2**: 找等价的"寄存器搬运片段"——`__libc_csu_init` 结构变了,但 libc 里(leak 后)一定有大量 `mov rsi/rdx` 组合;或用 one_gadget 一步起 shell 绕开传参。
**Q3**: csu 里的 `call [r12+rbx*8]` 让我很别扭,还得布一个函数指针表?
**A3**: 是的,设 rbx=0,r12 指向一个存着目标函数地址的可写位置(如 GOT 项或你写的地址)。若嫌麻烦且已 leak libc,直接用 libc gadget 更省事。判据:静态无 libc 才硬用 csu,有 libc 优先 libc gadget。
**Q4**: gadget 实在拼不出所需寄存器组合?
**A4**: 转 SROP(sigreturn)。用一个 `syscall; ret` 加可控的 signal frame,一次性设置所有寄存器(rax/rdi/rsi/rdx/rip 全控),绕过逐个 gadget 拼凑。前提是能控栈布下整个 frame 且能设 rax=15。

### libc 版本未知:识别它再谈 ret2libc
**Q1**: 远程 ret2libc,但不知道远程 libc 版本,offset 全靠猜?
**A1**: 先泄露至少一个 libc 函数的真实地址(通过 GOT 里已解析的项,如 puts@got),把该函数低 12 位(页内偏移固定)拿去 libc-database 查匹配版本。有两个函数地址就能唯一确定。
**Q2**: 只能泄露一个函数地址,库匹配出好几个候选?
**A2**: 用第二个函数进一步收敛,或直接对每个候选 libc 都算一遍 system/binsh 偏移挨个试。远程可交互时试错成本低,先按最可能版本打。
**Q3**: 一个地址都 leak 不到怎么确定 libc?
**A3**: 转 DynELF(通过一个"任意地址泄露"原语在线解析符号,不需要知道 libc 版本)或 ret2dlresolve(压根不 leak libc)。从"识别版本"转成"根本不依赖版本"。
**Q4**: 匹配到版本了,本地用同版本 libc 打通,远程还是失败?
**A4**: 检查是否用了正确的加载器/libc 运行本地测试(`LD_PRELOAD` 或 patchelf 换成远程同版本 libc 本地复现)。本地用系统 libc 打通不代表远程能通,一定要本地就用远程那份 libc 复现。

### 泄露机会只有一次:泄露什么最划算
**Q1**: 程序只给一次输出机会,leak 一个地址后就没了,该 leak 谁?
**A1**: leak "信息密度最高"的:优先 libc 地址(libc 里 system/binsh/gadget/one_gadget 全有,一个基址解锁一切)。PIE 基址次之。Canary 只在需要二次溢出且过 Canary 时才优先。
**Q2**: 但我第二阶段还需要 PIE 基址和 libc 两个?
**A2**: 想办法一次 leak 出能连锁的那个。比如 leak 栈上残留:栈里常同时有 libc 地址(__libc_start_main 返回地址)、PIE 地址(main 返回链)、栈地址。选一个能通过固定偏移推出其他的位置。
**Q3**: 一次机会且 leak 完程序就退出,来不及用?
**A3**: 那这次交互必须在同一条链里"leak + 用"。用 ret2csu/ROP 先调 puts 泄露,再让控制流回到一个可再次接收输入的点(如 main 或 vuln 函数),第二次收 payload。关键是让程序别退出——把返回地址指回可利用函数。
**Q4**: 程序结构上就是一次性、无法回环?
**A4**: 转 ret2dlresolve 或 SROP 这类"无需 leak"的一次成型打法,把两阶段压成一阶段。无泄露不可回环时,正交转向到不依赖泄露的技术。

### 输出被 \x00 截断:选对泄露函数
**Q1**: 用 puts 泄露地址,结果地址里有 `\x00` 被截断,只收到半个?
**A1**: 64 位有效地址高位常是 `\x00`,puts 遇 0 停。改用 `write(1, addr, n)` 按固定长度输出,不受 0 截断。判据:要泄露原始字节流就别用字符串函数。
**Q2**: 只能用 puts,没有 write 可调?
**A2**: 利用 puts 会补一个换行、且从目标地址打到第一个 `\x00` 的特性,精心选泄露起点让你要的 6 字节恰好完整、后面紧跟 `\x00`。或分多次 leak,每次错位一字节拼出完整地址。
**Q3**: 泄露出来的 6 字节我怎么补成 8 字节地址?
**A3**: 64 位用户态地址高 2 字节几乎恒为 `\x00`,收到 6 字节后手动补两个 `\x00`(小端)即可。`u64(data.ljust(8,'\x00'))` 是标准写法。
**Q4**: printf 泄露时遇到 `%s` 碰到不可读地址直接崩?
**A4**: 换 `%p`(打印指针值本身,不解引用)或定位到确定可读的槽位。`%s` 要求参数是合法指针,盲目 `%s` 易崩,先用 `%p` 侦察栈布局再精确取。

### 栈空间不够放 ROP 链:栈迁移
**Q1**: 溢出能覆盖返回地址,但后面栈空间太小,放不下完整 ROP 链?
**A1**: 用 stack pivot:把 rsp 迁到一块你能控制的大空间(bss/堆/已写入数据区)。经典手法 `leave; ret`(把 rbp 设成目标-8)或 `pop rsp; ret`/`xchg`。链的主体提前写到目标区。
**Q2**: 迁到哪块内存最稳?
**A2**: 选地址已知且够大的可写段,通常是 `.bss` 固定地址(无 PIE 时)或先 read 一大段数据到某处再迁过去。判据:目标区地址已知 + 权限可写 + 空间足够。
**Q3**: `leave; ret` 迁移后发现 rbp 链被打乱,后续崩了?
**A3**: 记住 `leave` = `mov rsp,rbp; pop rbp`,你控制的是 rbp,迁移后新栈顶是你设的地址处,且会再 pop 一次。布局时预留这个 pop 消耗的 8 字节,别少算。
**Q4**: 溢出长度小到连一次迁移 gadget 都布不下?
**A4**: 转"两次读入"思路:第一次溢出只做最小动作——把控制流引回一个 read/gets,往固定地址读入完整第二阶段 payload,同时迁栈过去。短溢出的正交解法是"用程序自己的输入函数扩容"。

### 格式化字符串 + 栈溢出并存:先用哪个
**Q1**: 一个程序同时有格式化字符串和栈溢出两个洞,先用哪个?
**A1**: 通常格式化串当"侦察/泄露与任意写"工具、栈溢出当"最终控流"武器。先用 fmt 泄露 Canary/libc/PIE 破掉保护,再用栈溢出一击致命。分工:一个供信息,一个给控制。
**Q2**: 只用格式化字符串能不能一把梭,不碰栈溢出?
**A2**: 能——fmt 的 `%n` 可任意地址写,直接改 GOT(如把 printf@got 改成 system)或改返回地址。若 RELRO 是 Partial,改 GOT 最省事。判据:GOT 可写就优先 fmt 改 GOT。
**Q3**: Full RELRO,GOT 不可写,fmt 的 `%n` 无处下手?
**A3**: 转 fmt 改"栈上的返回地址"或 `__malloc_hook`/`__free_hook`(旧 libc)/ exit_hook / `__stack_chk_fail`GOT 等仍可写的函数指针。GOT 锁死时,把任意写目标转到其他可写的控制流指针。
**Q4**: fmt 偏移(第几个参数)数不清?
**A4**: 发 `AAAA%p.%p.%p...` 或 `%1$p %2$p...`,看第几个 `%p` 回显出 0x41414141,那就是你输入所在的参数位。定位偏移靠这个自识别标记,别硬数栈。

### 溢出机会短且只有一次:partial overwrite
**Q1**: PIE 开着,只能覆盖返回地址的低 1~2 字节,基址又 leak 不到,怎么办?
**A1**: 用 partial overwrite:只改返回地址低字节。因为 PIE 按页对齐,低 12 位固定,改低 1.5 字节(利用低 12 位已知 + 高 4 位爆破)能把控制流跳到同页/邻近的目标 gadget 或后门,而无需完整基址。
**Q2**: 需要跳的目标和返回地址不在同一页(低 12 位不同)?
**A2**: 改低 2 字节(16 位),其中高 4 位是随机的,需 1/16 爆破。远程可重连时爆破成本可接受。判据:跳距在 4KB 内改 1.5 字节几乎稳,跨页就得赌高位。
**Q3**: 每次都重启且不可爆破?
**A3**: 转找"同一页内就有的可用目标"——重新审视目标函数/gadget 与溢出点返回地址的相对位置,选一个天然近的落点(如同函数内的后门分支)。不可爆破时把落点选到确定页内。

### 完全无泄露无输出:ret2dlresolve / BROP
**Q1**: 程序啥都不输出,leak 不了任何地址,但有栈溢出,还能打吗?
**A1**: 能。两条路:①ret2dlresolve——伪造 `Elf_Rela`/`Elf_Sym`/字符串,让动态链接器 `_dl_runtime_resolve` 帮你把 `system` 解析并调用,全程不需要知道任何 libc 地址;②BROP——远程盲打逐字节爆 gadget。
**Q2**: ret2dlresolve 的前提是什么?
**A2**: 需要 Partial RELRO(否则 dl_resolve 流程被 Full RELRO 破坏)、能控 rsp 到你伪造结构处、且知道二进制自身的 .plt/.dynamic 布局(无 PIE 或已知基址)。pwntools 有 `Ret2dlresolvePayload` 帮你构造。
**Q3**: Full RELRO 让 dlresolve 也失效?
**A3**: 转 BROP(前提是 fork 型服务、崩溃行为可观测)。通过"栈金丝雀爆破 + stop gadget 探测 + brop gadget 定位 + PLT 扫描"逐步在无源码无二进制下建出 puts 泄露。这是纯黑盒远程的终极正交打法。
**Q4**: 不是 fork 服务,BROP 也做不了?
**A4**: 那回到本地二进制找"隐性泄露"——错误信息、返回值、时间侧信道、崩溃与否的布尔信号。哪怕一个 bit 的输出都可能被放大成 oracle。彻底无 oracle 时,承认此路死,回主流程找别的漏洞点。

### seccomp 沙箱下:orw 读 flag
**Q1**: 拿到执行流但 execve 被 seccomp ban,起不了 shell,怎么拿 flag?
**A1**: 转 orw ROP/shellcode:`open("flag")` → `read(fd, buf, n)` → `write(1, buf, n)`。不碰 shell,直接把 flag 文件内容打到 stdout。先 dump seccomp 确认 open/read/write 放行。
**Q2**: open 被禁但 openat 放行?
**A2**: 用 openat(dirfd=AT_FDCWD=-100, path, flags)。现代 libc 的 open 本就走 openat,syscall 号换成 openat 即可,参数多一个 dirfd。别死磕 open 号。
**Q3**: 沙箱禁了 write,但允许 read?
**A3**: 转其他输出通道:`sendfile`、`writev`、或利用已有 stdout 相关 syscall;甚至用侧信道(读到 flag 后按内容分支触发不同可观测行为逐字节爆)。输出被堵就换输出原语。
**Q4**: seccomp 用了 `ARCH` 检查禁 x86_64,只让 x32/i386 syscall?
**A4**: 这是"换架构调用约定"陷阱。用 `retfq` 切到 32 位模式(ret2csu 里凑 cs=0x23)或直接用被放行的调用号表。识别到 arch 过滤就意识到要换 syscall ABI。

### 静态编译二进制:自身就是武器库
**Q1**: `file` 显示 statically linked,没有 libc 可 ret2,怎么打?
**A1**: 静态二进制把 libc 全打包进来了,gadget 和 syscall 极其丰富。直接 `ROPgadget --binary ./bin` 搜 `pop rax/rdi/rsi/rdx` 和 `syscall`,自己拼 execve("/bin/sh",0,0)。不需要 leak,地址都是固定的(除非 PIE)。
**Q2**: 静态里 `/bin/sh` 字符串找不到?
**A2**: 用 ROP 调 read 往 .bss 写 `/bin/sh\x00`,再执行 execve。静态二进制 .bss 地址固定,写完直接用。判据:静态 + 无 PIE = 一切地址已知,缺字符串就自己写。
**Q3**: 静态且开了 PIE(少见但有)?
**A3**: 那又回到需要 leak 基址的老路——找一次泄露拿 PIE 基址,之后所有静态 gadget 加基址。别被"静态"迷惑而忘了 PIE 仍要基址。
**Q4**: gadget 搜出来一堆但凑不齐 execve 的 rax=59?
**A4**: 找 `pop rax; ret`;没有就找 `xor eax,eax` 系列加加法凑,或用 `mov eax, ...` 片段。静态里 `pop rax` 几乎必有;实在没有,用 SROP 用 signal frame 设 rax。

### 溢出后程序会二次校验/主动 crash:绕检测
**Q1**: 溢出成功但程序在返回前做了完整性校验(比对 magic/长度),直接退出?
**A1**: 先逆清校验逻辑:它检查什么、在哪比对。若检查栈上某标志,就在 payload 里把该标志也填成合法值,让校验通过。溢出不等于无脑填满,要保留合法结构。
**Q2**: 校验的是 Canary 之外的自定义 cookie?
**A2**: 当成"第二道 Canary"处理:要么泄露它一起填回,要么找不经过该校验的控制流路径。逻辑上和绕 Canary 同构,复用那套思路。
**Q3**: 校验通不过且泄露不了 cookie?
**A3**: 转"提前劫持"——在校验发生前就把控制流夺走。比如覆盖一个在校验代码之前被调用的函数指针/GOT 项,让程序还没走到校验就已跳到我这。把打击点前移到检测点之前。

### off-by-one:抬栈与改低字节
**Q1**: 只能多写 1 字节(off-by-one),覆盖不到返回地址,有戏吗?
**A1**: 有。栈上 off-by-one 常能改到 SFP(保存的 rbp)的最低字节,造成栈帧"抬移",leave;ret 后 rsp 落到你可控区域,间接控流。这叫 off-by-one 抬栈/frame 错位。
**Q2**: 改 rbp 低字节后怎么变成控 PC?
**A2**: 让 rbp 指向你预先布置的假栈帧(内含目标返回地址),函数 `leave;ret` 时把假帧里的地址弹进 rip。关键是精确算 rbp 低字节改成多少能落到你控制的数据上。
**Q3**: 溢出的那 1 字节是 `\x00`(NULL off-by-one)?
**A3**: 那更受限,只能把某指针/长度低字节清零。看清零后能否让"缓冲区边界扩大"或"指针指向低地址结构"形成新原语。NULL 字节 off-by-one 多用于堆,栈上要具体看清零谁。
**Q4**: 1 字节实在做不出稳定利用?
**A4**: 转找程序里能"放大"这 1 字节的循环/复制——若这 1 字节改了一个后续被当长度/计数用的变量,就可能撬动一次更大的越界。把注意力从"1 字节本身"转到"这 1 字节污染了谁"。

### 崩溃了但分不清栈溢出还是堆:定位破坏类型
**Q1**: 程序崩了,但我不确定是栈溢出还是堆破坏,怎么快速判定?
**A1**: 看崩溃点和被踩地址。崩在 `ret`/返回、被踩地址是栈上返回地址 → 栈溢出;崩在 `free`/`malloc` 内部、报 corruption/unlink → 堆;崩在解引用一个被写坏的堆指针 → 堆 overflow/UAF。崩溃现场决定漏洞类型。
**Q2**: 崩在 memcpy/strcpy 内部,两边都可能?
**A2**: 看目标缓冲区来自栈(rbp 相对寻址)还是堆(malloc 返回值)。反查该 buffer 分配处:局部数组是栈,malloc 是堆。分配处一看便知。
**Q3**: 判定错了方向,按栈溢出搞半天不通?
**A3**: 及时回到崩溃现场重判。若返回地址一直完好、Canary 没触发,大概率不是栈溢出,转堆或逻辑维度。别因为"标题写着栈溢出"就锁死,以崩溃证据为准。

### 收发同步:交互时机决定成败
**Q1**: exp 时对时不对,像随机失败,可能是收发没同步?
**A1**: 极可能。用 `recvuntil(b'提示符')` 卡准每个交互边界后再 send,避免在程序还没读时就发、或没收全就继续。所有"随机失败"先怀疑同步,而非利用逻辑。
**Q2**: 程序没有明显提示符,不知道 recvuntil 收到哪?
**A2**: 用 `recv(timeout=)` 试探它到底吐了什么,把真实输出片段当同步锚点。或在关键处小睡加日志观察节奏。先摸清协议再自动化。
**Q3**: leak 的数据和后续输出粘在一起,切不干净?
**A3**: 精确按字节数 `recv(n)` 取 leak,或用其前后固定分隔串 `recvuntil` 夹取。粘包时按结构精确切,别用 `recvline` 赌换行位置。
**Q4**: 同步全对但远程 tube 时不时断?
**A4**: 转排查网络/靶机稳定性与是否触发了远程的崩溃重启,把 exp 做成可自动重连重试(尤其爆破类),用失败次数统计而非单次成败判断利用是否成立。

### one_gadget 约束不满足:调栈或换 gadget
**Q1**: leak 到 libc 想用 one_gadget 一步 getshell,但跑出来说约束不满足(如 `[rsp+0x40]==NULL`)?
**A1**: one_gadget 每个候选都有执行时的寄存器/栈约束。先看当前 rsp/寄存器状态是否天然满足某个候选;不满足就调整——在跳 one_gadget 前用 ROP 把约束要求的内存/寄存器清成 NULL。
**Q2**: 三个候选约束都满足不了?
**A2**: 放弃 one_gadget,老实用 `system("/bin/sh")` 两三个 gadget 的常规 ret2libc。one_gadget 是捷径不是必经,约束难满足时常规路更稳。
**Q3**: 栈上恰好有值挡着约束,清不掉?
**A3**: 换个调用时机——在函数返回链的不同位置触发 one_gadget,那里栈状态不同,可能天然满足另一个候选。或先 stack pivot 到一块干净可控区域再触发,人为制造满足约束的栈环境。

### read 固定字节限制溢出长度:二次读扩容
**Q1**: `read(0, buf, N)` 的 N 刚好只够覆盖返回地址加一两个 gadget,链放不下?
**A1**: 第一阶段用这有限长度做最小 ROP:调一次 `read` 往固定可写地址(.bss)读入完整第二阶段链,并同时栈迁移过去。用程序自己的 read 突破长度上限。
**Q2**: 只够覆盖返回地址,连一个 gadget 都多不出来?
**A2**: 那第一步只把返回地址改到"函数入口再来一遍"(如 vuln 或 main),形成可多次输入的循环,逐次积累。或 partial overwrite 跳到一段能重新读输入的代码。
**Q3**: 迁栈到 .bss 但 PIE 开着 .bss 地址未知?
**A3**: 先解决 leak 拿基址,或迁到已 leak 的栈/libc 相关可写地址。地址未知时迁移目标必须选一个已知地址,否则先补 leak 这一环。

### ASLR 本地关远程开:别依赖固定地址
**Q1**: 本地 `echo 0 > randomize_va_space` 关了 ASLR 打通,远程开着就废,问题在哪?
**A1**: 本地关 ASLR 让 libc/栈地址固定,你的 exp 可能硬编码了这些地址。远程 ASLR 开着地址每次变。必须把所有 libc/栈绝对地址改成"leak 后动态计算"。
**Q2**: 怎么系统性找出 exp 里的"违规硬编码"?
**A2**: 本地也开 ASLR 复现。凡是开了就失败的地址,都是需要动态化的。养成本地就开 ASLR 调试的习惯,别用关 ASLR 骗自己。
**Q3**: 有个地址实在 leak 不到只能赌?
**A3**: 若该地址是 libc 内且已 leak libc 基址,就该能算出来——重查是不是漏用了基址。若是栈地址,转"栈迁移到已知区"或"用环境无关技术"消除对该栈地址的依赖,而不是赌 ASLR。

### 复用 main 返回:多次溢出攒信息
**Q1**: 一次溢出只能做一件事(leak 或 getshell 二选一),但我两件都要,怎么办?
**A1**: 让第一次溢出的 ROP 链末尾把控制流返回到 `main`(或 vuln 函数)开头,形成"打完回到起点"的循环。第一轮 leak libc,第二轮拿着 libc 地址真正 getshell。核心是链尾 ret 到可重入点。
**Q2**: 返回 main 后栈状态乱了,第二次溢出偏移变了?
**A2**: 注意 main 重入时 rsp 可能已偏移。要么在链里把 rsp 也修正回原始位置,要么接受偏移变化、按新布局重算第二轮 payload。调试时对比两轮进入 vuln 时的 rsp。
**Q3**: 程序结构上 main 结束就 exit,回不去?
**A3**: 转找其他可重入点(处理循环、菜单 dispatch),把返回地址指那儿。若全程一次性,转"单链内 leak+用"(ROP 里先 puts 再继续接收)或无泄露技术。回环不了就把两步压一步。

### GOT 可写:改 GOT 劫持控制流
**Q1**: Partial RELRO,GOT 可写,我有个任意写原语,最省事的控流方式?
**A1**: 改 GOT:把一个后续必被调用的函数(如 `printf`/`free`/`atoi`)的 GOT 项改成 `system`(或 one_gadget)。等程序下次调它、且参数恰好是可控字符串(如 `atoi(user_input)`),就变成 `system(user_input)`。选"参数可控"的那个 GOT 改。
**Q2**: 改哪个 GOT 项收益最大?
**A2**: 选调用时第一个参数(rdi)天然是我可控字符串的函数——`atoi/strlen/printf` 常吃用户输入。把它改成 system,下次传 `/bin/sh` 即起 shell,无需额外传参 gadget。
**Q3**: Full RELRO,GOT 只读,改不了?
**A3**: 转其他可写函数指针:libc 的 hook(旧版本 `__free_hook`/`__malloc_hook`)、`exit` 相关的 `__exit_funcs`/tls-storage、或栈上返回地址。GOT 锁死时把劫持目标转到仍可写的间接调用点。
**Q4**: 改了 GOT 但那函数后续根本没被再调用?
**A4**: 白改了。先确认目标函数在你写入后的执行路径上"确实会被调用"。选劫持目标前,先在调试器里确认调用时机与参数,别改一个死项。

### 纯静态 ret2syscall:凑寄存器发 syscall
**Q1**: 静态无 libc、NX 开,要 execve("/bin/sh",0,0),怎么用 syscall 直接干?
**A1**: 拼 ROP 设 `rax=59, rdi=binsh_addr, rsi=0, rdx=0`,再 `syscall; ret`。gadget 全从静态二进制搜。binsh 字符串没有就先 read 写进 .bss。这是不依赖任何库函数的最底层打法。
**Q2**: `pop rdx; ret` 找不到,rdx 清不了?
**A2**: 找等价:`xor edx,edx`、`pop rdx; pop rbx; ret`、或调用一个会顺手把 rdx 设 0 的函数。实在不行用 ret2csu(它能设 rdx)。rdx 是常见短板,csu 是兜底。
**Q3**: `syscall` gadget 都没有?
**A3**: 静态二进制几乎必有 syscall 指令(libc 系统调用封装里)。用 `ROPgadget --binary bin | grep syscall`。若真没有(极端裁剪),转 `int 0x80`(32 位)或找 vsyscall/vdso。
**Q4**: 寄存器凑齐了但 execve 返回 -14(EFAULT)?
**A4**: binsh 地址不对或那块不可读。确认写入的 `/bin/sh\x00` 地址正确、以 NULL 结尾、且 rdi 指向它。EFAULT 是地址问题,回去核对写入与传参地址一致性。

### 该硬刚栈溢出还是找逻辑漏洞:取舍判据
**Q1**: 面前程序有栈溢出迹象,但保护全开利用很难,值不值得死磕?
**A1**: 评估 ROI。若保护全开且无泄露点,栈溢出可能要极复杂链;先花小时间盒扫逻辑漏洞(整数溢出、条件竞争、格式化串、越界读写、后门)。选"到 flag 路径最短"的,而非"最先看到的"。
**Q2**: 怎么判断逻辑漏洞更快?
**A2**: 看是否存在"一步到位"的原语——一个任意读/任意写/直接命令执行的逻辑缺陷,往往比拼几十个 gadget 快得多。有明显逻辑洞时优先它。
**Q3**: 两边都不明显,时间有限先投哪?
**A3**: 先投"信息收集"——把泄露原语找齐。有了泄露,栈溢出难度骤降;没有泄露,再强的溢出也难打。信息优先级高于急着控流。
**Q4**: 死磕栈溢出一个时间盒无进展?
**A4**: 强制切换维度:换漏洞类型、换泄露手段、换利用技术(dlresolve/SROP/BROP)。转向要果断,判据是"同一坑连续无新进展"就换,不和一条路谈恋爱。

### stripped 二进制:定位关键函数
**Q1**: 二进制被 strip,IDA/Ghidra 里全是 sub_xxxx,怎么找到 main 和漏洞函数?
**A1**: 从 `_start` 找 `__libc_start_main` 的第一个参数(rdi/栈)即 main。再从 main 里的输入/输出调用(read/scanf/printf,这些是导入符号还在)交叉引用扩散,定位处理用户输入的关键函数。
**Q2**: 连库函数调用都看不出名字?
**A2**: 动态链接的库函数在 PLT/GOT 里仍有符号(除非静态)。看 call 指向的 plt 项名字。静态 strip 才真难,那时靠 FLIRT 签名/字符串引用/系统调用号识别。
**Q3**: 静态 + strip,函数全裸?
**A3**: 用签名匹配(Ghidra/IDA 的 libc 签名库)恢复标准库函数名,再靠字符串引用("please input"之类)定位处理逻辑。把已识别的库函数当锚点向外扩。
**Q4**: 关键函数就是认不出,逆向卡死?
**A4**: 转动态:直接 fuzz 找崩溃点,gdb 在崩溃处回溯调用栈,反过来定位是哪个函数。静态认不出时,让程序自己崩给你指路。

### 发现后门函数:直接跳还是有坑
**Q1**: 逆向发现一个明显后门(如内含 `system("/bin/sh")` 的未被调用函数),直接把返回地址改成它就行?
**A1**: 大概率行,但先看两点:①栈对齐(64 位 movaps,需要时先 ret 对齐或跳后门里 push 之后的地址)②后门是否需要参数已就位。No PIE 时地址固定直接跳;PIE 时仍需 leak 基址或 partial overwrite。
**Q2**: 直接跳后门入口崩在 movaps?
**A2**: 跳到后门内 `system` 调用前那条指令之后一点(跳过 push rbp 造成的错位),或返回链里先加一个 `ret` gadget 对齐。经典"后门差一个对齐"坑。
**Q3**: 后门需要某个参数等于 magic 才 getshell?
**A3**: 那不是纯地址跳转,要把参数也在栈/寄存器里设好(32 位栈传参,64 位设 rdi)。逆清后门的判断条件,连参数一起构造。
**Q4**: "后门"其实是陷阱(调用后触发检测或删 flag)?
**A4**: 警惕过于明显的后门。先静态读全后门逻辑再跳。若是陷阱,转真正的漏洞利用路径,别被诱饵带偏——出题人有时故意放假后门。

### 泄露栈地址后:靠 argv/环境定位数据
**Q1**: 我 leak 到一个栈地址,想把 `/bin/sh` 放栈上并让 rdi 指它,如何稳定定位?
**A1**: 栈地址每次变,但相对偏移稳定。以 leak 到的栈地址为基准算相对偏移到你写入字符串的位置。或利用固定存在的 `argv[0]`/环境变量(它们在栈高地址,程序路径可能含可控串)。
**Q2**: 栈上找不到稳定可控的字符串位置?
**A2**: 别用栈,转写到地址固定的 .bss(No PIE 时)。栈地址依赖 leak 且偏移易受环境变化影响,可写固定段更稳。判据:能用固定地址就别赌栈。
**Q3**: leak 的栈地址在两次运行间相对偏移也变?
**A3**: 说明栈布局受环境变量/argc 影响。远程环境变量未知会让偏移漂移。转向"环境无关"数据落点(bss/堆已知地址),消除对精确栈偏移的依赖。

### 远程一直打不通:系统性排查方法论
**Q1**: 本地稳、远程死活不通,不想瞎试,有没有排查清单?
**A1**: 有,按嫌疑从高到低:①libc 版本(用远程 libc 本地 patchelf 复现)②栈对齐(链首加 ret 试)③收发同步(recvuntil 卡边界)④硬编码地址(开本地 ASLR 复现揪出)⑤one_gadget 约束/环境栈偏移。逐项排除,别乱改。
**Q2**: 怎么快速验证是不是 libc 问题?
**A2**: 拿远程泄露的函数地址低 12 位查库,若和你用的 libc 不符,基本就是它。换成匹配版本本地 patchelf 复现;本地通了远程大概率也通。libc 是远程失败第一嫌疑。
**Q3**: 每项都排了还是不通,怀疑人生?
**A3**: 加"远程可观测性":分阶段发 payload,每阶段用一个能观测的动作(leak 一个值/触发一次输出)确认走到哪一步崩。把黑盒失败切成有 checkpoint 的分段,定位到具体哪一 gadget/哪一步挂。
**Q4**: 分段发现是某个 gadget 在远程行为不同?
**A4**: 可能该 gadget 属于 libc 而版本不同导致语义变化,或落在了对齐敏感点。换用二进制自身(版本无关)的等价 gadget,或调整链让该步落在对齐边界。把"依赖远程未知量"的那一环替换成"确定量"。
**Q5**: 彻底排不出,时间快到?
**A5**: 换一条整体更鲁棒的利用链:优先 ret2dlresolve(去 libc 依赖)、栈迁移(去栈地址依赖)、write 定长泄露(去截断依赖)。当单点排查无果,用"更少假设的利用架构"整体替换,往往比继续 debug 旧链更快通。
