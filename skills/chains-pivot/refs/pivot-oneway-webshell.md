# 网络可达性 · 仅有单向命令通道时如何建立到内部网段的网络可达性

### 通道方向性的先判定
**Q1**: 拿到一个能执行命令但只见回显的入口,怎么判它是真"单向"还是"其实能双向,只是我没测出来"?
**A1**: 别急着上代理。先分别测两个方向:主机A 向我这里发起 TCP/UDP/ICMP/DNS 出站探针,记下成功和失败的组合;再从我这边向 主机A 的常见端口做入站握手。把"入站表"和"出站表"分开列,单向/双向/半开的差异会直接决定后面选反向、正向还是拉模式。
**Q2**: 探针都返回不确定(既没到我这也没报错)怎么办?
**A2**: 说明命令回显对网络行为不透明。转向【带外观测维度】:让主机A 触发一个必然会经过外部可观测点的动作(比如 DNS 解析一个受控的权威域名),自己在权威侧看有没有查询到,回避对回显的依赖。
**Q3**: 若权威侧也没看到,是不是就死了?
**A3**: 不一定。可能是主机A 没有直接出网,必须经过某个代理/网关。此时问题就从"能不能出"变成"经过谁出"——转向识别代理配置(环境变量、系统注册表、PAC、DNS 分域)。
**Q4**: 若确认是双向可达但延迟高抖动大呢?
**A4**: 说明"能通"不代表"能承载交互"。把通道用途分层:短命令走高延迟通道,大流量另找低时延路径,不要一根管子吃掉所有场景。

### 出站协议探测的顺序
**Q1**: 要探出站,先试哪种协议最划算?
**A1**: 通用启发是越像正常业务越优先:DNS → HTTPS 到大众端点 → HTTP → 指定目的端口 TCP → ICMP → 任意 UDP。背后判据是"低噪声、被拦截概率小、失败也不显眼"。
**Q2**: 每种协议要测什么信号?
**A2**: 三件事:能否建立连接(SYN-ACK)、能否发送应用层数据、返回内容是否被改写(如透明代理会重写 UA、TLS 拦截会换证书)。缺一都会误判"通了但其实不通"。
**Q3**: 如果全部无回声怎么办?
**A3**: 转【反向观测维度】——让主机A 主动做一个必经外部的动作(权威 DNS 查询、公网时间同步),在外部观察是否收到。观察点不在主机A,就绕开了回显盲区。
**Q4**: 探测本身会不会触发告警?
**A4**: 会。所以顺序里越靠前的越"无害",不要一上来就全端口 TCP 扫。判据是"单次探测最坏后果"要小于"多探一次省下的时间价值"。

### 出站白名单形状的假设
**Q1**: 若怀疑有严格出站白名单,怎么假设它的形状?
**A1**: 典型形状:代理按【域名分类】放行,而不是按端口。先假设是 FQDN 分类白名单,再验证是不是 IP 段/SNI 检查。
**Q2**: 怎么低成本区分 FQDN 白名单和 SNI 检查?
**A2**: 拿"知名分类域名"和"新注册域名"分别做 TLS 握手到同端口,再拿"IP 直连不带 SNI"和"带假 SNI"两组对照。差异能反推粒度。
**Q3**: 若确认是 SNI 检查、域前置也失效呢?
**A3**: 【转向合法 SaaS 承载维度】——把隧道流量寄生到"业务必须放行"的类目(源代码托管、协作平台、云存储 API)。不是继续钻同一层,而是切换承载。
**Q4**: 若连 DNS 都被分域(内部 DNS 只解析内网)呢?
**A4**: 说明这台机器没有名字解析出网,必须走内部代理。思路改成识别代理配置,把隧道套进代理里,而不是绕过它。

### 反向连接失败的止损
**Q1**: 试了反向连接到公网监听,但打不通,该继续变形还是换路?
**A1**: 先分类失败原因:是"TCP 握手都完不成"(多为被墙)还是"握手完成后立即被断"(多为应用层检测)。判据不清就继续瞎试是浪费预算。
**Q2**: 若是应用层检测,值得试哪些变形?
**A2**: 换端口(80/443/53)、换协议封装(HTTP CONNECT、WebSocket、TLS)、换 TLS 指纹、换目的 ASN。这些变形回答的是"检测的粒度",而不是"能不能通"。
**Q3**: 全变形都失败怎么办?
**A3**: 【转向拉模式】——不再让主机A 主动连出,而是让它周期性 pull 一个"必然能到"的位置(SaaS 存储、允许列表内的域名)。方向从 push 反转为 pull,通道特征从"长连接"变成"短轮询"。
**Q4**: 拉模式带宽不够跑代理怎么办?
**A4**: 拉模式只承载"控制平面"(下发命令、拿小结果),把"数据平面"另找路径,例如通过已经拉起的第一跳再挖第二层隧道。

### 从回显命令升级到交互式壳
**Q1**: web shell 的执行是"每次一条命令,输出回显",没法用 vim/ssh 这类交互工具。要不要升级?
**A1**: 只有当后续动作【必须】交互(输入密码、按 y/n、看进度条、维持环境变量)时才升级。能用非交互替代(expect 一次性脚本、把命令拼成一行)就不升级,升级本身会引入落地文件和额外通道。
**Q2**: 升级路径优先怎么排?
**A2**: 从轻到重:管道拼接 → 环境变量注入 → 半交互 pty(python/script/socat) → 全交互反向 shell(带窗口大小同步)。前面的能满足就不用后面的。
**Q3**: 若目标上没有 python/perl/script,pty 起不来怎么办?
**A3**: 【转向"把交互挪到本地"维度】——用能带状态的封装(Expect 脚本、one-shot 命令包)在本地拼装,把每一步都变成非交互命令投递过去,而不是硬要在远端起 pty。
**Q4**: 拉起 pty 后卡在窗口大小/信号处理上怎么办?
**A4**: 说明壳的稳定性问题而不是可达性问题。要在同一根管子上加"心跳/窗口同步"控制帧,或者直接换更稳的承载(SSH-over-隧道)。

### 落地二进制的取舍
**Q1**: 要往 主机A 上放一个隧道工具,先决定什么?
**A1**: 决定"链接方式"和"体积"。静态链接省依赖但大、动态链接小但受目标 libc 版本约束。先摸清目标发行版和 libc 版本再选,别盲目丢最新静态版。
**Q2**: 传输方式怎么选?
**A2**: 优先看通道带宽:小工具走 base64 直接贴 → 走 curl/wget 拉 → 走分片重组。判据是"传输时间 + 被检测风险"最低。
**Q3**: 目标磁盘只读或极紧张怎么办?
**A3**: 【转向"无落地"维度】——用内存执行(如通过解释器加载、fd 直接 exec、把工具塞进临时文件系统)。或者干脆改用系统自带工具(ssh、socat、nc、bash /dev/tcp)拼隧道,不落自己的二进制。
**Q4**: 落地了但杀软立即清掉呢?
**A4**: 说明面对的不只是可达性问题,还叠了主机安全维度。要么改名/加壳/延迟执行绕过静态特征,要么退回"用系统自带"路线,要么先处理主机安全再回来处理网络。

### 落地目录的可写可执行判据
**Q1**: 要落地一个二进制,选哪个目录?
**A1**: 三个条件同时满足:当前用户可写、noexec 未挂载、被巡检监控的概率低。先 `mount` 看每个分区的挂载选项,别只看 `ls -la` 的权限。
**Q2**: 常见的坑是什么?
**A2**: /tmp、/var/tmp、/dev/shm 常被 noexec;用户家目录可写但被 EDR 盯;/var/log 有写权限但不能执行。判据是"能写"和"能执行"是两码事。
**Q3**: 所有可写目录都 noexec 怎么办?
**A3**: 【转向"绕过 noexec 的执行方式"维度】——用解释器执行脚本(bash/python/perl)、用 ld.so 直接加载 ELF、把逻辑做成 shared object 让已运行进程加载。执行不一定要靠"exec 一个文件"。
**Q4**: 若连解释器都被限制呢?
**A4**: 退到"复用已有可执行"——利用系统自带的合法工具(curl/socat/ssh/openssl)组合出隧道,不再引入自己的二进制。

### 命令回显缺失时的信息回带
**Q1**: 执行命令但完全没有回显(盲命令),要怎么建通道?
**A1**: 先解决"回带"再谈"通道"。把结果编码到一个自己能观测的侧信道:DNS 查询名、HTTP 请求 URI、时序差异。判据是"侧信道带宽够不够传下一步决策所需的信息"。
