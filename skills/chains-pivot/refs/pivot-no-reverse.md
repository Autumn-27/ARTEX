# 网络可达性 · 出站方向受限(无法回连)时的连接方向决策

### 先判断"无法回连"是全面阻断还是选择性阻断
**Q1**: 反向 shell 打不回来,是不是整条出站方向都死了?
**A1**: 别急着换姿势。先分层验证:目标能不能解析外部域名(DNS 出站)、能不能拉公共 HTTP(S) 页面、能不能 ping 出去。三个维度只要有一个通,就不是"全断"而是"选择性断"。判据:阻断特征是"协议维度"还是"目的地维度",这决定后续用协议伪装还是用中转点。
**Q2**: 目标只能盲执行,没有交互回显,怎么判断?
**A2**: 用最小副作用探针——让目标发起一次带唯一标识的请求到公网可控端点(HTTP/DNS 各一份),自己这端看日志。收到 = 该协议通;没收到 = 要么协议被封要么执行没落地,再交叉验证。
**Q3**: DNS 通但 HTTP 不通,说明什么?
**A3**: 大概率有强制代理或应用层白名单。DNS 通常靠内网递归服务器出去,HTTP 走独立 egress 规则。此时思路要正交切换到"利用现有 DNS 通道"或"寻找代理"。
**Q4**: 这条路根本不通(连 DNS 都出不去),往哪转?
**A4**: 放弃"从内主动出"的方向,正交转到"从外向内"——找一个当前主机能对外暴露的服务端口(比如已监听的 Web 服务)作为正向 shell 入口,由外部主动连进来。方向反转是这类阻断的核心破局思路。
**Q5**: 怎么避免探测本身触发告警?
**A5**: 用低频、拟态正常流量的探针(比如访问一个真实存在的公共域名),而不是敲一个明显的 attacker.example。频率控制在正常业务的量级以下。

### 协议维度选型:TCP / UDP / ICMP 谁最有希望
**Q1**: 已知 TCP 高端口全封,该优先押 UDP 还是 ICMP?
**A1**: 看目标网络画像。企业出口通常允许 DNS(53/UDP)、NTP(123/UDP),ICMP echo 也常放行用于运维监测;严格环境可能反过来。判据:先测"业务必需协议"的通道,业务离不开的通道被封的概率最低。
**Q2**: 三个都能通一部分,选哪个搭隧道?
**A2**: 权衡三点:带宽(TCP > UDP > ICMP)、延迟稳定性(TCP 最稳)、隐蔽性(与业务混杂度)。日常运营场景选 TCP 走 443;短小控制信令场景 UDP/ICMP 更隐蔽。
**Q3**: ICMP 通但被限速,还值得用吗?
**A3**: 只作为控制通道(下发短命令、心跳),数据面另找。混合方向:控制走 ICMP,数据走别的载体。
**Q4**: 三种都不通怎么办?
**A4**: 转向"应用层载体"维度——不再依赖裸协议出站,改用目标已被允许访问的应用服务(邮件网关、代码托管、云对象存储、聊天 API)作为消息中继。方向从"协议隧道"跳到"应用中继"。
**Q5**: 怎么判断某协议是否被状态化跟踪?
**A5**: 观察双向包能否配对通过。若发起包出去、回程被丢,说明状态跟踪或不对称路由。此时得让"回程也从内向外发起",而不是等外部回包。

### HTTP(S) 出站是否能作为隧道载体
**Q1**: 目标能访问互联网 Web,该直接搭 HTTP 隧道吗?
**A1**: 先看有没有强制代理。curl 一个 IP 直连的公网端点,若失败但访问域名成功,说明存在代理或 DNS 强制。判据:是否需要经过 proxy,直接影响隧道客户端的选型。
**Q2**: 存在 TLS 中间人代理,自签 CA 注入客户端信任,还能建 TLS 隧道吗?
**A2**: 能,但载荷会被解开。要么用双层加密(隧道内再套一层),要么伪装成合规业务(SNI 与 Host 对齐白名单域名),避免代理内容策略挑刺。
**Q3**: 只允许特定域名白名单出站,怎么办?
**A3**: 正交转向"域前置"或"合规域名寄生"——利用白名单里的公共 CDN/云服务作为跳板域名。前提是这些服务确实存在于允许列表。评估其可行性时,重点看 SNI 校验严不严。
**Q4**: HTTP 出得去但被内容 IDS 敏感规则匹配,如何降低特征?
**A4**: 三条路:降频(拉长心跳)、拟态(嵌入正常 JSON/图片)、变形(自定义编码+分片)。这是隐蔽性—带宽的权衡,不追求速度就选最像业务的形态。
**Q5**: HTTP 完全不通,往哪转?
**A5**: 转"DNS 载体"或"云存储轮询"方向。DNS 通常最后一个被封,云对象存储(读写公共 bucket)是低门槛替代方案。

### DNS 隧道的适用性与代价评估
**Q1**: DNS 是当前唯一通道,能承载什么?
**A1**: 承载小带宽控制流没问题(几十 bps~几 kbps),交互 shell 勉强,文件传输极慢。判据:先算一次操作要多少字节、能否切分成 DNS 查询字符串长度以内。
**Q2**: 内网 DNS 只递归少数固定后缀怎么办?
**A2**: 判断是否有"内网可解析域"能被利用(比如某些环境为方便运维会转发所有.xxx 后缀)。若无,回退到只做"泄漏心跳"用途,不指望搭双向隧道。
**Q3**: DNS over HTTPS(DoH)通不通?
**A3**: 若 HTTPS 白名单允许了 DoH 提供商,DoH 是绕开内网 DNS 检查的一条路,但特征明显、易被专项策略封。评估要不要用,看防守方检测成熟度。
