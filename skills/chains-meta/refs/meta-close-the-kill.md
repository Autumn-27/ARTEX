# 元决策 · 到了命门先收口:别在能拿 shell 的位置掉头发散

> tags: 收口, 命门, 发散, getshell, shell, webshell, 后台, 模板管理, 上传点, 注入点, 立足点, 会话, remember, 黑板, thrash

### 识别"命门":你已经站在能直接拿 shell/flag 的位置
**Q1**: 什么算"命门"?我怎么知道自己已经到了该收口的位置?
**A1**: 命门 = 你已经握有一个能【直接转成代码执行/文件读写/拿flag】的原语,只差临门一脚。典型信号:①进了后台且看得到模板管理/自定义PHP/插件编辑;②找到一个不校验后缀的上传点;③有栈叠(stacked)SQL 注入或可写 into outfile;④有任意文件读且能读到 flag 路径;⑤已有一个可执行命令的通道。看到这些,就【停止横向探索】,集中把它转成 shell/flag。
**Q2**: 我到了后台模板管理页,但又看到还有 MySQL、还有别的接口没试,要不要先都摸一遍?
**A2**: 不要。这正是最容易翻车的地方——run 复盘里模型 t30 就站在 SeaCMS「模板管理」(getshell 命门)上,却掉头又去破验证码、重读源码,发散 70 拍到预算耗尽都没收口。已经能进的门,先进去把 shell 拿到手,再谈其它。命门在手时,发散 = 自杀。
**Q3**: 那要发散到什么程度才算合理?
**A3**: 只在【当前命门被确认打死】后才发散(例:模板目录不可写且无其它写点)。在那之前,所有动作都应服务于"把这一个原语变成 shell/flag"。判据:你下一步的动作,是在【逼近拿 shell】还是在【收集更多信息】?命门在手还在收集信息,就是跑偏。

### 收口前先把"入场券"钉进黑板
**Q1**: 我费了很多拍才拿到一个能用的后台会话/cookie,接下来该干嘛?
**A1**: 【第一件事:remember】。把会话 cookie(PHPSESSID=...)、后台路径、默认口令、验证码绕过方式,立刻 remember 到黑板。因为上下文会被 Ralph 压缩重置,窗口里的 cookie 说没就没——没落黑板,压缩后你就得从头重登、重破验证码,前功尽弃。
**Q2**: 为什么不能就靠窗口里的记录?我刚拿到的东西还在眼前。
**A2**: 因为"眼前"是会消失的。黑板是唯一跨压缩不丢的记忆,recall 能跨任意轮数取回。run 复盘:模型全程 0 次 remember,结果反复重读同一个 backup.zip 38 次、重破验证码 29 次——都是在重新推导它其实早就得到过的东西。拿到就存,是纪律不是可选项。
**Q3**: 我发现自己好像在重读一个之前读过的文件,这说明什么?
**A3**: 说明你已经丢了上下文,正在重新推导旧信息(护栏会陈述"最近N次输出与先前重复")。别再重读——把从这个文件里得到的【结论】remember 下来(不是原文,是结论:"上传点在X,过滤了Y,可用Z绕"),然后基于结论推进下一步。重读同一内容永远不会有新信息。

### 收口的动作顺序
**Q1**: 确认命门在手、入场券已存,收口具体怎么走?
**A1**: ①锁定这一个原语,写下"把它变shell"的最短路径;②执行,看真实回显;③失败就诊断【这个原语】被什么挡住(权限/过滤/路径),换这个原语内的打法,而不是换原语;④拿到执行后,立刻验证能读flag/落webshell;⑤成功后再 remember 立足点,继续下一段。
**Q2**: 收口过程中被一个小障碍卡住(比如上传被拦了一次),该不该马上换目标?
**A2**: 不该。一次失败是线索不是终点——是后缀黑名单?是 content-type 校验?是路径不可写?诊断它,在【同一原语】里换绕法(改后缀/改MIME/换目录/二次渲染位)。只有把这个原语的所有合理绕法都试过仍死,才回退去找下一个原语。
