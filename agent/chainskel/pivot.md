# chains-pivot L3 决策骨架(场景→判据→转向;蒸馏自 chains 语料,完整 Q&A 见 skills/chains-pivot/refs/)
- 场景:初始 RCE 后立足点怎么建(foothold ladder)|判据:优先写 webshell 建持久主通道——复用入站 HTTP、零出网依赖、混在业务流量里;反弹 shell 只作临时通道|转向:需 PTY 提权/大文件/隧道调试才临时拉反弹,用完即收、受管 TTL 不常驻
- 场景:目标完全不出网(no-reverse)|判据:分层验证 DNS/HTTP/ICMP 出站,判"协议维度"还是"目的地维度"阻断;全断即确认无出网|转向:只能靠 webshell 会话执行;或转拉模式——周期 pull 可控 SaaS/白名单域名取指令
- 场景:起隧道前摸出网能力|判据:curl/nc/dig/ping 分层测 TCP 443/80/53、UDP 53/123、ICMP、DNS 递归;探测须拟态低频|转向:全被 reset 即白名单出网,看 DNS 兜底与强制代理(环境变量/pac),走 CONNECT 出
- 场景:正向 listen 还是反向 connect back|判据:默认反向——正向需公网可达端口且监听显眼;反向穿 NAT/防火墙自然|转向:仅当目标本身对外暴露服务或出向严封入向有洞才正向;里层级联反向连边界机中转
- 场景:代理方案选型(端口转发/SOCKS/tun)|判据:能直连不上代理,每多一跳多一倍失败面;"目标数×端口数"任一为集合才升级 SOCKS|转向:探索模式先上 SOCKS,收敛后回退单端口转发;任意协议/ICMP 才上 tun(需权限)
- 场景:信道选择(TCP 被封后)|判据:TCP 优先 443>80>53,避开 4444/8888 等高位口;TCP 全封按 DNS>UDP>ICMP——DNS 存活率最高但带宽极小(KB/s 级)只作命令通道|转向:ICMP 只跑控制信令;白名单用域前置/合法 SaaS 中转;强制代理走 CONNECT
- 场景:隧道被拦或突然断链|判据:分层定位 L3→L4→TLS→应用层;L4 拦换端口,L7 拦换特征(uTLS 伪装 JA3/SNI、WebSocket over 443);特定命令 100% 失败=特征匹配,二分定位触发串|转向:逐层降级——换协议→换载体→换节点,别在告警窗口硬撞
- 场景:长连接被 idle-timeout 掐断|判据:二分法测出中间设备 idle 阈值,应用层心跳设阈值 1/2~2/3、加随机抖动;周期规律是最大破绽|转向:心跳救不回就换短连接/轮询模型,牺牲交互换稳定
- 场景:单层 webshell 上做内网探测|判据:先不发包拿被动六表——路由表、ARP(arp -a)、netstat 既有连接、hosts、DNS 缓存、SNMP;非默认静态路由必通有价值段,netstat 对端是已知可连的高成功率目标|转向:被动不够再慢扫/24,只扫 22/80/443/445/3389/1433/3306/6379/8080
- 场景:深度侦察发现新网段后|判据:慢速 SYN 探活后只对活主机指纹;并发压到 10~20,别对 /8 全端口喷;双网卡机用 ARP 表跨段交叉比对识别|转向:扫描触发告警立即停,转纯被动嗅探(只听不发),备第二条隧道链路
- 场景:选哪台机器当跳板|判据:三维打分——网络位置(可达段数)、监控敏感度(EDR/日志)、活跃度;理想是"位置好+监控弱+闲置"|转向:域控/堡垒机/CI 只过路不驻留(不落地、内存 socks、用完即拆);拿不下就选次优先撑起
- 场景:多层 pivot 链路管理|判据:控制在三层以内——每层延迟叠加、可用性相乘(四层 99% 只剩 96%),任一抖全链断;同段选一最稳机器做代表|转向:同层双机双活冗余;每层独立健康检查、错峰重连防雪崩;某层被检测只替换该层,别拆整条链
- 场景:低权用户/落地受限|判据:反向连接不需监听,低权即可起;/dev/shm 常可执行,memfd_create/ld.so 可绕 noexec;"能写"与"能执行"是两码事,先 mount 看挂载选项|转向:不能落地就用 LOLBin——ssh -D/-R、bash /dev/tcp、netsh portproxy 拼隧道
- 场景:只有 DNS 出网的极限场景|判据:建 DNS 隧道当命令通道(几十 bps~几 KB/s);命令与文件分通道——文件传合法 SaaS 再通知 C2 下载;降检出必须牺牲带宽|转向:连 DNS 都断就承认此路不通,转一次性任务拿数据即撤,或换机器回侦察找新面
